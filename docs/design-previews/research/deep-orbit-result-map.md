# Deep Orbit result experience by lesson

Research snapshot: November 6, 2026, repository HEAD `8550adf7`. This document proposes product design. It changes no lesson, exercise, runtime, or assessment.

## Findings that shape the design

Every launched lesson already has at least one exercise result declaration. Across 56 current lesson sources, all 65 unique exercise references resolve to YAML with `recordResult()` calls. The 90 declarations comprise 73 tables, 13 series, and four text results. These are source declarations, not proof that a failed run always reaches capture or that production shows every result.

The shared addition should supply trustworthy result context, selection, recovery, and saved-run actions. Each lesson then uses the viewer that answers its crew task. A tensor grid, model score plot, generated report, and runtime fallback trace require different interactions. A universal accuracy card would misrepresent most of the course.

The first two lessons now use the same 12 fictional readings with an explicit sensor header. Many later exercises explicitly use synthetic practice fixtures, mock loaders, controlled callbacks, or supplied fictional scores. Their epilogues often describe a different crew record. Keep these sources visible and separate. This design does not silently replace fixtures, invent a shared trained model, or convert a story measurement into learner evidence. Any future content migration must update briefing, concepts, challenge, hints, recall, and epilogue together.

## Reading the coverage matrix

- “Current” lists every exercise reference in that lesson, including secondary incident and rehearsal exercises. The linked line opens its first result declaration. Result kinds describe existing capture, with counts when a kind repeats.
- The task/source column paraphrases current lesson framing and current exercise provenance. The viewer and interaction column proposes changes. None of the proposed interaction implies that its full supporting data already exists.
- Current result capture commonly occurs within test blocks. Keep execution verdict, result availability, interpretation, assistance, and learning assessment as separate states. A failed interpretation should not hide useful measured output.
- Keep each section’s story and artwork visible before related technical work. Place the active result below its exercise in Challenge. Show a small accurate result reference in a later section only when it supports that section. Preserve recall-answer reveals and earned epilogues.
- Preserve optional concept references as supplied examples. Existing build-service decisions and the room-occupancy assignment are deliberate transfer tasks with different data, not unnoticed switches in the crew recording.

Current source review covered the 56 lesson frontmatter task/consequence records and activity references, all 65 exercise instructions and result declarations, and selected calculation/fixture code. This is a source-based design investigation. It does not renew the older full pedagogical audit or report executed corpus, browser, or learner-study evidence. Current MDX and YAML override stale titles, fixtures, and objective records in the September learning-map JSON.

## Persistence and story boundaries

Save a bounded result when revisiting it helps the task. Early arithmetic traces can remain session results until learner research shows a return need. Reuse the implemented normalization and first-network saved-run stages first, then finish the planned evaluation stage. Do not make all 65 exercises permanent project milestones by default.

Every saved result needs a visible lesson/activity identity, data source, code/content version, timestamp, assistance record, result completeness, and owner/storage scope. Restoring a result should bring back its compatible code and clearly label stale data. A later failed run must not destroy the previous saved evidence. A fresh run after changed code is new evidence, with no implied improvement.

The story can acknowledge the operation the learner completed, such as an arranged chart, inspected prediction, or withheld section. It must not invent a scientific finding or reward a story choice with altered scores. Preserve the canon’s missed capture, unknown event labels, fixed canary, and final unanswered operator note. Keep story decisions optional and explicitly ungraded.
