# Favicon & Icons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dynamic, theme-adaptive favicon and apple touch icon to tensorcraft.app so the site has a browser tab icon and a visible icon in Google search results.

**Architecture:** Next.js App Router route-based icon generation using `ImageResponse`. A `tc_theme` cookie set in the theme layout tells the icon routes which theme color to use. A static `favicon.ico` provides a fallback for legacy browsers.

**Tech Stack:** Next.js `ImageResponse` (from `next/og`), `next/headers` cookies API, `@tensorcraft/themes` palette data, `@tensorcraft/shared` DEFAULT_THEME constant.

**Spec:** `docs/superpowers/specs/2026-04-15-favicon-design.md`

### Task 1: Set `tc_theme` cookie in theme layout

**Files:**
- Modify: `apps/web/app/themes/[slug]/layout.tsx`

- [ ] **Step 1: Modify the theme layout to set a cookie**

The layout already resolves the theme slug from params. Add a cookie set call using `next/headers`:

```tsx
import { notFound } from "next/navigation";
import { cookies } from "next/headers";
import { themes } from "@tensorcraft/themes";

export default async function ThemeLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const theme = themes[slug];
  if (!theme) notFound();

  const cookieStore = await cookies();
  cookieStore.set("tc_theme", slug, {
    path: "/",
    maxAge: 60 * 60 * 24 * 365,
    sameSite: "lax",
  });

  return <div data-theme={slug}>{children}</div>;
}
```

- [ ] **Step 2: Verify the cookie is set**

Run the dev server and navigate to a theme page (e.g. `/themes/deep-orbit`). Open browser DevTools > Application > Cookies and confirm `tc_theme` is set to `deep-orbit`. Navigate to `/themes/neon-protocol` and confirm it updates to `neon-protocol`.

Run: `pnpm --filter web dev`

### Task 2: Create dynamic favicon (`icon.tsx`)

**Files:**
- Create: `apps/web/app/icon.tsx`

- [ ] **Step 1: Create the dynamic icon route**

This uses the same `ImageResponse` pattern as the existing `apps/web/app/api/og/route.tsx`:

```tsx
import { ImageResponse } from "next/og";
import { cookies } from "next/headers";
import { themes } from "@tensorcraft/themes";
import { DEFAULT_THEME } from "@tensorcraft/shared";

export const runtime = "edge";
export const size = { width: 32, height: 32 };
export const contentType = "image/png";

export default async function Icon() {
  const cookieStore = await cookies();
  const themeSlug = cookieStore.get("tc_theme")?.value || DEFAULT_THEME;
  const primary =
    themes[themeSlug]?.palette.primary ||
    themes[DEFAULT_THEME].palette.primary;

  return new ImageResponse(
    <div
      style={{
        width: "100%",
        height: "100%",
        display: "flex",
        alignItems: "center",
        justifyContent: "center",
        backgroundColor: primary,
        color: "#1C1C1C",
        fontSize: 18,
        fontWeight: 700,
        fontFamily: "monospace",
      }}
    >
      T_
    </div>,
    { ...size },
  );
}
```

- [ ] **Step 2: Verify the favicon renders**

Run the dev server and check the browser tab for the icon. It should show `T_` on a green background. Navigate to a different theme page and hard-refresh to see the color change.

Run: `pnpm --filter web dev`

### Task 4: Create static `favicon.ico` fallback

**Files:**
- Create: `apps/web/app/favicon.ico`

- [ ] **Step 1: Generate a static favicon.ico**

Use a script to create a minimal .ico file from the Deep Orbit green brand mark. Since `ImageResponse` can't produce .ico format, generate a 32x32 PNG and convert it:

```bash
# From the project root, use a Node script to generate the .ico:
node -e "
const { createCanvas } = require('canvas');
// If canvas isn't available, use an alternative approach
" 2>/dev/null

# Alternative: create a minimal SVG-based favicon as a data URI in the head
# Or: download a pre-built .ico from a favicon generator
```

Since generating a proper .ico programmatically requires additional tooling, the simplest approach is to use the dynamic `icon.tsx` as the primary favicon (which Next.js auto-detects) and skip the static .ico. Next.js App Router prioritizes `icon.tsx` over `favicon.ico`, and all modern browsers support PNG favicons.

**Decision: Skip `favicon.ico` - the dynamic `icon.tsx` covers all modern browsers and crawlers. Google's crawler supports dynamic favicons.**
