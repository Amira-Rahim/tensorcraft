Last module's autoencoder left holes in its latent space: sample a random point and the decoder hands back garbage, because nothing was ever trained near it. The fix is not more training. It is changing what the encoder outputs. Two vectors instead of one: a mean and a variance, a region instead of a pin.

## Points vs. Distributions

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="variational-encoding.ts">
{`import * as tf from '@tensorflow/tfjs';

// Regular autoencoder: input → single point in latent space
// The space has gaps — random points may decode to garbage
function regularEncoder(inputDim: number, latentDim: number) {
  const model = tf.sequential();
  model.add(tf.layers.dense({ inputShape: [inputDim], units: 256, activation: 'relu' }));
  model.add(tf.layers.dense({ units: latentDim }));  // single point
  return model;
}

// VAE encoder: input → distribution (mean + variance) in latent space
// The space is forced to be smooth — every point decodes to something valid
function vaeEncoder(inputDim: number, latentDim: number) {
  const input = tf.input({ shape: [inputDim] });
  const hidden = tf.layers.dense({ units: 256, activation: 'relu' }).apply(input);

  // Two output heads: mean and log-variance
  const mu = tf.layers.dense({ units: latentDim, name: 'mu' }).apply(hidden);
  const logVar = tf.layers.dense({ units: latentDim, name: 'logVar' }).apply(hidden);

  return tf.model({
    inputs: input,
    outputs: [mu, logVar] as tf.SymbolicTensor[],
  });
}`}
</CodeBlock>

## Why Log-Variance?

We output `log(variance)` instead of `variance` directly because variance must be positive, but neural network outputs can be any number. Taking the exponential of log-variance guarantees positivity.

<CodeBlock language="typescript" title="log-variance.ts">
{`import * as tf from '@tensorflow/tfjs';

// logVar can be any real number: -2.5, 0, 3.7
// exp(logVar) is always positive: 0.08, 1.0, 40.4
// This is the actual variance

// Frontend parallel: CSS uses log-like scales for font sizes
// font-size: 0.75rem, 1rem, 1.25rem, 1.5rem, 2rem
// The scale is exponential, not linear — small changes at small sizes,
// big changes at large sizes. Same idea as exp(logVar).

function latentSample(mu: tf.Tensor, logVar: tf.Tensor): tf.Tensor {
  const std = logVar.mul(0.5).exp();       // std = exp(logVar / 2)
  const epsilon = tf.randomNormal(std.shape as number[]);
  return mu.add(std.mul(epsilon));         // sample = mu + std * noise
}`}
</CodeBlock>

## Challenge

<DerivationDrawer summary="ELBO: the loss VAE actually minimizes">
VAE training maximizes the **Evidence Lower Bound (ELBO)** on log p(x):

`log p(x) ≥ E_{q(z|x)}[ log p(x|z) ] - KL[ q(z|x) || p(z) ]`

Two terms:
- **Reconstruction:** `E_{q(z|x)}[log p(x|z)]` — how well does z decode back to x? Equivalent to MSE for Gaussian likelihood, BCE for Bernoulli.
- **KL regularization:** `KL[ q(z|x) || p(z) ]` — how far is the encoder's distribution q(z|x) from the prior p(z) = N(0, I)?

The encoder outputs `μ(x), σ(x)` for each z dimension. We sample `z ~ N(μ, σ²)` (via the reparameterization trick, next lesson) and decode.

**Why both terms?** Without KL, the encoder could spike σ → 0 and place each x at a unique point, a deterministic autoencoder. Without reconstruction, the encoder ignores x entirely. The β-VAE variant scales the KL term to control the tradeoff: high β = more disentangled latent, lower reconstruction quality.
</DerivationDrawer>
