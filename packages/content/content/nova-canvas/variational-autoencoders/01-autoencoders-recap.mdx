You use compression every day. Brotli compresses your JavaScript bundles. JPEG compresses your images. gzip compresses your API responses. An autoencoder is a neural network that learns its own compression algorithm, customized for the specific data it sees.

## The Compression Pipeline

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="autoencoder.ts">
{`import * as tf from '@tensorflow/tfjs';

// JS: Brotli compression pipeline
// Original JS (1 MB) → compress → Brotli (200 KB) → decompress → JS (1 MB)
// The 200 KB version IS the data, just in a compact representation

// ML: Autoencoder compression pipeline
// Image (784) → encoder → Latent (16) → decoder → Image (784)

function buildAutoencoder(inputDim: number, latentDim: number) {
  const encoder = tf.sequential();
  encoder.add(tf.layers.dense({
    inputShape: [inputDim], units: 256, activation: 'relu'
  }));
  encoder.add(tf.layers.dense({ units: 128, activation: 'relu' }));
  encoder.add(tf.layers.dense({ units: latentDim, activation: 'relu' }));

  const decoder = tf.sequential();
  decoder.add(tf.layers.dense({
    inputShape: [latentDim], units: 128, activation: 'relu'
  }));
  decoder.add(tf.layers.dense({ units: 256, activation: 'relu' }));
  decoder.add(tf.layers.dense({ units: inputDim, activation: 'sigmoid' }));

  // Combined model for training
  const input = tf.input({ shape: [inputDim] });
  const encoded = encoder.apply(input);
  const decoded = decoder.apply(encoded);
  const autoencoder = tf.model({
    inputs: input,
    outputs: decoded as tf.SymbolicTensor,
  });

  autoencoder.compile({
    optimizer: 'adam',
    loss: 'meanSquaredError',
  });

  return { encoder, decoder, autoencoder };
}`}
</CodeBlock>

## Training and Reconstruction

The autoencoder trains by trying to reproduce its input. The loss is the difference between the original and the reconstruction. Watch `val_loss` alongside `loss`: when the bottleneck is wide enough to copy the input instead of compressing it, training loss keeps dropping while validation loss flattens out.

<CodeBlock language="typescript" title="train-autoencoder.ts">
{`import * as tf from '@tensorflow/tfjs';

async function trainAutoencoder(
  autoencoder: tf.LayersModel,
  data: tf.Tensor2D,
  epochs: number = 50
) {
  // Input = Output: the model learns to reconstruct its own input
  await autoencoder.fit(data, data, {
    epochs,
    batchSize: 32,
    validationSplit: 0.1,
    callbacks: {
      onEpochEnd: (epoch, logs) => {
        console.log(
          \`Epoch \${epoch}: loss=\${logs?.loss.toFixed(4)}, val_loss=\${logs?.val_loss.toFixed(4)}\`
        );
      },
    },
  });
}

// THE LIMITATION: autoencoders reconstruct, but cannot generate
// If you sample a random point in the latent space,
// the decoder might produce garbage; the space has "holes"
// VAEs fix this by forcing the latent space to be smooth and continuous`}
</CodeBlock>

<DerivationDrawer summary="Bottleneck dimension as compression bound">
An autoencoder learns to map input x → latent z → reconstruction x̂. Loss is reconstruction:

`L = ||x - x̂||²`

The **bottleneck dimension** dim(z) constrains how much information the model can route through. If x is a 784-pixel MNIST digit and z is dim 8, the autoencoder must compress 784 floats into 8 floats with minimal loss.

**The linear ceiling:** a dim-k autoencoder built from linear layers can at best span the top k principal components, which is exactly what PCA finds. Nonlinear activations are what let an autoencoder beat that ceiling, bending its k axes to follow curved structure that straight ones miss.

**What changes with VAE (next lesson):** the latent is no longer a single vector but a distribution, which forces the model to learn smooth latent geometry.
</DerivationDrawer>
