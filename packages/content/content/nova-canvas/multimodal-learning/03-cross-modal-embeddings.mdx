<Dialogue speaker="Samir">
It is like shared component props. A `ButtonProps` interface works whether the component is React, React Native, or a web component. The interface is the same even though the implementation is completely different.
</Dialogue>

Shared interfaces let different implementations communicate. Cross-modal embeddings do the same: images and text live in the same vector space, sharing the same "interface" (dimensionality and distance metric), even though they come from completely different encoders.

{`import * as tf from '@tensorflow/tfjs';

// Projection head: maps encoder output to the shared space
// Like an adapter pattern: different implementations, same interface
function buildProjectionHead(inputDim: number, outputDim: number): tf.LayersModel {
  const input = tf.input({ shape: [inputDim] });

  let x = tf.layers.dense({
    units: outputDim, activation: 'relu'
  }).apply(input) as tf.SymbolicTensor;
  x = tf.layers.dense({
    units: outputDim, activation: 'linear'
  }).apply(x) as tf.SymbolicTensor;

  // L2 normalize: all embeddings on the unit hypersphere
  const normalized = tf.layers.layerNormalization().apply(x) as tf.SymbolicTensor;

  return tf.model({ inputs: input, outputs: normalized });
}

// Full cross-modal system
class CrossModalEmbedder {
  imageEncoder: tf.LayersModel;
  textEncoder: tf.LayersModel;
  imageProjection: tf.LayersModel;
  textProjection: tf.LayersModel;

  constructor(embeddingDim: number = 256) {
    this.imageEncoder = buildImageEncoder(512);
    this.textEncoder = buildTextEncoder(10000, 32, 512);
    this.imageProjection = buildProjectionHead(512, embeddingDim);
    this.textProjection = buildProjectionHead(512, embeddingDim);
  }

  encodeImage(image: tf.Tensor4D): tf.Tensor2D {
    const features = this.imageEncoder.predict(image) as tf.Tensor2D;
    return this.imageProjection.predict(features) as tf.Tensor2D;
  }

  encodeText(tokens: tf.Tensor2D): tf.Tensor2D {
    const features = this.textEncoder.predict(tokens) as tf.Tensor2D;
    return this.textProjection.predict(features) as tf.Tensor2D;
  }

  // Cross-modal similarity: image vs text
  similarity(image: tf.Tensor4D, text: tf.Tensor2D): tf.Scalar {
    const imgEmb = this.encodeImage(image).squeeze() as tf.Tensor1D;
    const txtEmb = this.encodeText(text).squeeze() as tf.Tensor1D;
    return cosineSimilarity(imgEmb, txtEmb);
  }
}

<DerivationDrawer summary="Why CLIP-style alignment generalizes to unseen modalities">
**CLIP**: aligns image embeddings with text embeddings via contrastive learning over 400M image-text pairs.

**Why this generalizes to zero-shot tasks:** the shared embedding space is dense: for any new (image, text) pair, both can be encoded and their cosine similarity computed directly. No retraining needed.

**Math: what alignment gives you:**

`sim(image, text) = cos(image_encoder(image), text_encoder(text))`

- **Zero-shot classification:** rank classes by `sim(image, prompt(class))`.
- **Image retrieval:** rank a corpus of images by `sim(image_i, query_text)`.
- **Image generation guidance:** maximize `sim(generator(z), prompt)` over z.

**Limits of CLIP-style alignment:**
- The embedding space is shared but not perfectly aligned, so the same concept may have slightly different vectors per modality.
- Long-tail concepts (rare nouns, specialized vocab) are under-represented in training data, embed poorly.
- The cosine geometry forces all relationships to be "similarity": no notion of negation, hierarchy, or temporal order.

Newer approaches (LLaVA, BLIP-2) keep CLIP's image encoder but replace the alignment with a generative LLM that can reason about multimodal input.
</DerivationDrawer>
