## The Bottleneck

The latent dimension is a bottleneck. A 28x28 image has 784 values. Compressing that into 16 dimensions means the encoder must learn which 16 numbers best capture the image's essence.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="dimensionality-tradeoff.ts">
{`import * as tf from '@tensorflow/tfjs';

// Frontend: design system with different numbers of tokens
// Minimal: 3 properties control everything
// --hue, --scale, --density
// Expressive but constrained

// Full: 20 properties for fine control
// --color-primary, --color-secondary, --spacing-xs, --spacing-sm, ...
// Flexible but complex

// ML: autoencoder with different bottleneck sizes
function buildAutoencoder(latentDim: number) {
  const model = tf.sequential();
  // Encoder
  model.add(tf.layers.dense({ inputShape: [784], units: 256, activation: 'relu' }));
  model.add(tf.layers.dense({ units: latentDim, activation: 'relu' }));  // bottleneck
  // Decoder
  model.add(tf.layers.dense({ units: 256, activation: 'relu' }));
  model.add(tf.layers.dense({ units: 784, activation: 'sigmoid' }));
  return model;
}

// Too small (2 dims): blurry reconstructions, lost detail
const tiny = buildAutoencoder(2);

// Good balance (16 dims): captures key features
const balanced = buildAutoencoder(16);

// Too large (256 dims): barely compressing, no useful structure
const large = buildAutoencoder(256);`}
</CodeBlock>

## Measuring the Tradeoff

How do you know if your latent space is the right size? Measure reconstruction error: how well the decoder can rebuild the original from the compressed code.

<CodeBlock language="typescript" title="measure-reconstruction.ts">
{`import * as tf from '@tensorflow/tfjs';

async function measureReconstruction(
  model: tf.Sequential,
  testData: tf.Tensor2D
): Promise<number> {
  const reconstructed = model.predict(testData) as tf.Tensor;
  // Mean squared error between original and reconstruction
  const mse = testData.sub(reconstructed).square().mean();
  return (await mse.array()) as number;
}

// Compare: latentDim=2 → MSE ~0.08 (blurry)
//          latentDim=16 → MSE ~0.02 (good)
//          latentDim=128 → MSE ~0.005 (diminishing returns)`}
</CodeBlock>

## Challenge

<Exercise slug="count-dimensions" />

<DerivationDrawer summary="Intrinsic dimension: why N-dim data may live on a much smaller manifold">
**Ambient dimension:** the number of features in the data (e.g. 784 for MNIST 28x28 grayscale).

**Intrinsic dimension:** the actual degrees of freedom. For MNIST handwritten digits, the intrinsic dim is estimated at ~7-15, even though pixels have 784 axes, valid digits live on a 10-dim manifold.

**How to estimate:**

- **PCA:** count components needed to capture 95% variance. Linear, fast, lower-bound on true dim.
- **Local PCA:** PCA in a neighborhood of each sample. Captures local manifold dimension.
- **TwoNN, MLE estimators:** information-theoretic. More accurate for nonlinear manifolds.

**Implication for latent dim choice:**
- Latent dim ≪ intrinsic dim: information loss, blurry reconstructions
- Latent dim ≈ intrinsic dim: clean reconstruction, disentangled axes
- Latent dim ≫ intrinsic dim: redundancy, collapse to subspace, harder to interpret

For most natural-image datasets, intrinsic dim is 50-200; latent dim 64-256 is the empirical sweet spot.
</DerivationDrawer>
