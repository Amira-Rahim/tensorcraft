A URL shortener takes a long URL and compresses it into a short code. The short code is not random — it encodes the original URL in a way that can be reversed. A latent space works exactly the same way, but for images, sounds, or any complex data.

## Encoding and Decoding

Every latent space has two operations: **encode** (compress data into the space) and **decode** (reconstruct data from the space). Together they form an autoencoder.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="latent-space-concept.ts">
{`import * as tf from '@tensorflow/tfjs';

// Frontend: URL shortener — encode/decode
const urlMap = new Map<string, string>();
function encode(url: string): string {
  const code = btoa(url).slice(0, 6);
  urlMap.set(code, url);
  return code; // compressed representation
}
function decode(code: string): string {
  return urlMap.get(code)!; // reconstruct original
}

// ML: Autoencoder — encode/decode
// Image (784 dims) → Latent code (16 dims) → Reconstructed image (784 dims)
const encoder = tf.sequential();
encoder.add(tf.layers.dense({ inputShape: [784], units: 128, activation: 'relu' }));
encoder.add(tf.layers.dense({ units: 16, activation: 'relu' }));  // bottleneck

const decoder = tf.sequential();
decoder.add(tf.layers.dense({ inputShape: [16], units: 128, activation: 'relu' }));
decoder.add(tf.layers.dense({ units: 784, activation: 'sigmoid' }));

// Encode an image to its latent position
// const latentCode = encoder.predict(imageData);  // [1, 784] → [1, 16]

// const reconstruction = decoder.predict(latentCode);  // [1, 16] → [1, 784]`}

## Why Latent Spaces Matter

The magic is what happens *inside* the latent space. Similar images end up near each other. A face with glasses and a face without glasses might differ by just one dimension. This structure is not designed — it emerges from training.

<CodeBlock language="typescript" title="latent-similarity.ts">
{`import * as tf from '@tensorflow/tfjs';

// In a well-trained latent space:
// - Similar inputs map to nearby points
// - The distance between points is meaningful
// - Moving smoothly through the space creates smooth transitions

// Analogy: CSS color space
// hsl(0, 100%, 50%)   → red
// hsl(10, 100%, 50%)  → orange-red (nearby in hue dimension)
// hsl(180, 100%, 50%) → cyan (far away in hue dimension)
// The HSL space is a "latent space" for colors — each dimension means something

// A trained encoder does the same for complex data:
// Two similar faces → nearby latent vectors
// Two different faces → distant latent vectors
function cosineSimilarity(a: tf.Tensor1D, b: tf.Tensor1D): tf.Scalar {
  const dotProduct = a.dot(b);
  const normA = a.norm();
  const normB = b.norm();
  return dotProduct.div(normA.mul(normB)) as tf.Scalar;
}`}
</CodeBlock>

<DerivationDrawer summary="Latent variables: the bottleneck principle">
A **latent variable** is an unobserved variable inferred from observations. The bottleneck principle: if a model must reconstruct/predict X from a smaller representation z, z is forced to capture only the most-information-preserving features of X.

**Information-theoretic view:**

`I(X; z) = H(X) − H(X | z)`     (mutual information)

The encoder maximizes I(X; z) subject to a capacity constraint on z (small dim, or KL penalty). This is the **information bottleneck** — discard noise, keep signal.

**Practical consequence:**
- Small latent dim → forced compression, learns most-salient features (good for downstream tasks).
- Large latent dim → more reconstruction fidelity, less generalization, easier overfitting.
- VAE adds Gaussian prior → latent space is smooth (interpolations decode coherently).
</DerivationDrawer>
