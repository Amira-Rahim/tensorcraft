Two clocks run in every browser tab. `requestAnimationFrame` ticks roughly every 16.67ms for the eyes; `AudioContext.currentTime` advances with sample-level precision for the ears. Sync means electing one as the source of truth and making the other follow. You've solved this shape of problem with scroll positions, mouse coordinates, API timestamps. The clocks are new; the discipline isn't.

## The Two Clocks

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="sync-clocks.ts">
{`// The browser has two timing systems. You already use both.
// Visual: requestAnimationFrame, ~16.67ms intervals (60fps)
// Audio: AudioContext.currentTime, microsecond precision

const audioCtx = new AudioContext();
const analyser = audioCtx.createAnalyser();
analyser.fftSize = 256;
const frequencyData = new Uint8Array(analyser.frequencyBinCount);
const timeDomainData = new Uint8Array(analyser.fftSize);

// Connect audio source → analyser → speakers
// source.connect(analyser).connect(audioCtx.destination);

function syncLoop() {
  requestAnimationFrame(syncLoop);

  // Read current audio state; this is your bridge
  analyser.getByteFrequencyData(frequencyData);
  analyser.getByteTimeDomainData(timeDomainData);

  // Extract features for visual generation
  const bass = average(frequencyData.slice(0, 4));    // Low frequencies
  const mids = average(frequencyData.slice(4, 32));   // Mid frequencies
  const highs = average(frequencyData.slice(32, 64)); // High frequencies
  const amplitude = Math.max(...timeDomainData) / 255;

  // Drive visuals from audio features
  renderVisualization({ bass, mids, highs, amplitude });
}

function average(arr: Uint8Array): number {
  return arr.reduce((sum, v) => sum + v, 0) / arr.length / 255;
}`}
</CodeBlock>

## Neural Audio-Visual Generation

<CodeBlock language="typescript" title="av-generation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Shared latent space drives both audio and visual generation
// Same z vector → coherent output across modalities
class AVGenerator {
  private visualDecoder: tf.LayersModel;
  private audioDecoder: tf.LayersModel;

  constructor(visualDecoder: tf.LayersModel, audioDecoder: tf.LayersModel) {
    this.visualDecoder = visualDecoder;
    this.audioDecoder = audioDecoder;
  }

  async generate(latent: tf.Tensor) {
    // Same latent vector produces both visual and audio output
    const [visual, audio] = await Promise.all([
      this.visualDecoder.predict(latent) as tf.Tensor,
      this.audioDecoder.predict(latent) as tf.Tensor,
    ]);

    return {
      imageData: await visual.data() as Float32Array,
      audioData: await audio.data() as Float32Array,
    };
  }

  // Smooth transitions: interpolate latent space over time
  async generateSequence(z1: tf.Tensor, z2: tf.Tensor, steps: number) {
    const frames = [];
    for (let i = 0; i < steps; i++) {
      const alpha = i / (steps - 1);
      const z = z1.mul(1 - alpha).add(z2.mul(alpha));
      frames.push(await this.generate(z));
    }
    return frames;
  }
}

// Both modalities evolve together: one latent walk, two outputs
const generator = new AVGenerator(visualModel, audioModel);
const sequence = await generator.generateSequence(z1, z2, 60); // 1 second at 60fps`}
</CodeBlock>

## Reactive Canvas

<CodeBlock language="typescript" title="reactive-canvas.ts">
{`// Map audio features to canvas parameters
function renderVisualization(features: {
  bass: number; mids: number; highs: number; amplitude: number;
}) {
  const canvas = document.getElementById('viz') as HTMLCanvasElement;
  const ctx = canvas.getContext('2d')!;

  // Bass drives background color intensity
  const bgIntensity = Math.floor(features.bass * 40);
  ctx.fillStyle = \`rgb(\${bgIntensity}, \${bgIntensity * 0.5}, \${bgIntensity * 2})\`;
  ctx.fillRect(0, 0, canvas.width, canvas.height);

  // Mids drive shape count and size
  const shapeCount = Math.floor(features.mids * 20) + 1;
  const shapeSize = features.amplitude * 100;

  for (let i = 0; i < shapeCount; i++) {
    const x = (canvas.width / shapeCount) * i + shapeSize / 2;
    const y = canvas.height / 2 + Math.sin(Date.now() / 1000 + i) * features.highs * 100;

    ctx.beginPath();
    ctx.arc(x, y, shapeSize * (0.5 + features.highs), 0, Math.PI * 2);
    ctx.fillStyle = \`hsla(\${i * 30 + features.bass * 360}, 70%, 60%, \${features.amplitude})\`;
    ctx.fill();
  }
}`}

<DerivationDrawer summary="Drift compensation: keeping audio + visual aligned">
Audio and visual events sampled by separate clocks drift over time. Even tiny rate mismatches (e.g. 44099 vs 44100 Hz) accumulate to seconds over minutes.

**Audio-visual sync requirements (ITU-R BT.1359):**
- Lip-sync acceptable: audio between 45ms before and 125ms after video
- Imperceptible: audio between 15ms before and 45ms after video

**Drift estimation:** tag both streams with timestamps from a shared monotonic clock (`performance.now()` for browser). Compare expected vs actual sample-time gap:

`drift_per_minute = (actual_audio_samples − expected_audio_samples) / total_minutes`

**Compensation strategies:**
- **Resampling:** stretch/shrink audio to match video timeline (use sinc interpolation, ~5ms latency).
- **Drop/duplicate samples:** crude but cheap. Audible at high drift rates.
- **Phase Vocoder:** time-stretch without pitch change. Preserves audio quality at the cost of phasey artifacts.
- **PLL (phase-locked loop):** continuously micro-adjust playback rate to track video clock. Used in OS-level audio mixers.

For browser inference, `AudioContext.outputLatency` reports actual sample queue depth → use to compute drift in real-time.
</DerivationDrawer>
