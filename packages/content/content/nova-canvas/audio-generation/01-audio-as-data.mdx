## Waveforms Are Arrays

<BridgeCallout bridge={frontmatter.concept.bridge} />

Every sound you have ever heard through a browser was a `Float32Array`. The Web Audio API decodes compressed audio into PCM samples: raw amplitude values at regular time intervals. TensorFlow.js tensors use the exact same underlying data type.

<CodeBlock language="typescript" title="audio-to-tensor.ts">
{`import * as tf from '@tensorflow/tfjs';

// Load audio using the Web Audio API you already know
const audioCtx = new AudioContext();
const response = await fetch('/audio/ambient.wav');
const arrayBuffer = await response.arrayBuffer();
const audioBuffer = await audioCtx.decodeAudioData(arrayBuffer);

// getChannelData returns Float32Array, already tensor-compatible
const channelData = audioBuffer.getChannelData(0);
console.log('Samples:', channelData.length);       // 44100 * duration
console.log('Sample rate:', audioBuffer.sampleRate); // 44100

// Wrap it in a tensor; zero transformation needed
const waveform = tf.tensor1d(channelData);
console.log('Tensor shape:', waveform.shape); // [numSamples]

// Normalize to [-1, 1] range (usually already normalized, but be safe)
const normalized = waveform.div(waveform.abs().max());`}
</CodeBlock>

## From Waveform to Spectrogram

A waveform tells you amplitude over time. A spectrogram tells you which frequencies are present at each moment. It is a 2D image where the x-axis is time, the y-axis is frequency, and pixel brightness is magnitude.

<CodeBlock language="typescript" title="spectrogram.ts">
{`// Build a spectrogram using Short-Time Fourier Transform
// This is windowed FFT, same concept as CSS scroll-driven animations
// sampling the page at intervals

function buildSpectrogram(
  audio: Float32Array,
  fftSize: number = 1024,
  hopSize: number = 512
): tf.Tensor2D {
  const frames: number[][] = [];
  for (let i = 0; i + fftSize <= audio.length; i += hopSize) {
    const frame = audio.slice(i, i + fftSize);
    // Apply Hann window to reduce spectral leakage
    const windowed = applyHannWindow(frame);
    const magnitudes = computeFFTMagnitudes(windowed);
    frames.push(Array.from(magnitudes));
  }
  // Shape: [numFrames, fftSize/2]; it is a 2D image
  return tf.tensor2d(frames);
}

function applyHannWindow(frame: Float32Array): Float32Array {
  const windowed = new Float32Array(frame.length);
  for (let i = 0; i < frame.length; i++) {
    const multiplier = 0.5 * (1 - Math.cos(2 * Math.PI * i / (frame.length - 1)));
    windowed[i] = frame[i] * multiplier;
  }
  return windowed;
}

const spectrogram = buildSpectrogram(channelData);
console.log('Spectrogram shape:', spectrogram.shape);
// [numTimeFrames, numFrequencyBins], a grayscale image`}
</CodeBlock>

A spectrogram is an image. That single insight is the bridge between everything you have built with visual generation and the world of audio. The same convolutional networks, the same latent spaces, the same generation techniques: they all apply.

<DerivationDrawer summary="Sample rate, Nyquist, and why audio is rank-2 for ML">
**Audio as a function:** continuous-time pressure wave x(t).

**Digital audio:** sample x(t) at discrete intervals. Sample rate fs (samples/second):

- 8 kHz: telephone quality (limited to 4 kHz audible content)
- 16 kHz: speech recognition standard
- 22.05 kHz: low-quality music
- 44.1 kHz: CD-quality (humans can hear up to ~20 kHz)
- 48 kHz: video/professional audio standard

**Nyquist–Shannon sampling theorem:** to represent frequencies up to F, you need sample rate ≥ 2F. Sampling at 44.1 kHz captures up to ~22 kHz (the audible range). Aliasing (frequencies above fs/2 wrapping into the lower band) is why audio engineering puts an anti-aliasing low-pass filter before the ADC.

**Tensor shapes for ML:**
- Mono waveform: [time]                            shape [N]
- Stereo waveform: [time, channel]                 shape [N, 2]
- Batched mono: [batch, time]                      shape [B, N]
- Spectrogram: [time, frequency]                   shape [T, F]
- Mel spectrogram: [time, mel_bins]                 shape [T, M] (M=80 typical)

Most speech/audio models work on mel spectrograms, not raw waveforms. Mel binning compresses 22 kHz into ~80 perceptually-meaningful bands.
</DerivationDrawer>
