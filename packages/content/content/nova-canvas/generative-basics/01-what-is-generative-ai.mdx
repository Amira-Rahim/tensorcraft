## Discriminative vs. Generative

For this lesson, compare two tasks. A **discriminative** classifier estimates a label from an input image. A **generative** image model produces samples from a learned distribution. Our generator starts with noise. Other generators also use a prompt, earlier tokens, or another input; not every ML method fits this two-task comparison.

<BridgeCallout bridge={frontmatter.concept.bridge} />

You already use controlled randomness in JavaScript. Every time you call `Math.random()` to pick a procedural color, jitter a retry delay, or seed a test fixture, you are doing the conceptual equivalent of what a generative model does: producing something new from a source of randomness. The generator learns statistical patterns from examples. Those patterns can include mistakes, bias, and repeated images; the training objective does not define artistic quality.

## Input and output contracts

Changing a loss function changes the training objective. It does not change the number of output values a layer produces. These untrained models demonstrate the two shapes; neither produces useful predictions yet.

<CodeBlock language="typescript" title="model-shapes.ts">
{`import * as tf from '@tensorflow/tfjs';

const classifier = tf.sequential();
classifier.add(tf.layers.dense({ inputShape: [784], units: 1, activation: 'sigmoid' }));

const generator = tf.sequential();
generator.add(tf.layers.dense({ inputShape: [100], units: 64, activation: 'relu' }));
generator.add(tf.layers.dense({ units: 784, activation: 'sigmoid' }));

// Batch dimension first; 784 pixels can be reshaped to 28 by 28.
console.log(classifier.outputShape); // [null, 1]
console.log(generator.outputShape);  // [null, 784]`}
</CodeBlock>

## The Core Idea

A generative model learns a probability distribution from training data. Once trained, you sample from that distribution to create new instances. It aims to capture patterns that generalize beyond those examples. It can also memorize them and produce close copies. New random input does not guarantee an original output. [Carlini and colleagues demonstrated training-image extraction from diffusion models](https://arxiv.org/abs/2301.13188).

<CodeBlock language="typescript" title="simple-generation.ts">
{`import * as tf from '@tensorflow/tfjs';

// The simplest possible "generative model":
// Learn the mean and variance of data, then sample new points
const trainingData = tf.tensor1d([2.1, 1.9, 2.3, 2.0, 1.8, 2.2]);

const mean = trainingData.mean();
const variance = trainingData.sub(mean).square().mean();
const std = variance.sqrt();

// Generate new samples that look like the training data
const newSamples = tf.randomNormal([10]).mul(std).add(mean);
console.log(await newSamples.array());
// Values near the fitted mean, sampled from our normal approximation`}
</CodeBlock>

<DerivationDrawer summary="Discriminative vs generative: model what?">
**Discriminative classifier:** models p(label | data). Examples include logistic regression and a neural network trained to classify images.

**Generative model:** models a data distribution, possibly conditioned on a label or prompt. Some models expose a likelihood; others generate samples without directly evaluating it. Examples include VAEs, GANs, diffusion models, and autoregressive language models.

**Bayes connection:**

`p(label | data) = p(data | label) · p(label) / p(data)`

If you can evaluate p(data | label) and p(label), Bayes' rule gives p(label | data). A discriminative classifier models the latter directly. Cost and accuracy depend on the task, data, and implementation.

**When generative is the right tool:**
- You need new samples (image generation, music, text)
- You want to model data without class labels
- You want candidate values for missing data, with uncertainty checked against held-out examples

Low likelihood can be one anomaly score, but it is not a guarantee that an input is anomalous or that uncertainty is calibrated.
</DerivationDrawer>
