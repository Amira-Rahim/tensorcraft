<Dialogue speaker="Erdem">
The gallery prints are one meter wide. I need at least 1024 by 1024 pixels. Can the model do that?
</Dialogue>

<Dialogue speaker="Samir">
Directly? No. Memory scales quadratically with resolution. A 1024x1024 image has 256 times more pixels than 64x64. The browser tab would crash before step one. So we do what responsive images do: generate at 64x64 where diffusion is fast, then hand it to a lightweight super-resolution model. `srcset` for pixels.
</Dialogue>

<Dialogue speaker="Rohan">
`srcset` picks a file that already exists. Ours does not exist until the second model makes it. Same move though: the print gets the full render, the kiosk gets the sketch.
</Dialogue>

The economics work because the two stages have different jobs. The base model does all the creative work at 64x64, where twenty steps of a distilled denoiser cost about two seconds. The upscaler only has to add plausible detail to an image that already exists, so the climb to print size costs one forward pass instead of a second diffusion run.

## Cascaded Generation Pipeline

<CodeBlock language="typescript" title="cascaded-pipeline.ts">
{`import * as tf from '@tensorflow/tfjs';

// Super-resolution model: upscale 64x64 -> 256x256
function buildSuperResModel(): tf.LayersModel {
  const input = tf.input({ shape: [64, 64, 3] });

  // Upscale 2x: 64 -> 128
  let x = tf.layers.upSampling2d({ size: [2, 2] }).apply(input) as tf.SymbolicTensor;
  x = tf.layers.conv2d({
    filters: 64, kernelSize: 3, padding: 'same', activation: 'relu'
  }).apply(x) as tf.SymbolicTensor;

  // Upscale 2x: 128 -> 256
  x = tf.layers.upSampling2d({ size: [2, 2] }).apply(x) as tf.SymbolicTensor;
  x = tf.layers.conv2d({
    filters: 32, kernelSize: 3, padding: 'same', activation: 'relu'
  }).apply(x) as tf.SymbolicTensor;

  // Output: 256x256x3
  const output = tf.layers.conv2d({
    filters: 3, kernelSize: 3, padding: 'same', activation: 'sigmoid'
  }).apply(x) as tf.SymbolicTensor;

  return tf.model({ inputs: input, outputs: output });
}

// The full cascaded pipeline
async function generateHighRes(
  baseModel: tf.LayersModel,
  superResModel: tf.LayersModel,
  prompt: tf.Tensor2D,
  guidanceScale = 7.5
): Promise<tf.Tensor4D> {
  // Stage 1: fast diffusion at 64x64
  console.time('base-generation');
  const lowRes = await generateWithGuidance(
    baseModel, prompt, 20, guidanceScale // only 20 steps!
  );
  console.timeEnd('base-generation'); // ~2.1 seconds

  // Stage 2: upscale to 256x256
  console.time('super-resolution');
  const highRes = superResModel.predict(lowRes) as tf.Tensor4D;
  console.timeEnd('super-resolution'); // ~1.3 seconds

  lowRes.dispose();
  return highRes; // total: ~3.4 seconds
}

// From 43 seconds to 3.4 seconds, at the same 64x64 base resolution:
// - Fewer denoising steps (100 -> 20), each through a smaller distilled U-Net
// - The climb to 256x256 handled by one upscaler pass, not by diffusion`}

<DerivationDrawer summary="Cascaded vs latent diffusion for high-res">
**Naive scaling fails:** running a U-Net at 1024×1024 with reasonable batch size exceeds memory on most hardware. Two solutions:

**Cascaded diffusion** (Imagen):
```
base model:    text → 64×64 image
upsampler 1:  64×64 + text → 256×256
upsampler 2:  256×256 + text → 1024×1024
```
Each stage is a separate diffusion model conditioned on the previous output.

**Latent diffusion** (Stable Diffusion):
```
VAE encoder:  1024×1024 image → 128×128 latent  (8× downsample, 4 channels)
diffusion in latent space:  128×128×4 → 128×128×4
VAE decoder:  128×128 latent → 1024×1024 image
```
Diffusion runs on the small latent. The VAE adds quality loss (the latent can't represent every image perfectly) but compute is ~64× cheaper.

**Tradeoff:** cascaded preserves detail better but costs more inference. Latent is cheaper but VAE quirks (color shifts, fine-detail blurring) become the bottleneck. Most modern systems use latent diffusion.
</DerivationDrawer>
