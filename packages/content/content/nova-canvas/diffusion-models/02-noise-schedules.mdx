Rohan's correction sets the stakes. The noise schedule (also called the beta schedule) fixes how much noise enters at each timestep during training, and that decides which timesteps the model gets practice on. A linear schedule hands most of that practice to timesteps that are already unrecoverable static.

## Linear vs Cosine Schedules

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="noise-schedules.ts">
{`import * as tf from '@tensorflow/tfjs';

// LINEAR SCHEDULE: constant rate of noise addition
// Like transition-timing-function: linear (mechanical, unnatural)
function linearSchedule(timesteps: number): number[] {
  const betaStart = 0.0001;
  const betaEnd = 0.02;
  const betas: number[] = [];
  for (let i = 0; i < timesteps; i++) {
    betas.push(betaStart + (betaEnd - betaStart) * (i / (timesteps - 1)));
  }
  return betas;
}

// COSINE SCHEDULE: slow start, faster middle, slow end
// Like transition-timing-function: ease-in-out (preserves structure)
function cosineSchedule(timesteps: number, s = 0.008): number[] {
  const alphaBar = (t: number) => {
    const angle = ((t / timesteps + s) / (1 + s)) * (Math.PI / 2);
    return Math.cos(angle) ** 2;
  };

  const betas: number[] = [];
  for (let i = 1; i <= timesteps; i++) {
    const beta = 1 - alphaBar(i) / alphaBar(i - 1);
    betas.push(Math.min(beta, 0.999)); // clip for stability
  }
  return betas;
}

// Compare: how much signal remains at each step?
function cumulativeAlpha(betas: number[]): number[] {
  const alphas = betas.map(b => 1 - b);
  const cumAlpha: number[] = [];
  let product = 1;
  for (const a of alphas) {
    product *= a;
    cumAlpha.push(product);
  }
  return cumAlpha;
}

const linear = cumulativeAlpha(linearSchedule(1000));
const cosine = cumulativeAlpha(cosineSchedule(1000));

// At step 500, halfway through the DDPM default T = 1000:
console.log('Linear alpha_bar[500]:', linear[500].toFixed(3));  // ~0.08
console.log('Cosine alpha_bar[500]:', cosine[500].toFixed(3));  // ~0.49
// Cosine still holds half the signal at the midpoint; linear is down to 8%.
// betaStart/betaEnd above are tuned for T = 1000. Reuse them at T = 100 and
// the same code barely dents the image.`}
</CodeBlock>

## Applying the Schedule to Noise

<CodeBlock language="typescript" title="apply-schedule.ts">
{`// Use cumulative alpha to add noise at any timestep directly
function addNoiseAtStep(
  image: tf.Tensor4D,
  noise: tf.Tensor4D,
  alphaBar: number
): tf.Tensor4D {
  // x_t = sqrt(alpha_bar) * x_0 + sqrt(1 - alpha_bar) * noise
  const signalCoeff = Math.sqrt(alphaBar);
  const noiseCoeff = Math.sqrt(1 - alphaBar);

  return tf.add(
    tf.mul(image, tf.scalar(signalCoeff)),
    tf.mul(noise, tf.scalar(noiseCoeff))
  ) as tf.Tensor4D;
}

// A quarter of the way through a cosine schedule, most of the image is still there
const schedule = cumulativeAlpha(cosineSchedule(100));
const img = tf.randomUniform([1, 64, 64, 3]) as tf.Tensor4D;
const noise = tf.randomNormal([1, 64, 64, 3]) as tf.Tensor4D;

const noisy25 = addNoiseAtStep(img, noise, schedule[25]);
console.log('Signal preserved at step 25:', (schedule[25] * 100).toFixed(1) + '%');`}
</CodeBlock>

<DerivationDrawer summary="β schedule + ᾱ accumulation">
The noise schedule β_1, β_2, ..., β_T controls how much noise is added at each timestep. Common choices:

- **Linear:** `β_t = β_min + (t/T)(β_max - β_min)`. Original DDPM. Common values: β_min = 0.0001, β_max = 0.02, T = 1000.
- **Cosine:** `ᾱ_t = cos²((t/T + s) / (1 + s) · π/2)`. Pushes more noise into early timesteps. Better quality for image generation.
- **Sigmoid:** smoother transitions for very long T.

**The cumulative product ᾱ_t = ∏(1 - β_s) determines how much signal remains at step t.** When ᾱ_t ≈ 1, x_t is mostly x_0. When ᾱ_t ≈ 0, x_t is mostly noise. The transition from signal to noise should be gradual to give the model enough learning signal at every t.

**T (number of steps)** trades quality for compute. T = 1000 is the original DDPM; sampling can be accelerated to T = 50 (DDIM) or even T = 4 (consistency models) at the cost of quality.
</DerivationDrawer>
