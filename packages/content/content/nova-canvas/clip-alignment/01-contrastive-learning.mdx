<Dialogue speaker="Rohan">
A/B testing works by comparison. You show variant A to half your users and variant B to the other half. You learn which is better not from theory but from direct comparison. Contrastive learning works the same way.
</Dialogue>

<Dialogue speaker="Erdem">
So the model sees a batch of images and captions and has to figure out which go together?
</Dialogue>

<Dialogue speaker="Rohan">
Exactly. In a batch of 32, there are 32 correct pairs and 992 incorrect pairs. The model learns by getting better at telling them apart. Learning by comparison — not by memorization.
</Dialogue>

You already use A/B testing to learn what works by comparison. Contrastive learning applies the same principle to embeddings — the model learns which image-text pairs match by comparing them against mismatches.

## Learning by Comparison

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="contrastive-learning.ts">
{`import * as tf from '@tensorflow/tfjs';

// A/B TESTING ANALOGY:
// Variant A = image-text pair that matches (positive)
// Variant B = image-text pair that doesn't match (negative)
// Metric = similarity score (like conversion rate)
// Goal = the model should "prefer" the correct pairing

// InfoNCE Loss: the core of contrastive learning
function infoNCELoss(
  imageEmbeddings: tf.Tensor2D, // [batch, dim]
  textEmbeddings: tf.Tensor2D,  // [batch, dim]
  temperature: number = 0.07
): tf.Scalar {
  // Normalize embeddings to unit vectors
  const normImages = tf.div(
    imageEmbeddings,
    tf.norm(imageEmbeddings, 2, 1, true)
  );
  const normTexts = tf.div(
    textEmbeddings,
    tf.norm(textEmbeddings, 2, 1, true)
  );

  // Compute all-pairs similarity matrix
  // similarities[i][j] = cosine similarity of image_i and text_j
  const similarities = tf.matMul(normImages, normTexts, false, true);

  // Scale by temperature (sharpens the distribution)
  const logits = tf.div(similarities, tf.scalar(temperature));

  // Labels: image_i should match text_i (the diagonal)
  const batchSize = imageEmbeddings.shape[0];
  const labels = tf.range(0, batchSize, 1, 'int32');
  const oneHot = tf.oneHot(labels, batchSize);

  // Symmetric loss: image->text + text->image
  const lossI2T = tf.losses.softmaxCrossEntropy(oneHot, logits);
  const lossT2I = tf.losses.softmaxCrossEntropy(oneHot, logits.transpose());

  return tf.div(tf.add(lossI2T, lossT2I), tf.scalar(2)) as tf.Scalar;
}

// Temperature controls "confidence":
// Low temp (0.01): model must be very sure — sharp distribution
// High temp (1.0): model can be uncertain — flat distribution
// Default (0.07): balanced — a well-tuned A/B test`}
</CodeBlock>

<DerivationDrawer summary="InfoNCE / NT-Xent contrastive loss formula">
**InfoNCE loss** for a batch of N pairs `(anchor_i, positive_i)`, with all other positives in the batch acting as negatives:

```
L_i = −log( exp(sim(a_i, p_i) / τ) / Σ_{j=1..N} exp(sim(a_i, p_j) / τ) )
```

- `sim(a, b)`: cosine similarity, often `a · b / (||a|| · ||b||)`
- `τ`: temperature, controls sharpness (typical 0.05 to 0.5; lower = harder negatives matter more)
- Numerator: similarity to true positive
- Denominator: similarity to all candidates (including the positive)

**Effective batch size matters massively.** Larger batch = more negatives per positive = harder learning task = better representations. CLIP trained with batch size 32,768. SimCLR showed batch 4096+ is needed for ImageNet-quality representations.

**Symmetric loss** (CLIP-style, both directions):

`L_total = (L_image-to-text + L_text-to-image) / 2`

For a batch of (image, caption) pairs: image_i should match caption_i (and only caption_i), AND caption_i should match image_i.
</DerivationDrawer>
