The discriminator is the mirror image of the generator. Where the generator *expands* noise into an image, the discriminator *compresses* an image into a single number: the probability that the input is real.

## The Downscaling Pipeline

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="discriminator-architecture.ts">
{`import * as tf from '@tensorflow/tfjs';

function buildDiscriminator(): tf.Sequential {
  const model = tf.sequential();

  // Layer 1: Receive flattened image
  model.add(tf.layers.dense({
    inputShape: [784],
    units: 512,
    activation: 'leakyReLU',
  }));
  model.add(tf.layers.dropout({ rate: 0.3 }));

  // Layer 2: Compress further
  model.add(tf.layers.dense({
    units: 256,
    activation: 'leakyReLU',
  }));
  model.add(tf.layers.dropout({ rate: 0.3 }));

  // Output: single probability — real (1) or fake (0)
  model.add(tf.layers.dense({
    units: 1,
    activation: 'sigmoid',
  }));

  return model;
}

const discriminator = buildDiscriminator();
discriminator.compile({
  optimizer: tf.train.adam(0.0002, 0.5),
  loss: 'binaryCrossentropy',
  metrics: ['accuracy'],
});`}
</CodeBlock>

## Why Dropout Matters

Dropout randomly deactivates neurons during training. For discriminators, this is critical: without it, the discriminator learns too fast and the generator cannot keep up.

<CodeBlock language="typescript" title="dropout-balance.ts">
{`import * as tf from '@tensorflow/tfjs';

// Frontend analogy: progressive form validation
// Simple check first, detailed check later
function validateForm(data: FormData): { valid: boolean; confidence: number } {
  // Level 1: Quick format check (like first dense layer)
  if (!data.email?.includes('@')) return { valid: false, confidence: 0.9 };

  // Level 2: Deeper check (like second dense layer)
  if (data.email.split('@')[1].length < 3) return { valid: false, confidence: 0.7 };

  // Final verdict (like sigmoid output)
  return { valid: true, confidence: 0.85 };
}

// Dropout = randomly skipping some checks during training
// This prevents the validator from becoming TOO strict TOO fast
// Without dropout: discriminator crushes generator early
// With dropout: discriminator stays beatable → generator improves`}
</CodeBlock>

## Generator + Discriminator: The Full GAN

<CodeBlock language="typescript" title="full-gan.ts">
{`import * as tf from '@tensorflow/tfjs';

// The combined model: noise → generator → discriminator → real/fake
function buildGAN(generator: tf.Sequential, discriminator: tf.Sequential) {
  // Freeze discriminator weights when training generator
  discriminator.trainable = false;

  const ganInput = tf.input({ shape: [100] });
  const generated = generator.apply(ganInput);
  const validity = discriminator.apply(generated);

  const gan = tf.model({ inputs: ganInput, outputs: validity as tf.SymbolicTensor });
  gan.compile({
    optimizer: tf.train.adam(0.0002, 0.5),
    loss: 'binaryCrossentropy',
  });
  return gan;
}`}
</CodeBlock>

<DerivationDrawer summary="Discriminator gradient math + label smoothing">
**Discriminator loss** (binary cross-entropy formulation):

`L_D = −E[log D(x)] − E[log(1 − D(G(z)))]`

- First term: minimized when D(x) → 1 on real samples.
- Second term: minimized when D(G(z)) → 0 on fakes.

**Gradient:** `∂L_D / ∂θ_D` updates D to better separate. When D becomes too strong, `D(G(z)) ≈ 0` → second-term gradient vanishes (log(1-0) = 0) → G stops getting useful signal. This is the **vanishing generator gradient** problem.

**Label smoothing fix:** replace target `1` with `0.9` for real labels (and `0` with `0.1` for fakes). Prevents D from being too confident, keeps gradients flowing to G. Common in modern GAN training.
</DerivationDrawer>
