Think of a template engine. You feed it a small data object — title, items, theme — and it expands that into a full HTML page. Every template call produces a different page, but they all follow the same structure. A generator does the same thing: small input, structured output.
</Dialogue>

A generator is an upscaling pipeline. It takes a compact noise vector (the seed) and progressively expands it through layers until it reaches the target resolution. Each layer adds detail and structure.

## The Upscaling Pipeline

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="generator-architecture.ts">
{`import * as tf from '@tensorflow/tfjs';

function buildGenerator(noiseDim: number = 100): tf.Sequential {
  const model = tf.sequential();

  // Layer 1: Expand noise into a base representation
  model.add(tf.layers.dense({
    inputShape: [noiseDim],
    units: 256,
    activation: 'leakyReLU',
  }));
  model.add(tf.layers.batchNormalization());

  // Layer 2: Further expansion
  model.add(tf.layers.dense({
    units: 512,
    activation: 'leakyReLU',
  }));
  model.add(tf.layers.batchNormalization());

  // Layer 3: Expand to image dimensions
  model.add(tf.layers.dense({
    units: 1024,
    activation: 'leakyReLU',
  }));
  model.add(tf.layers.batchNormalization());

  // Output layer: 784 pixels (28x28), sigmoid for [0,1] range
  model.add(tf.layers.dense({
    units: 784,
    activation: 'sigmoid',
  }));

  return model;
}

const generator = buildGenerator();
console.log(generator.summary());
// Input: [null, 100]  → Output: [null, 784]`}
</CodeBlock>

## Key Design Choices

Three architectural decisions define a good generator:

<CodeBlock language="typescript" title="design-choices.ts">
{`import * as tf from '@tensorflow/tfjs';

// 1. ACTIVATION: LeakyReLU for hidden layers
// Regular ReLU kills gradients (output = 0 for negative input)
// LeakyReLU lets a small gradient through: max(0.2 * x, x)
// This keeps the generator learning even in "dead zones"

// 2. BATCH NORMALIZATION: stabilizes training
// Without it, each layer's input distribution shifts during training
// BatchNorm normalizes each layer's input → faster, more stable training
// Rule: BatchNorm after dense, before activation (or after — both work)

// 3. OUTPUT ACTIVATION: sigmoid or tanh
// sigmoid: output in [0, 1] — good for images normalized to [0, 1]
// tanh: output in [-1, 1] — good for images normalized to [-1, 1]

// Why not ReLU for the output?
// ReLU has no upper bound — pixel values could explode
// We need bounded output for valid image data

function buildGeneratorV2(noiseDim: number): tf.Sequential {
  const model = tf.sequential();
  model.add(tf.layers.dense({
    inputShape: [noiseDim], units: 256,
  }));
  model.add(tf.layers.batchNormalization());
  model.add(tf.layers.leakyReLU({ alpha: 0.2 }));

  model.add(tf.layers.dense({ units: 512 }));
  model.add(tf.layers.batchNormalization());
  model.add(tf.layers.leakyReLU({ alpha: 0.2 }));

  model.add(tf.layers.dense({ units: 784, activation: 'tanh' }));
  return model;
}`}
</CodeBlock>
