<Dialogue speaker="Hassan Al-Rashid">
Never optimize without a plan. I have watched engineers spend three weeks quantizing a model that needed an architecture change. Profile first. Set your budget. Then execute in order of impact.
</Dialogue>

In JavaScript, your build optimization follows a systematic order: tree-shake unused code, minify what remains, compress the output, code-split for lazy loading. You do not choose that order; the bundler does, and it is the same order every build. Model optimization needs the same sequencing, with one difference that costs money if you miss it: here the order changes the result. Prune then quantize and you get a different model than quantize then prune.

{`interface OptimizationStep {
  name: string;
  expectedSizeReduction: string;
  risk: 'low' | 'medium' | 'high';
  accuracyImpact: string;

const optimizationPipeline: OptimizationStep[] = [
  {
    name: '1. Architecture Review',
    expectedSizeReduction: '30-60%',
    risk: 'low',
    accuracyImpact: 'None if done correctly'
  },
  {
    name: '2. Weight Pruning',
    expectedSizeReduction: '50-90%',
    risk: 'medium',
    accuracyImpact: '0-5% loss typical'
  },
  {
    name: '3. Quantization (Float32 → Int8)',
    expectedSizeReduction: '75% (4x smaller)',
    risk: 'low',
    accuracyImpact: '0-2% loss typical'
  },
  {
    name: '4. Knowledge Distillation',
    expectedSizeReduction: '60-95%',
    risk: 'medium',
    accuracyImpact: '1-5% loss typical'
  },
  {
    name: '5. Combined + Fine-tune',
    expectedSizeReduction: 'Compound savings',
    risk: 'high',
    accuracyImpact: 'Must validate carefully'
  }
];

// JS parallel:
// 1. Architecture → Component refactoring
// 2. Pruning → Tree-shaking
// 3. Quantization → Minification
// 4. Distillation → Code-splitting
// 5. Combined → Full production build config`}
</CodeBlock>

The steps are not independent. They compound, and they interfere, which is why the order in the list is the order you run them. Multiply the survival ratios: architecture review leaves 60% of the original, pruning halves that, quantization cuts it by another factor of four. That is 0.075 of the original, roughly 13x smaller, which puts a 1.8GB model at about 135MB. Run pruning after quantization instead and you get a different number, because there is less signal left to decide which weights to drop.

## Challenge
