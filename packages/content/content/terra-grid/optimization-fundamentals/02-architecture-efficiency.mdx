<Dialogue speaker="Hassan Al-Rashid">
Before you compress a model, ask whether the architecture itself is efficient. You would not minify a React component that re-renders 60 times per second. You would fix the component first.
</Dialogue>

The cheapest optimization is not compression — it is choosing the right architecture from the start. Just as `React.memo` and `useMemo` prevent unnecessary computation in your components, efficient architectures prevent unnecessary computation in your model.

## The Bottleneck Pattern

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="efficient-architecture.ts">
{`import * as tf from '@tensorflow/tfjs';

// Naive: 512 → 512 direct connection
function naiveModel(): tf.Sequential {
  const model = tf.sequential();
  model.add(tf.layers.dense({ inputShape: [256], units: 512, activation: 'relu' }));
  model.add(tf.layers.dense({ units: 512, activation: 'relu' })); // 262,656 params
  model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
  return model;
}

// Efficient: 512 → 32 → 512 bottleneck
function efficientModel(): tf.Sequential {
  const model = tf.sequential();
  model.add(tf.layers.dense({ inputShape: [256], units: 512, activation: 'relu' }));
  model.add(tf.layers.dense({ units: 32, activation: 'relu' }));  // 16,416 params
  model.add(tf.layers.dense({ units: 512, activation: 'relu' })); // 16,896 params
  model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
  return model;
}

const naive = naiveModel();
const efficient = efficientModel();

console.log(\`Naive: \${naive.countParams()} params\`);     // 394,241
console.log(\`Efficient: \${efficient.countParams()} params\`); // 164,897
// 58% fewer parameters with comparable capacity`}
</CodeBlock>

The bottleneck forces the model to learn a compressed representation — like reducing 512 dimensions down to 32 essential features, then expanding back. It is the model architecture equivalent of lazy loading: only compute what you actually need.
