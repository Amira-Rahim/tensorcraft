<Dialogue speaker="Hassan Al-Rashid">
Before you compress a model, ask whether the architecture itself is efficient. You would not buy a bigger machine to run a loop that scans the same array a million times. You would fix the loop.
</Dialogue>

The cheapest optimization is choosing the right architecture from the start, before any compression. An index that turns a nested scan into a lookup is the same move at a different scale: the work never happens, because the design stopped asking for it.

## The Bottleneck Pattern

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="efficient-architecture.ts">
{`import * as tf from '@tensorflow/tfjs';

// Naive: 512 → 512 direct connection
function naiveModel(): tf.Sequential {
  const model = tf.sequential();
  model.add(tf.layers.dense({ inputShape: [256], units: 512, activation: 'relu' }));
  model.add(tf.layers.dense({ units: 512, activation: 'relu' })); // 262,656 params
  model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
  return model;
}

// Efficient: 512 → 32 → 512 bottleneck
function efficientModel(): tf.Sequential {
  const model = tf.sequential();
  model.add(tf.layers.dense({ inputShape: [256], units: 512, activation: 'relu' }));
  model.add(tf.layers.dense({ units: 32, activation: 'relu' }));  // 16,416 params
  model.add(tf.layers.dense({ units: 512, activation: 'relu' })); // 16,896 params
  model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
  return model;
}

const naive = naiveModel();
const efficient = efficientModel();

console.log(\`Naive: \${naive.countParams()} params\`);     // 394,753
console.log(\`Efficient: \${efficient.countParams()} params\`); // 165,409
// 58% fewer parameters, and the 32-unit layer is where you pay for it`}
</CodeBlock>

The bottleneck forces the model to learn a compressed representation, like reducing 512 dimensions down to 32 essential features, then expanding back. That squeeze is the whole mechanism, and it is also the cost. Everything the model wants to say about a reading has to fit through 32 numbers. Capacity you did not need is gone, and capacity you did need may be gone too. The parameter count tells you nothing about which one happened, so measure accuracy before you keep the change.
