<Dialogue speaker="Tariq Hussain">
Last month someone deployed a model that benchmarked at 45ms on their laptop and ran at 890ms on the gateway. We need standardized benchmarks that reflect real device performance. No more surprises in the field.
</Dialogue>

The timing primitives here are the familiar ones, `performance.mark()` and `performance.measure()`, with ML-specific rituals layered on: warm-up runs, batch sizes, and memory tracking. One vocabulary note before the code: p95 is the latency that 95% of runs beat; the slowest 5% live above it, and on an edge gateway those are the runs that matter.

## Standardized Measurement

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="benchmark-model.ts">
{`import * as tf from '@tensorflow/tfjs';

interface BenchmarkResult {
  meanMs: number;
  p95Ms: number;
  p99Ms: number;
  throughputPerSec: number;
  peakMemoryMB: number;
}

async function benchmarkModel(
  model: tf.LayersModel,
  inputShape: number[],
  warmupRuns: number = 10,
  measureRuns: number = 100
): Promise<BenchmarkResult> {
  const input = tf.randomNormal([1, ...inputShape]);

  // Warm-up: let JIT optimize (like browser JIT for JS)
  for (let i = 0; i < warmupRuns; i++) {
    const pred = model.predict(input) as tf.Tensor;
    pred.dispose();
  }

  // Measure
  const times: number[] = [];
  for (let i = 0; i < measureRuns; i++) {
    const start = performance.now();
    const pred = model.predict(input) as tf.Tensor;
    pred.dataSync(); // Force synchronous completion
    const elapsed = performance.now() - start;
    times.push(elapsed);
    pred.dispose();
  }

  input.dispose();
  times.sort((a, b) => a - b);

  return {
    meanMs: times.reduce((a, b) => a + b) / times.length,
    p95Ms: times[Math.floor(times.length * 0.95)],
    p99Ms: times[Math.floor(times.length * 0.99)],
    throughputPerSec: 1000 / (times.reduce((a, b) => a + b) / times.length),
    peakMemoryMB: tf.memory().numBytes / (1024 * 1024)
  };
}`}
</CodeBlock>

The warm-up phase is critical. Just as V8's JIT compiler optimizes hot functions after a few calls, TensorFlow.js optimizes tensor operations after initial runs. Skipping warm-up gives you artificially slow first-run numbers.
