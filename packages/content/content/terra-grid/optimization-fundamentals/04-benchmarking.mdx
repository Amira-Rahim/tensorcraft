<Dialogue speaker="Tariq Hussain">
Last month someone deployed a model that benchmarked at 45ms on their laptop and ran at 890ms on the gateway. We need standardized benchmarks that reflect real device performance. No more surprises in the field.
</Dialogue>

You already have the clock: `performance.now()`, the same clock `performance.measure()` reads, available as a global in Node and in the browser. What changes is the ritual around it: warm-up runs before any number counts, and percentiles instead of an average. One vocabulary note before the code. p95 is the latency 95% of runs come in under. The slowest 5% live above it, and on an edge gateway those are the runs that wake Tariq up.

## Standardized Measurement

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="benchmark-model.ts">
{`import * as tf from '@tensorflow/tfjs';

interface BenchmarkResult {
  meanMs: number;
  p95Ms: number;
  p99Ms: number;
  throughputPerSec: number;
  peakMemoryMB: number;
}

async function benchmarkModel(
  model: tf.LayersModel,
  inputShape: number[],
  warmupRuns: number = 10,
  measureRuns: number = 100
): Promise<BenchmarkResult> {
  const input = tf.randomNormal([1, ...inputShape]);

  // Warm-up: first runs pay one-time kernel compilation and buffer allocation
  for (let i = 0; i < warmupRuns; i++) {
    const pred = model.predict(input) as tf.Tensor;
    pred.dispose();
  }

  // Measure
  let peakBytes = 0;
  const times: number[] = [];
  for (let i = 0; i < measureRuns; i++) {
    const start = performance.now();
    const pred = model.predict(input) as tf.Tensor;
    pred.dataSync(); // Force synchronous completion
    const elapsed = performance.now() - start;
    peakBytes = Math.max(peakBytes, tf.memory().numBytes);
    times.push(elapsed);
    pred.dispose();
  }

  input.dispose();
  times.sort((a, b) => a - b);

  return {
    meanMs: times.reduce((a, b) => a + b) / times.length,
    p95Ms: times[Math.floor(times.length * 0.95)],
    p99Ms: times[Math.floor(times.length * 0.99)],
    throughputPerSec: 1000 / (times.reduce((a, b) => a + b) / times.length),
    peakMemoryMB: peakBytes / (1024 * 1024)
  };
}`}
</CodeBlock>

The warm-up phase is not optional, and the reason is not JIT. The first call to `predict` makes TensorFlow.js compile a kernel for every op in the graph and allocate the buffers those kernels write into. That bill is paid once. Measure the first ten runs and you are timing compilation, not inference.
