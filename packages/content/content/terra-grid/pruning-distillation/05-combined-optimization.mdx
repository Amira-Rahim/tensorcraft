In JavaScript, your production build combines every optimization: tree-shaking removes dead code, minification shrinks what remains, compression reduces transfer size, and code splitting loads only what is needed. Each technique is independent, but together they achieve reductions that no single technique could.

<CodeBlock language="typescript" title="combined-optimization.ts">
{`interface OptimizationPipeline {
  step: string;
  inputSizeMB: number;
  outputSizeMB: number;
  reduction: string;
  accuracyRetained: number;
}

function calculatePipeline(
  originalSizeMB: number,
  originalAccuracy: number
): OptimizationPipeline[] {
  const steps: OptimizationPipeline[] = [];
  let currentSize = originalSizeMB;
  let currentAccuracy = originalAccuracy;

  // Step 1: Knowledge Distillation (teacher → student)
  // Like code splitting: extract route-specific code
  const distilledSize = currentSize * 0.2; // 5x reduction
  const distilledAcc = currentAccuracy * 0.98; // 2% accuracy cost
  steps.push({
    step: '1. Distillation (code splitting)',
    inputSizeMB: currentSize,
    outputSizeMB: distilledSize,
    reduction: \`\${(currentSize / distilledSize).toFixed(0)}x\`,
    accuracyRetained: distilledAcc
  });
  currentSize = distilledSize;
  currentAccuracy = distilledAcc;

  // Step 2: Structured Pruning (remove dead neurons)
  // Like dead code elimination: remove whole units, not lines
  const prunedSize = currentSize * 0.5; // 2x reduction
  const prunedAcc = currentAccuracy * 0.99; // 1% accuracy cost
  steps.push({
    step: '2. Structured Pruning (dead code elimination)',
    inputSizeMB: currentSize,
    outputSizeMB: prunedSize,
    reduction: \`\${(currentSize / prunedSize).toFixed(0)}x\`,
    accuracyRetained: prunedAcc
  });
  currentSize = prunedSize;
  currentAccuracy = prunedAcc;

  // Step 3: Quantization (Float32 → Int8)
  // Like minification: reduce representation size
  const quantizedSize = currentSize * 0.25; // 4x reduction
  const quantizedAcc = currentAccuracy * 0.988; // 1.2% accuracy cost
  steps.push({
    step: '3. Quantization (minification)',
    inputSizeMB: currentSize,
    outputSizeMB: quantizedSize,
    reduction: \`\${(currentSize / quantizedSize).toFixed(0)}x\`,
    accuracyRetained: quantizedAcc
  });

  return steps;
}

const pipeline = calculatePipeline(200, 0.985);
pipeline.forEach(s => {
  console.log(\`\${s.step}: \${s.inputSizeMB.toFixed(1)}MB → \${s.outputSizeMB.toFixed(1)}MB (\${s.reduction})\`);
});
// 1. Distillation (code splitting): 200.0MB → 40.0MB (5x)
// 2. Structured Pruning (dead code elimination): 40.0MB → 20.0MB (2x)
// 3. Quantization (minification): 20.0MB → 5.0MB (4x)
// Total: 200MB → 5MB = 40x reduction
// Accuracy: 98.5% → 94.4% before recovery training, 2.6 points under the 97% turbine floor`}
</CodeBlock>

The order matters. Distillation picks the architecture, so it runs first: pruning and quantization can only shrink the network they are handed. Pruning goes next because it changes which weights exist, and quantization goes last because its Int8 scales are calibrated from the final weight distribution. Webpack has the same dependency: tree-shaking decides what code survives before the minifier renames what is left.
