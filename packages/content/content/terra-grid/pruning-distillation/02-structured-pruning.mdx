<Dialogue speaker="Tariq Hussain">
Your sparse model has the same number of weights — most of them are just zero. The ARM processor still iterates over all of them. I need the model to be physically smaller, not just mostly zeros. Remove entire neurons.
</Dialogue>

Unstructured pruning (zeroing individual weights) is like commenting out lines of code — the file is the same size. Structured pruning is like dead code elimination — removing entire functions. The result is physically smaller and runs faster on real hardware.

## Remove Entire Neurons

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="structured-pruning.ts">
{`// Score each neuron by the L1 norm of its weights
function scoreNeurons(weightMatrix: number[][]): number[] {
  return weightMatrix.map(neuronWeights =>
    neuronWeights.reduce((sum, w) => sum + Math.abs(w), 0)
  );
}

// Remove the lowest-scoring neurons
function structuredPrune(
  weightMatrix: number[][],
  pruneRatio: number
): number[][] {
  const scores = scoreNeurons(weightMatrix);
  const sortedScores = [...scores].sort((a, b) => a - b);
  const threshold = sortedScores[Math.floor(scores.length * pruneRatio)];

  // Keep only neurons above threshold (dead code elimination)
  return weightMatrix.filter((_, i) => scores[i] >= threshold);
}

// Example: 8 neurons, prune 50%
const weights = [
  [0.9, -0.8, 0.7],   // L1 = 2.4 — keep
  [0.01, 0.02, -0.01], // L1 = 0.04 — prune
  [-0.6, 0.5, 0.8],   // L1 = 1.9 — keep
  [0.003, -0.002, 0.001], // L1 = 0.006 — prune
  [0.7, 0.6, -0.9],   // L1 = 2.2 — keep
  [-0.01, 0.005, 0.008], // L1 = 0.023 — prune
  [0.4, -0.5, 0.6],   // L1 = 1.5 — keep
  [0.002, 0.001, -0.003], // L1 = 0.006 — prune
];

const pruned = structuredPrune(weights, 0.5);
console.log(\`Before: \${weights.length} neurons, \${weights.length * 3} params\`);
console.log(\`After: \${pruned.length} neurons, \${pruned.length * 3} params\`);
// Before: 8 neurons, 24 params → After: 4 neurons, 12 params
// Physically smaller — actual speedup on ARM`}
</CodeBlock>

The key difference: unstructured pruning creates a sparse matrix (same shape, many zeros). Structured pruning creates a smaller dense matrix (fewer rows, no zeros). ARM processors handle dense matrices much more efficiently than sparse ones.
