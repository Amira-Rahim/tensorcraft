## Different Precision for Different Layers

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="mixed-precision.ts">
{`type Precision = 'float32' | 'float16' | 'int8';

interface LayerConfig {
  name: string;
  params: number;
  precision: Precision;
  sensitive: boolean;
}

function bytesPerParam(precision: Precision): number {
  switch (precision) {
    case 'float32': return 4;
    case 'float16': return 2;
    case 'int8': return 1;
  }
}

function assignPrecision(layers: LayerConfig[]): LayerConfig[] {
  return layers.map((layer, i) => {
    // First and last layers: keep higher precision (sensitive)
    // Middle layers: quantize aggressively (robust)
    const isBoundaryLayer = i === 0 || i === layers.length - 1;
    return {
      ...layer,
      precision: isBoundaryLayer ? 'float16' : 'int8',
      sensitive: isBoundaryLayer,
    };
  });
}

function totalSizeMB(layers: LayerConfig[]): number {
  return layers.reduce((sum, l) =>
    sum + (l.params * bytesPerParam(l.precision)) / (1024 * 1024), 0);
}

const layers: LayerConfig[] = [
  { name: 'input_dense', params: 131072, precision: 'float32', sensitive: true },
  { name: 'hidden_1', params: 262144, precision: 'float32', sensitive: false },
  { name: 'hidden_2', params: 262144, precision: 'float32', sensitive: false },
  { name: 'output', params: 512, precision: 'float32', sensitive: true },
];

console.log('All Float32:', totalSizeMB(layers).toFixed(2) + 'MB'); // 2.50MB
const mixed = assignPrecision(layers);
console.log('Mixed precision:', totalSizeMB(mixed).toFixed(2) + 'MB'); // 0.75MB`}
</CodeBlock>

The first and last layers drop only as far as Float16, because they touch raw sensor values and produce the final prediction. The middle layers, which work on abstract features, tolerate Int8 well. Which layers are fragile is measured, not assumed: a network with a different shape can put its sensitive layers somewhere else entirely, so run the sweep on your own model before you assign anything.

<DerivationDrawer summary="Mixed-precision training: loss scaling math">
"Mixed precision" names two different practices, and this module teaches one of them. The lesson above is the inference-side one: pick a storage format per layer so the finished model fits the device. Below is the training-side one: keep FP32 master weights, run forward and backward in FP16 so training runs faster. Same phrase, different problem.

**Mixed-precision training** keeps FP32 master weights but does forward/backward in FP16 for speed.

**The problem:** FP16 has range `~6e-8` to `~65504`. Most ML gradients fall in `1e-8` to `1e-3`, partly below FP16's smallest normal value → **gradient underflow** (gradients become 0).

**Loss scaling fix:**

```
1. Compute loss L in FP16
2. Scale: L_scaled = L · S         where S is a large constant (e.g. 2^15 = 32768)
3. Backprop on L_scaled: gradients are ALSO scaled by S (chain rule)
4. Gradients in FP16 are now in a representable range
5. Before applying optimizer step, unscale: g_unscaled = g_scaled / S
6. Apply optimizer step on FP32 master weights using unscaled gradients
7. Cast updated FP32 weights back to FP16 for next forward pass
```

**Dynamic loss scaling:** S is adjusted automatically. If any gradient overflows (NaN/Inf), skip the step and halve S. If many steps pass without overflow, double S. PyTorch's `GradScaler` and TF's `LossScaleOptimizer` do this.

**Why FP32 master weights?** Optimizer state (Adam's m, v) and weight updates need full precision: accumulating tiny updates (`-α · g`) in FP16 loses them to roundoff. Master weights are FP32; only the forward/backward arithmetic uses FP16.
</DerivationDrawer>
