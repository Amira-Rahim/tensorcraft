<Dialogue speaker="Priya Sharma">
We have 47 models already trained and deployed in Float32. I'm not retraining all of them. Give me a way to quantize them as-is.
</Dialogue>

Reach for the Webpack comparison, but hold it loosely. `terser` transforms your JavaScript after you write it, and post-training quantization converts trained weights after training. What carries over is the timing: both operate on a finished artifact, no source changes, no retraining. What does not carry over is the guarantee. Minified code behaves byte-for-byte like the original. Quantized weights are rounded to 256 integer buckets, the outputs shift, and accuracy can drop several points until you give the converter calibration data to set the ranges.

<CodeBlock language="typescript" title="post-training-quantize.ts">
{`// Post-training quantization: Float32 → Int8
function quantizeWeights(weights: Float32Array): {
  quantized: Int8Array;
  scale: number;
  zeroPoint: number;
} {
  // Find the range of values (like finding variable name lengths for minification)
  let min = Infinity, max = -Infinity;
  for (const w of weights) {
    if (w < min) min = w;
    if (w > max) max = w;
  }

  // Calculate scale factor: map [min, max] → [-128, 127]
  const scale = (max - min) / 255;
  const zeroPoint = Math.round(-min / scale) - 128;

  // Quantize each weight
  const quantized = new Int8Array(weights.length);
  for (let i = 0; i < weights.length; i++) {
    quantized[i] = Math.round(weights[i] / scale) + zeroPoint;
    quantized[i] = Math.max(-128, Math.min(127, quantized[i]));
  }

  return { quantized, scale, zeroPoint };
}

// Dequantize for inference
function dequantizeWeight(value: number, scale: number, zeroPoint: number): number {
  return (value - zeroPoint) * scale;
}

// Example: quantize a small weight array
const original = new Float32Array([0.123, -0.456, 0.789, -0.012, 0.345]);
const { quantized, scale, zeroPoint } = quantizeWeights(original);

console.log('Original size:', original.byteLength, 'bytes');   // 20 bytes
console.log('Quantized size:', quantized.byteLength, 'bytes'); // 5 bytes — 4x smaller`}
</CodeBlock>

The process is mechanical: find the min and max of each weight tensor, compute a scale factor, and map every floating-point value to the nearest integer in [-128, 127]. Information is lost, just as minified code loses readability, but the behavior is preserved within acceptable tolerance.

<DerivationDrawer summary="Calibration math for PTQ">
**Post-training quantization (PTQ)** picks `scale` and `zero_point` per tensor by observing activations on a small calibration dataset. Methods:

**Min-max:** `scale = (max − min) / 255`. Simple but sensitive to outliers: one extreme activation widens the range and reduces precision for the bulk of values.

**Percentile:** `scale = (P99.9 − P0.1) / 255`. Clips outliers. Trades some accuracy on rare extreme inputs for better resolution on typical inputs.

**Entropy (KL-divergence):** find scale that minimizes `KL(P_FP32 || P_INT8)`: choose the scale that makes the quantized distribution most similar to the original. Standard in TensorRT.

**Symmetric quantization:** `zero_point = 0`, range `[-127, 127]`. Faster on hardware (no zero-point arithmetic) but loses one value. Per-channel symmetric quantization for weights + per-tensor asymmetric for activations is the common production setup.

**Accuracy hit:** typically 0.5-2% top-1 accuracy drop on ImageNet for INT8 models. If unacceptable, move to QAT (next lesson).
</DerivationDrawer>
