<Dialogue speaker="Hassan Al-Rashid">
After Site 23, every model has a minimum accuracy threshold. For safety-critical systems like turbine monitoring, 97% accuracy is the floor. For environmental telemetry, 92% is acceptable. Know your threshold before you compress.
</Dialogue>

JPEG quality 85 produces images visually identical to the original at 60% smaller. Quality 20 produces visible artifacts but is 90% smaller. The right choice depends on the use case. Quantization asks the same question of a model: how much accuracy loss can this use case absorb?

## Finding the Knee

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="accuracy-vs-size.ts">
{`interface QuantizationResult {
  format: string;
  sizeMB: number;
  accuracy: number;
  sizeReduction: string;
  acceptable: boolean;
}

function evaluateQuantization(
  originalSizeMB: number,
  originalAccuracy: number,
  minAccuracy: number
): QuantizationResult[] {
  const results: QuantizationResult[] = [
    {
      format: 'Float32 (original)',
      sizeMB: originalSizeMB,
      accuracy: originalAccuracy,
      sizeReduction: '1x',
      acceptable: originalAccuracy >= minAccuracy
    },
    {
      format: 'Float16',
      sizeMB: originalSizeMB / 2,
      accuracy: originalAccuracy - 0.001, // ~0.1% loss
      sizeReduction: '2x',
      acceptable: (originalAccuracy - 0.001) >= minAccuracy
    },
    {
      format: 'Int8 (post-training)',
      sizeMB: originalSizeMB / 4,
      accuracy: originalAccuracy - 0.012, // ~1.2% loss
      sizeReduction: '4x',
      acceptable: (originalAccuracy - 0.012) >= minAccuracy
    },
    {
      format: 'Int8 (QAT)',
      sizeMB: originalSizeMB / 4,
      accuracy: originalAccuracy - 0.005, // ~0.5% loss with QAT
      sizeReduction: '4x',
      acceptable: (originalAccuracy - 0.005) >= minAccuracy
    },
  ];
  return results;
}

// Safety-critical: turbine monitoring (97% floor)
const turbine = evaluateQuantization(200, 0.985, 0.97);
turbine.forEach(r => console.log(
  \`\${r.format}: \${r.sizeMB}MB, \${(r.accuracy * 100).toFixed(1)}%, \${r.acceptable ? 'PASS' : 'FAIL'}\`
));
// Float32: 200MB, 98.5%, PASS
// Float16: 100MB, 98.4%, PASS
// Int8 (post-training): 50MB, 97.3%, PASS
// Int8 (QAT): 50MB, 98.0%, PASS ← best choice`}
</CodeBlock>

For safety-critical applications, QAT is worth the extra training time because it preserves more accuracy at the same compression ratio. For non-critical telemetry, post-training quantization is faster and good enough.

<DerivationDrawer summary="Bits per parameter vs accuracy curve">
**Empirical accuracy-vs-bits curve** (ImageNet ResNet-50, common reference):

```
FP32 (32 bits):  76.1% top-1 accuracy   100% size (~100 MB)
FP16 (16 bits):  76.1% top-1 accuracy   50% size (~50 MB)
INT8  (8 bits):  75.2% top-1 accuracy   25% size (~25 MB)
INT4  (4 bits):  ~73% top-1 accuracy    12.5% size (~12.5 MB)  -- requires QAT
INT2  (2 bits):  ~67% top-1 accuracy    6.25% size              -- experimental
Binary (1 bit): ~50% top-1 accuracy     3.1% size               -- specialized
```

**Pattern:** going from FP32→FP16 is essentially free (no accuracy hit, half the size). FP16→INT8 typically loses 0.5-2% accuracy. Below INT8, accuracy degrades superlinearly with bit reduction.

**The right operating point depends on:**
- Inference budget (memory + latency)
- Accuracy floor (regulatory, business, safety)
- Calibration data availability (for PTQ) or labeled data (for QAT)

**Per-layer mixed quantization:** sensitive layers (attention output projection, first/last layers) stay FP16; bulk of network is INT8. Common in production. Results in ~30-40% size reduction with minimal accuracy hit.
</DerivationDrawer>
