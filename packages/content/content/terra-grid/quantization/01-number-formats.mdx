You choose image formats every day. PNG for lossless screenshots, WebP for balanced quality and size, AVIF for maximum compression. Each format trades quality for file size. Number formats in ML make the exact same tradeoff — but with numerical precision instead of visual quality.

## The Precision Spectrum

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="number-formats.ts">
{`// Number format comparison
interface NumberFormat {
  name: string;
  bytesPerValue: number;
  range: string;
  precision: string;
}

const formats: NumberFormat[] = [
  { name: 'Float32', bytesPerValue: 4, range: '±3.4e38', precision: '7 decimal digits' },
  { name: 'Float16', bytesPerValue: 2, range: '±65504', precision: '3 decimal digits' },
  { name: 'Int8',    bytesPerValue: 1, range: '-128 to 127', precision: '256 distinct values' },
];

// Calculate model size in each format
function modelSizeInFormat(paramCount: number, format: NumberFormat): number {
  return (paramCount * format.bytesPerValue) / (1024 * 1024); // MB
}

const params = 10_000_000; // 10M parameter model

formats.forEach(f => {
  console.log(\`\${f.name}: \${modelSizeInFormat(params, f).toFixed(1)}MB\`);
});
// Float32: 38.1MB
// Float16: 19.1MB
// Int8:     9.5MB — 4x smaller than Float32

// The key question: does 1 byte per weight preserve enough information?
// For most models: yes, with 0-2% accuracy loss.
// That is like going from PNG to WebP — visually identical, much smaller.`}
</CodeBlock>

A 10-million parameter model goes from 38.1MB in Float32 to 9.5MB in Int8. That is a 4x reduction with typically less than 2% accuracy loss. The parallel to image compression is direct: WebP images look identical to PNG at 30% the file size.

<DerivationDrawer summary="FP32 vs FP16 vs INT8 vs FP8 representations">
**IEEE 754 layout:**

```
FP32: 1 sign bit | 8 exponent bits | 23 mantissa bits   = 32 bits total
FP16: 1 sign bit | 5 exponent bits | 10 mantissa bits   = 16 bits total
FP8 (E4M3): 1 + 4 + 3 = 8 bits
INT8: signed 8-bit integer, range [-128, 127]
```

**Dynamic range** (largest representable / smallest nonzero):
- FP32: ~10^76
- FP16: ~10^9 (overflow risk above 65504, underflow below 6e-8)
- FP8: ~10^4 (very narrow — needs careful per-tensor scaling)
- INT8: 256 distinct values, scale-shift to map to model's value range

**Quantization formula** (FP32 → INT8 with affine quantization):

```
x_int = round((x_float − zero_point) / scale)
x_recovered = x_int · scale + zero_point
```

Where `scale = (x_max − x_min) / 255` and `zero_point = round(−x_min / scale)`. Per-tensor (one scale for the whole tensor) is simpler; per-channel (one scale per output channel of conv/dense) is more accurate but more compute.
</DerivationDrawer>
