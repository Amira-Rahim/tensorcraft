## Define the protected contribution

Two datasets are **adjacent** when they differ by the contribution we promise to protect. Adding or removing one reading gives record-level protection. Adding or removing a farm's entire history is a stronger, different requirement. Record-level accounting does not automatically protect the whole farm.

A randomized mechanism M is (epsilon, delta)-differentially private if, for every adjacent pair D and D', and every set of possible outputs S:

`P(M(D) in S) <= exp(epsilon) * P(M(D') in S) + delta`

Epsilon controls the multiplicative bound. Delta is an additive allowance in this inequality, not a per-record probability of being reconstructed. Smaller values give a tighter bound. The guarantee limits the extra information from participation; it does not erase knowledge an observer already has. See [NIST's introduction](https://www.nist.gov/blogs/cybersecurity-insights/differential-privacy-privacy-preserving-data-analysis-introduction-our) and [Dwork and Roth, chapter 2](https://www.cis.upenn.edu/~aaroth/Papers/privacybook.pdf).

## Bound the effect before adding noise

Clipping a vector to L2 norm C limits its length. For a sum of separately clipped contributions, adding or removing one contribution changes the sum by at most C. Replacing one contribution by another can change it by as much as 2C. This maximum change is the query's **sensitivity**.

These are different contracts. Clipping an already averaged batch is not the same operation as clipping each example before aggregation.

<CodeBlock language="typescript" title="clipping.ts">
{`function clipVector(values: number[], bound: number): number[] {
  const norm = Math.sqrt(values.reduce((sum, value) => sum + value * value, 0));
  const factor = norm === 0 ? 1 : Math.min(1, bound / norm);
  return values.map(value => value * factor);
}

const clipped = clipVector([3, 4], 1);
console.log(clipped); // [0.6, 0.8], up to floating-point rounding
// A replacement can move from [1, 0] to [-1, 0]: distance 2.`}
</CodeBlock>

For one Gaussian release, a textbook sufficient noise scale is `c * sensitivity / epsilon`, with `c` strictly greater than `sqrt(2 * ln(1.25 / delta))`. This bound assumes `0 < epsilon < 1` and `0 < delta < 1`; it is not a general-purpose training accountant. [Dwork and Roth, appendix A](https://www.cis.upenn.edu/~aaroth/Papers/privacybook.pdf).

<CodeBlock language="typescript" title="one-release-noise.ts">
{`function oneReleaseSigma(sensitivity: number, epsilon: number, delta: number): number {
  if (!Number.isFinite(sensitivity) || sensitivity < 0 ||
      !(epsilon > 0 && epsilon < 1) || !(delta > 0 && delta < 1)) {
    throw new Error('Use finite sensitivity >= 0, 0 < epsilon < 1, 0 < delta < 1');
  }
  const c = 1.01 * Math.sqrt(2 * Math.log(1.25 / delta));
  return c * sensitivity / epsilon;
}

const sigma = oneReleaseSigma(1, 0.5, 1e-5);
// Assumes sensitivity 1 for this one release. No training run is certified here.`}
</CodeBlock>

## Practice the numerical operations

The exercise supplies a function that returns independent standard-normal draws, with mean zero and variance one. Multiply each draw by sigma to set its standard deviation. Uniform draws from `Math.random() - 0.5` do not implement this Gaussian mechanism.

<Exercise slug="private-training" />

These operations alone do not establish differential privacy. Private training also needs a validated sampling scheme, a suitable random-number implementation, and accounting for every release. In DP-SGD, clipping happens per example before aggregation. The sampling rate, noise multiplier, and number of steps affect the final privacy bound. [TensorFlow Privacy's tutorial](https://www.tensorflow.org/responsible_ai/privacy/tutorials/classification_privacy) shows those dependencies; [Abadi and colleagues](https://arxiv.org/abs/1607.00133) describe the training method.

Repeated releases consume privacy budget together. Basic composition sums their epsilon and delta bounds; tighter accountants can improve that bound under their assumptions. A per-step epsilon is not the budget for the whole run. Use a reviewed implementation and record the protected unit, accounting method, total budget, and utility measurements before sharing real updates.
