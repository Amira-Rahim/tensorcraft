A deploy that cannot take the service down has a standard shape: unpack the new release into `releases/3.2.1`, run its checks there while `current` still points at the old one, then flip `current` with a single atomic rename. The previous release stays on disk, so rollback is one more flip. That is the right transport model for OTA: download, verify, stage, activate, zero downtime. It is the wrong risk model. New code behaves identically on every request, so one smoke test clears the fleet. New weights can shift the prediction distribution the moment they activate, and nothing throws, because predictions keep arriving on schedule. So this pipeline adds what a release swap never needed: staged rollout, shadow inference running old and new side by side, and an accuracy gate against a holdout set before the rest of the fleet sees the update.

## The Update Lifecycle

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="ota-lifecycle.ts">
{`import * as tf from '@tensorflow/tfjs';

type UpdateState = 'idle' | 'downloading' | 'verifying' | 'staging' | 'activating' | 'active' | 'failed';

interface OTAManager {
  currentVersion: string;
  stagedVersion: string | null;
  state: UpdateState;
}

async function performOTAUpdate(
  manager: OTAManager,
  updateUrl: string,
  newVersion: string,
  expectedChecksum: string,
): Promise<boolean> {
  // Phase 1: Download (like fetching a release tarball)
  manager.state = 'downloading';
  const packageData = await fetch(updateUrl).then(r => r.arrayBuffer());

  // Phase 2: Verify integrity (like the integrity hash in a lockfile)
  manager.state = 'verifying';
  const checksum = await computeChecksum(packageData);
  if (checksum !== expectedChecksum) {
    manager.state = 'failed';
    console.error('Checksum mismatch: update rejected');
    return false;
  }

  // Phase 3: Stage (a release that is on disk but not current yet). Store
  // under the version's own key so staging the next update cannot
  // overwrite the model now running.
  manager.state = 'staging';
  manager.stagedVersion = newVersion;
  await writeToStorage(\`model-\${newVersion}\`, packageData);

  // Phase 4: Gate on accuracy, not just on shape. A random-noise probe
  // proves the graph loads. It says nothing about whether the new weights
  // still agree with the old ones on real sensor data. On the fleet this
  // phase also scores the staged model against a stored holdout set and
  // shadows the live model for one inference cycle before any device
  // promotes it.
  //
  // parseArtifacts splits the downloaded package into the three things
  // tf.io.fromMemory expects: modelTopology, weightSpecs, and weightData.
  const stagedModel = await tf.loadLayersModel(tf.io.fromMemory(parseArtifacts(packageData)));
  const testInput = tf.randomNormal([1, 24]);
  const testOutput = stagedModel.predict(testInput) as tf.Tensor;
  const outputValid = testOutput.shape[1] === 3;
  testInput.dispose();
  testOutput.dispose();
  stagedModel.dispose();

  if (!outputValid) {
    manager.state = 'failed';
    manager.stagedVersion = null;
    await deleteFromStorage(\`model-\${newVersion}\`);
    return false;
  }

  // Phase 5: Activate (the pointer flip)
  manager.state = 'activating';
  // One pointer write, not two byte copies. Two awaited copies are not
  // atomic: lose power between them and the device boots with a truncated
  // current model and nothing to fall back to. Write both models under
  // their own keys, then flip a single active-version record.
  await setActivePointer({
    active: \`model-\${manager.stagedVersion}\`,
    rollback: \`model-\${manager.currentVersion}\`,
  });
  manager.currentVersion = newVersion;
  manager.stagedVersion = null;
  manager.state = 'active';

  console.log('OTA update complete; new model active');
  return true;
}`}
</CodeBlock>

## Delta Updates

Sending a full model over a $0.50/MB satellite link is expensive. Delta updates send only what changed, like git sending diffs instead of full snapshots:

<CodeBlock language="typescript" title="delta-update.ts">
{`interface DeltaUpdate {
  fromVersion: string;
  toVersion: string;
  changedLayers: string[];
  delta: ArrayBuffer;    // only the changed weights
  fullSizeMB: number;
  deltaSizeMB: number;
}

function applyDelta(currentWeights: ArrayBuffer, delta: DeltaUpdate): ArrayBuffer {
  // Like applying a git patch: merge changes into existing weights
  const current = new Float32Array(currentWeights);
  const patch = new Float32Array(delta.delta);

  // Apply weight updates at specified offsets
  const result = new Float32Array(current);
  let offset = 0;
  for (const layerName of delta.changedLayers) {
    const layerSize = getLayerSize(layerName);
    const layerOffset = getLayerOffset(layerName);
    result.set(patch.slice(offset, offset + layerSize), layerOffset);
    offset += layerSize;
  }

  console.log(\`Delta update: \${delta.deltaSizeMB}MB vs \${delta.fullSizeMB}MB full\`);
  // Savings track how much of the model you retrained, not the method.
  // Fine-tune the last two layers and the delta is a few percent of the
  // artifact. Retrain end to end and almost every weight moves, so the
  // delta is the full model plus offset bookkeeping: ship the package.
  return result.buffer;
}`}
</CodeBlock>

<Dialogue speaker="Elif Yilmaz">
Before you celebrate the bandwidth savings: a delta patch is also an attack surface. Anyone who can flip bits in transit can steer weights. The checksum guards the artifact; sign the delta too, or don't ship it.
</Dialogue>
