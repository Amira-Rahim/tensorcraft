Nothing reaches the npm registry without a `package.json`, a version number, and an integrity hash; loose files are not a release. Model deployment deserves the same rigor. A model package bundles everything needed for inference into a single, versioned, verifiable artifact.

## Anatomy of a Model Package

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="model-package.ts">
{`import * as tf from '@tensorflow/tfjs';
import { createHash } from 'crypto';

interface ModelPackage {
  manifest: {
    name: string;
    version: string;            // semver, like package.json
    created: string;
    inputShape: number[];
    outputShape: number[];
    trainedOn: string;          // sensor distribution these weights learned
    preprocessing: PreprocessConfig;
  };
  weights: ArrayBuffer;          // the model weights binary
  checksum: string;              // SHA-256 of weights
  bundleTag: string;             // ties the checksum to the version
}

interface PreprocessConfig {
  normalization: { mean: number[]; std: number[] };
  featureOrder: string[];
  inputRange: [number, number];
}

function createPackage(
  model: tf.LayersModel,
  weights: ArrayBuffer,
  config: PreprocessConfig,
  version: string,
  trainedOn: string,
): ModelPackage {
  const checksum = createHash('sha256')
    .update(Buffer.from(weights))
    .digest('hex');

  return {
    manifest: {
      name: 'terra-grid-intelligence',
      version,
      created: new Date().toISOString(),
      inputShape: model.inputs[0].shape.map(d => d ?? 1),   // [1, 24] sensor features
      outputShape: model.outputs[0].shape.map(d => d ?? 1), // [1, 3] normal, warning, critical
      trainedOn,                                            // e.g. 'sector-7 june distribution'
      preprocessing: config,
    },
    weights,
    checksum,
    // Binds the checksum to the version so a repackaged artifact fails the
    // pairing check. It is not a signature: both inputs travel with the
    // package, so anyone who can rewrite the weights can rewrite this too.
    // Real deployment approval needs a key the packager holds and the
    // device does not.
    bundleTag: createHash('sha256')
      .update(checksum + version)
      .digest('hex'),
  };
}`}
</CodeBlock>

## Integrity Verification

Subresource Integrity (SRI) hashes let a page reject a CDN script whose bytes changed. They work because the expected hash sits in your HTML, on a path the CDN does not control. A model checksum ships inside the package it is checking, so it proves the weights arrived intact, not that you are the one who sent them. It catches corruption. Substitution needs a signing key the packager holds and the device only verifies.

<CodeBlock language="typescript" title="verify-package.ts">
{`function verifyPackage(pkg: ModelPackage): boolean {
  // Like checking <script integrity="sha256-...">
  const computedChecksum = createHash('sha256')
    .update(Buffer.from(pkg.weights))
    .digest('hex');

  if (computedChecksum !== pkg.checksum) {
    console.error('INTEGRITY FAILURE: weights corrupted in transit');
    return false;
  }

  const expectedTag = createHash('sha256')
    .update(pkg.checksum + pkg.manifest.version)
    .digest('hex');

  if (expectedTag !== pkg.bundleTag) {
    console.error('TAG MISMATCH: these weights were packaged under a different version');
    return false;
  }

  console.log(\`Package \${pkg.manifest.name}@\${pkg.manifest.version} verified\`);
  return true;
}

// On the edge device:
const pkg = await downloadPackage('terra-grid-intelligence', '2.1.0');
if (!verifyPackage(pkg)) {
  console.error('Aborting deployment; falling back to previous version');
  await rollback();
}`}
</CodeBlock>
