<Dialogue speaker="Dr. Karimi">
And unlike your code, no compiler ever rejects the wrong order. Clinical notes are full of these traps. "No fever, but reports nausea": the meaning flips mid-sentence.

<Dialogue speaker="MEDI">
Alert: current bag-of-words model cannot distinguish "denied chest pain" from "reported chest pain." Both contain the same unigrams.

Strip the order out of a sentence and you strip out part of its meaning. A bag-of-words model does exactly that. "No fever, but reports nausea" becomes an unordered pile of tokens, and nothing records whether the negation landed on the fever or the nausea. You already manage this constraint in async code, where `fetch` then `render` produces a different application state than `render` then `fetch`. In clinical text, the same inversion changes the medical record, and getting it wrong has real consequences.

{`import * as tf from '@tensorflow/tfjs';

// These two sentences share the same words
// but have opposite meanings
const sentenceA = 'patient denied chest pain';
const sentenceB = 'patient reported chest pain';

// Bag-of-words: loses order, can't distinguish negation
const vocab = new Map([
  ['patient', 0], ['denied', 1], ['reported', 2],
  ['chest', 3], ['pain', 4], ['no', 5], ['in', 6],
]);

function toBow(text: string): number[] {
  const bow = new Array(vocab.size).fill(0);
  text.toLowerCase().split(/\\s+/).forEach(w => {
    const id = vocab.get(w);
    if (id !== undefined) bow[id]++;
  });
  return bow;
}

// "no pain" and "pain" both have bow_pain = 1
console.log('BoW A:', toBow(sentenceA)); // [1, 1, 0, 1, 1, 0, 0]
console.log('BoW B:', toBow(sentenceB)); // [1, 0, 1, 1, 1, 0, 0]

// Sequence representation: preserves order
function toSequence(text: string): number[] {
  return text.toLowerCase().split(/\\s+/).map(w => vocab.get(w) ?? -1);
}

const seqA = toSequence(sentenceA); // [0, 1, 3, 4]
const seqB = toSequence(sentenceB); // [0, 2, 3, 4]
console.log('Seq A:', seqA); // Position 1 is "denied" (1)
console.log('Seq B:', seqB); // Position 1 is "reported" (2)

// As tensors, ready for a sequence model
const tensorA = tf.tensor1d(seqA, 'int32');
const tensorB = tf.tensor1d(seqB, 'int32');
console.log('Tensor A shape:', tensorA.shape);`}
</CodeBlock>

## Clinical Negation: The Most Dangerous Pattern

Negation is the most dangerous pattern in clinical NLP. "No fever" and "fever" mean opposite things but share the same keyword. This is exactly like how `if (!isValid) save()` and `if (isValid) save()` execute the same function but under opposite conditions.

## From Bag to Sequence

<Dialogue speaker="Vikram">
Think of it this way. A bag-of-words is like dumping all your async calls into Promise.all: you lose the ordering. A sequence model is like an async/await chain, where each step depends on what came before.
</Dialogue>

<CodeBlock language="typescript" title="sequence-representation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Build a vocabulary from clinical text
function buildVocab(texts: string[]): Map<string, number> {
  const vocab = new Map<string, number>();
  vocab.set('<PAD>', 0);
  vocab.set('<UNK>', 1);
  let id = 2;
  for (const text of texts) {
    for (const word of text.toLowerCase().split(/\\s+/)) {
      if (!vocab.has(word)) vocab.set(word, id++);
    }
  }
  return vocab;
}

// Convert text to padded sequence
function textToSequence(
  text: string,
  vocab: Map<string, number>,
  maxLen: number
): number[] {
  const tokens = text.toLowerCase().split(/\\s+/);
  const ids = tokens.map(t => vocab.get(t) ?? 1); // 1 = <UNK>
  // Pad or truncate to maxLen
  while (ids.length < maxLen) ids.push(0); // 0 = <PAD>
  return ids.slice(0, maxLen);
}

const notes = [
  'patient denied chest pain',
  'patient reported chest pain',
  'no known drug allergies',
];
const vocab = buildVocab(notes);
const maxLen = 8;

const sequences = notes.map(n => textToSequence(n, vocab, maxLen));
const inputTensor = tf.tensor2d(sequences, [3, maxLen], 'int32');
console.log('Input shape:', inputTensor.shape); // [3, 8]
inputTensor.print();`}
</CodeBlock>

<DerivationDrawer summary="Why position matters for recurrence and attention">
Sequence models receive a sequence x_1, x_2, ..., x_n. Two architectural choices:

**Recurrent (RNN):** position is implicit. `h_t = f(h_{t-1}, x_t)`. Order is enforced because `h_t` depends on `h_{t-1}`.

**Attention (Transformer):** position is NOT inherent. The attention formula is permutation-equivariant: shuffling input tokens shuffles output tokens but produces the same per-token computation. To break this and let attention learn order, we add **positional encodings** (fixed sinusoidal vectors or learned embeddings) to the token embeddings before the first attention layer.

`x_t' = embedding(x_t) + positional(t)`

Without positional encoding, a transformer treats "not good" and "good not" identically. With it, the model can learn that order matters.
</DerivationDrawer>
