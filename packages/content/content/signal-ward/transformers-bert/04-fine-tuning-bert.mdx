## Inheritance, Not Rewriting

<BridgeCallout bridge={frontmatter.concept.bridge} />

BERT's encoder layers already understand language structure. You add a small classification head on top, train primarily that head, and keep the updates to the encoder small enough that what it already knows survives.

<CodeBlock language="typescript" title="fine-tune-clinical.ts">
{`import * as tf from '@tensorflow/tfjs';

// Simulated pre-trained BERT encoder
function createPretrainedEncoder(dModel: number, numLayers: number) {
  const input = tf.input({ shape: [dModel] });
  let x: tf.SymbolicTensor = input;

  for (let i = 0; i < numLayers; i++) {
    x = tf.layers.dense({
      units: dModel,
      activation: 'relu',
      name: \`encoder_layer_\${i}\`
    }).apply(x) as tf.SymbolicTensor;
  }

  return tf.model({ inputs: input, outputs: x });
}

// Fine-tuning: extend the base with a classification head
function fineTuneForClassification(
  encoder: tf.LayersModel,
  dModel: number,
  numLabels: number,
  learningRate: number = 2e-5
): tf.LayersModel {
  const input = tf.input({ shape: [dModel] });
  const encoded = encoder.apply(input) as tf.SymbolicTensor;

  // Task-specific head: the "subclass methods"
  const dropped = tf.layers.dropout({ rate: 0.1 }).apply(encoded) as tf.SymbolicTensor;
  const output = tf.layers.dense({
    units: numLabels,
    activation: 'softmax',
    name: 'clinical_classifier'
  }).apply(dropped) as tf.SymbolicTensor;

  const model = tf.model({ inputs: input, outputs: output });

  // Small learning rate preserves pre-trained knowledge
  model.compile({
    optimizer: tf.train.adam(learningRate),
    loss: 'categoricalCrossentropy',
    metrics: ['accuracy']
  });

  return model;
}

// Build the pipeline
const dModel = 64;
const encoder = createPretrainedEncoder(dModel, 4);
const clinicalModel = fineTuneForClassification(encoder, dModel, 5);

// Clinical condition labels:
// 0: Active, 1: Resolved, 2: Chronic, 3: Suspected, 4: Ruled-out
const labels = ['Active', 'Resolved', 'Chronic', 'Suspected', 'Ruled-out'];

// Simulated clinical training data
const xTrain = tf.randomNormal([200, dModel]);
const yTrain = tf.oneHot(tf.randomUniform([200], 0, 5, 'int32'), 5);

await clinicalModel.fit(xTrain, yTrain, {
  epochs: 3,
  batchSize: 16,
  validationSplit: 0.2,
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      console.log(\`Epoch \${epoch + 1}: loss=\${logs.loss.toFixed(4)}, acc=\${logs.acc.toFixed(4)}\`);
    }
  }
});`}
</CodeBlock>

## Catastrophic Forgetting: The Override Trap

<Dialogue speaker="Vikram">
The biggest danger in fine-tuning is catastrophic forgetting. If your learning rate is too high or you train too many epochs, the model overwrites its pre-trained knowledge, and nothing in the new task's loss curve will tell you.
</Dialogue>

Three strategies to prevent catastrophic forgetting:

1. **Small learning rate**: 2e-5 instead of 1e-3, gentle updates that refine rather than overwrite
2. **Few epochs**: 3-4 epochs, not 50; the model already knows language
3. **Gradual unfreezing**: Train only the head first, then progressively unfreeze encoder layers

<CodeBlock language="typescript" title="gradual-unfreezing.ts">
{`import * as tf from '@tensorflow/tfjs';

function gradualUnfreeze(
  model: tf.LayersModel,
  totalLayers: number,
  epoch: number
): void {
  // Phase 1 (epochs 0-1): Only classification head is trainable
  // Phase 2 (epochs 2-3): Top encoder layer unfreezes
  // Phase 3 (epochs 4+): All layers trainable with discriminative LR

  const unfreezeFrom = Math.max(0, totalLayers - epoch);

  model.layers.forEach((layer, idx) => {
    if (layer.name === 'clinical_classifier') {
      layer.trainable = true;  // always trainable
    } else if (idx >= unfreezeFrom) {
      layer.trainable = true;  // progressively unfreeze top layers
    } else {
      layer.trainable = false; // keep frozen
    }
  });

  console.log(\`Epoch \${epoch}: \${model.layers.filter(l => l.trainable).length} trainable layers\`);
}

// Discriminative learning rates: lower layers learn slower
function discriminativeLR(
  baseRate: number,
  layerIndex: number,
  totalLayers: number
): number {
  // Each layer down gets a smaller learning rate
  const factor = Math.pow(0.7, totalLayers - layerIndex);
  return baseRate * factor;
}

// Layer 0 (bottom): 2e-5 * 0.7^4 = ~4.8e-6
// Layer 3 (top):    2e-5 * 0.7^1 = ~1.4e-5
// Classifier head:  2e-5 (full rate)
for (let i = 0; i < 5; i++) {
  console.log(\`Layer \${i} LR: \${discriminativeLR(2e-5, i, 5).toExponential(2)}\`);
}`}
</CodeBlock>

<DerivationDrawer summary="Fine-tuning learning rate schedule">
Fine-tuning a pretrained model uses a **much smaller learning rate** than training from scratch: typically 1e-5 to 5e-5 for BERT, vs 1e-3 for from-scratch training.

**Why so small?** Pretrained weights are already in a useful region of the loss landscape. A large LR would overshoot and destroy what was learned (catastrophic forgetting). Small LR refines instead of restructures.

**Standard schedule:**
```
warmup: linearly increase LR from 0 to peak over first 10% of steps
decay:  linearly decrease LR from peak to 0 over remaining 90% of steps
```

**Layer-wise LR decay:** different LRs per layer: top layers (closer to output) get higher LR, bottom layers (closer to input, more general features) get lower LR. Bottom = features you want to preserve; top = features specific to the new task. Common decay factor: 0.95 per layer downward.

**Discriminative learning rate** is the same idea; fast.ai popularized this for vision transfer learning.
</DerivationDrawer>
