## The Sequential Bottleneck

<BridgeCallout bridge={frontmatter.concept.bridge} />

RNNs have a fundamental problem: information from early words must pass through every subsequent step to reach the end. In a long clinical note, by the time the model reaches "discontinue warfarin," it may have degraded information about "started heparin" from three paragraphs earlier.

<CodeBlock language="typescript" title="rnn-vs-transformer.ts">
{`import * as tf from '@tensorflow/tfjs';

// RNN approach: sequential, O(n) steps
function rnnProcess(tokens: tf.Tensor2D) {
  const seqLen = tokens.shape[0];
  const hiddenDim = 64;
  // One set of weights, reused at every step. That reuse is what makes it recurrent.
  const Wih = tf.randomNormal([tokens.shape[1], hiddenDim]);
  const Whh = tf.randomNormal([hiddenDim, hiddenDim]);
  let hidden = tf.zeros([1, hiddenDim]);

  for (let t = 0; t < seqLen; t++) {
    const token = tokens.slice([t, 0], [1, -1]);
    // Each step depends on the previous hidden state
    hidden = tf.tanh(tf.add(tf.matMul(token, Wih), tf.matMul(hidden, Whh)));
  }
  return hidden.reshape([hiddenDim]); // final hidden state: bottleneck!
}

// Transformer approach: parallel, O(1) depth
function transformerProcess(tokens: tf.Tensor2D) {
  const dk = 16;
  const Wq = tf.randomNormal([tokens.shape[1], dk]);
  const Wk = tf.randomNormal([tokens.shape[1], dk]);
  const Wv = tf.randomNormal([tokens.shape[1], dk]);

  const Q = tf.matMul(tokens, Wq);
  const K = tf.matMul(tokens, Wk);
  const V = tf.matMul(tokens, Wv);

  // ALL token relationships computed in ONE operation
  const scores = tf.matMul(Q, K.transpose()).div(Math.sqrt(dk));
  const weights = tf.softmax(scores, -1);
  return tf.matMul(weights, V); // every token has full context
}

const tokens = tf.randomNormal([20, 32]) as tf.Tensor2D;
const output = transformerProcess(tokens);
console.log('All tokens processed in parallel:', output.shape);`}
</CodeBlock>

## The Three Advantages

1. **Parallelism**: All positions computed simultaneously; GPUs love this
2. **Constant path length**: Any two words are connected in one attention step
3. **No information bottleneck**: Each token retains its own representation

The bill for all three arrives in the score matrix. `tf.matMul(Q, K.transpose())` is n by n, so attention costs O(n²) in time and memory where an RNN costs O(n). At 20 tokens that is 400 scores and nobody notices. At a 3,000-token discharge summary it is nine million, per head, per layer.

<Dialogue speaker="Vikram">
For clinical text, the constant path length is the payoff. A drug mentioned in the admission note and a contraindication mentioned in the lab results are directly connected. No information decay over distance.
</Dialogue>

<DerivationDrawer summary="Sinusoidal positional encoding (the formula)">
Self-attention is permutation-equivariant: shuffle input tokens, output shuffles the same way. To break this and inject position information, add a positional encoding vector to each token embedding:

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

- `pos` is the token's position (0, 1, 2, ...)
- `i` indexes the embedding dimension (0 to d_model/2)
- The frequencies span from `1` (i=0) to `1/10000` (i=d_model/2) on a geometric scale

**Why sinusoids?** 
- Each pair of dimensions (2i, 2i+1) is a rotation by angle `pos / 10000^(2i/d_model)`. Different pairs rotate at different frequencies, like a clock with multiple hands.
- **Relative-position invariance:** `PE(pos+k)` is a fixed linear function of `PE(pos)` (rotation matrix at angle `k / 10000^(...)`). The model can learn to attend by relative position.
- Generalizes to longer sequences than seen in training (sinusoids are defined for any pos).

**Modern alternatives:** RoPE (Rotary Position Embeddings) and ALiBi modify attention scores directly using position, instead of adding to embeddings. Most modern LLMs use RoPE.
</DerivationDrawer>
