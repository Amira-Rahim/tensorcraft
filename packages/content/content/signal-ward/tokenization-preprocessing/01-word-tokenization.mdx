`String.split()` works on CSV rows and search queries because you chose the delimiter. In a clinical note the delimiters were chosen by whoever typed it between patients, and some of the punctuation is load-bearing: the slash in `130/85` is the reading, not a separator.

## Simple Splitting vs. Real Tokenization

<BridgeCallout bridge={frontmatter.concept.bridge} />

Naive `split(' ')` breaks on spaces but misses punctuation attached to words. Clinical text needs smarter splitting.

<CodeBlock language="typescript" title="word-tokenizer.ts">
{`// Naive: splits on spaces only
'BP: 120/80, temp 98.6F.'.split(' ');
// ['BP:', '120/80,', 'temp', '98.6F.']
// Problems: punctuation stuck to words

// Better: regex-based word extraction
function wordTokenize(text: string): string[] {
  return text.toLowerCase().match(/[a-z0-9]+(?:\\.[0-9]+)?/g) || [];
}

wordTokenize('BP: 120/80, temp 98.6F.');
// ['bp', '120', '80', 'temp', '98.6', 'f']

// Clinical-aware: preserve meaningful patterns
function clinicalTokenize(text: string): string[] {
  return text.toLowerCase()
    .match(/[a-z]+(?:[-'][a-z]+)*|[0-9]+(?:\\.[0-9]+)?(?:\\/[0-9]+(?:\\.[0-9]+)?)?/g) || [];
}

clinicalTokenize('BP: 120/80, temp 98.6F, non-insulin dependent.');
// ['bp', '120/80', 'temp', '98.6', 'f', 'non-insulin', 'dependent']`}
</CodeBlock>

## Handling Clinical Edge Cases

The same pattern again, this time wrapped in whitespace normalization so the tabs and newlines in an exported record do not leak into tokens. Watch what it still does to a dose.

<CodeBlock language="typescript" title="clinical-edges.ts">
{`function clinicalTokenizeWithCleanup(text: string): string[] {
  // Normalize whitespace
  const normalized = text.toLowerCase().replace(/\\s+/g, ' ').trim();

  // Match: words (with hyphens), numbers (with decimals/fractions), standalone punctuation
  const tokens = normalized.match(
    /[a-z]+(?:[-'][a-z]+)*|[0-9]+(?:\\.[0-9]+)?(?:\\/[0-9]+(?:\\.[0-9]+)?)?/g
  ) || [];

  return tokens;
}

// Test with real clinical text
const note = "Pt c/o chest pain x 2 days. BP 130/85. Started on aspirin 81mg daily.";
console.log(clinicalTokenizeWithCleanup(note));
// ['pt', 'c', 'o', 'chest', 'pain', 'x', '2', 'days', 'bp', '130/85',
//  'started', 'on', 'aspirin', '81', 'mg', 'daily']

// 81mg came out as '81' and 'mg'. The tokenizer has no idea those belong
// together, so the model has to learn the association from scratch, and
// '81' now means the same thing whether it was milligrams or a heart rate.`}
</CodeBlock>

## From Tokens to IDs

The model does not take strings. Every token has to become a number first, and the vocabulary is what decides which number.

<CodeBlock language="typescript" title="tokens-to-ids.ts">
{`const vocab = new Map([['chest', 4], ['pain', 5], ['aspirin', 6]]);

const ids = clinicalTokenize('chest pain, aspirin').map(t => vocab.get(t) ?? 0);
// [4, 5, 6]
// Unknown words collapse to 0. Every drug name outside the vocabulary is the
// same number to the model, so the vocabulary decides what it can tell apart.`}
</CodeBlock>
