## Simple Splitting vs. Real Tokenization

<BridgeCallout bridge={frontmatter.concept.bridge} />

Naive `split(' ')` breaks on spaces but misses punctuation attached to words. Clinical text needs smarter splitting.

<CodeBlock language="typescript" title="word-tokenizer.ts">
{`// Naive: splits on spaces only
'BP: 120/80, temp 98.6F.'.split(' ');
// ['BP:', '120/80,', 'temp', '98.6F.']
// Problems: punctuation stuck to words

// Better: regex-based word extraction
function wordTokenize(text: string): string[] {
  return text.toLowerCase().match(/[a-z0-9]+(?:\.[0-9]+)?/g) || [];
}

wordTokenize('BP: 120/80, temp 98.6F.');
// ['bp', '120', '80', 'temp', '98.6', 'f']

// Clinical-aware: preserve meaningful patterns
function clinicalTokenize(text: string): string[] {
  return text.toLowerCase()
    .match(/[a-z]+(?:[-'][a-z]+)*|[0-9]+(?:\.[0-9]+)?(?:\/[0-9]+(?:\.[0-9]+)?)?/g) || [];
}

clinicalTokenize('BP: 120/80, temp 98.6F, non-insulin dependent.');
// ['bp', '120/80', 'temp', '98.6', 'f', 'non-insulin', 'dependent']`}
</CodeBlock>

## Handling Clinical Edge Cases

Medical text has patterns that general-purpose tokenizers struggle with: vitals with slashes, hyphenated drug names, decimal measurements.

<CodeBlock language="typescript" title="clinical-edges.ts">
{`function robustClinicalTokenize(text: string): string[] {
  // Normalize whitespace
  const normalized = text.toLowerCase().replace(/\s+/g, ' ').trim();

  // Match: words (with hyphens), numbers (with decimals/fractions), standalone punctuation
  const tokens = normalized.match(
    /[a-z]+(?:[-'][a-z]+)*|[0-9]+(?:\.[0-9]+)?(?:\/[0-9]+(?:\.[0-9]+)?)?/g
  ) || [];

  return tokens;
}

// Test with real clinical text
const note = "Pt c/o chest pain x 2 days. BP 130/85. Started on aspirin 81mg daily.";
console.log(robustClinicalTokenize(note));
// ['pt', 'c', 'o', 'chest', 'pain', 'x', '2', 'days', 'bp', '130/85',
//  'started', 'on', 'aspirin', '81', 'daily']`}
</CodeBlock>
