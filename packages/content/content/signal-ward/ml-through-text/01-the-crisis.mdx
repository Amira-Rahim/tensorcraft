## Choose a Baseline Before a Model

A phrase check such as `note.includes('no known allergies')` can miss negation or an abbreviation. A model can miss those too, particularly when a hospital writes notes differently from its training data.

Start with an abbreviation dictionary and explicit rules as a baseline. Compare their errors with a trained model on the same held-out notes. A hybrid may use ML to extract possible medication mentions, then consult a maintained interaction database. The choice depends on measured errors and the review workflow; clinical text does not automatically require ML.

An ML pipeline has stages the way any request path does, in the browser or on the server: data comes in, gets transformed, flows through a model, and produces a prediction.

<CodeBlock language="typescript" title="ml-pipeline-overview.ts">
{`import * as tf from '@tensorflow/tfjs';

// A request path has stages, browser or server:
// input → validation → transform → output

// In an ML pipeline, data flows the same way:
// Raw Text → Preprocessing → Model → Prediction

// Step 1: Represent text features as numbers
// Each position = a feature (e.g., contains "allergy", contains "penicillin", etc.)
const noteFeatures = tf.tensor([1, 1, 0, 1, 0]);

// Step 2: Hand-chosen demo weights, not fitted to clinical data
const weights = tf.tensor([0.8, 0.9, 0.1, 0.7, 0.2]);

// Step 3: Compute a weighted sum; no activation or training occurs here
const score = noteFeatures.mul(weights).sum();
console.log('Demo weighted sum:', score.dataSync()[0]);
// Approximately 2.4. This is arithmetic, not a calibrated risk or
// a validated alert threshold. Training comes in later lessons.`}
</CodeBlock>
