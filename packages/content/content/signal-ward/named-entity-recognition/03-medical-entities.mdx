## A Type System for Clinical Language

<BridgeCallout bridge={frontmatter.concept.bridge} />

In TypeScript, a union type like `Drug | Condition | Procedure` tells the compiler: "This value can be one of several shapes, and each shape has different properties." Medical NER works the same way. Each entity type has distinct characteristics:

- **DRUG**: Dictionary words (methotrexate, warfarin), often ending in -olol, -pril, -statin
- **CONDITION**: Dictionary words (diabetes, hypertension), abbreviations (RA, HTN, CHF)
- **DOSAGE**: Numeric patterns (15mg, 100mcg, 2.5ml)
- **FREQUENCY**: Temporal terms (daily, weekly, bid, tid, prn)
- **PROCEDURE**: Medical actions (intubation, biopsy, catheterization)

Like TypeScript's type guards, each entity type has its own validation logic.

<CodeBlock language="typescript" title="medical-entities.ts">
{`import * as tf from '@tensorflow/tfjs';

// Medical entity type system, like TypeScript union types
// type MedicalEntity = Drug | Condition | Dosage | Frequency | Procedure;

const MEDICAL_ENTITIES = {
  DRUG: ['methotrexate', 'lisinopril', 'warfarin', 'heparin', 'aspirin', 'ibuprofen'],
  CONDITION: ['diabetes', 'hypertension', 'arthritis', 'pneumonia', 'sepsis'],
  DOSAGE: [],  // pattern-based: /^\d+\.?\d*(mg|mcg|ml|g|units|iu)$/i
  FREQUENCY: ['daily', 'weekly', 'bid', 'tid', 'qid', 'prn', 'q.d.'],
  PROCEDURE: ['intubation', 'catheterization', 'biopsy', 'mri', 'ct']
};

// Pattern matchers, like TypeScript type guards
const DOSAGE_PATTERN = /^\d+\.?\d*(mg|mcg|ml|g|units|iu)$/i;

// Abbreviation resolver, like a type alias map
const ABBREV_MAP: Record<string, string> = {
  'RA': 'CONDITION',   // rheumatoid arthritis
  'DM': 'CONDITION',   // diabetes mellitus
  'HTN': 'CONDITION',  // hypertension
  'CHF': 'CONDITION',  // congestive heart failure
  'COPD': 'CONDITION', // chronic obstructive pulmonary disease
  'ABX': 'DRUG'        // antibiotics
};

// Type guard: classify a single token
function classifyToken(token: string): string {
  const lower = token.toLowerCase();

  // Check each type's dictionary, like narrowing a union type
  for (const [type, terms] of Object.entries(MEDICAL_ENTITIES)) {
    if (terms.includes(lower)) return type;
  }

  // Check pattern-based types, like regex type guards
  if (DOSAGE_PATTERN.test(token)) return 'DOSAGE';

  // Check abbreviation map, like type alias resolution
  if (token.toUpperCase() in ABBREV_MAP) return ABBREV_MAP[token.toUpperCase()];

  return 'O'; // outside: no type match
}

// Classify an entire sentence
function classifySentence(
  tokens: string[]
): Array<{ token: string; label: string }> {
  return tokens.map(token => ({
    token,
    label: classifyToken(token)
  }));
}

// Neural approach: embedding → BiLSTM → Dense → BIO tags
function buildMedicalNerModel(
  vocabSize: number,
  embedDim: number,
  hiddenDim: number,
  numTags: number
): tf.LayersModel {
  const input = tf.input({ shape: [null] });

  const embedding = tf.layers.embedding({
    inputDim: vocabSize,
    outputDim: embedDim
  }).apply(input) as tf.SymbolicTensor;

  // Bidirectional LSTM captures left and right context
  const lstm = tf.layers.bidirectional({
    layer: tf.layers.lstm({
      units: hiddenDim,
      returnSequences: true
    }) as tf.RNNLayer
  }).apply(embedding) as tf.SymbolicTensor;

  // Dense layer per token, like assigning a type to each element
  const output = tf.layers.timeDistributed({
    layer: tf.layers.dense({ units: numTags, activation: 'softmax' })
  }).apply(lstm) as tf.SymbolicTensor;

  return tf.model({ inputs: input, outputs: output });
}

// Example
const tokens = ['Patient', 'has', 'RA', 'taking', 'methotrexate', '15mg', 'weekly'];
const result = classifySentence(tokens);
console.log(result);
// [{ token: 'Patient', label: 'O' },
//  { token: 'has', label: 'O' },
//  { token: 'RA', label: 'CONDITION' },       // abbreviation resolved
//  { token: 'taking', label: 'O' },
//  { token: 'methotrexate', label: 'DRUG' },  // dictionary match
//  { token: '15mg', label: 'DOSAGE' },         // pattern match
//  { token: 'weekly', label: 'FREQUENCY' }]    // dictionary match`}

## Precision, Recall, and F1

<Dialogue speaker="Imran">
How do we know the model is correct? Finding 90% of drugs means nothing if it also flags "patient" as a drug 30% of the time. We need the TypeScript equivalent of strict mode, something that catches false positives and false negatives.
</Dialogue>

Just like TypeScript's strict mode catches both "value used as wrong type" (false positive) and "type not checked" (false negative), NER evaluation uses three metrics:

- **Precision**: Of tokens the model labeled as DRUG, how many actually are drugs? (How many false positives?)
- **Recall**: Of all actual drugs in the text, how many did the model find? (How many false negatives?)
- **F1**: The harmonic mean of precision and recall, the single number that balances both

In a clinical setting, a false negative (missing a drug) can be as dangerous as a false positive (hallucinating one). Both metrics matter.
