<Dialogue speaker="Vikram">

</Dialogue>

## Opening and Closing Tags for NLP

<BridgeCallout bridge={frontmatter.concept.bridge} />

In HTML, `<span class="drug">` tells the browser: "A drug entity starts here." `</span>` tells it: "The drug entity ends here." BIO tagging encodes the same information in a flat sequence:

| HTML | BIO |
|------|-----|
| `<span class="drug">` | `B-DRUG` |
| content inside the tag | `I-DRUG` |
| `</span>` (implicit at next B or O) | next tag |
| text outside any tag | `O` |

The critical insight: in HTML, forgetting to close a tag merges everything into one element. In BIO, forgetting the B tag on a new entity merges it with the previous one.

<CodeBlock language="typescript" title="bio-tagging.ts">
{`import * as tf from '@tensorflow/tfjs';

// BIO tag set — like a vocabulary of HTML tags for clinical text
const BIO_TAGS = [
  'O',                          // outside any entity (plain text)
  'B-DRUG', 'I-DRUG',          // <span class="drug">...</span>
  'B-CONDITION', 'I-CONDITION', // <span class="condition">...</span>
  'B-DOSAGE', 'I-DOSAGE',      // <span class="dosage">...</span>
  'B-PROCEDURE', 'I-PROCEDURE' // <span class="procedure">...</span>
];

interface EntitySpan {
  text: string;
  type: string;
  tokens: string[];
  startIdx: number;
  endIdx: number;
}

// Encoding: annotations → BIO tags (like adding HTML tags to raw text)
function tokensToBioTags(
  tokens: string[],
  entities: Array<{ start: number; end: number; type: string }>
): string[] {
  const tags = new Array(tokens.length).fill('O');

  for (const entity of entities) {
    // B tag = opening tag
    tags[entity.start] = \`B-\${entity.type}\`;
    // I tags = content inside the tag
    for (let i = entity.start + 1; i < entity.end; i++) {
      tags[i] = \`I-\${entity.type}\`;
    }
  }

  return tags;
}

// Decoding: BIO tags → entity spans (like parsing HTML back into a DOM)
function bioTagsToEntities(tokens: string[], tags: string[]): EntitySpan[] {
  const entities: EntitySpan[] = [];
  let current: EntitySpan | null = null;

  for (let i = 0; i < tokens.length; i++) {
    if (tags[i].startsWith('B-')) {
      // Opening tag — close any previous entity, start a new one
      if (current) entities.push(current);
      const type = tags[i].substring(2);
      current = {
        text: tokens[i],
        type,
        tokens: [tokens[i]],
        startIdx: i,
        endIdx: i + 1
      };
    } else if (tags[i].startsWith('I-') && current) {
      // Inside tag — extend the current entity
      current.tokens.push(tokens[i]);
      current.text += ' ' + tokens[i];
      current.endIdx = i + 1;
    } else {
      // O tag or I without a preceding B — close any open entity
      if (current) entities.push(current);
      current = null;
    }
  }
  if (current) entities.push(current);
  return entities;
}

// Example: "Patient has rheumatoid arthritis taking methotrexate"
const tokens = ['Patient', 'has', 'rheumatoid', 'arthritis', 'taking', 'methotrexate'];
const tags = ['O', 'O', 'B-CONDITION', 'I-CONDITION', 'O', 'B-DRUG'];
//             plain  plain  <condition>    </condition>  plain  <drug/>

const entities = bioTagsToEntities(tokens, tags);
console.log(entities);
// [{ text: 'rheumatoid arthritis', type: 'CONDITION', ... },
//  { text: 'methotrexate', type: 'DRUG', ... }]`}
</CodeBlock>

## Why B Matters: Preventing Tag Merge

<Dialogue speaker="Imran">
What happens if a patient has "diabetes hypertension" — two conditions listed back to back?
</Dialogue>

<Dialogue speaker="Vikram">
Without the B tag, both words get I-CONDITION. The decoder merges them into one entity: "diabetes hypertension." The B tag on "hypertension" is like a new opening `<span>` — it signals a separate entity starts there, even though the type is the same.
</Dialogue>

Consider the difference:

- **Wrong:** `I-CONDITION I-CONDITION` → "diabetes hypertension" (one merged entity)
- **Correct:** `B-CONDITION B-CONDITION` → "diabetes" and "hypertension" (two separate entities)

This mirrors the HTML rule: you can't nest two `<span>` elements without proper opening tags for each.
