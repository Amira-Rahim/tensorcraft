<Dialogue speaker="Vikram">
Imran, think of a Map in JavaScript. You pass in a key, you get back a value. An embedding layer starts there: you pass in a token ID, you get back a vector. The difference? During training, the vectors update automatically.
</Dialogue>

<Dialogue speaker="Imran">
So it is like a Map where the values optimize themselves based on how well the model performs?
</Dialogue>

<Dialogue speaker="Vikram">
That's the trainable part, yes. The piece your Map never has to deal with is a missing key. Map.get returns undefined and you handle it inline. An embedding layer has no row at all for an unseen token, so it needs an UNK entry or a subword fallback before the lookup ever runs.
</Dialogue>

<Dialogue speaker="Imran">
And we start the values from the medical vectors we loaded last lesson?
</Dialogue>

<Dialogue speaker="Vikram">
Right. Pre-trained rows where we have them, random rows where we don't. Training moves both.
</Dialogue>

An embedding layer is a matrix with one row per vocabulary entry, indexed by integer token ID. The rows are learnable parameters: during training, the network adjusts them through backpropagation, so the embedding space evolves to serve the model's task.

## The Trainable Lookup Table

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="embedding-as-lookup.ts">
{`import * as tf from '@tensorflow/tfjs';

// A JavaScript Map: key -> value (fixed)
const jsLookup = new Map<number, number[]>();
jsLookup.set(0, [0.1, -0.3, 0.5]);  // 'aspirin'
jsLookup.set(1, [0.4, 0.2, -0.1]);  // 'ibuprofen'
jsLookup.set(2, [-0.2, 0.7, 0.3]);  // 'penicillin'
// Values never change

// An embedding layer: tokenID -> vector (trainable)
const embeddingLayer = tf.layers.embedding({
  inputDim: 3,     // vocabulary size (number of keys)
  outputDim: 3,    // vector dimensions (value size)
});

// Same lookup operation
const tokenId = tf.tensor2d([[0]], [1, 1], 'int32');
const vector = embeddingLayer.apply(tokenId) as tf.Tensor;
vector.print(); // Random initial values; will be learned during training

// Unlike the Map, these values update during training
// to minimize the model's loss function.`}
</CodeBlock>

## Building a Model with an Embedding Layer

<CodeBlock language="typescript" title="embedding-model.ts">
{`import * as tf from '@tensorflow/tfjs';

const vocabSize = 500;
const embeddingDim = 32;
const maxSeqLength = 20;

// Build a simple clinical note classifier
const model = tf.sequential();

// Layer 1: Embedding; maps token IDs to dense vectors
model.add(tf.layers.embedding({
  inputDim: vocabSize,
  outputDim: embeddingDim,
  inputLength: maxSeqLength,
}));

// Layer 2: Average the word vectors into a single document vector
model.add(tf.layers.globalAveragePooling1d());

// Layer 3: Classify the document
model.add(tf.layers.dense({
  units: 1,
  activation: 'sigmoid', // binary classification: allergy or not
}));

model.compile({
  optimizer: 'adam',
  loss: 'binaryCrossentropy',
  metrics: ['accuracy'],
});

model.summary();
// Layer 1: embedding, 500 * 32 = 16,000 trainable parameters
// Layer 2: global_average_pooling1d, 0 parameters
// Layer 3: dense, 33 parameters (32 weights + 1 bias)`}
</CodeBlock>

## Initializing with Pre-trained Weights

<Dialogue speaker="MEDI">
Initialization report: 5 of 7 vocabulary entries have pre-trained medical vectors. Those rows start with meaningful representations. The remaining rows start with small random values and learn only from task-specific training data.
</Dialogue>

<CodeBlock language="typescript" title="pretrained-init.ts">
{`// Simulated pre-trained medical vectors
const pretrainedVectors: Record<string, number[]> = {
  'aspirin':    [0.82, 0.21, -0.11],
  'ibuprofen':  [0.74, 0.29, -0.18],
  'penicillin': [-0.12, 0.81, 0.62],
  'allergy':    [0.45, 0.67, -0.23],
  'pain':       [0.55, -0.33, 0.22],
};

function buildEmbeddingMatrix(
  vocab: Map<string, number>,
  pretrained: Record<string, number[]>,
  embeddingDim: number
): number[][] {
  const matrix: number[][] = [];

  for (let i = 0; i < vocab.size; i++) {
    // Default: small random values for unknown words
    matrix.push(Array.from({ length: embeddingDim },
      () => (Math.random() - 0.5) * 0.1
    ));
  }

  // Overwrite with pre-trained vectors where available
  let loaded = 0;
  for (const [word, idx] of vocab) {
    if (pretrained[word]) {
      matrix[idx] = [...pretrained[word]];
      loaded++;
    }
  }

  console.log(loaded + '/' + vocab.size + ' words initialized from pre-trained vectors');
  return matrix;
}

const vocab = new Map([
  ['<PAD>', 0], ['<UNK>', 1], ['aspirin', 2],
  ['ibuprofen', 3], ['penicillin', 4], ['allergy', 5], ['pain', 6],
]);

const weightMatrix = buildEmbeddingMatrix(vocab, pretrainedVectors, 3);`}
</CodeBlock>

## Frozen vs. Fine-tuned

<CodeBlock language="typescript" title="frozen-vs-finetuned.ts">
{`// Option 1: Frozen embeddings; do not update during training
// Use when: small dataset, pre-trained vectors match your domain well
const frozenModel = tf.sequential();
frozenModel.add(tf.layers.embedding({
  inputDim: vocab.size,
  outputDim: 3,
  weights: [tf.tensor2d(weightMatrix)],
  trainable: false,  // locked: gradients will not flow here
}));
// Like importing a library and using it as-is

// Option 2: Fine-tuned embeddings; allow small adjustments
// Use when: large dataset, need to adapt pre-trained vectors to your task
const fineTunedModel = tf.sequential();
fineTunedModel.add(tf.layers.embedding({
  inputDim: vocab.size,
  outputDim: 3,
  weights: [tf.tensor2d(weightMatrix)],
  trainable: true,  // unlocked: will adjust during training
}));
// Like forking a library and customizing it

// Option 3: From scratch, no pre-trained initialization
// Use when: very large dataset, highly specialized domain
const scratchModel = tf.sequential();
scratchModel.add(tf.layers.embedding({
  inputDim: vocab.size,
  outputDim: 3,
  // No weights: starts random, learns everything from your data
}));
// Like writing a library from scratch`}
</CodeBlock>

<DerivationDrawer summary="Embedding layer = lookup table = single matrix multiply">
A neural network 'embedding layer' is a learnable matrix `E` of shape `[vocab_size, d_embed]`. Looking up the embedding for token id `t` is row indexing:

`embedding(t) = E[t, :]`

**Equivalent matrix view:** if `t` is one-hot encoded as a vector with 1 at position t and 0 elsewhere, then:

`embedding(t) = one_hot(t) · E`

This is a single matrix multiply: sparse, but mathematically the same as the lookup. Backprop updates only the row corresponding to the input token.

**Storage cost:** `vocab_size × d_embed × 4 bytes`. For 50k vocab and d=768, that's ~150MB just for the embedding table. Larger LLMs have embedding tables that dominate parameter count.

**Tied embeddings:** language models often tie the input embedding with the output (next-token prediction) projection, the same matrix used for both. Halves the parameter count and often improves quality.
</DerivationDrawer>
