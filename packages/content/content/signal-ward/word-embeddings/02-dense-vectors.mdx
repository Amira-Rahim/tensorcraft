## From Sparse to Dense

<BridgeCallout bridge={frontmatter.concept.bridge} />

One-hot encoding gave each word a 50,000-dimensional sparse vector, one dimension per clinical term. Word2Vec compresses that into a dense 64 or 128-dimensional vector where every dimension carries learned signal.

<CodeBlock language="typescript" title="embedding-layer.ts">
{`import * as tf from '@tensorflow/tfjs';

// An embedding layer is a trainable lookup table
// Input: token ID (integer) -> Output: dense vector (float[])
const vocabSize = 1000;
const embeddingDim = 64;

const embeddingLayer = tf.layers.embedding({
  inputDim: vocabSize,     // how many words in the vocabulary
  outputDim: embeddingDim, // dimensions per word vector
});

// Look up the embedding for a single token
const tokenId = tf.tensor2d([[42]], [1, 1], 'int32');
const vector = embeddingLayer.apply(tokenId) as tf.Tensor;
console.log(vector.shape); // [1, 1, 64]: one 64-dimensional vector

// Look up embeddings for a sequence of tokens
const sequence = tf.tensor2d([[42, 17, 8, 103]], [1, 4], 'int32');
const vectors = embeddingLayer.apply(sequence) as tf.Tensor;
console.log(vectors.shape); // [1, 4, 64]: four 64-dim vectors

// The embedding layer starts with random weights.
// During training, Word2Vec adjusts these weights so that
// words appearing in similar contexts get similar vectors.`}
</CodeBlock>

## How Word2Vec Learns

Word2Vec uses a simple training signal: predict a word from its neighbors (CBOW) or predict neighbors from a word (Skip-gram). Words that successfully predict each other's contexts end up with similar vectors.

<CodeBlock language="typescript" title="word2vec-concept.ts">
{`// Skip-gram intuition: given a word, predict its context
// Training sentence: "prescribed aspirin for chronic pain"
//
// If center word is "aspirin":
//   Predict: "prescribed", "for", "chronic", "pain"
//
// If center word is "ibuprofen" (from another sentence):
//   Predict: "prescribed", "for", "inflammation", "pain"
//
// Both "aspirin" and "ibuprofen" predict similar context words
// ("prescribed", "for", "pain"), so their vectors converge.

// Simulated trained embeddings (4D for illustration)
const trainedEmbeddings: Record<string, number[]> = {
  'aspirin':      [0.82, 0.21, -0.11, 0.53],  // painkiller cluster
  'ibuprofen':    [0.74, 0.29, -0.18, 0.45],  // painkiller cluster
  'penicillin':   [-0.12, 0.81, 0.62, -0.22], // antibiotic cluster
  'amoxicillin':  [-0.19, 0.73, 0.68, -0.15], // antibiotic cluster
  'appendectomy': [0.08, -0.31, 0.14, 0.91],  // procedure cluster
};`}
</CodeBlock>

## Measuring Similarity

<Dialogue speaker="MEDI">
Cosine similarity measures the angle between two vectors. A value near 1.0 means the vectors point in the same direction; the words have similar meanings. A value near 0 means they are unrelated.
</Dialogue>

<CodeBlock language="typescript" title="cosine-similarity.ts">
{`function cosineSimilarity(a: number[], b: number[]): number {
  const dot = a.reduce((sum, val, i) => sum + val * b[i], 0);
  const normA = Math.sqrt(a.reduce((sum, val) => sum + val * val, 0));
  const normB = Math.sqrt(b.reduce((sum, val) => sum + val * val, 0));
  return dot / (normA * normB);
}

// Painkillers cluster together
console.log('aspirin ~ ibuprofen:',
  cosineSimilarity(trainedEmbeddings['aspirin'], trainedEmbeddings['ibuprofen']).toFixed(3)
); // 0.990: very similar

// Painkillers are far from antibiotics
console.log('aspirin ~ penicillin:',
  cosineSimilarity(trainedEmbeddings['aspirin'], trainedEmbeddings['penicillin']).toFixed(3)
); // -0.107: unrelated, pointing slightly apart

// Antibiotics cluster together
console.log('penicillin ~ amoxicillin:',
  cosineSimilarity(trainedEmbeddings['penicillin'], trainedEmbeddings['amoxicillin']).toFixed(3)
); // 0.991: very similar

// Unlike one-hot encoding, dense vectors capture real relationships.
// The model now knows that aspirin and ibuprofen are related
// even if it has only seen one of them in a specific context.`}
</CodeBlock>

<DerivationDrawer summary="Dense vector geometry: cosine similarity + dot product">
Word embeddings are dense vectors of dimension d (typically 100-1000). Two operations dominate:

**Dot product:** `a · b = Σ a_i · b_i`, sensitive to vector magnitude.

**Cosine similarity:** normalizes for magnitude:

`cos(a, b) = (a · b) / (||a|| · ||b||)`

Cosine returns values in [-1, 1]. Most embedding similarity comparisons use cosine because it ignores how 'long' the vectors are and focuses on direction (semantic meaning) rather than magnitude (frequency artifact).

**Why dimension matters:** in a d-dimensional space, random vectors have expected cosine ~0. Two vectors are 'similar' when their cosine is meaningfully above this baseline. Higher d gives more room to encode distinctions but also more noise in the baseline.
</DerivationDrawer>
