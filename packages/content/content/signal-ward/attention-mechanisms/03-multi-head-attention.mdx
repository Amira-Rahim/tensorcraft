## One Element, Many Listeners

<BridgeCallout bridge={frontmatter.concept.bridge} />

In a clinical note like "Increase methotrexate to 20mg weekly due to persistent joint inflammation," a single attention head might learn to connect "methotrexate" to "joint inflammation." But we also need a head that connects "20mg" to "weekly," and another that links "increase" to the temporal context. Multi-head attention runs these analyses in parallel.

<CodeBlock language="typescript" title="multi-head-attention.ts">
{`import * as tf from '@tensorflow/tfjs';

function multiHeadAttention(
  input: tf.Tensor2D,
  numHeads: number,
  dModel: number
) {
  const dk = dModel / numHeads;
  const seqLen = input.shape[0];
  const heads: tf.Tensor2D[] = [];

  for (let h = 0; h < numHeads; h++) {
    // Each head has its own projection matrices
    const Wq = tf.randomNormal([dModel, dk]);
    const Wk = tf.randomNormal([dModel, dk]);
    const Wv = tf.randomNormal([dModel, dk]);

    const Q = tf.matMul(input, Wq);
    const K = tf.matMul(input, Wk);
    const V = tf.matMul(input, Wv);

    // Scaled dot-product attention per head
    const scores = tf.matMul(Q, K.transpose()).div(Math.sqrt(dk));
    const weights = tf.softmax(scores, -1);
    const headOutput = tf.matMul(weights, V) as tf.Tensor2D;
    heads.push(headOutput);
  }

  // Concatenate all heads: [seqLen, dk * numHeads] = [seqLen, dModel]
  const concatenated = tf.concat(heads, 1) as tf.Tensor2D;

  // Final linear projection
  const Wo = tf.randomNormal([dModel, dModel]);
  const output = tf.matMul(concatenated, Wo);

  return output; // [seqLen, dModel]
}

// 10 tokens, 4 attention heads, 64-dim model
const input = tf.randomNormal([10, 64]) as tf.Tensor2D;
const output = multiHeadAttention(input, 4, 64);
console.log('Output shape:', output.shape); // [10, 64]`}
</CodeBlock>

## What Do Heads Specialize In?

Research on clinical transformers shows heads naturally specialize:
- **Head 1** might learn syntactic relationships (subject-verb agreement)
- **Head 2** might learn entity coreference ("the patient... she... her")
- **Head 3** might learn negation scope ("denied" modifying "chest pain")
- **Head 4** might learn medication-condition pairs

<Dialogue speaker="Vikram">
We don't tell the heads what to specialize in. They discover it during training. That's the beauty: the model finds structure we might not have thought to look for.
</Dialogue>

<DerivationDrawer summary="Multi-head: parallel attentions concatenated then projected">
Single attention computes one weighted view. **Multi-head** runs h parallel attentions with separate projections, then concatenates and projects:

```
head_i = Attention(X · W_Q^i, X · W_K^i, X · W_V^i)   for i in 1..h
MultiHead(X) = Concat(head_1, ..., head_h) · W_O
```

**Dimensions:** if `d_model = 512` and `h = 8`, each head's `d_k = d_model / h = 64`. Total parameter count of multi-head is similar to a single full-dim attention, so this is a way to express richer relationships without paying a parameter cost.

**Why heads specialize:** different heads end up attending to different patterns (some to syntax, some to semantics, some to position). The specialization is emergent; you can't assign roles.
</DerivationDrawer>
