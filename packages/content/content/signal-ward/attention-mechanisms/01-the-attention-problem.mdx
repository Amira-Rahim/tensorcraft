## The Problem with Equal Attention

<BridgeCallout bridge={frontmatter.concept.bridge} />

Our LSTM from Module 4 is a `reduce`: it folds the note word by word into one accumulator, and the accumulator is all that survives. Summarize a patient's whole history in one sentence and you lose the line that mattered.

Consider: "Patient denied chest pain but reported shortness of breath." If every word carries the same weight, nothing ties "denied" to "chest pain" rather than to "shortness of breath". The note reads as though both symptoms were reported.

<CodeBlock language="typescript" title="attention-scores.ts">
{`import * as tf from '@tensorflow/tfjs';

// Simulated hidden states for 5 words: [seqLen, hiddenDim]
const hiddenStates = tf.randomNormal([5, 64]);

// A query vector: what are we looking for?
const query = tf.randomNormal([64]);

// Compute raw attention scores via dot product
const scores = tf.matMul(
  hiddenStates,
  query.reshape([64, 1])
).squeeze(); // shape: [5]

// Scale by sqrt(d) so large dot products don't saturate the softmax
const scaled = scores.div(tf.scalar(Math.sqrt(64)));

// Normalize with softmax: the weights now sum to 1
const weights = tf.softmax(scaled);
console.log('Attention weights:', await weights.array());

// Create weighted combination: the "attended" representation
const attended = tf.matMul(
  weights.reshape([1, 5]),
  hiddenStates
).squeeze(); // shape: [64]
console.log('Attended vector shape:', attended.shape);`}
</CodeBlock>

The dot product measures similarity between the query and each hidden state. Words that match what we're looking for get higher scores. Softmax turns those scores into a probability distribution, a set of weights that sum to 1.

## Challenge

Compute attention weights for a sequence of clinical tokens.

<Exercise slug="compute-attention" />

<DerivationDrawer summary="Attention as a soft argmax over a similarity score">
Attention answers: "given query Q, how much should I weight each key K?" The weight per key is a scaled dot product passed through softmax:

`weight_i = softmax( Q · K_i / √d_k )`

**Why scale by √d_k?** Without it, dot products grow with dimension (variance scales with d_k), which pushes softmax into saturation regions where gradients vanish. Dividing by √d_k keeps the variance ~1 so the softmax stays in its useful range during training.

The attention output is a weighted sum of values:

`Attention(Q, K, V) = softmax(Q · Kᵀ / √d_k) · V`
</DerivationDrawer>
