Reading one discharge summary carefully takes four minutes. Forty minutes of the hour are already gone.

<Dialogue speaker="Dr. Karimi">
One document, one answer. That was a proof of concept. This patient has 47 records across two hospital systems. Emergency notes, lab results, imaging reports, discharge summaries. Some in Spanish. We cannot comprehend 47 documents sequentially. We need to retrieve the right ones first.
</Dialogue>

<Dialogue speaker="Khalil">
It is the shape of any handler that queries before it renders. The data call finishes first, and the template only ever sees rows that came back. Retrieve the right documents first, then hand only those to the QA model. That is Retrieval-Augmented Generation.
</Dialogue>

The word doing the work there is `await`. The handler blocks on its query before it renders, so the output can only describe data that actually came back. RAG puts the same block in front of generation: nothing is generated until retrieval returns, and the model answers from those passages instead of from whatever its weights happen to hold. What differs is downstream of the await. A template prints what you passed it or prints nothing. A decoder can write a sentence that appeared in none of the passages, which is why what reaches it matters more here than it does in a render.

## The RAG Pattern

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="rag-pipeline.ts">
{`import * as tf from '@tensorflow/tfjs';

// RAG Pipeline: Retrieve → Augment → Generate
// Same pattern as a server handler: query first, then render

interface Document {
  id: string;
  text: string;
  metadata: { language: string; docType: string; date: string };
}

interface RetrievalResult {
  document: Document;
  score: number;
}

class VectorIndex {
  private embeddings: tf.Tensor2D | null = null;
  private documents: Document[] = [];

  // Index documents by computing and storing their embeddings
  async index(docs: Document[], embedFn: (text: string) => Promise<tf.Tensor1D>): Promise<void> {
    this.documents = docs;
    const vectors: tf.Tensor1D[] = [];

    for (const doc of docs) {
      const embedding = await embedFn(doc.text);
      vectors.push(embedding);
    }

    // Stack into a matrix: [numDocs, embDim]
    this.embeddings = tf.stack(vectors) as tf.Tensor2D;
    vectors.forEach(v => v.dispose());  // Clean up individual tensors
  }

  // Retrieve top-k documents by cosine similarity
  async retrieve(query: string, embedFn: (text: string) => Promise<tf.Tensor1D>, k: number = 3): Promise<RetrievalResult[]> {
    if (!this.embeddings) throw new Error('Index is empty');

    const queryEmb = await embedFn(query);

    // Cosine similarity: dot product of normalized vectors
    const queryNorm = queryEmb.div(queryEmb.norm());
    const docsNorm = this.embeddings.div(
      this.embeddings.norm('euclidean', 1, true)
    );

    const scores = tf.matMul(docsNorm, queryNorm.expandDims(1))
      .squeeze([1]);

    const scoreArray = await scores.array() as number[];

    // Sort by score, take top k
    const ranked = scoreArray
      .map((score, i) => ({ document: this.documents[i], score }))
      .sort((a, b) => b.score - a.score)
      .slice(0, k);

    queryEmb.dispose();
    queryNorm.dispose();
    docsNorm.dispose();
    scores.dispose();

    return ranked;
  }
}

// Complete RAG pipeline
async function ragAnswer(
  question: string,
  index: VectorIndex,
  embedFn: (text: string) => Promise<tf.Tensor1D>,
  qaModel: (question: string, context: string) => Promise<string>
): Promise<{ answer: string; sources: RetrievalResult[] }> {
  // 1. Retrieve relevant documents
  const retrieved = await index.retrieve(question, embedFn, 3);

  // 2. Augment: combine retrieved docs into context
  const context = retrieved
    .map(r => r.document.text)
    .join('\\n---\\n');

  // 3. Generate answer from context
  const answer = await qaModel(question, context);

  return { answer, sources: retrieved };
}`}
</CodeBlock>

## Clinical RAG in Action

<CodeBlock language="typescript" title="clinical-rag.ts">
{`// Index 47 patient documents, answer in milliseconds
const index = new VectorIndex();
await index.index(patientRecords, embedDocument);

const result = await ragAnswer(
  "Has this patient ever had an allergic reaction to penicillin?",
  index,
  embedDocument,
  comprehend
);

console.log('Answer:', result.answer);
// → "Patient reported severe allergic reaction to penicillin-class antibiotics (2015)"

console.log('Sources:');
result.sources.forEach((s, i) => {
  console.log(\`  \${i + 1}. [\${s.document.metadata.docType}] \${s.document.metadata.date} (score: \${s.score.toFixed(3)})\`);
});
// → 1. [discharge_summary] 2019-03-14 (score: 0.912)
// → 2. [allergy_record] 2015-08-22 (score: 0.887)
// → 3. [medication_list] 2023-11-01 (score: 0.743)`}
</CodeBlock>

One of those three documents is in Spanish. Cross-lingual retrieval only works if the encoder saw both languages during training: a monolingual English model puts `alergia a la penicilina` nowhere near `penicillin allergy`, and the Guatemala record never enters the top three. Check what your embedding model was trained on before you tell a clinician the system reads every chart in the file.
