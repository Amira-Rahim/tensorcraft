<Dialogue speaker="Amir">
At Meridian, our first surveillance model choked because the feature maps were too large. A 224x224 input with 64 filters means over 3 million values per layer. Pooling solves this. You take each 2x2 region and keep only the max value. Same idea as responsive images. You downsample, but the important features survive.
</Dialogue>

<Dialogue speaker="Noor">
So it is like serving a 400px image instead of an 800px one via srcset? You lose resolution but the content is still recognizable.
</Dialogue>

Srcset is gentler than that. The 800px original still sits on the server; the browser just picked a smaller variant. Max pooling has no original to fall back on. Only the strongest activation in each region moves forward, and the rest is discarded permanently; the downsampled tensor cannot reconstruct what it threw away. The two main types are max pooling (keep the strongest activation) and average pooling (keep the mean); max is far more common because strong activations usually signal important features.

## Why Downsample?

After convolution, feature maps can be enormous. A 224x224 image with 64 filters produces 64 feature maps of 224x224 each. That is over 3.2 million values. Pooling reduces spatial dimensions while preserving the most important activations.

<CodeBlock language="typescript" title="pooling-operations.ts">
{`// Max pooling: keep the strongest activation in each region
function maxPool2D(
  input: number[][],
  poolSize: number
): number[][] {
  const iH = input.length;
  const iW = input[0].length;
  const oH = Math.floor(iH / poolSize);
  const oW = Math.floor(iW / poolSize);

  const output: number[][] = Array.from({ length: oH }, () =>
    new Array(oW).fill(0)
  );

  for (let r = 0; r < oH; r++) {
    for (let c = 0; c < oW; c++) {
      let maxVal = -Infinity;
      for (let pr = 0; pr < poolSize; pr++) {
        for (let pc = 0; pc < poolSize; pc++) {
          const val = input[r * poolSize + pr][c * poolSize + pc];
          if (val > maxVal) maxVal = val;
        }
      }
      output[r][c] = maxVal;
    }
  }

  return output;
}

// Average pooling: take the mean of each region
function avgPool2D(
  input: number[][],
  poolSize: number
): number[][] {
  const iH = input.length;
  const iW = input[0].length;
  const oH = Math.floor(iH / poolSize);
  const oW = Math.floor(iW / poolSize);

  const output: number[][] = Array.from({ length: oH }, () =>
    new Array(oW).fill(0)
  );

  for (let r = 0; r < oH; r++) {
    for (let c = 0; c < oW; c++) {
      let sum = 0;
      for (let pr = 0; pr < poolSize; pr++) {
        for (let pc = 0; pc < poolSize; pc++) {
          sum += input[r * poolSize + pr][c * poolSize + pc];
        }
      }
      output[r][c] = sum / (poolSize * poolSize);
    }
  }

  return output;
}

// Example: 4x4 feature map with 2x2 max pooling
const featureMap = [
  [1, 3, 2, 1],
  [4, 6, 5, 2],
  [7, 2, 1, 8],
  [3, 1, 4, 9],
];

console.log(maxPool2D(featureMap, 2));
// [[6, 5],
//  [7, 9]]
// Each 2x2 block reduced to its maximum value

console.log(avgPool2D(featureMap, 2));
// [[3.5, 2.5],
//  [3.25, 5.5]]
// Each 2x2 block reduced to its average`}
</CodeBlock>

## Dimension Reduction

<CodeBlock language="typescript" title="pooling-dimensions.ts">
{`// Pooling output size:
// outputSize = Math.floor(inputSize / poolSize)
// (assuming stride === poolSize, no overlap)

function pooledDimensions(
  inputHeight: number,
  inputWidth: number,
  poolSize: number,
  numFilters: number
): { shape: [number, number, number]; reduction: number } {
  const oH = Math.floor(inputHeight / poolSize);
  const oW = Math.floor(inputWidth / poolSize);

  const inputTotal = inputHeight * inputWidth * numFilters;
  const outputTotal = oH * oW * numFilters;

  return {
    shape: [oH, oW, numFilters],
    reduction: Math.round((1 - outputTotal / inputTotal) * 100),
  };
}

// After conv: [224, 224, 32] feature maps
const result = pooledDimensions(224, 224, 2, 32);
console.log(result.shape);     // [112, 112, 32]
console.log(result.reduction); // 75, removed 75% of spatial data

// After two pooling layers: [56, 56, 32]
const result2 = pooledDimensions(112, 112, 2, 32);
console.log(result2.shape);    // [56, 56, 32]

// Surveillance image pipeline:
// 224x224x32 -> pool -> 112x112x32 -> pool -> 56x56x32
// From 1,605,632 values to 100,352: 94% reduction!`}
</CodeBlock>

<DerivationDrawer summary="Pooling output size + parameter count">
**Pooling has zero learnable parameters.** It downsamples by taking the max or mean over each window.

For input width W, pool size K, stride S (often S = K):

`W_out = floor((W - K) / S) + 1`

With `K = S = 2` (the standard), `W_out = floor(W/2)`. A 224×224 input becomes 112×112 after one max-pool.

**Information loss is permanent:** max-pool keeps only the highest activation per window. The downsampled tensor cannot reconstruct the original. This is by design: pooling enforces translation invariance and reduces compute.

**Average pooling** preserves more low-frequency information; max pooling preserves the strongest activation regardless of position. Which one to use depends on whether the task cares about edge-like features (max) or texture-like features (average).
</DerivationDrawer>
