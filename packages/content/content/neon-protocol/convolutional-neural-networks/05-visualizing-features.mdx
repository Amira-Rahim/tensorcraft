## Inspecting Activations

Each conv filter produces a 2D activation map. High values indicate regions where the filter detected its target pattern. By normalizing and visualizing these maps, you can see exactly what the network has learned.

<CodeBlock language="typescript" title="activation-extraction.ts">
{`// DevTools inspection:
// document.querySelector('.card')
//   -> see computed styles, box model, layout contribution

// CNN inspection:
// model.getLayer('conv2d_1').output
//   -> see activation patterns, feature detection, spatial response

interface ActivationMap {
  filterIndex: number;
  map: number[][];        // normalized 0-1 values
  maxActivation: number;  // peak response strength
  description: string;    // what this filter likely detects
}

// Normalize an activation map to 0-1 range for visualization
function normalizeMap(raw: number[][]): number[][] {
  let min = Infinity;
  let max = -Infinity;

  for (const row of raw) {
    for (const val of row) {
      if (val < min) min = val;
      if (val > max) max = val;
    }
  }

  const range = max - min;
  if (range === 0) return raw.map(row => row.map(() => 0));

  return raw.map(row =>
    row.map(val => (val - min) / range)
  );
}

// Simulate extracting activations from a conv layer
function extractActivations(
  featureMaps: number[][][],  // [numFilters][height][width]
  layerName: string
): ActivationMap[] {
  const layerDescriptions: Record<string, string[]> = {
    conv1: [
      'horizontal edges',
      'vertical edges',
      'diagonal gradients (top-left to bottom-right)',
      'diagonal gradients (top-right to bottom-left)',
      'brightness transitions',
      'dark-to-light boundaries',
      'texture frequency detector',
      'contrast edges',
    ],
    conv2: [
      'corners and junctions',
      'circular shapes (lens outlines)',
      'rectangular boundaries',
      'parallel lines (housing edges)',
      'grid patterns',
      'curved edges',
      'angular transitions',
      'concentric patterns',
    ],
    conv3: [
      'camera dome shapes',
      'camera box housings',
      'lens assemblies',
      'mounting brackets',
      'cable connections',
      'LED indicator clusters',
      'ventilation grilles',
      'antenna structures',
    ],
  };

  const descriptions = layerDescriptions[layerName] || [];

  return featureMaps.map((raw, i) => {
    const normalized = normalizeMap(raw);
    let peakVal = -Infinity;
    for (const row of raw) {
      for (const val of row) {
        if (val > peakVal) peakVal = val;
      }
    }

    return {
      filterIndex: i,
      map: normalized,
      maxActivation: peakVal,
      description: descriptions[i] || 'learned feature ' + i,
    };
  });
}`}

<DerivationDrawer summary="What feature-map magnitude actually means">
A feature map is the output of one filter, shape `[H_out, W_out]` per filter per layer. Visualizing it as an image: bright pixels = high activation = strong response of that filter at that spatial position.

**Caveats:**
- Magnitude is not normalized; comparing brightness across filters or layers is misleading without per-channel rescaling.
- A bright pixel at position (i, j) means the filter's pattern was detected in the receptive field around (i, j) of the input. The receptive field grows with depth: a layer-3 filter integrates over a much larger input region than a layer-1 filter.
- Multiple filters can fire on the same input region. "This is the dog filter" is post-hoc storytelling about what a high-magnitude filter responded to, not a guarantee.

**For interpretability**, combine feature maps with gradient-based methods (Grad-CAM, integrated gradients) that show which input pixels caused the activation, not just where the activation was.
</DerivationDrawer>
