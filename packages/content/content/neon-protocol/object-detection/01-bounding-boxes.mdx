I spent six years at Meridian building their drone vision pipeline. Every frame, every detection. It all starts with a bounding box. Four numbers that say: "there is something here." You've used getBoundingClientRect() a thousand times. Same concept. Meridian just does it with neural networks instead of the DOM.
</Dialogue>

<Dialogue speaker="Noor">
Wait. Their multi-billion credit surveillance system outputs the same data structure as me checking if a tooltip overflows the viewport?
</Dialogue>

<Dialogue speaker="Amir">
The same four numbers. X, Y, width, height. The difference is how you get them.
</Dialogue>

Call `getBoundingClientRect()` on a tooltip and you get `{ x: 120, y: 80, width: 60, height: 40 }`. Run a detection model on a surveillance frame and you get `[0.19, 0.17, 0.09, 0.08]`. Same rectangle, same four numbers, one difference: the model's coordinates are normalized to the 0-1 range instead of pixels. Every object the network finds in an image comes back as one of these rectangles, a **bounding box**.

## Bounding Boxes: DOMRects for Images

<BridgeCallout bridge={frontmatter.concept.bridge} />

A detection model outputs one rectangle per object it finds, plus a label and a confidence score for each.

<CodeBlock language="typescript" title="bounding-box-basics.ts">
{`// Frontend: element.getBoundingClientRect() returns:
// { x: 120, y: 45, width: 200, height: 150, top, right, bottom, left }

// ML: a bounding box is the same idea
// [x, y, width, height], but normalized to 0-1

interface BoundingBox {
  x: number;      // left edge (0-1)
  y: number;      // top edge (0-1)
  width: number;  // box width (0-1)
  height: number; // box height (0-1)
  label: string;  // what was detected
  confidence: number; // how sure the model is (0-1)
}

// A drone detected at the center of a 640x480 image:
// Pixel coordinates: x=220, y=140, w=200, h=200
// Normalized: x=220/640, y=140/480, w=200/640, h=200/480

const detection: BoundingBox = {
  x: 0.344,
  y: 0.292,
  width: 0.3125,
  height: 0.417,
  label: 'meridian-drone',
  confidence: 0.94,
};`}
</CodeBlock>

## Why Normalize?

Normalization makes bounding boxes resolution-independent. The same box description works on a 640px preview and a 4K feed.

<CodeBlock language="typescript" title="coordinate-conversion.ts">
{`// Convert pixel coordinates to normalized (0-1) coordinates
function toNormalized(
  pixelBox: { x: number; y: number; width: number; height: number },
  imageWidth: number,
  imageHeight: number
): { x: number; y: number; width: number; height: number } {
  return {
    x: pixelBox.x / imageWidth,
    y: pixelBox.y / imageHeight,
    width: pixelBox.width / imageWidth,
    height: pixelBox.height / imageHeight,
  };
}

// Convert normalized coordinates back to pixels
function toPixels(
  normalizedBox: { x: number; y: number; width: number; height: number },
  imageWidth: number,
  imageHeight: number
): { x: number; y: number; width: number; height: number } {
  return {
    x: normalizedBox.x * imageWidth,
    y: normalizedBox.y * imageHeight,
    width: normalizedBox.width * imageWidth,
    height: normalizedBox.height * imageHeight,
  };
}

// This is why Meridian's system works on any camera resolution
// The model outputs normalized boxes, then scales to display size
// Exactly like CSS: width: 50% works at any viewport width

const drone = { x: 220, y: 140, width: 200, height: 200 };
const normalized = toNormalized(drone, 640, 480);
console.log(normalized);
// { x: 0.344, y: 0.292, width: 0.3125, height: 0.417 }

// Render on a 1920x1080 display:
const displayBox = toPixels(normalized, 1920, 1080);
console.log(displayBox);
// { x: 660, y: 315, width: 600, height: 450 }`}
</CodeBlock>

## Box Formats

Detection models use different box formats. YOLO emits center-based boxes, COCO annotations use corner-plus-size, and evaluation code usually wants two corners. You convert between them constantly.

<CodeBlock language="typescript" title="box-formats.ts">
{`// Format 1: [x, y, width, height]: "xywh" (top-left corner + size)
// Used by: COCO dataset, many web APIs
// Same as getBoundingClientRect()!

// Format 2: [x_center, y_center, width, height]: "cxcywh"
// Used by: YOLO models
// The center point + dimensions

// Format 3: [x_min, y_min, x_max, y_max]: "xyxy" (two corners)
// Used by: Pascal VOC, Faster R-CNN

function xywhToCxcywh(box: number[]): number[] {
  const [x, y, w, h] = box;
  return [x + w / 2, y + h / 2, w, h];
}

function cxcywhToXywh(box: number[]): number[] {
  const [cx, cy, w, h] = box;
  return [cx - w / 2, cy - h / 2, w, h];
}

function xywhToXyxy(box: number[]): number[] {
  const [x, y, w, h] = box;
  return [x, y, x + w, y + h];
}

// Converting formats is like converting between
// { left, top, width, height } and { left, top, right, bottom }
// in CSS positioning`}
</CodeBlock>
