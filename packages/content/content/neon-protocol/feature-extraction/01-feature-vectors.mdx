<Dialogue speaker="Amir">
When I worked at Meridian, we processed 14 million camera frames per hour. You cannot store 14 million images. But you can store 14 million vectors of 512 numbers each. A feature vector is an image compressed down to what the network considers important, stripped of everything it doesn't.
</Dialogue>

<Dialogue speaker="Noor">
So it is like hashing. A hash function takes arbitrary input and produces a fixed-size fingerprint. You cannot reconstruct the original, but you can compare fingerprints efficiently.
</Dialogue>

A cryptographic hash is built so that flipping one bit of the input scrambles the whole digest; near-collisions are the failure case you engineer against. A feature extractor is built for the reverse: nudge the input a little and the vector moves a little. Both hand back a fixed-size output; only one of them keeps similarity intact. That is what makes a feature vector searchable, and it is why you cannot use one where you need the other.

## Images to Numbers

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="feature-extraction.ts">
{`import * as tf from '@tensorflow/tfjs';

// A 224x224 RGB image = 150,528 values
// MobileNetV2's feature vector = 1,280 values
// Compression ratio: 118:1

// To extract features, use a pre-trained model without the classification head
// The layer feeding the classification head is the one you want

async function extractFeatures(image: tf.Tensor3D): Promise<tf.Tensor1D> {
  // Load MobileNet and get the feature layer
  const mobilenet = await tf.loadGraphModel(
    'https://tfhub.dev/google/tfjs-model/imagenet/mobilenet_v2_100_224/feature_vector/3/default/1',
    { fromTFHub: true }
  );

  // Preprocess: resize and normalize
  const preprocessed = tf.tidy(() => {
    const resized = tf.image.resizeBilinear(image.expandDims(0), [224, 224]);
    return resized.div(255.0); // normalize to [0, 1]
  });

  // Extract features
  const features = mobilenet.predict(preprocessed) as tf.Tensor2D;
  return features.squeeze() as tf.Tensor1D; // [1280]
}

// The result: a 1280-number fingerprint of the image
// Similar images will have similar fingerprints
// Unlike crypto hashes, similarity is preserved`}
</CodeBlock>

## Manual Feature Extraction

<CodeBlock language="typescript" title="manual-features.ts">
{`// You can also build a feature extractor by slicing a trained model
// This is like removing the last layer of a classification network

async function buildFeatureExtractor() {
  // Load a pre-trained classification model
  const fullModel = await tf.loadLayersModel('model/model.json');

  // Find the layer before the final classification head
  const featureLayer = fullModel.layers[fullModel.layers.length - 2];

  // Create a new model that outputs at that layer
  const featureExtractor = tf.model({
    inputs: fullModel.input,
    outputs: featureLayer.output,
  });

  return featureExtractor;
}

// Compression comparison for a 512-value feature vector:
// Raw image:    224 * 224 * 3 = 150,528 float32 values = 588 KB
// Feature vec:  512 float32 values = 2 KB
// Ratio:        ~294x compression
// And the features carry more meaning than raw pixels`}
</CodeBlock>

<DerivationDrawer summary="Why dense vectors carry meaning a flat array doesn't">
A feature vector is a point in d-dimensional space chosen so that **distances encode similarity**. Two such vectors (called embeddings) have small distance ⟺ they share semantic structure.

**Mathematical property required:** the embedding map `f: input → R^d` should preserve a meaningful relation. Common choices:

- **Triplet loss:** `||f(a) − f(p)|| < ||f(a) − f(n)||` for anchor a, positive p, negative n.
- **Contrastive (NT-Xent):** pull matched pairs together, push every other item in the batch apart, all in one loss.
- **Reconstruction (autoencoder):** preserves variance via `||x − decode(f(x))||²`.

**Curse of dimensionality:** in high d, all random vectors become near-orthogonal (cosine ≈ 0). Useful structure must be learned, not assumed. Random initialization gives uniform-distance embeddings, meaningless until trained.
</DerivationDrawer>
