<Dialogue speaker="NEON">
Responsive design adapts a three-column desktop layout to a single-column mobile view. The content is identical — the spatial arrangement changes. Dimensionality reduction does the same thing for data. A 512-dimensional feature space is projected into 2 dimensions. The clusters, the relationships, the neighborhoods — they are preserved. Only the coordinate system changes.
</Dialogue>

<Dialogue speaker="Kira">
So PCA is like switching from a grid layout to a flex column? You keep the content order but compress the spatial dimensions?
</Dialogue>

In responsive design, you reorganize content to fit smaller screens while preserving the reading order and visual hierarchy. PCA reorganizes data to fit fewer dimensions while preserving the directions of greatest variance. Both are lossy compressions that prioritize the most important structure.

## PCA: Principal Component Analysis

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="pca-reduction.ts">
{`import * as tf from '@tensorflow/tfjs';

// PCA steps:
// 1. Center the data (subtract the mean)
// 2. Compute the covariance matrix
// 3. Find eigenvectors (principal components)
// 4. Project onto top-k components

function simplePCA(data: tf.Tensor2D, targetDims: number): tf.Tensor2D {
  // data shape: [numSamples, 512]

  // Step 1: Center the data
  const mean = data.mean(0); // [512]
  const centered = data.sub(mean); // [numSamples, 512]

  // Step 2: Covariance matrix
  const n = data.shape[0];
  const cov = centered.transpose().matMul(centered).div(n - 1);
  // [512, 512]

  // Step 3: Eigendecomposition (simplified — use SVD in practice)
  // In TF.js, use SVD: U * S * V^T = centered
  const { u, s, v } = tf.linalg.svd(centered);
  // v columns are principal components

  // Step 4: Project onto top-k components
  const topComponents = v.slice([0, 0], [-1, targetDims]); // [512, 2]
  const projected = centered.matMul(topComponents); // [numSamples, 2]

  return projected;
}

// 512 dimensions → 2 dimensions
// Like 3-column grid → 1-column stack
// The most important relationships survive the projection`}
</CodeBlock>

## t-SNE vs PCA

<CodeBlock language="typescript" title="tsne-vs-pca.ts">
{`// PCA: Linear projection. Fast. Preserves global structure.
//   Like CSS Flexbox: items reflow linearly
//
// t-SNE: Non-linear mapping. Slow. Preserves local neighborhoods.
//   Like CSS Grid with auto-placement: items cluster by similarity

// When to use which:
// PCA:  Quick overview, initial exploration, preprocessing
// t-SNE: Publication-quality cluster visualization

// t-SNE in the browser (simplified concept):
// 1. Compute pairwise similarities in high-D (Gaussian)
// 2. Compute pairwise similarities in low-D (t-distribution)
// 3. Minimize the difference (KL divergence) via gradient descent
// 4. Points that were close in 512-D stay close in 2-D

// For the resistance's war room display:
// PCA for real-time updates (fast enough for streaming)
// t-SNE for the weekly intelligence briefing (better clusters)

interface ReductionConfig {
  method: 'pca' | 'tsne';
  targetDims: 2 | 3;
  perplexity?: number; // t-SNE only: neighborhood size (5-50)
}

// The holotable uses PCA for the live drone feed,
// switching to t-SNE when Lin needs detailed cluster analysis`}
</CodeBlock>
