## The Mixed Scales Problem

One upstream service logs timestamps in epoch seconds, another in epoch millis, and the same moment lands in your pipeline as `1755561600` and `1755561600000`. Any Node service that ingests third-party data converts them to one scale at the door, because no comparison downstream is safe until it does. Pixel normalization does that job for images.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="ingest-vs-ml-normalization.ts">
{`// Node: ingest normalization gives every source one time scale
// Before: service A logs 1755561600 (epoch seconds),
//         service B logs 1755561600000 (epoch millis)
// After:  both stored as millis: every comparison downstream is safe

// ML: pixel normalization does the same thing
// Before: nighttime image pixels [3, 8, 12, 5]
//         daytime image pixels  [201, 245, 230, 218]
// Daytime mean 223.5, nighttime mean 7:
// the model "hears" the daytime image about 32x louder

// After normalization: both map to [0, 1] range
// Night: [0.0, 0.56, 1.0, 0.22]
// Day:   [0.0, 1.0, 0.66, 0.39]
// Equal volume: the model can focus on patterns, not brightness`}
</CodeBlock>

## Why Raw Pixels Break Training

Neural networks learn by adjusting weights based on input values. The gradient for a weight scales with the input feeding it, so a pixel at 240 pushes 48 times harder on the update than a pixel at 5. An image spanning [200, 255] moves the weights far more than one spanning [0, 50], on brightness alone.

<Dialogue speaker="Noor">
So without normalization, the model pays more attention to bright images just because their numbers are bigger? That's like a component with higher CSS specificity getting all the styling priority regardless of relevance.
</Dialogue>

<Dialogue speaker="NEON">
Specificity is a tiebreak rule the browser applies on purpose. Magnitude dominance is an accident of arithmetic. Nobody decided bright pixels matter more; the gradients simply scale with the input values. Normalization removes the accident.
</Dialogue>

## Min-Max Normalization

The simplest approach: map all values to the [0, 1] range. The loop below is the definition; the challenge asks for the same thing as `t.sub(t.min()).div(t.max().sub(t.min()))`.

<CodeBlock language="typescript" title="min-max-normalize.ts">
{`type PixelGrid = number[][];

function minMaxNormalize(pixels: PixelGrid): number[][] {
  // Step 1: Find the global min and max
  // (the extremes that define this image's raw scale)
  let min = Infinity;
  let max = -Infinity;

  for (const row of pixels) {
    for (const pixel of row) {
      if (pixel < min) min = pixel;
      if (pixel > max) max = pixel;
    }
  }

  // Step 2: Guard against division by zero
  // (a flat image has no range to scale)
  const range = max - min;
  if (range === 0) {
    return pixels.map(row => row.map(() => 0));
  }

  // Step 3: Scale every pixel to [0, 1]
  return pixels.map(row =>
    row.map(pixel => (pixel - min) / range)
  );
}`}
</CodeBlock>

The formula `(value - min) / (max - min)` is the same math behind CSS `calc()` percentage calculations and progress bar widths: `width: calc((current - start) / (end - start) * 100%)`.

## Z-Score Standardization

For more advanced models, z-score normalization centers data around zero with unit variance. Each value becomes "how many standard deviations from the mean."

<CodeBlock language="typescript" title="z-score-normalize.ts">
{`function calculateMean(pixels: PixelGrid): number {
  let sum = 0;
  let count = 0;
  for (const row of pixels) {
    for (const pixel of row) {
      sum += pixel;
      count++;
    }
  }
  return count === 0 ? 0 : sum / count;
}

function calculateStd(pixels: PixelGrid, mean: number): number {
  let sumSquaredDiff = 0;
  let count = 0;
  for (const row of pixels) {
    for (const pixel of row) {
      sumSquaredDiff += (pixel - mean) ** 2;
      count++;
    }
  }
  return count === 0 ? 0 : Math.sqrt(sumSquaredDiff / count);
}

function zScoreNormalize(pixels: PixelGrid): number[][] {
  const mean = calculateMean(pixels);
  const std = calculateStd(pixels, mean);

  if (std === 0) {
    return pixels.map(row => row.map(() => 0));
  }

  return pixels.map(row =>
    row.map(pixel => (pixel - mean) / std)
  );
}`}
</CodeBlock>

Z-score values can be negative (darker than average) or positive (brighter than average), with most values falling between -3 and 3. The zero point has moved: it sits at the dataset's average brightness now, not at black.

## Channel-Wise Normalization

Real images have three channels (RGB). Each channel may have different statistical properties: red neon signs create high red values, dark alleys have low blue values. Normalize each channel against statistics computed across the whole dataset, not per image. Per-image min-max stretches every channel to full range, which destroys the difference just described: a red-lit alley and a blue-lit one both come out with a saturated red channel.

<CodeBlock language="typescript" title="channel-normalize.ts">
{`interface RGBImage {
  red: PixelGrid;
  green: PixelGrid;
  blue: PixelGrid;
}

interface ChannelStats {
  mean: [number, number, number];
  std: [number, number, number];
}

// Computed once over every training image, then reused forever
function normalizeRGBImage(image: RGBImage, stats: ChannelStats): RGBImage {
  const scale = (grid: PixelGrid, mean: number, std: number) =>
    grid.map(row => row.map(p => (p / 255 - mean) / std));

  return {
    red: scale(image.red, stats.mean[0], stats.std[0]),
    green: scale(image.green, stats.mean[1], stats.std[1]),
    blue: scale(image.blue, stats.mean[2], stats.std[2]),
  };
}

// ImageNet standard values: the ingest convention the whole field shares
const IMAGENET_STATS: ChannelStats = {
  mean: [0.485, 0.456, 0.406],
  std: [0.229, 0.224, 0.225],
};`}
</CodeBlock>
