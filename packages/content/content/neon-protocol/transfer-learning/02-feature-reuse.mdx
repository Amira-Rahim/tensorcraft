Run the stolen model on a drone photo and it answers with a confident wrong label: warplane, or kite. There is no drone class in ImageNet, so the label was never going to land. The machinery that produced it is the part worth stealing.

<Dialogue speaker="NEON">
A Button component does not care if it lives in a shopping cart or a login form. A convolutional filter that detects vertical edges does not care if the edge belongs to a cat's ear or a drone's wing. Meridian paid two million credits for that insight. You are getting it free, which seems fair.
</Dialogue>

<Dialogue speaker="Noor">
So the early layers of a model are like a component library, generic building blocks that work everywhere?
</Dialogue>

<Dialogue speaker="NEON">
For the first few layers, yes. The analogy decays with depth. A layer-2 edge detector is a Box primitive: it works anywhere. A layer-11 "golden retriever" detector is somebody else's checkout page. Reuse the primitives. Replace the pages.
</Dialogue>

Take NEON's decay curve seriously; it is the entire economics of transfer learning. A model's internal features (edges, textures, shapes) compose into objects it was never trained on; what is missing is only the layer that names them. `Button`, `Input`, and `Card` do the same when they compose into an app their authors never imagined. You import the components without caring how they were built. The catch is depth: the deeper the layer, the more it belongs to someone else's app.

## The Feature Hierarchy

<BridgeCallout bridge={frontmatter.concept.bridge} />

A component library is organized in layers of abstraction. Primitives like `Box` and `Text` compose into `Card` and `ListItem`, which compose into `ProductGrid` and `UserProfile`. Neural networks learn the same hierarchical structure automatically during training.

<CodeBlock language="typescript" title="feature-hierarchy.ts">
{`// Component library hierarchy:
// Primitives:  Box, Text, Icon           → universal across all apps
// Components:  Button, Input, Card        → reusable across most apps
// Patterns:    SearchBar, NavMenu         → reusable across similar apps
// Pages:       ProductPage, Checkout      → specific to one app

// Neural network feature hierarchy:
// Layer 1-2:   Edges, gradients, colors   → universal across all vision tasks
// Layer 3-5:   Textures, patterns, curves → reusable across most vision tasks
// Layer 6-10:  Parts (wheels, wings, eyes) → reusable across similar tasks
// Layer 11+:   Full objects (car, drone)   → specific to the training dataset

// The deeper you go, the more specific the features become
// But the early layers? Universal. Like primitives in a design system.

interface FeatureLevel {
  layerRange: string;
  detects: string;
  analogy: string;
  transferability: 'universal' | 'high' | 'moderate' | 'task-specific';
}

const hierarchy: FeatureLevel[] = [
  {
    layerRange: 'Layer 1-2',
    detects: 'Edges, gradients, color blobs',
    analogy: 'Box, Text, Icon: raw primitives',
    transferability: 'universal',
  },
  {
    layerRange: 'Layer 3-5',
    detects: 'Textures, repeating patterns, corners',
    analogy: 'Button, Input, Card: composable components',
    transferability: 'high',
  },
  {
    layerRange: 'Layer 6-10',
    detects: 'Object parts: wheels, wings, faces',
    analogy: 'SearchBar, NavMenu: assembled patterns',
    transferability: 'moderate',
  },
  {
    layerRange: 'Layer 11+',
    detects: 'Full objects: specific car models, breeds',
    analogy: 'ProductPage, Checkout: app-specific screens',
    transferability: 'task-specific',
  },
];`}
</CodeBlock>

## Extracting Reusable Features

You can extract features from any intermediate layer of a pre-trained model. The earlier the layer, the more universal the features.

<CodeBlock language="typescript" title="extract-features.ts">
{`import * as tf from '@tensorflow/tfjs';

// Extract features from an intermediate layer
// Like importing only the components you need:
// import { Card } from '@ui/components'; // not the whole library

async function buildFeatureExtractor(
  model: tf.LayersModel,
  layerName: string
): Promise<tf.LayersModel> {
  // Find the target layer
  const targetLayer = model.getLayer(layerName);

  // Create a new model that outputs from that layer
  // Everything after is discarded, like tree-shaking unused components
  const featureExtractor = tf.model({
    inputs: model.input,
    outputs: targetLayer.output,
  });

  return featureExtractor;
}

// Features from early layers transfer to ANY vision task
// Features from later layers only transfer to SIMILAR tasks

function analyzeTransferability(
  layerIndex: number,
  totalLayers: number
): string {
  const depth = layerIndex / totalLayers;

  if (depth < 0.3) return 'Universal: edges and gradients work everywhere';
  if (depth < 0.7) return 'Reusable: textures and object parts transfer broadly';
  return 'Task-specific: expect to retrain these layers';
}`}
</CodeBlock>

## Why Cats Help You Find Drones

<CodeBlock language="typescript" title="cross-domain-transfer.ts">
{`// A model trained on ImageNet (cats, dogs, cars, boats) hands you most of a
// drone detector. Not the label. The machinery underneath it.
// The FEATURES are shared, even when the OBJECTS are different.

// Cat ear edge     → same edge detector → Drone wing edge
// Fur texture      → same texture detector → Carbon fiber texture
// Round eye shape  → same shape detector → Camera lens shape

// This is why component libraries work across projects:
// A <Card> component does not know it was first built for a blog.
// It works equally well in a dashboard, an admin panel, or a drone tracker.

interface FeatureTransferExample {
  feature: string;
  sourceObject: string;
  targetObject: string;
  layerDepth: 'early' | 'middle' | 'late';

const transfers: FeatureTransferExample[] = [
