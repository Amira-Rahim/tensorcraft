## From Single FFT to Spectrogram

<BridgeCallout bridge={frontmatter.concept.bridge} />

An FFT of one frame gives one row: frequency content across that frame's time interval. To see how frequencies change over time, you slide a window across the signal and compute the FFT at each position.

<CodeBlock language="typescript" title="stft.ts">
{`import * as tf from '@tensorflow/tfjs';

/**
 * Short-Time Fourier Transform (STFT)
 * Slide a window across the signal, compute one FFT at each position.
 *
 * Think of it like a scrolling viewport across a timeline:
 * at each scroll position, you analyze what's visible in the window.
 *
 * tfjs ships it. Three arguments: the signal, how many samples each FFT
 * sees (the frame), and how far the frame slides between FFTs (the hop).
 * Frame i starts at sample i * hop, and a frame only counts when it fits
 * inside the signal whole, so the row count comes out of all three.
 */
function stftMagnitudes(signal: number[], frameLength: number, frameStep: number): number[][] {
  return tf.tidy(() => {
    const frames = tf.signal.stft(tf.tensor1d(signal), frameLength, frameStep, frameLength);  // complex64
    return tf.abs(frames).arraySync() as number[][];
    // Explicit FFT length = frameLength; the default may round up.
    // Result shape: [numFrames, floor(frameLength/2) + 1]
    // Each row = one time step
    // Each column = one frequency bin
    // Values = magnitude (how strong that frequency is at that time)
  });
}

// A stand-in capture, sized to fit on this page: four seconds of one hull
// channel at 256 Hz, so 1024 samples. A catalogued 23 Hz line runs the
// whole way through, and a 73.4 Hz tone switches on for the second second
// and again for the fourth. Real gaps between pulses are far longer.
const signal = Array.from({ length: 1024 }, (_, i) => {
  const t = i / 256;
  const pulsing = (i >= 256 && i < 512) || i >= 768;
  return 0.4 * Math.sin(2 * Math.PI * 23 * t)
    + (pulsing ? 0.05 * Math.sin(2 * Math.PI * 73.4 * t) : 0);
});

// frameLength=256, frameStep=128 → 1 + floor((1024 - 256) / 128) = 7 frames
const spec = stftMagnitudes(signal, 256, 128);
console.log('Time steps:', spec.length);          // 7
console.log('Frequency bins:', spec[0].length);   // 129

// One thing the built-in does that you did not ask for: it multiplies every
// frame by a Hann taper before the FFT (its windowFn defaults to
// tf.signal.hannWindow). Lesson 5 is about why. Measured on a tone that
// fills a 64-sample frame at amplitude 1: the frame's raw FFT peaks at
// 32.0, and the same frame through this function peaks at 16.0.`}
</CodeBlock>

For this exercise, slice each frame, take its FFT and stack the magnitudes without a taper. This is a rectangular window. Its hard edges can spread a tone across bins, called spectral leakage. Lesson 5 adds tapering and measures the resulting changes in peak width and height.

## Reading a Spectrogram

<CodeBlock language="typescript" title="reading-spectrogram.ts">
{`// The spectrogram is a 2D array:
// spectrogram[timeStep][frequencyBin] = magnitude

// Just like the DevTools waterfall:
// waterfall[timePosition][eventType] = duration

// Find when the anomalous frequency appears
function findAnomalyWindows(
  spectrogram: number[][],
  targetBin: number,
  threshold: number,
): number[] {
  const windows: number[] = [];
  for (let t = 0; t < spectrogram.length; t++) {
    if (spectrogram[t][targetBin] > threshold) {
      windows.push(t);
    }
  }
  return windows;
}

// The 73.4 Hz anomaly in hull-array data (sampleRate=256, windowSize=256):
// bin = Math.round(73.4 * windowSize / sampleRate) = 73
const anomalyBin = Math.round(73.4 * 256 / 256);

// 2.0 is a magnitude floor picked by eye off this capture's quiet windows.
// It is not a constant. rfft magnitudes scale with window size and signal
// amplitude, so a floor that works here is wrong for the next capture.
const activeWindows = findAnomalyWindows(spec, anomalyBin, 2.0);
console.log('Anomaly appears at windows:', activeWindows);
// [2, 6]. Those two windows sit inside a burst and read 2.88. Windows 1, 3
// and 5 straddle the start or the end of one, so only half their samples
// carry the tone and they read about 1.5, under the floor. Some windows
// listed and some missing is how a spectrogram says intermittent rather
// than steady. That is all this capture can say about timing: spec spans
// 4 seconds end to end, 7 windows, each 1 s wide, hopping 0.5 s, and on
// the real capture that is shorter than one gap between pulses.`}
</CodeBlock>

## Window Size Tradeoff

<CodeBlock language="typescript" title="window-tradeoff.ts">
{`// Window size trades the two resolutions against each other:
// - Large window → better frequency resolution, worse time resolution
// - Small window → better time resolution, worse frequency resolution
// This is the "Heisenberg uncertainty" of signal processing.

// Same tension as a rolling average over a stream: widen the window and
// the estimate gets steadier, but you lose the ability to say when the
// change actually happened.

// Small window: precise in time, blurry in frequency
const fineTime = stftMagnitudes(signal, 64, 32);
// Window span 0.25s (time blur), 4 Hz per bin. That 64 counts SAMPLES
// from one channel, a quarter second at 256 Hz. Module 1's archive row
// carried a 64 as well, and that one counted hull channels.

// Large window: precise in frequency, blurry in time
const fineFreq = stftMagnitudes(signal, 512, 256);
// Window span 2s (time blur), 0.5 Hz per bin

// Middle setting for this four-second demonstration
const balanced = stftMagnitudes(signal, 256, 128);
// Window span 1s (time blur), 1 Hz per bin`}
</CodeBlock>

<DerivationDrawer summary="Short-time Fourier transform (STFT) math">
A spectrogram is a sequence of FFTs computed on overlapping windows of the signal:

```
for each window position t:
  windowed = x[t:t+W] · w(W)              // multiply by window function
  X[t, k]  = FFT(windowed)
spectrogram[t, k] = |X[t, k]|²            // power convention; the code in
                                          // this module plots |X| (magnitude):
                                          // same picture, squared contrast
```

**Parameters:**
- **W (window size):** larger W = better frequency resolution, worse time resolution. A longer frame measures frequency more finely but spreads the measurement over more time.
- **Hop (stride between windows):** smaller hop = more overlap, smoother spectrogram, more compute. Common: hop = W/4 (75% overlap).
- **w(W) (window function):** Hann, Hamming, Blackman: all taper edges to reduce spectral leakage when the signal isn't periodic in W. The built-in above applies Hann by default; the challenge's hand-rolled version skips it. Lesson 5 builds one.

**Output shape:** `[num_windows, num_frequencies]`. With sample rate fs and window W, bin spacing is `fs / W`. The ability to separate nearby tones also depends on the window and noise. Each row blurs events across the window's span, `W / fs`; consecutive rows advance by `hop / fs`.
</DerivationDrawer>
