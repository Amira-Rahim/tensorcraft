The FFT tells us which frequencies are present — but not *when* they appear. The anomaly might pulse, might drift, might appear only during specific intervals. We need to see frequency content over time. We need a spectrogram.
</Dialogue>

<Dialogue speaker="Ensign Demir">
So we compute the FFT at different time windows and stack them together? That sounds like... the DevTools performance waterfall. Time on one axis, event types on another, colored by duration.
</Dialogue>

You've used the Chrome DevTools performance waterfall dozens of times. Time runs along the x-axis, different event types (scripting, rendering, painting) stack on the y-axis, and color or width shows intensity. A spectrogram is exactly the same visualization — time on x, frequency on y, color intensity showing magnitude.

## From Single FFT to Spectrogram

<BridgeCallout bridge={frontmatter.concept.bridge} />

A single FFT gives you one column of the spectrogram — all frequencies at one moment. To see how frequencies change over time, you slide a window across the signal and compute the FFT at each position.

<CodeBlock language="typescript" title="stft.ts">
{`import * as tf from '@tensorflow/tfjs';

/**
 * Short-Time Fourier Transform (STFT)
 * Slide a window across the signal, compute FFT at each position.
 *
 * Think of it like a scrolling viewport across a timeline —
 * at each scroll position, you analyze what's visible in the window.
 */
function stft(
  signal: number[],
  windowSize: number,   // how many samples per FFT (e.g., 256)
  hopSize: number,      // how far to slide between windows (e.g., 128)
): number[][] {
  const spectrogram: number[][] = [];
  const numWindows = Math.floor((signal.length - windowSize) / hopSize) + 1;

  for (let i = 0; i < numWindows; i++) {
    const start = i * hopSize;
    const windowSlice = signal.slice(start, start + windowSize);

    // Compute FFT for this time window
    const magnitudes = tf.tidy(() => {
      const windowTensor = tf.tensor1d(windowSlice);
      const fft = tf.spectral.rfft(windowTensor);
      return tf.abs(fft).arraySync() as number[];
    });

    spectrogram.push(magnitudes);
  }

  return spectrogram;
  // Result shape: [numWindows, windowSize/2 + 1]
  // Each row = one time step
  // Each column = one frequency bin
  // Values = magnitude (how strong that frequency is at that time)
}

// Example: 4 seconds of signal at 128 Hz = 512 samples
// windowSize=256, hopSize=128 → 3 time windows
const spec = stft(signal, 256, 128);
console.log('Time steps:', spec.length);          // 3
console.log('Frequency bins:', spec[0].length);   // 129`}
</CodeBlock>

## Reading a Spectrogram

<CodeBlock language="typescript" title="reading-spectrogram.ts">
{`// The spectrogram is a 2D array:
// spectrogram[timeStep][frequencyBin] = magnitude

// Just like the DevTools waterfall:
// waterfall[timePosition][eventType] = duration

// Find when the anomalous frequency appears
function findAnomalyWindows(
  spectrogram: number[][],
  targetBin: number,
  threshold: number,
): number[] {
  const windows: number[] = [];
  for (let t = 0; t < spectrogram.length; t++) {
    if (spectrogram[t][targetBin] > threshold) {
      windows.push(t);
    }
  }
  return windows;
}

// The 73.4 Hz anomaly with sampleRate=128, windowSize=256:
// bin = Math.round(73.4 * 256 / 128) = 147
const anomalyBin = Math.round(73.4 * 256 / 128);
const activeWindows = findAnomalyWindows(spec, anomalyBin, 2.0);
console.log('Anomaly appears at windows:', activeWindows);
// Shows the anomaly pulses — it's not constant, it's periodic`}
</CodeBlock>

## Window Size Tradeoff

<CodeBlock language="typescript" title="window-tradeoff.ts">
{`// Window size creates a fundamental tradeoff:
// - Large window → better frequency resolution, worse time resolution
// - Small window → better time resolution, worse frequency resolution
// This is the "Heisenberg uncertainty" of signal processing.

// Like responsive design breakpoints:
// - Wide breakpoint (1200px) → detailed layout but misses narrow behaviors
// - Narrow breakpoint (320px) → catches mobile behavior but loses detail

// Small window: precise in time, blurry in frequency
const fineTime = stft(signal, 64, 32);
// Resolution: time = 0.5s, freq = 2 Hz per bin

// Large window: precise in frequency, blurry in time
const fineFreq = stft(signal, 512, 256);
// Resolution: time = 4s, freq = 0.25 Hz per bin

// Good default: balance both
const balanced = stft(signal, 256, 128);
// Resolution: time = 1s, freq = 0.5 Hz per bin`}
</CodeBlock>
