Demir has the layout right: time on the x-axis, the second quantity on the y-axis, and a picture you read whole instead of row by row. Two things change on the way across. The waterfall sizes its bars by duration; a spectrogram spends color on magnitude. And a waterfall cell is an event that either happened or did not, while every cell of a spectrogram carries a computed amount of energy, including the ones that read as empty. Read enough spectrograms and a DevTools waterfall starts looking like a spectrogram of a page load.

## From Single FFT to Spectrogram

<BridgeCallout bridge={frontmatter.concept.bridge} />

A single FFT gives you one row of the spectrogram array: all frequencies at one moment. To see how frequencies change over time, you slide a window across the signal and compute the FFT at each position.

<CodeBlock language="typescript" title="stft.ts">
{`import * as tf from '@tensorflow/tfjs';

/**
 * Short-Time Fourier Transform (STFT)
 * Slide a window across the signal, compute FFT at each position.
 *
 * Think of it like a scrolling viewport across a timeline:
 * at each scroll position, you analyze what's visible in the window.
 */
function stft(
  signal: number[],
  windowSize: number,   // how many samples per FFT (e.g., 256)
  hopSize: number,      // how far to slide between windows (e.g., 128)
): number[][] {
  const spectrogram: number[][] = [];
  const numWindows = Math.floor((signal.length - windowSize) / hopSize) + 1;

  for (let i = 0; i < numWindows; i++) {
    const start = i * hopSize;
    const windowSlice = signal.slice(start, start + windowSize);

    // Compute FFT for this time window
    const magnitudes = tf.tidy(() => {
      const windowTensor = tf.tensor1d(windowSlice);
      const fft = tf.spectral.rfft(windowTensor);
      return tf.abs(fft).arraySync() as number[];
    });

    spectrogram.push(magnitudes);
  }

  return spectrogram;
  // Result shape: [numWindows, windowSize/2 + 1]
  // Each row = one time step
  // Each column = one frequency bin
  // Values = magnitude (how strong that frequency is at that time)
}

// Example: 4 seconds of hull-array signal at 256 Hz = 1024 samples
// windowSize=256, hopSize=128 → 7 time windows
const spec = stft(signal, 256, 128);
console.log('Time steps:', spec.length);          // 7
console.log('Frequency bins:', spec[0].length);   // 129`}
</CodeBlock>

That `stft` cuts rectangular slices: `signal.slice` and nothing else. A hard cut at a slice's edges invents frequency content the signal never had, and lesson 5 builds the taper that fixes it. Leave it out here. The challenge grades unwindowed magnitudes, so tapering this code drops the 10 Hz peak it checks from 32.0 to 15.7 and the test fails.

## Reading a Spectrogram

<CodeBlock language="typescript" title="reading-spectrogram.ts">
{`// The spectrogram is a 2D array:
// spectrogram[timeStep][frequencyBin] = magnitude

// Just like the DevTools waterfall:
// waterfall[timePosition][eventType] = duration

// Find when the anomalous frequency appears
function findAnomalyWindows(
  spectrogram: number[][],
  targetBin: number,
  threshold: number,
): number[] {
  const windows: number[] = [];
  for (let t = 0; t < spectrogram.length; t++) {
    if (spectrogram[t][targetBin] > threshold) {
      windows.push(t);
    }
  }
  return windows;
}

// The 73.4 Hz anomaly in hull-array data (sampleRate=256, windowSize=256):
// bin = Math.round(73.4 * windowSize / sampleRate) = 73
const anomalyBin = Math.round(73.4 * 256 / 256);

// 2.0 is a magnitude floor picked by eye off this capture's quiet windows.
// It is not a constant. rfft magnitudes scale with window size and signal
// amplitude, so a floor that works here is wrong for the next capture.
const activeWindows = findAnomalyWindows(spec, anomalyBin, 2.0);
console.log('Anomaly appears at windows:', activeWindows);
// The log names the windows where bin 73 clears the floor. If some windows
// are listed and some are missing, the tone is intermittent rather than
// steady. That is all this capture can say. spec spans 4 seconds end to
// end: 7 windows, each 1 s wide, hopping 0.5 s. That is shorter than one
// gap between pulses, so timing the gaps needs a capture minutes long.`}
</CodeBlock>

## Window Size Tradeoff

<CodeBlock language="typescript" title="window-tradeoff.ts">
{`// Window size trades the two resolutions against each other:
// - Large window → better frequency resolution, worse time resolution
// - Small window → better time resolution, worse frequency resolution
// This is the "Heisenberg uncertainty" of signal processing.

// Same tension as a rolling average over a stream: widen the window and
// the estimate gets steadier, but you lose the ability to say when the
// change actually happened.

// Small window: precise in time, blurry in frequency
const fineTime = stft(signal, 64, 32);
// Window span 0.25s (time blur), 4 Hz per bin. That 64 counts SAMPLES
// from one channel, a quarter second at 256 Hz. Module 1's archive row
// carried a 64 as well, and that one counted hull channels.

// Large window: precise in frequency, blurry in time
const fineFreq = stft(signal, 512, 256);
// Window span 2s (time blur), 0.5 Hz per bin

// Good default: balance both
const balanced = stft(signal, 256, 128);
// Window span 1s (time blur), 1 Hz per bin`}
</CodeBlock>

<DerivationDrawer summary="Short-time Fourier transform (STFT) math">
A spectrogram is a sequence of FFTs computed on overlapping windows of the signal:

```
for each window position t:
  windowed = x[t:t+W] · w(W)              // multiply by window function
  X[t, k]  = FFT(windowed)
spectrogram[t, k] = |X[t, k]|²            // power convention; the code in
                                          // this module plots |X| (magnitude):
                                          // same picture, squared contrast
```

**Parameters:**
- **W (window size):** larger W = better frequency resolution, worse time resolution. Heisenberg uncertainty for signal processing.
- **Hop (stride between windows):** smaller hop = more overlap, smoother spectrogram, more compute. Common: hop = W/4 (75% overlap).
- **w(W) (window function):** Hann, Hamming, Blackman: all taper edges to reduce spectral leakage when the signal isn't periodic in W. The `stft` above skips it. Lesson 5 builds one.

**Output shape:** `[num_windows, num_frequencies]`. With sample rate fs and window W, frequency resolution is `fs / W`. Each row blurs events across the window's span, `W / fs`; consecutive rows advance by `hop / fs`.
</DerivationDrawer>
