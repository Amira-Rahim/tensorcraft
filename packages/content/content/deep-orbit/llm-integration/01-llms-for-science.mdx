This example follows the exercise's narrow contract: one JSON object, with
no other braces in the surrounding text. First locate the complete object.
Then let `JSON.parse` reject malformed JSON. Parsing alone does not establish
that the fields match your reporting interface.

| Required field | Accepted values | Examples to reject |
| --- | --- | --- |
| `classification` | `noise`, `anomaly`, or `unknown` | Missing field or `alien` |
| `confidence` | Finite number from 0 through 1 | `"0.95"`, `null`, or 1.2 |
| `reasoning` | String with a non-whitespace character | Missing field or `"   "` |

Numeric zero passes. A truthiness check would reject it incorrectly. Accept
extra fields while checking these three by name. If any check fails, throw
before returning an analysis to the next stage. For general model replies,
use a defined structured-output contract and parser rather than assuming
that an arbitrary brace-delimited passage is the intended object.

The activity lets you inspect that boundary one field at a time. Its valid
`anomaly` reply is a supplied test answer, including when a test prompt names
7741. It provides no evidence for that reading's correct label. The client
accepts structure. Farah still checks each claim against sources.

{`interface LLMClient {
  complete(prompt: string, options?: { system?: string; temperature?: number; maxTokens?: number }): Promise<string>;
}

// This server adapter expects the chat-completions contract shown below.
// Other APIs need their own adapters. Configure an actual model ID.
// Keep provider keys on the server. The browser calls an authenticated
// server route and never receives the provider key.
function createLLMClient(apiKey: string, baseUrl: string, modelId: string): LLMClient {
  return {
    async complete(prompt, options = {}) {
      const response = await fetch(\`\${baseUrl.replace(/\\/$/, '')}/v1/chat/completions\`, {
        method: 'POST',
        signal: AbortSignal.timeout(30_000),
        headers: { 'Content-Type': 'application/json', Authorization: \`Bearer \${apiKey}\` },
        body: JSON.stringify({
          model: modelId,
          messages: [
            { role: 'system', content: options.system ?? 'Report only what the supplied evidence supports. State missing evidence.' },
            { role: 'user', content: prompt },
          ],
          temperature: options.temperature ?? 0.3,
          max_tokens: options.maxTokens ?? 1024,
        }),
      });
      if (!response.ok) throw new Error(\`LLM request failed: HTTP \${response.status}\`);
      const data = await response.json();
      const content = data?.choices?.[0]?.message?.content;
      if (typeof content !== 'string' || !content.trim()) throw new Error('Missing text response');
      return content; // text validated. Claims still unchecked
    },
  };
}

// Integration inputs: server configuration supplies all three constants.
const llm = createLLMClient(API_KEY, BASE_URL, MODEL_ID);
const report = await llm.complete(\`Draft a summary of these fictional mission counts:
Total events: 12,001. Normal: 11,847. Anomalous: 153. Unclassified: 1.
Do not infer the cause or significance of the unclassified event.\`);`}
</CodeBlock>

<ConceptReference summary="How a language model generates text">

## How the model produces a reply

A decoder language model predicts the next token from the tokens before it. Tokens are pieces of text, with sizes that depend on the tokenizer and language. The model produces logits, raw scores for the possible next tokens. Softmax turns those scores into probabilities. A decoding rule picks a token, adds it to the text, and repeats until a stop condition is met.

Inference usually has two phases. **Prefill** processes the supplied prompt. **Decoding** generates new tokens, commonly one at a time while reusing cached attention keys and values. It does not normally recompute the entire prompt for every token. Some serving systems generate candidates in larger groups, then verify them. Token count alone therefore does not tell you the number or duration of runtime calls.

Like the forecaster, this model predicts what comes next. Here it predicts a token. The earlier forecaster predicts three sensor values. It uses a different architecture and a different way of choosing its output from the LSTM you built.

## What a Transformer Does With the Prompt

In dense self-attention, each token has a query, key and value produced by learned projections. The model compares every query with the keys that its mask allows. A decoder's causal mask blocks access to future tokens. An explicit T-by-T score matrix has 6,400 entries at T = 80 and 25,600 at T = 160. That quadratic scaling matters for dense attention over a full prompt. Optimized kernels can avoid storing the entire matrix, and cached decoding has a different cost.

Each head uses its own learned projections. The model combines the head outputs. Its blocks also use feed-forward layers, residual connections and normalization alongside attention. A model's supported context length is a limit on the token sequence. Keep room for its answer as well as its prompt.

For positive sampling **temperature** T, divide the vocabulary logits by T before softmax. Smaller values concentrate probability on higher-scoring tokens. Larger values flatten it. A zero-temperature API setting commonly requests greedy selection. Implementations handle that setting separately to avoid dividing by zero. Ties and serving details can still affect repeatability. This setting does not change the attention softmax inside the model or verify a claim.

Next-token training rewards predictions of text in the training distribution. Later training can improve instruction following and factual performance, but neither objective checks a new report against your ship's measurements. A fluent answer still needs evidence.

The [original transformer paper](https://arxiv.org/html/1706.03762v7#S3) describes the attention and block structure. Hugging Face’s [cache explanation](https://huggingface.co/docs/transformers/v4.57.1/cache_explanation) shows how a model reuses cached keys and values during decoding.

The onboard language component and its bundle sizes belong to the fictional mission. This adapter demonstrates the HTTP boundary. It does not download or implement that component. The browser runtime lab measures a separate pretrained sentiment model.

## The review after parsing

<CodeBlock language="typescript" title="workflow.ts">
{`// Farah's report review:
// 1. CONTEXT: provide data and instructions
// 2. GENERATE: LLM produces a draft
// 3. REVIEW: expert checks for accuracy
// 4. CORRECT: fix any errors or hallucinations
// 5. APPROVE: human signs off on final output

interface AnalysisWorkflow {
  context: string;      // raw data and instructions
  draft: string;        // LLM-generated output
  corrections: string[];// expert corrections
  approved: boolean;    // human sign-off
  approvedBy: string;   // who verified
}

// A hallucination is a plausible but false generated statement.
// Check claims against the measurements before approving the draft.

function screenNumbers(
  draft: string,
  actualData: Record<string, number>,
): { matched: number[]; unmatched: number[] } {
  // This screen only compares numbers. It cannot verify facts. It finds numbers
  // absent from the data but ignores source fields, units and meaning.
  // Even a matched value can support a false sentence.
  const claims = draft.replace(/(\\d),(?=\\d)/g, '$1').match(/-?\\d+(?:\\.\\d+)?/g) ?? [];
  const values = Object.values(actualData);
  const matched: number[] = [];
  const unmatched: number[] = [];

  for (const claim of claims) {
    const n = parseFloat(claim);
    if (values.some((v) => Math.abs(v - n) <= 0.05)) matched.push(n);
    else unmatched.push(n);
  }
  return { matched, unmatched };
}

// Run it on a draft with one invented figure:
const check = screenNumbers(
  'Across 12,001 catalogued events, 153 were anomalous and 1 resists ' +
  'classification. A cluster of 9 anomalies repeats hourly.',
  { totalEvents: 12001, anomalous: 153, unclassified: 1 },
);
console.log(check.matched);    // [12001, 153, 1]
console.log(check.unmatched);  // [9]: no such cluster in the data
// Lesson 3 checks structured claims against named source fields.
// Neither this numeric screen nor those field checks can approve free text.`}
</CodeBlock>
