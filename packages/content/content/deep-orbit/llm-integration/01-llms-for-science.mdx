Nazari's skepticism is the right default. ## LLMs as Developer Tools

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="llm-client.ts">
{`// An LLM client is a typed fetch wrapper. Nothing here is new except
// what comes back: a string with no schema and no guarantees.
interface LLMClient {
  complete(prompt: string, options?: { system?: string; temperature?: number; maxTokens?: number }): Promise<string>;
}

// In production, this calls an API (OpenAI, Anthropic, etc.). Most
// providers expose a messages-shaped chat API, each with its own
// dialect (Anthropic, for one, takes system as a top-level field,
// not a message role). For DEEP SCAN, we point it at the ship's
// onboard model.
async function createLLMClient(apiKey: string, baseUrl: string): Promise<LLMClient> {
  return {
    async complete(prompt, options = {}) {
      const response = await fetch(\`\${baseUrl}/v1/chat/completions\`, {
        method: 'POST',
        headers: {
          'Content-Type': 'application/json',
          'Authorization': \`Bearer \${apiKey}\`,
        },
        body: JSON.stringify({
          messages: [
            { role: 'system', content: options.system ?? 'You are the Archimedes signal-analysis assistant. Report only what the provided data supports.' },
            { role: 'user', content: prompt },
          ],
          temperature: options.temperature ?? 0.3,  // low temp for factual analysis
          max_tokens: options.maxTokens ?? 1024,
        }),
      });
      const data = await response.json();
      return data.choices[0].message.content;
    },
  };
}

// Usage: draft a signal analysis report
const llm = await createLLMClient(API_KEY, BASE_URL);
const report = await llm.complete(\`
Summarize the following signal classification results:
- Total signals analyzed: 12,001
- Normal signals: 11,847 (98.7%)
- Anomalous signals: 153 (1.3%)
- Unclassified: 1 (0.008%)

Focus on the single unclassified signal and its significance.
\`);`}
</CodeBlock>

## What You Are Actually Calling

Strip the HTTP away and the thing on the other end is a model you have already built the parts of. A language model is a classifier. Given a sequence of tokens (word pieces, roughly three quarters of a word each), it emits one score per possible next token, softmax turns the scores into a probability distribution, and one token is sampled from it. Append the sample, run again, repeat until a stop token. Six hundred words of report is about eight hundred forward passes, one per token, each a next-token prediction: the shape of module 6's next-value prediction, except the output is one of tens of thousands of classes instead of three continuous numbers, which is what makes it classification.

Inside each pass, the mechanism that reads the prompt is the attention you built in module 8, stacked dozens of layers deep and run with many heads at once: every token scores every other token, softmax spends the budget, and the weighted sum becomes the next layer's input. The prompt is the window. The context limit is the sequence length, the same T you windowed at 80. And `temperature` is a knob on module 8's softmax: divide the scores by it before the exponentials, and a low value sharpens the distribution toward the single likeliest token while a high value flattens it toward a coin toss. That is why the client above sets 0.3 for a factual draft, and why lesson 4 insists that a sharpened distribution is a more repeatable one, not a more truthful one.

What is new is only scale. The weights were trained on more text than any crew could read, which is why the model writes fluent paragraphs about instruments the Archimedes does not carry. Fluency is what next-token prediction optimizes. Truth was never in the loss.

## The Human-AI Workflow

<CodeBlock language="typescript" title="workflow.ts">
{`// The workflow mirrors Copilot usage:
// 1. CONTEXT: provide data and instructions
// 2. GENERATE: LLM produces a draft
// 3. REVIEW: expert checks for accuracy
// 4. CORRECT: fix any errors or hallucinations
// 5. APPROVE: human signs off on final output

interface AnalysisWorkflow {
  context: string;      // raw data and instructions
  draft: string;        // LLM-generated output
  corrections: string[];// expert corrections
  approved: boolean;    // human sign-off
  approvedBy: string;   // who verified
}

// CRITICAL: LLMs can hallucinate, generating plausible but false statements
// Always verify claims against actual data
// Like reviewing Copilot suggestions: accept what's correct, fix what's not

function validateClaims(
  draft: string,
  actualData: Record<string, number>,
): { valid: string[]; invalid: string[] } {
  // Every number in the draft is a claim. Extract them in reading
  // order (commas stripped so "12,001" parses), then ask whether SOME
  // value in the data sits within tolerance. A claim does not care
  // which field it came from; a fabricated one matches none.
  const claims = draft.replace(/(\\d),(?=\\d)/g, '$1').match(/-?\\d+(?:\\.\\d+)?/g) ?? [];
  const values = Object.values(actualData);
  const valid: string[] = [];
  const invalid: string[] = [];

  for (const claim of claims) {
    const n = parseFloat(claim);
    if (values.some((v) => Math.abs(v - n) <= 0.05)) valid.push(claim);
    else invalid.push(claim);
  }
  return { valid, invalid };
}

// Run it on a draft with one invented figure:
const check = validateClaims(
  'Across 12,001 catalogued events, 153 were anomalous and 1 resists ' +
  'classification. A cluster of 9 anomalies repeats hourly.',
  { totalEvents: 12001, anomalous: 153, unclassified: 1 },
);
console.log(check.valid);    // ['12001', '153', '1']
console.log(check.invalid);  // ['9']  ← no such cluster in the data
// Module 9 lesson 3 hardens this checker against retrieved RAG rows;
// the contract is already here: extract, compare, refuse to trust prose.`}
</CodeBlock>
