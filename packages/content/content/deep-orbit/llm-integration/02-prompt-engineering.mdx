>
> v1: `"Analyze this signal data."` · OUTPUT: three generic paragraphs about signals in the abstract, one recommendation to consult a domain expert, zero numbers from the actual reading.

Do the review before reading on. What would the model have needed to produce something a scientist could sign? Who is it supposed to be, what situation is it in, which data is it looking at, what shape should the answer take? Every gap you can name is a line the prompt failed to include.

<Dialogue speaker="Dr. Farah">
My first prompt was 'Analyze this signal data.' The output was useless: generic, vague, no structure. When I added role, context, data, and format instructions, the output became precise enough to include in the report. Your review probably found three of the four. Format is the one people skip, because output without it still reads like English right up until you try to parse it.
</Dialogue>

Nothing about the model changed between Farah's useless prompt and her precise one; the only diff is words. A search for `error` returns the whole index; a search for the exact string `Error when checking : expected dense_Dense1_input to have shape [null,3]` returns the one answer. Specificity and structure decide what you get back, and a prompt is a query.

One word does double duty across these two lessons. Lesson 1's client set a `role` on every message it sent, which is the API's label for whose turn it is: the system message that stands behind the whole call, then the user's. The role in Farah's four parts is a line of English inside that user message, naming who the model should answer as. It is the same word at two different layers.

## From Vague to Precise

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="prompt-evolution.ts">
{`// Level 1: Vague, like searching for "error"
const vaguePrompt = "Analyze this signal data.";
// Output: generic paragraph about signals (useless)

// Level 2: Specific role + context
const betterPrompt = \`You are a deep space signal analyst aboard a research vessel.
Analyze the following signal reading and classify it as noise or anomaly.
Signal: amplitude=1024 counts, frequency=73.4Hz, phase=0.23rad\`;
// Output: decent analysis but unstructured

// Level 3: Structured with format instructions
const structuredPrompt = \`You are a deep space signal analyst. Respond in JSON only.

Signal reading (archive sample 7741):
- Amplitude: 1024 counts (normal band: 570-1560)
- Frequency: 73.4 Hz (known natural: 5, 12, 23, 47 Hz)
- Phase: 0.23 rad

Classify this signal. Respond with:
{
  "classification": "noise" | "anomaly",
  "confidence": 0.0-1.0,
  "reasoning": "brief explanation",
  "anomalous_features": ["list of unusual features"]
}\`;
// Output: parseable JSON with clear reasoning`}
</CodeBlock>

None of those three signal lines quotes a model input. The classifier reads amplitude, frequency and phase after module 4 min-max normalizes all three to 0 to 1, and the prompt reports what the instruments logged instead. Amplitude is the hull sensor's own count against its 2048-count full scale, so the 0.50 the classifier saw goes into the prompt as 1024. Frequency is the line the transform found, in hertz, rather than the model's zero-crossing count. That count is taken over a 64-sample window, which is a quarter second of tape at the array's 256 Hz rate. Phase is radians rather than the normalized angle. Those are the numbers a scientist reading the draft can check against an instrument, and this prompt is written for that reader.

The band in the prompt is the one module 7 measured, converted into the counts a scientist can check against an instrument. Its normal-period readings, in normalized units, give mean 0.52, standard deviation 0.15, p5 0.28 and p95 0.76. Against the sensor's 2048-count full scale that p5 to p95 span is roughly 570 to 1560 counts, and the hull sensors saturate at 2048, so no capture reads above it. 1024 counts normalizes to 0.50, inside the normal band and 0.13 standard deviations below the mean, which is why the z-score gate cleared it. The other two dials sit near mid-scale rather than on it. 73.4 Hz is 37 zero crossings in that quarter-second window, 0.59 of the 63-crossing ceiling. 0.23 rad is 0.54 of the way across the minus-pi-to-pi span. Module 3's trained network scored this reading 51.8 percent, unwilling to commit either way. Every dial reads normal on its own. That leaves the model one thing to notice: 73.4 Hz is not in the natural set the context line hands it.

## Prompt Templates

<CodeBlock language="typescript" title="templates.ts">
{`// Reusable prompt templates, like React component templates.
// This is Farah's v8, the last version her red pen still marked up: all
// four parts are here, and the epilogue names the one line v9 added.

interface SignalData {
  amplitude: number;   // hull counts against the sensor's 2048-count full scale
  frequency: number;   // the FFT line under review, in Hz, not the zero-crossing count
  phase: number;       // radians
}

function classificationPrompt(signal: SignalData): string {
  return \`You are DEEP SCAN, an AI signal classification system.

## Context
You are analyzing signals from deep space Sector 7-G.
Normal amplitude range: 570 to 1560 counts.

## Signal Data
- Amplitude: \${signal.amplitude} counts
- Frequency: \${signal.frequency} Hz
- Phase: \${signal.phase} rad

## Task
Classify this signal and explain your reasoning.

## Output Format (JSON)
{
  "classification": "noise" | "anomaly" | "unknown",
  "confidence": <0.0 to 1.0>,
  "reasoning": "<2-3 sentences>",
  "risk_level": "low" | "medium" | "high"
}\`;
}

// Parse the response
function parseClassification(response: string) {
  const jsonMatch = response.match(/\\{[\\s\\S]*\\}/);
  if (!jsonMatch) throw new Error('No JSON found in response');
  return JSON.parse(jsonMatch[0]);
}`}
</CodeBlock>
