Generating a full report in one shot is the monolithic-component mistake: mediocre output and nothing you can verify in isolation. Sections are components: each gets its own data, its own prompt, and its own review.

## Section-by-Section Generation

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="report-pipeline.ts">
{`import { verifyClaims } from './verify-claims';  // the checker from lesson 3

interface ReportSection {
  heading: string;
  prompt: string;
  data: string;
  generated?: string;
  validated?: boolean;
}

async function generateReport(
  sections: ReportSection[],
  llm: LLMClient,
): Promise<ReportSection[]> {
  for (const section of sections) {
    const prompt = \`## Task
Write the "\${section.heading}" section of a scientific signal analysis report.

## Data
\${section.data}

## Requirements
\${section.prompt}

## Format
- Use markdown
- Every number you write has to appear in the Data block above, copied from it exactly
- Keep to 200-300 words
- Be precise and factual\`;

    const content = await llm.complete(prompt, { temperature: 0.2 });
    section.generated = content;
    // This is where section.validated comes from: lesson 3's checker, run over
    // the numbers in THIS section's own data. Strip the thousands separators
    // on both sides first. Leave them in and "12,001" tokenizes as 12 and 001.
    // The evidence set then reads 12, 1, 11, 847, 153, 1. Neither total the
    // report stated survives that split, and three of the numbers standing in
    // for them (12, 11 and 847) were never in the report at all. A section
    // claiming 847 anomalies would validate. One quoting the real 12001
    // would not.
    const plain = (text: string) => text.replace(/(\\d),(?=\\d)/g, '$1');
    const rows = [(plain(section.data).match(/-?\\d+(\\.\\d+)?/g) ?? []).map(parseFloat)];
    section.validated = verifyClaims(plain(content), rows).fabricated.length === 0;
  }

  return sections;
}

// Define the report template
const reportSections: ReportSection[] = [
  {
    heading: 'Executive Summary',
    prompt: 'Summarize key findings in 3-4 sentences. Lead with the anomaly discovery.',
    data: 'Total: 12,001 signals. Normal: 11,847. Anomalous: 153. Unclassified: 1.',
  },
  {
    heading: 'Anomaly Analysis',
    prompt: 'Detail the unclassified signal: frequency, timing pattern, Fibonacci structure.',
    data: anomalyDataSummary,
  },
  // ... additional sections
];

const marked = await generateReport(reportSections, llm);
// Assembling the marked sections into a signable document is the challenge below.`}
</CodeBlock>

The pipeline passes `temperature: 0.2` on every section call. Temperature divides the scores before the last softmax, the one that picks the next token, so a low value sharpens that distribution toward the likeliest token and the same prompt returns close to the same draft twice. A sharpened distribution is a more repeatable one, not a more truthful one: at temperature zero the model takes its likeliest token every time, and an instrument it invented once is the likeliest token again on the next run. Farah's Band-3 cluster back in lesson 1 arrived at 0.3. What catches a claim like that is the validation line under the generate call. Temperature has no part in it.

## Challenge

The model has written the sections and the validator has marked each one. Assemble the document a human can sign: the validated sections in order, and an honest list of what was withheld.
