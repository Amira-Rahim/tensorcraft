The LLM has no knowledge of our specific signals. If I ask about Band-7 anomalies, it will either hallucinate or say it doesn't know. We need to retrieve the relevant data first and inject it into the prompt. Retrieval-Augmented Generation.
</Dialogue>

<Dialogue speaker="Ensign Demir" expression="breakthrough">
That's Server Components! Fetch data on the server, then render with it. RAG fetches data from the signal database, then generates a response with it.
</Dialogue>

Demir's mapping holds at the pipeline level: retrieve real records first, then generate from them instead of from whatever the model half-remembers. The step with no Server Component equivalent is the last one: a component can't contradict its props. A generator can.

## The RAG Pipeline

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="rag-pipeline.ts">
{`interface Signal {
  id: string;
  timestamp: string;
  band: string;
  classification: string;
  confidence: number;
  amplitude: number;
  frequency: number;
  anomalyScore: number;
}

// Step 1: RETRIEVE: find relevant signals from the database
async function retrieveSignals(
  query: string,
  db: Signal[],
): Promise<Signal[]> {
  // Parse query for filters
  const bandMatch = query.match(/band[- ]?(\\w+)/i);
  const hoursMatch = query.match(/(\\d+)\\s*hours/i);
  const wantsAnomalies = /anomal/i.test(query);

  let results = [...db];

  if (bandMatch) {
    results = results.filter(s => s.band.toLowerCase() === bandMatch[1].toLowerCase());
  }
  if (hoursMatch) {
    const cutoff = Date.now() - parseInt(hoursMatch[1]) * 3600 * 1000;
    results = results.filter(s => new Date(s.timestamp).getTime() > cutoff);
  }
  if (wantsAnomalies) {
    results = results.filter(s => s.classification === 'anomaly');
  }

  return results.slice(0, 20);  // limit context size
}

// The honest label for the above: keyword-and-metadata retrieval. It
// works here because the catalogue is 12,001 STRUCTURED rows with named
// fields you can match on. Production RAG over prose replaces this
// function with embeddings: every document and every query mapped to a
// vector, retrieval = cosine similarity, top-k. Different machinery,
// identical contract: retrieve -> ground -> verify. When your corpus
// stops having fields, swap this one function and keep the contract.

// Step 2: AUGMENT: inject retrieved data into prompt
function buildRAGPrompt(query: string, signals: Signal[]): string {
  const signalContext = signals.map(s =>
    \`[\${s.timestamp}] Band \${s.band}: \${s.classification} (conf=\${s.confidence}, amp=\${s.amplitude}, freq=\${s.frequency}Hz, anomalyScore=\${s.anomalyScore})\`
  ).join('\\n');

  return \`You are DEEP SCAN's analysis assistant. Answer based ONLY on the provided signal data.
If the data doesn't contain the answer, say "insufficient data."

## Retrieved Signal Data
\${signalContext}

## Question
\${query}

## Instructions
- Cite specific signals by timestamp
- Include quantitative details (counts, averages, ranges)
- Flag any uncertainty\`;
}

// Step 3: GENERATE: get grounded response
async function querySignals(query: string, db: Signal[], llm: LLMClient): Promise<string> {
  const relevant = await retrieveSignals(query, db);
  const prompt = buildRAGPrompt(query, relevant);
  return llm.complete(prompt);
}

// Usage:
const answer = await querySignals(
  "Show me all anomalous signals in Band-7 from the last 72 hours",
  signalDatabase,
  llm,
);`}
