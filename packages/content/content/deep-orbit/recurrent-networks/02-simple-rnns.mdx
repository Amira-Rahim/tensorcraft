      import * as tf from '@tensorflow/tfjs';

      function runCell(readings, recurrentWeight, inputWeight, bias) {
        const states = [];
        let h = 0;
        for (const reading of readings) {
          h = Math.tanh(recurrentWeight * h + inputWeight * reading + bias);
          states.push(h);
        }
        return states;
      }

      function buildCellLayer(timeSteps) {
        const model = tf.sequential();
        const cell = tf.layers.simpleRNN({ units: 1, inputShape: [timeSteps, 1], returnSequences: true });
        model.add(cell);
        const [kernel, recurrentKernel, biasTensor] = model.getWeights();
        return {
          model,
          inputWeight: kernel.dataSync()[0],
          recurrentWeight: recurrentKernel.dataSync()[0],
          bias: biasTensor.dataSync()[0],
        };
      }

      function decayFactors(states, recurrentWeight) {
        const factors = [];
        let product = 1;
        for (const h of states) {
          product *= recurrentWeight * (1 - h * h);
          factors.push(product);
        }
        return factors;
      }

<Dialogue speaker="Ensign Demir">
So an RNN is just... a reducer? It takes the previous hidden state and the new input, runs them through a function, and outputs new hidden state? That is what I do every time I rebuild state by replaying an event log.
</Dialogue>

The cell itself is small: a weight for the previous hidden state, a weight for the input, a bias, a `tanh`. What makes it recurrent is the wiring: the output loops back in as the next step's hidden state. Small enough, in fact, to run by hand before anyone argues about analogies:

<CodeBlock language="typescript" title="reducer-with-memory.ts">
{`import * as tf from '@tensorflow/tfjs';

// One RNN step: newHidden = tanh(0.8 * prevHidden + 1.0 * input)
// (weights hand-picked for the drill, bias 0)
let h = tf.scalar(0);
for (const x of [0.5, 0.9, 0.5]) {
  const next = tf.tidy(() => tf.tanh(h.mul(0.8).add(x)));
  h.dispose();
  h = next;
  console.log(h.dataSync()[0].toFixed(4));
}
h.dispose();
// 0.4621
// 0.8537
// 0.8284  ← the same 0.5 that scored 0.4621 two steps ago`}
</CodeBlock>

## The Learned Reducer

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="rnn-as-reducer.ts">
{`import * as tf from '@tensorflow/tfjs';

// Event replay: you write the state transition function
function signalReducer(state: { count: number; trend: string }, action: { value: number }) {
  const trend = action.value > 0.5 ? 'rising' : 'falling';
  return { count: state.count + 1, trend };
}

// RNN: the network LEARNS the state transition function
// At each time step:
//   newHidden = tanh(W_h * prevHidden + W_x * input + bias)
//
// W_h and W_x are weight matrices learned during training
// tanh squashes output to [-1, 1]
// prevHidden is a learned summary influenced by earlier steps, not a lossless log.

// Build a simple RNN in TF.js
const model = tf.sequential();
model.add(tf.layers.simpleRNN({
  units: 32,           // hidden state size (the shape of the state you carry)
  inputShape: [5, 3],  // 5 time steps, 3 features each
}));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

model.compile({ optimizer: 'adam', loss: 'binaryCrossentropy', metrics: ['accuracy'] });

// Input: [batch, timeSteps, features] = [32, 5, 3]
const x = tf.randomNormal([32, 5, 3]);
const y = tf.tidy(() => tf.randomUniform([32, 1]).round());

// Shape drill only. Random labels do not define a generalizable signal.
// A flexible model may fit them; a falling training loss would not prove
// useful forecasting. Compare against held-out data with meaningful labels.
await model.fit(x, y, { epochs: 10 });

x.dispose();
y.dispose();
model.dispose();`}
</CodeBlock>

You can read those weights straight off the model. `model.layers[0].getWeights()` returns three tensors for the recurrent layer: the input kernel, shaped [features, units], then the recurrent kernel, shaped [units, units], then the bias, one number per unit. The order is the library's rather than the formula's, since the lesson writes the recurrent term first and TF.js stores the input kernel first. The layer creates those weights when it is built, either explicitly or as part of a model. Build a one-unit cell over a one-feature sequence and those three tensors hold one number each: the `recurrentWeight`, `inputWeight` and `bias` of the drill at the top of this lesson, initialized by the layer. Input and recurrent kernels use their initializers; the default bias is zero.

## How the RNN Processes a Sequence

<CodeBlock language="typescript" title="rnn-unrolled.ts">
{`// Unrolling the RNN: what happens at each time step:

// Time step 0: hidden = f(zeros, input[0])
// Time step 1: hidden = f(hidden, input[1])  ← remembers step 0
// Time step 2: hidden = f(hidden, input[2])  ← remembers steps 0-1
// Time step 3: hidden = f(hidden, input[3])  ← remembers steps 0-2
// Time step 4: hidden = f(hidden, input[4])  ← remembers steps 0-3

// The final hidden state is a fixed-size summary of the sequence
// We pass it to a Dense layer for classification

// Return sequences: get hidden state at EVERY step (not just the last)
const modelAllSteps = tf.sequential();
modelAllSteps.add(tf.layers.simpleRNN({
  units: 32,
  inputShape: [5, 3],
  returnSequences: true,  // output shape: [batch, 5, 32] instead of [batch, 32]
}));
// Useful when you need the full temporal output (e.g., for stacking RNN layers)
modelAllSteps.dispose();`}
</CodeBlock>

## The Vanishing Gradient Problem

Backpropagation through time applies the backward pass across the unrolled sequence. In this one-unit cell, each recurrent step multiplies the gradient by the recurrent weight and the local slope of tanh. Repeated factors below one shrink it. With weight 0.8 and states close to zero, 60 such factors give about 1.5e-6. There is no universal 10- or 20-step limit: learnable distance depends on weights, states, data and optimization. With multiple units the factors are matrices, so the scalar example is an illustration rather than a complete diagnosis.

Nothing bounds the recurrent weight, though, so the product can sit above 1 for a stretch of steps. Raise that 0.8 to 1.5, start the cell at zero and feed it readings near 0.001. The gradient grows on the way back instead of shrinking: the direct derivative of the state at step 14 with respect to the initial state reaches roughly 173 in this example. A spike like that is what gradient clipping is for. The norm of a gradient is its length: square every component, add them up, take the square root. Pick a ceiling, and on any step whose norm passes it, scale every component down by the same factor before the optimizer applies them. TF.js 4.22 has no clipping option on its optimizers, so that cap is one you write yourself.

In this particular constant-input example, tanh eventually saturates. The state approaches 0.8590 and the local factor falls to about 0.393, so the gradient shrinks again. That is not a guarantee for all inputs or weights. For example, an exactly zero state and zero input can remain at zero while a recurrent weight above one amplifies its derivative. Inspect the actual gradient history instead of assuming every explosion will end this way.

## Challenge

The drill at the top of this lesson ran one cell by hand for three readings. Write that loop yourself, for any window and any weights, in plain JavaScript numbers and Math.tanh: the drill's tf.scalar version is for reading, and the graded loop has no tensors in it. One thing it grades is the carry: the same reading has to score one number early in a window and a different number later, and it can only do that if the state you hand from step to step is real.

Then build the library's version of the same cell, a one-unit `tf.layers.simpleRNN`, and read its three weights off the model. The grader runs your loop on those weights and puts it beside what the layer computes for the same readings, step by step. The two agree to about seven decimal places when your recurrence is the one TF.js runs, for this small fixture; use a tolerance appropriate to the sequence and backend. Nothing is memorizable here, because the layer draws its own weights at random every time it is built.
