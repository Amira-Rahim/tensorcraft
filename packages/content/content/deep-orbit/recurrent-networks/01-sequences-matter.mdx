## Why Feedforward Networks Fail at Sequences

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="feedforward-limitation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Feedforward network: each input is independent
// It sees: [0.5, 0.3, 0.7] → classify
// Then:    [0.8, 0.2, 0.9] → classify (no memory of previous)

// But the signal has TEMPORAL patterns:
// t=0: [0.5, 0.3, 0.7]  (rising)
// t=1: [0.8, 0.2, 0.9]  (still rising)
// t=2: [0.3, 0.1, 0.4]  (falling)
// t=3: [0.5, 0.3, 0.7]  (rising again) ← THE PATTERN REPEATS

// A feedforward network processes each time step in isolation
// It cannot detect: "the signal rises, falls, then rises again"

// What we need: a model that sees multiple time steps at once
// Input shape changes from [features] to [timeSteps, features]

// Preparing sequential input: create sliding windows
function createSequences(data: number[][], windowSize: number): number[][][] {
  const sequences: number[][][] = [];
  for (let i = 0; i <= data.length - windowSize; i++) {
    sequences.push(data.slice(i, i + windowSize));
  }
  return sequences;
}

// Raw signal readings (each row = one time step with 3 features)
const readings = [
  [0.5, 0.3, 0.7],
  [0.8, 0.2, 0.9],
  [0.3, 0.1, 0.4],
  [0.5, 0.3, 0.7],
  [0.9, 0.4, 0.8],
];

// Create sequences of 3 time steps each
const sequences = createSequences(readings, 3);
console.log(sequences.length);  // 3 sequences
console.log(sequences[0]);
// [[0.5, 0.3, 0.7], [0.8, 0.2, 0.9], [0.3, 0.1, 0.4]]
// ^ This IS the pattern: rise-rise-fall`}
</CodeBlock>

<Dialogue speaker="Dr. Farah">
Look at what the slicing bought you. Row for row, nothing changed. The pattern only exists across rows, in the order they arrive: [rising, falling, rising] and [falling, rising, rising] are the same three values telling two different stories. Order carries information, and the model we have throws it away at the door.
</Dialogue>

It is the React list-key problem wearing a lab coat. Render a list without stable keys and React can't track which items moved, were added, or were removed; identity gets lost in the reorder. Here, position itself is the information, and a model that sees one row at a time never had it to lose.

## Sequence Shape: [batch, timeSteps, features]

<CodeBlock language="typescript" title="sequence-tensors.ts">
{`import * as tf from '@tensorflow/tfjs';

// Feedforward input: [batch, features]
// Shape: [32, 3]: 32 samples, each with 3 features
const feedforwardInput = tf.randomNormal([32, 3]);

// Sequential input: [batch, timeSteps, features]
// Shape: [32, 5, 3]: 32 samples, each a window of 5 time steps, each with 3 features
const sequentialInput = tf.randomNormal([32, 5, 3]);

// The extra dimension is TIME
// Think of it like:
// - Feedforward: a single photo (width × height)
// - Sequential: a video (frames × width × height)

// Or in React terms:
// - Feedforward: rendering a single component from props
// - Sequential: rendering an animation from a keyframe sequence

console.log('Feedforward shape:', feedforwardInput.shape);  // [32, 3]
console.log('Sequential shape:', sequentialInput.shape);     // [32, 5, 3]

feedforwardInput.dispose();
sequentialInput.dispose();`}
</CodeBlock>

<RecallPrompt
  question="You feed a feedforward network three readings one at a time: [0.5, 0.3, 0.7], then [0.8, 0.2, 0.9], then [0.4, 0.6, 0.1]. You run them again in reverse order. What changes about the three scores, and what does not?"
  answer="Each reading keeps the exact score it had; the list of scores just comes back in a different order. The network scores every reading in isolation, so nothing about a reading's score depends on what preceded it. Note the trap in the other direction: shuffling the three numbers INSIDE one reading does change its score, because a dense layer holds a separate weight per input position. Position within a vector matters to it. Position within a sequence does not, because it never sees the sequence at all."
