      import * as tf from '@tensorflow/tfjs';

      const sigmoid = (z) => 1 / (1 + Math.exp(-z));

      function lstmStep(prevHidden, prevCell, x, weights) {
        const preact = (row, j) => row[0] * prevHidden[j] + row[1] * x[j] + row[2];
        const newCell = prevCell.map((c, j) => {
          const forget = sigmoid(preact(weights.forget[j], j));
          const store = sigmoid(preact(weights.input[j], j));
          const candidate = Math.tanh(preact(weights.candidate[j], j));
          return forget * c + store * candidate;
        });
        const newHidden = newCell.map((c, j) => sigmoid(preact(weights.output[j], j)) * Math.tanh(c));
        return { newCell, newHidden };
      }

      function buildLstmCell(timeSteps) {
        const model = tf.sequential();
        const cell = tf.layers.lstm({ units: 1, inputShape: [timeSteps, 1], recurrentActivation: 'sigmoid', returnSequences: true });
        model.add(cell);
        const [kernel, recurrentKernel, biasTensor] = model.getWeights();
        const inputColumns = Array.from(kernel.dataSync());
        const recurrentColumns = Array.from(recurrentKernel.dataSync());
        const biases = Array.from(biasTensor.dataSync());
        const gateRow = (column) => [recurrentColumns[column], inputColumns[column], biases[column]];
        return {
          model,
          weights: {
            input: [gateRow(0)],
            forget: [gateRow(1)],
            candidate: [gateRow(2)],
            output: [gateRow(3)],
          },
        };
      }

## One stored value, two results

<BridgeCallout bridge={frontmatter.concept.bridge} />

The **cell state** holds the running value. The **hidden state** is the gated
output passed to the next step or layer. Closing the output gate can hide a
value while the cell keeps it.

Demir first checks the arithmetic with a supplied example from the challenge.
One cell-state value starts at `2`. Each gate's weighted sum is zero, so
sigmoid gives each gate `0.5`. The candidate uses tanh: `tanh(0)` is `0`.
This is a check of the cell calculation, separate from the archive model.

Follow that one value through the update:

1. The forget gate keeps `0.5 * 2 = 1` from the old cell.
2. The input gate adds `0.5 * 0 = 0` from the candidate.
3. Adding those contributions gives a new cell value of `1`.
4. The output gate passes `0.5 * tanh(1)`, about `0.381`, as the hidden output.

<CodeBlock language="typescript" title="lstm-gates.ts">
{`const previousCell = 2;
const forgetGate = 0.5;
const inputGate = 0.5;
const outputGate = 0.5;
const candidate = Math.tanh(0);

const kept = forgetGate * previousCell;
const added = inputGate * candidate;
const newCell = kept + added;
const newHidden = outputGate * Math.tanh(newCell);

console.log({ newCell, newHidden }); // 1 and approximately 0.381`}
</CodeBlock>

In the activity, try a nonzero candidate, then close the input gate. The
candidate stops contributing. Close the output gate instead and compare the
cell value with the hidden output. Choose **Cell state** or **Hidden output** as the quantity to predict.
Changing only the output gate changes the hidden output while keeping the
new cell state fixed. These controls choose gate fractions directly. Your
challenge function will calculate them from weights.

## From weights to gate fractions

Each gate reads the previous hidden value and the current input. Its row of
weights is `[wHidden, wInput, bias]`. Multiply the two inputs by their weights,
add the bias, then apply sigmoid. The candidate uses the same weighted-sum
pattern with tanh.

Here is the forget row from another supplied challenge check:

<CodeBlock language="typescript" title="lstm-weighted-gate.ts">
{`const previousHidden = 0.6;
const currentInput = 0.75;
const forgetWeights = [-0.9, 0.4, -1.2];

const forgetSum = forgetWeights[0] * previousHidden
  + forgetWeights[1] * currentInput
  + forgetWeights[2];
const forgetGate = 1 / (1 + Math.exp(-forgetSum));

console.log(forgetSum); // -1.44
console.log(forgetGate); // approximately 0.192`}
</CodeBlock>

Use each gate's own row. After calculating the fractions, apply the same
keep, add, and expose steps shown above. A wider LSTM mixes inputs through
full matrices. This challenge uses one unit and one input feature so you can
check the library's calculation directly.

## Matching the library cell

Build the one-unit layer with `recurrentActivation: 'sigmoid'`. TensorFlow.js
4.22 otherwise defaults its gates to `hardSigmoid`, which computes
`max(0, min(1, 0.2 * z + 0.5))`. Matching the gate activations matters when you
compare your handwritten step with the library. The candidate and cell output
use tanh.

The layer stores its weights in three tensors:

| Tensor           | Shape for this one-unit cell | What each value multiplies   |
| ---------------- | ---------------------------- | ---------------------------- |
| Input kernel     | `[1, 4]`                     | Current input                |
| Recurrent kernel | `[1, 4]`                     | Previous hidden state        |
| Bias             | `[4]`                        | Added after the two products |

Their four columns use the same order:

| Column | 0          | 1           | 2         | 3           |
| ------ | ---------- | ----------- | --------- | ----------- |
| Role   | Input gate | Forget gate | Candidate | Output gate |

Read the matching column from each tensor. The forget gate, for example,
uses column `1`. Put the recurrent value first to match the challenge's
`[wHidden, wInput, bias]` row format.

<CodeBlock language="typescript" title="lstm-cell-weights.ts">
{`import * as tf from '@tensorflow/tfjs';

const model = tf.sequential();
model.add(tf.layers.lstm({
  units: 1,
  inputShape: [3, 1],
  recurrentActivation: 'sigmoid',
  returnSequences: true,
}));

const [kernel, recurrentKernel, bias] = model.getWeights();
const forgetRow = [
  recurrentKernel.dataSync()[1],
  kernel.dataSync()[1],
  bias.dataSync()[1],
];
console.log(forgetRow);

model.dispose();`}
</CodeBlock>

Repeat that column mapping for the input gate, candidate, and output gate.
The challenge needs one row inside each named weights array, such as
`weights.forget[0]`. Read the actual bias too. With `unitForgetBias: true`,
the forget bias starts at one while the other bias groups start at zero.

Start both hidden and cell state at `[0]` when comparing a fresh window.
Feed each returned state into your next step. With `returnSequences: true`,
the library returns a hidden output at every time step, so you can locate
the first disagreement. Matching shape alone cannot check the gate arithmetic
or column order.

## What repeated forgetting does

If the input gate stays closed, the candidate adds nothing. Each update
multiplies the existing cell value by the forget fraction. A fraction of
`0.99` repeated 100 times retains about `0.366` of the starting value.
A fraction of `0.9` retains about `0.000027`.

The direct cell-state gradient path picks up those forget factors too.
Fractions near one reduce decay on that path. Other gradient paths also run
through the gates, so an LSTM can still fail to learn a useful pattern.
The challenge checks the closed-input case with a nonzero candidate. Leaving
out the input gate would incorrectly add that candidate at every step.

## GRU comparison

A GRU uses update and reset gates with one hidden state. It has no separate
cell state or output gate. An LSTM has four parameter blocks for its three
gates and candidate. A GRU has three blocks, so the same input and hidden
widths use fewer parameters. Compare their quality on the same data and
evaluation procedure.

### The GRU uses fewer parameter blocks

This example uses the same input and hidden widths as the larger LSTM.
The parameter comparison concerns these configurations. It supplies no
comparison of model quality.

<CodeBlock language="typescript" title="gru-comparison.ts">
{`import * as tf from '@tensorflow/tfjs';

// GRU (Gated Recurrent Unit): one gate fewer, and a quarter fewer weights
// A GRU has two gates, update and reset. An LSTM has three.

// 1. UPDATE GATE: one value per dimension, doing the forget gate's job
//    and the input gate's job at once
//    update = sigmoid(W_z · [prevHidden, input] + b_z)
//    newHidden = update * prevHidden + (1 - update) * candidate
//    Keeping 70% of the old state means taking 30% of the new candidate

// 2. RESET GATE: how much of the previous hidden state the candidate
//    is allowed to see
//    reset = sigmoid(W_r · [prevHidden, input] + b_r)
//    candidate = tanh(W_c · [reset * prevHidden, input] + b_c)

// There is no separate cell state, so there is no output gate: the hidden
// state is the only thing the cell carries, and it leaves the cell whole

const gruModel = tf.sequential();
gruModel.add(tf.layers.gru({
  units: 64,
  recurrentActivation: 'sigmoid', // match the gate equations above
  inputShape: [80, 3],
}));
gruModel.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

// Comparison:
// LSTM: 4 sets of weight matrices: forget, input, and output gates plus the
//       candidate state
// GRU:  3 sets: reset gate, update gate, candidate state, which is exactly
//       25% fewer weights: 13,056 against the LSTM's 17,408 at these settings
// Which of the two scores better on a given series is a question you measure,
// so compare both on the same data and evaluation procedure.
gruModel.dispose();`}
</CodeBlock>
