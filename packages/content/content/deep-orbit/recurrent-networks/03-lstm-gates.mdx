The simple RNN forgets. Its gradients thin out by step twenty and are gone long before step seventy-three, where the pattern lives: the information from the early steps is multiplied through too many small numbers to survive. LSTMs solve this with gates: learned switches that control what flows through and what gets discarded.
</Dialogue>

<Dialogue speaker="Ensign Demir">
Gates, like a cache with TTL? Keep the important entries, let the stale ones expire?
</Dialogue>

<Dialogue speaker="Chief Nazari" expression="skeptical">
Don't tell me what it's like, Ensign. Tell me how far back it can hold a pattern, and what that costs after last night's six hours of nothing.
</Dialogue>

<Dialogue speaker="Dr. Farah">
Hundreds of steps, for roughly four times the parameters of the simple RNN. And there is no clock in an LSTM anywhere. A forget gate reads the current input together with the previous hidden state and outputs a number between 0 and 1 for every dimension of the cell state: keep 90% of this, drop most of that. Partial and learned, with no timer. Within a window it can carry the first step most of the way to the last, where the simple RNN lost it by step twenty, and a shape it has learned once, it recognizes whenever the stream brings that shape back, including in windows days past the ones it trained on.
</Dialogue>

The three gates (forget, input, output) are each a small sigmoid layer with its own learned weights. Farah said switches, but the [0,1] output makes each one closer to a dimmer: a gate can pass 30% of a value, not just all of it or none.

## Three Gates, One Cell

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="lstm-gates.ts">
{`// LSTM Cell: three gates controlling information flow

// 1. FORGET GATE: what to discard from memory
//    forgetGate = sigmoid(W_f · [prevHidden, input])
//    Output: values between 0 (forget completely) and 1 (keep fully)

// 2. INPUT GATE: what new information to store
//    inputGate = sigmoid(W_i · [prevHidden, input])
//    candidate = tanh(W_c · [prevHidden, input])
//    newCell = forgetGate * prevCell + inputGate * candidate

// 3. OUTPUT GATE: what to expose as hidden state
//    outputGate = sigmoid(W_o · [prevHidden, input])
//    newHidden = outputGate * tanh(newCell)

// The cell state is only scaled and added to at each step, never pushed
// through a weight matrix and a tanh the way the simple RNN's hidden
// state is. Walking backward along that path, the gradient picks up
// exactly one factor per step: the forget gate. A gate that learns to sit
// at 0.99 still leaves 0.37 of the signal 100 steps later; at 0.9 only
// 0.000027 survives, and a gate that learns to close cuts that
// dimension off on purpose. The decay is learned per dimension here,
// not forced by the wiring`}
</CodeBlock>

## Building an LSTM in TF.js

<CodeBlock language="typescript" title="lstm-model.ts">
{`import * as tf from '@tensorflow/tfjs';

// LSTM: drop-in replacement for SimpleRNN (same API, much better memory)
const model = tf.sequential();
model.add(tf.layers.lstm({
  units: 64,              // hidden state size
  inputShape: [80, 3],    // the SAME 80-step window the SimpleRNN failed on
  returnSequences: false,  // only need final output for classification
}));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

model.compile({ optimizer: 'adam', loss: 'binaryCrossentropy', metrics: ['accuracy'] });

// Shape drill with placeholder tensors: prove the [80, 3] pipeline runs
// end to end. Placeholder labels are random, so do NOT expect this loss
// to converge; nothing can learn noise. The real evidence that gates beat
// plain recurrence on this window is the previous lesson's failed run and
// tonight's archive replay below.
const x = tf.randomNormal([100, 80, 3]);  // 100 samples, 80 time steps
const y = tf.randomUniform([100, 1]).round();

const history = await model.fit(x, y, {
  epochs: 20,
  validationSplit: 0.2,
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      if (epoch % 5 === 0) {
        console.log(\`Epoch \${epoch}: loss=\${logs?.loss.toFixed(4)}, val_loss=\${logs?.val_loss.toFixed(4)}\`);
      }
    },
  },
});

x.dispose();
y.dispose();`}
</CodeBlock>

## GRU: The Lighter Alternative

<CodeBlock language="typescript" title="gru-comparison.ts">
{`import * as tf from '@tensorflow/tfjs';

// GRU (Gated Recurrent Unit): fewer parameters, often similar performance
// Two gates instead of three: update gate + reset gate

// 1. UPDATE GATE: one value per dimension, doing the forget gate's job
//    and the input gate's job at once
//    update = sigmoid(W_z · [prevHidden, input])
//    newHidden = update * prevHidden + (1 - update) * candidate
//    Keeping 70% of the old state means taking 30% of the new candidate

// 2. RESET GATE: how much of the previous hidden state the candidate
//    is allowed to see
//    reset = sigmoid(W_r · [prevHidden, input])
//    candidate = tanh(W_c · [reset * prevHidden, input])

// There is no separate cell state, so there is no output gate: the hidden
// state is the only thing the cell carries, and it leaves the cell whole

const gruModel = tf.sequential();
gruModel.add(tf.layers.gru({
  units: 64,
  inputShape: [80, 3],
}));
gruModel.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

// Comparison:
// LSTM: 4 sets of weight matrices: forget, input, and output gates plus the
//       candidate state (more parameters, better long-range memory)
// GRU:  3 sets: reset gate, update gate, candidate state (~25% fewer params, faster training)
// Rule of thumb: train both and compare. The GRU often wins when the training
//               set is small; the LSTM tends to win when dependencies run long`}
</CodeBlock>
