        const train = { xs: [], ys: [] };
        const evalSet = { xs: [], ys: [] };
        for (let i = 0; i + windowSize <= series.length; i++) {
          const end = i + windowSize;
          const window = series.slice(i, end);
          const label = labels[end - 1];
          if (end <= splitAt) {

            train.ys.push(label);

## Overlapping windows and misleading accuracy

A random split can be suitable for independent rows. These windows share readings, so they are not independent. This small example uses 200 readings and 8-step windows to show what goes wrong:

<CodeBlock language="typescript" title="the-mirror.ts">
{`// A 200-reading toy stream: a slow swell on a drift. Nothing random,
// so your numbers will match these exactly.
const series = Array.from({ length: 200 }, (_, t) =>
  0.007 * t + Math.sin((2 * Math.PI * t) / 80));

// Ground truth comes from OUTSIDE the waveform (the contact log says
// which stretches were confirmed activity). Window the stream with
// stride 1 and label each window by its final reading:
const inContact = (t: number) =>
  (t >= 30 && t < 62) || (t >= 100 && t < 132) || (t >= 168 && t < 190);
const pairs = Array.from({ length: 193 }, (_, i) => ({
  x: series.slice(i, i + 8),
  y: inContact(i + 7) ? 1 : 0,
}));

// A one-nearest-neighbor classifier: copy the label of the closest
// training window. It stores examples and performs no weight training.
const predict = (x: number[], train: typeof pairs) =>
  train.reduce(
    (best, p) => {
      const d = x.reduce((sum, v, j) => sum + (v - p.x[j]) ** 2, 0);
      return d < best.d ? { d, y: p.y } : best;
    },
    { d: Infinity, y: 0 },
  ).y;
const accuracy = (evalSet: typeof pairs, train: typeof pairs) =>
  evalSet.filter((p) => predict(p.x, train) === p.y).length / evalSet.length;

// WRONG: window the whole stream, THEN split (every 5th pair held out)
const evalA = pairs.filter((_, i) => i % 5 === 0);
const trainA = pairs.filter((_, i) => i % 5 !== 0);
console.log((100 * accuracy(evalA, trainA)).toFixed(1));  // 97.4

// RIGHT: split the stream at reading 160, THEN window each side
const trainB = pairs.slice(0, 153);      // windows fully inside [0, 160)
const evalB = Array.from({ length: 33 }, (_, i) => ({
  x: series.slice(160 + i, 168 + i),
  y: inContact(160 + i + 7) ? 1 : 0,
}));
console.log((100 * accuracy(evalB, trainB)).toFixed(1));  // 60.6`}
</CodeBlock>

The nearest-neighbor classifier gets 38 of 39 evaluation windows right: 97.4%. But adjacent 8-step windows share seven readings. Holding out every fifth window leaves it beside near-copies in the training set, often with the same label. That makes the score too optimistic for predicting a later, unseen period.

Splitting by time first removes shared readings. The later-period score is 60.6%. That set contains 22 contact windows out of 33, so always predicting contact would score 66.7%. The 36.8-point difference shows that the first evaluation answers the wrong question. It does not measure the effect of overlap alone, because the two evaluations also cover different periods.

## The Sliding Window Pattern

A new reading arrives every second. This LSTM takes the latest 80 readings as one input. When the next reading arrives, drop the oldest, add the new one and make the next prediction.

<BridgeCallout bridge={frontmatter.concept.bridge} />

Unlike disjoint stream chunks, adjacent 80-reading windows share 79 readings. That reuse creates overlapping training examples, which can leak readings across a split. Split the stream before creating the windows.

<CodeBlock language="typescript" title="sliding-window.ts">
{`// The makeWindows you wrote in 'Sequences Matter'. Both of its moving
// parts came from that exercise: the stride, and the label taken from
// the reading right after the window. The tensor pair it also returns is
// left off here. The argument in this lesson is about which reading
// labels a window, and that is settled in the arrays.
function makeWindows(
  data: number[][],
  windowSize: number,
  stride: number = 1,
): { xs: number[][][]; ys: number[][] } {
  const xs: number[][][] = [];
  const ys: number[][] = [];

  // the loop stops one position early, because the last window still
  // needs a future reading to point at
  for (let i = 0; i + windowSize < data.length; i += stride) {
    xs.push(data.slice(i, i + windowSize));
    ys.push(data[i + windowSize]);
  }

  return { xs, ys };
}

// Window 0: [s0, s1, s2, s3] to predict s4
// Window 1: [s1, s2, s3, s4] to predict s5   (stride 1: windows overlap)`}
</CodeBlock>

Choose the target to match the task. Forecasting predicts the reading after the window, `data[i + windowSize]`. Keep that reading outside the input, or the model could see the answer.

Classification works differently here: use the external log label at the window’s last reading, `labels[end - 1]`. The label is separate from the input features. Check that those features were available at prediction time. The small evaluation example and graded exercise use classification. `makeWindows` above demonstrates forecasting.

This stateless model only receives the history inside its window. The two events are 74 steps apart on the one-reading-per-second feed. Including both endpoints needs 75 readings, so an 80-reading window leaves five more for context. A 30-reading window cannot contain both events. More training cannot restore missing input, although a model might learn from other, shorter cues.

## Real-Time Streaming Buffer

<CodeBlock language="typescript" title="streaming-buffer.ts">
{`import * as tf from '@tensorflow/tfjs';

class SignalBuffer {
  private buffer: number[][] = [];
  private readonly windowSize: number;

  constructor(windowSize: number) {
    if (!Number.isInteger(windowSize) || windowSize < 1) throw new Error('Invalid window size');
    this.windowSize = windowSize;
  }

  push(reading: number[]): number[][] | null {
    this.buffer.push([...reading]);
    if (this.buffer.length > this.windowSize) {
      this.buffer.shift();
    }
    return this.buffer.length === this.windowSize ? [...this.buffer] : null;
  }
}

const buffer = new SignalBuffer(80);

// Integration sketch: the app supplies model, signalFeed and updateDashboard.
// Remove this handler on teardown. Reset the buffer after missing/out-of-order data.
signalFeed.addEventListener('reading', (event: CustomEvent) => {
  const window = buffer.push(event.detail.features);
  if (window) {
    const prediction = tf.tidy(() => {
      const input = tf.tensor3d([window]);
      return (model.predict(input) as tf.Tensor).dataSync();
    });
    updateDashboard(prediction);
  }
});`}
</CodeBlock>

## Challenge

The first evaluation shared readings with training. Cut the stream first, then create windows within each side. Inspect the returned training and evaluation rows before fitting the next model. The test values equal their reading indices, so a reading on the wrong side of the boundary reveals a leak.
