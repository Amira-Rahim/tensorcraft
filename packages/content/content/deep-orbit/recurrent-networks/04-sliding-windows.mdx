<Dialogue speaker="Ensign Demir">
The signal feed is continuous: readings every second, forever. But the LSTM needs fixed-size input: exactly 80 time steps. I need to convert a stream into windows, like IntersectionObserver processing what's currently in view.
</Dialogue>

Slice 80 readings. Step forward one. Slice again. That's the entire pipeline: a fixed-size window walks the continuous stream, and every position it stops at becomes one ready-made sample for the LSTM. Demir's IntersectionObserver instinct is close, but an observer only fires when an element crosses a threshold; the window manufactures data at every step.

## Ninety-Seven Percent, Briefly

Demir's first pipeline windows the eleven-day archive end to end, shuffles the pairs, holds out every fifth one for evaluation, and comes back with a score in the high nineties. Farah's response is to make him rebuild the experiment at a scale he can audit by hand before she reads a single decimal of it. Two hundred readings, 8-step windows, and a "model" too stupid to do anything except expose the split:

<CodeBlock language="typescript" title="the-mirror.ts">
{`// A 200-reading toy stream: a slow swell on a drift. Nothing random,
// so your numbers will match these exactly.
const series = Array.from({ length: 200 }, (_, t) =>
  0.007 * t + Math.sin((2 * Math.PI * t) / 80));

// Ground truth comes from OUTSIDE the waveform (the contact log says
// which stretches were confirmed activity). Window the stream with
// stride 1 and label each window by its final reading:
const inContact = (t: number) =>
  (t >= 30 && t < 62) || (t >= 100 && t < 132) || (t >= 168 && t < 190);
const pairs = Array.from({ length: 193 }, (_, i) => ({
  x: series.slice(i, i + 8),
  y: inContact(i + 7) ? 1 : 0,
}));

// The pettiest possible model: answer with the label of the closest
// training window. Pure lookup. Zero learning.
const predict = (x: number[], train: typeof pairs) =>
  train.reduce(
    (best, p) => {
      const d = x.reduce((sum, v, j) => sum + (v - p.x[j]) ** 2, 0);
      return d < best.d ? { d, y: p.y } : best;
    },
    { d: Infinity, y: 0 },
  ).y;
const accuracy = (evalSet: typeof pairs, train: typeof pairs) =>
  evalSet.filter((p) => predict(p.x, train) === p.y).length / evalSet.length;

// WRONG: window the whole stream, THEN split (every 5th pair held out)
const evalA = pairs.filter((_, i) => i % 5 === 0);
const trainA = pairs.filter((_, i) => i % 5 !== 0);
console.log((100 * accuracy(evalA, trainA)).toFixed(1));  // 97.4

// RIGHT: split the stream at reading 160, THEN window each side
const trainB = pairs.slice(0, 153);      // windows fully inside [0, 160)
const evalB = Array.from({ length: 33 }, (_, i) => ({
  x: series.slice(160 + i, 168 + i),
  y: inContact(160 + i + 7) ? 1 : 0,
}));
console.log((100 * accuracy(evalB, trainB)).toFixed(1));  // 60.6`}
</CodeBlock>

A lookup table with no learning in it scores 97.4 on the first split: 38 of 39 held-out windows. The leak is in the windowing arithmetic. With stride 1, window i and window i+1 share seven of their eight readings, so holding out every fifth pair leaves each evaluation window sitting between two training windows that are near-copies of it, labels included. The lookup finds the copy. 97.4 measures the overlap. Split the stream first and the copies vanish: 60.6 is what the lookup actually knows about readings it has never seen, and the 36.8-point gap is the size of the error Demir almost shipped to the bridge.

## The Sliding Window Pattern

<CodeBlock language="typescript" title="sliding-window.ts">
{`// rn/01's createSequences gave you the windows. Training pairs are a
// two-line delta on it:
function createWindows(
  signal: number[][],
  windowSize: number,
  stride: number = 1,        // NEW: how far the window jumps per step
): { inputs: number[][][]; labels: number[][] } {
  const inputs: number[][][] = [];
  const labels: number[][] = [];

  // stop one position earlier than createSequences did: the last
  // window still needs a future reading to point at
  for (let i = 0; i <= signal.length - windowSize - 1; i += stride) {
    inputs.push(signal.slice(i, i + windowSize));
    labels.push(signal[i + windowSize]);  // NEW: the reading AFTER the window
  }

  return { inputs, labels };
}

// Window 0: [s0, s1, s2, s3] → predict s4
// Window 1: [s1, s2, s3, s4] → predict s5   (stride 1: windows overlap)`}
</CodeBlock>

## Real-Time Streaming Buffer

<CodeBlock language="typescript" title="streaming-buffer.ts">
{`import * as tf from '@tensorflow/tfjs';

class SignalBuffer {
  private buffer: number[][] = [];
  private readonly windowSize: number;

  constructor(windowSize: number) {
    this.windowSize = windowSize;
  }

  push(reading: number[]): number[][] | null {
    this.buffer.push(reading);
    if (this.buffer.length > this.windowSize) {
      this.buffer.shift();
    }
    return this.buffer.length === this.windowSize ? [...this.buffer] : null;
  }
}

const buffer = new SignalBuffer(80);

signalFeed.addEventListener('reading', (event: CustomEvent) => {
  const window = buffer.push(event.detail.features);
  if (window) {
    const prediction = tf.tidy(() => {
      const input = tf.tensor3d([window]);
      return (model.predict(input) as tf.Tensor).dataSync();
    });
    updateDashboard(prediction);
  }
});`}
</CodeBlock>
