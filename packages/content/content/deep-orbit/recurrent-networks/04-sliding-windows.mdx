        const train = { xs: [], ys: [] };
        const evalSet = { xs: [], ys: [] };
        for (let i = 0; i + windowSize <= series.length; i++) {

          const window = series.slice(i, end);
          const label = labels[end - 1];

## Ninety-Seven Percent, Briefly

Shuffling before splitting is the right move when rows are independent. These rows are not. Two hundred readings, 8-step windows, and a "model" too stupid to do anything except expose the split:

<CodeBlock language="typescript" title="the-mirror.ts">
{`// A 200-reading toy stream: a slow swell on a drift. Nothing random,
// so your numbers will match these exactly.
const series = Array.from({ length: 200 }, (_, t) =>
  0.007 * t + Math.sin((2 * Math.PI * t) / 80));

// Ground truth comes from OUTSIDE the waveform (the contact log says
// which stretches were confirmed activity). Window the stream with
// stride 1 and label each window by its final reading:
const inContact = (t: number) =>
  (t >= 30 && t < 62) || (t >= 100 && t < 132) || (t >= 168 && t < 190);
const pairs = Array.from({ length: 193 }, (_, i) => ({
  x: series.slice(i, i + 8),
  y: inContact(i + 7) ? 1 : 0,
}));

// A one-nearest-neighbor classifier: copy the label of the closest
// training window. It stores examples rather than fitting network weights.
const predict = (x: number[], train: typeof pairs) =>
  train.reduce(
    (best, p) => {
      const d = x.reduce((sum, v, j) => sum + (v - p.x[j]) ** 2, 0);
      return d < best.d ? { d, y: p.y } : best;
    },
    { d: Infinity, y: 0 },
  ).y;
const accuracy = (evalSet: typeof pairs, train: typeof pairs) =>
  evalSet.filter((p) => predict(p.x, train) === p.y).length / evalSet.length;

// WRONG: window the whole stream, THEN split (every 5th pair held out)
const evalA = pairs.filter((_, i) => i % 5 === 0);
const trainA = pairs.filter((_, i) => i % 5 !== 0);
console.log((100 * accuracy(evalA, trainA)).toFixed(1));  // 97.4

// RIGHT: split the stream at reading 160, THEN window each side
const trainB = pairs.slice(0, 153);      // windows fully inside [0, 160)
const evalB = Array.from({ length: 33 }, (_, i) => ({
  x: series.slice(160 + i, 168 + i),
  y: inContact(160 + i + 7) ? 1 : 0,
}));
console.log((100 * accuracy(evalB, trainB)).toFixed(1));  // 60.6`}
</CodeBlock>

A nearest-neighbor classifier scores 97.4 on the first split: 38 of 39 held-out windows. The leak is in the windowing arithmetic. With stride 1, window i and window i+1 share seven of their eight readings. Holding out every fifth pair leaves each evaluation window sitting between two training windows that are near-copies of it, labels included. The lookup finds the copy. That score is optimistic for the intended task of predicting later, unseen periods. Split the stream first and the copies vanish: The chronological score of 60.6 describes a different, later period. Overlap and distribution differences both change the comparison. Twenty-two of those 33 windows are labeled in contact, so answering yes to every one of them would have scored 66.7. The 36.8-point gap warns Demir that the first evaluation does not answer the deployment question. It does not isolate overlap as the only cause.

## The Sliding Window Pattern

Readings every second, forever, and the LSTM takes exactly 80 of them at a time. Slice 80. Step forward one. Slice again. That is the entire pipeline: a fixed-size window walks the continuous stream, and every position it stops at becomes one ready-made sample.

<BridgeCallout bridge={frontmatter.concept.bridge} />

A framer drops every byte it emits, which would put each reading in exactly one chunk and never in another. The window steps forward by one and keeps the other seventy-nine, so a single reading turns up in dozens of samples. That reuse is where the training data comes from, and it is the reason the split above had to come first.

<CodeBlock language="typescript" title="sliding-window.ts">
{`// The makeWindows you wrote in 'Sequences Matter'. Both of its moving
// parts came from that exercise: the stride, and the label taken from
// the reading right after the window. The tensor pair it also returns is
// left off here; the argument in this lesson is about which reading
// labels a window, and that is settled in the arrays.
function makeWindows(
  data: number[][],
  windowSize: number,
  stride: number = 1,
): { xs: number[][][]; ys: number[][] } {
  const xs: number[][][] = [];
  const ys: number[][] = [];

  // the loop stops one position early, because the last window still
  // needs a future reading to point at
  for (let i = 0; i + windowSize < data.length; i += stride) {
    xs.push(data.slice(i, i + windowSize));
    ys.push(data[i + windowSize]);
  }

  return { xs, ys };
}

// Window 0: [s0, s1, s2, s3] → predict s4
// Window 1: [s1, s2, s3, s4] → predict s5   (stride 1: windows overlap)`}
</CodeBlock>

Which reading labels a window depends on the task, and this lesson shows both cases. Forecasting takes its target from the reading after the window. The label has to sit outside the window, because including it would let the model read its own answer. Here, per-window classification takes an external log label at the window's last reading. That does not put the answer into the features. You must still check that all input measurements were available at prediction time. The mirror above and the graded exercise are classification, so they label by `labels[end - 1]`. `makeWindows` here is forecasting, so it labels by `data[i + windowSize]`.

For the stateless model here, window size limits the input history. Lesson 2 put the pattern DEEP SCAN needs at a 74-step dependency on the one-sample-per-second feed, so an 80-step window holds it with six steps to spare. Set `windowSize` to 30 and no single sample ever contains the whole pattern, and no amount of training gets it back.

## Real-Time Streaming Buffer

<CodeBlock language="typescript" title="streaming-buffer.ts">
{`import * as tf from '@tensorflow/tfjs';

class SignalBuffer {
  private buffer: number[][] = [];
  private readonly windowSize: number;

  constructor(windowSize: number) {
    if (!Number.isInteger(windowSize) || windowSize < 1) throw new Error('Invalid window size');
    this.windowSize = windowSize;
  }

  push(reading: number[]): number[][] | null {
    this.buffer.push([...reading]);
    if (this.buffer.length > this.windowSize) {
      this.buffer.shift();
    }
    return this.buffer.length === this.windowSize ? [...this.buffer] : null;
  }
}

const buffer = new SignalBuffer(80);

// Integration sketch: the app supplies model, signalFeed and updateDashboard.
// Remove this handler on teardown; reset the buffer after missing/out-of-order data.
signalFeed.addEventListener('reading', (event: CustomEvent) => {
  const window = buffer.push(event.detail.features);
  if (window) {
    const prediction = tf.tidy(() => {
      const input = tf.tensor3d([window]);
      return (model.predict(input) as tf.Tensor).dataSync();
    });
    updateDashboard(prediction);
  }
});`}
</CodeBlock>

## Challenge

The mirror scored 97.4 because the stream was windowed before it was split. Build the honest version: cut the stream at a boundary first, then window each side, and prove that no reading crosses over. The grader hands you a series whose values are their own indices, so a leak shows up as a number on the wrong side.
