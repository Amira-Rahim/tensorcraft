      import * as tf from '@tensorflow/tfjs';

      const LIMITS = [
        { min: 0, max: 2048 },
        { min: 0, max: 63 },
        { min: -Math.PI, max: Math.PI },
      ];

      async function trainForecaster(xs, ys, epochs, providedModel) {
        const model = providedModel || tf.sequential();
        if (!providedModel) {
          model.add(tf.layers.lstm({ units: 8, inputShape: [xs.shape[1], xs.shape[2]] }));
          model.add(tf.layers.dense({ units: 3 }));
          model.compile({
            optimizer: tf.train.adam(0.01),
            loss: 'meanSquaredError',
            metrics: ['mae'],
          });
        }
        try {
          const history = await model.fit(xs, ys, { epochs, batchSize: 32 });
          return { model, history };
        } catch (error) {
          if (!providedModel) {
            model.optimizer.dispose();
            model.dispose();
          }
          throw error;
        }
      }

      function forecastMultiStep(model, seed, windowSize, steps, scaler) {
        if (!scaler || !Array.isArray(scaler.mean) || !Array.isArray(scaler.std) ||
            scaler.mean.length !== 3 || scaler.std.length !== 3 ||
            !scaler.mean.every(Number.isFinite) ||
            !scaler.std.every(value => Number.isFinite(value) && value > 0)) {
          throw new Error('Invalid scaler');
        }
        const bounds = LIMITS.map((limit, j) => ({
          min: (limit.min - scaler.mean[j]) / scaler.std[j],
          max: (limit.max - scaler.mean[j]) / scaler.std[j],
        }));
        const series = [...seed];
        const forecast = [];
        for (let step = 0; step < steps; step++) {
          const predicted = tf.tidy(() => {
            const input = tf.tensor3d([series.slice(-windowSize)]);
            const output = model.predict(input);
            return Array.from(output.dataSync());
          });
          if (predicted.length !== 3 || !predicted.every(Number.isFinite)) throw new Error('Invalid prediction');
          const bounded = predicted.map((value, j) =>
            Math.min(Math.max(value, bounds[j].min), bounds[j].max),
          );
          forecast.push(bounded);
          series.push(bounded);
        }
        return forecast;
      }

A list-based autocomplete filters known entries from what you typed. Our forecaster instead computes the next sensor values from a window of previous readings. Both propose what comes next, but the forecast is not selected from a fixed list. Its errors need measurement on later observations.

You will train a forecaster and feed its predictions back into the input to estimate later readings.

## Next-Value Prediction

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="prediction-model.ts">
{`import * as tf from '@tensorflow/tfjs';

// Prediction model: given 80 time steps, predict the next one.
// Integration sketch: split the raw series by time, build windows within
// each split, fit scaling on training data and supply trainX/trainY plus
// validationX/validationY in those same per-feature z-score units.
const model = tf.sequential();
model.add(tf.layers.lstm({
  units: 64,
  inputShape: [80, 3],
  returnSequences: false,
}));
model.add(tf.layers.dense({ units: 32, activation: 'relu' }));
model.add(tf.layers.dense({ units: 3 }));  // predict next [amplitude, frequency, phase]

// MSE loss for regression (not classification)
model.compile({
  optimizer: tf.train.adam(0.001),
  loss: 'meanSquaredError',
  metrics: ['mae'],
});

const history = await model.fit(trainX, trainY, {
  epochs: 50,
  batchSize: 32,
  validationData: [validationX, validationY],
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      if (epoch % 10 === 0) {
        console.log(\`Epoch \${epoch}: mae=\${logs?.mae.toFixed(4)}, val_mae=\${logs?.val_mae.toFixed(4)}\`);
      }
    },
  },
});`}
</CodeBlock>

Scale the three features before training. Here, the tensor’s last axis holds features; it is sometimes called the channel axis. Per-channel scaling means scaling each feature separately. The archive’s 64 sensor channels are a different use of that word.

The features have different units: amplitude counts stop at 2048, zero-crossing counts stop at 63, and phase uses radians. Without scaling, a 100-count amplitude error adds 10,000 to squared error, while a one-radian phase error adds only 1. Large inputs can also push gates into nearly flat parts of their activation curves, weakening their gradients. Scaling can help training, but useful forecasts still need testing against a last-value or seasonal baseline on the same later periods.


In module 1, `tf.moments(batch, 0)` calculated one mean per feature for a [rows, features] table. Here, `trainX` has shape [windows, 80, 3]. Reducing only axis 0 gives 240 means, one for each time-position and feature pair. That is not one mean per feature.

If calculating statistics from these windows, use `tf.moments(trainX, [0, 1])` to reduce both the window and time axes. This returns three means and variances. Take `variance.sqrt()` for standard deviations. A wrongly shaped [80, 3] mean still broadcasts without an error, so check the shape explicitly.

Overlapping windows count some readings repeatedly. Prefer calculating statistics from unique training readings before windowing, or document that repeated weighting. Replace a zero scale with 1. Save the means and scales for inference. Phase also wraps from +pi to -pi, even though those angles match. Raw-angle MSE treats them as far apart. A redesigned model can use sine and cosine features, with matching targets and error metrics.

MAE averages `Math.abs(predicted - actual)`. An error twice as large contributes twice as much. MSE squares errors, so doubling a miss makes its contribution four times larger. This example trains on MSE and reports MAE; that is a choice, not a requirement for every regression task. For multiple outputs, scale features deliberately and also report per-channel errors converted back to their original units.

## Multi-Step Forecasting

<CodeBlock language="typescript" title="multi-step.ts">
{`import * as tf from '@tensorflow/tfjs';

// Physical limits of the three features, from the same sensor spec the
// module-4 pipeline normalizes against. The hull sensors saturate at
// 2048 counts. "Frequency" is a zero-crossing count over one extraction
// window of 64 samples, which at 256 Hz is a quarter of a second, so 63
// is the most crossings that window can hold. Phase is in radians. The
// 64 channels of an archive row are a different 64: that is how many
// sensors report, not how long a window is.
const LIMITS = [
  { min: 0, max: 2048 },            // amplitude
  { min: 0, max: 63 },              // frequency
  { min: -Math.PI, max: Math.PI },  // phase
];

// The model reads and writes the z-scores it was trained on, so the
// limits move into that space with the same saved MEAN and STD. These
// arrays below are illustrative. Replace them with the exact statistics
// fitted for your model and stored beside its weights.
const MEAN = [1024, 32, 0];
const STD = [512, 16, 1];

const bounds = LIMITS.map((lim, j) => ({
  min: (lim.min - MEAN[j]) / STD[j],
  max: (lim.max - MEAN[j]) / STD[j],
}));
console.log(bounds[0]);  // { min: -2, max: 2 }
console.log(bounds[1]);  // { min: -2, max: 1.9375 }

const clamp = (reading: number[]) =>
  reading.map((v, j) => Math.min(Math.max(v, bounds[j].min), bounds[j].max));

console.log(clamp([2.4, 0.5, 0.1]));  // [2, 0.5, 0.1]
// 2.4 in these z-scores is 2,253 counts, past anything the sensors report.

// The rolling loop is implemented in the exercise below; supply that
// forecastMultiStep function before running this integration snippet.
// The process is: predict one reading, clamp
// it, push it onto the history, predict again. Each step builds a tensor
// for the window and gets one back from predict, so the tensor work goes
// inside tf.tidy.
//
// Clamp before the row goes back into the window. A fed-back forecast
// is the one place an out-of-range value poisons every later step.
// Step i + 1 reads this row as history, so an amplitude the sensors
// cannot produce becomes the model's own input for the rest of the run.

// A seed of 80 z-scored readings, oldest first. On the live feed these
// are the last 80 rows, scaled with the same MEAN and STD.
const recentWindow = Array.from({ length: 80 }, (_, i) => [
  Math.sin(i / 12),
  Math.cos(i / 12),
  0,
]);

// Forecast 47 steps ahead. The rolling loop is synchronous: predict,
// read the numbers out, clamp, push, repeat.
const forecast = forecastMultiStep(model, recentWindow, 80, 47, {
  mean: MEAN,
  std: STD,
});
// Inspect this run's output. No spike at a particular step is guaranteed.
model.optimizer.dispose(); // this example supplied an optimizer instance
model.dispose();
// The caller owns train/validation tensors and disposes them separately.`}
</CodeBlock>

Check what one step means. The demo predicts 47 one-second steps, less than a minute ahead. The bridge’s 47-minute countdown uses a separate series with one value per pulse, about 38 steps at the current spacing. A successful short forecast does not establish that a longer forecast will work.

Clamping keeps outputs inside the declared limits; it does not make a forecast accurate. Log how often it activates, reject non-finite outputs and compare errors by horizon. A zero or invalid scaler standard deviation must be handled before rollout.
