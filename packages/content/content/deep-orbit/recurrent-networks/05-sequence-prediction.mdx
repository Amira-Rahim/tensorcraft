## Next-Value Prediction

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="prediction-model.ts">
{`import * as tf from '@tensorflow/tfjs';

// Prediction model: given 80 time steps, predict the next one
const model = tf.sequential();
model.add(tf.layers.lstm({
  units: 64,
  inputShape: [80, 3],
  returnSequences: false,
}));
model.add(tf.layers.dense({ units: 32, activation: 'relu' }));
model.add(tf.layers.dense({ units: 3 }));  // predict next [amplitude, frequency, phase]

// MSE loss for regression (not classification)
model.compile({
  optimizer: tf.train.adam(0.001),
  loss: 'meanSquaredError',
  metrics: ['mae'],
});

const history = await model.fit(trainX, trainY, {
  epochs: 50,
  batchSize: 32,
  validationSplit: 0.2,
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      if (epoch % 10 === 0) {
        console.log(\`Epoch \${epoch}: mae=\${logs?.mae.toFixed(4)}, val_mae=\${logs?.val_mae.toFixed(4)}\`);
      }
    },
  },
});`}
</CodeBlock>

MAE is mean absolute error: the average of `Math.abs(predicted - actual)` across the batch, in the same units as the reading. MSE squares each error first, so one large miss moves it more than several small ones do, while MAE weights every miss the same. Train on MSE, because the squaring pushes the optimizer at the worst misses first. Report MAE, because it reads in the units on the instrument.

## Multi-Step Forecasting

<CodeBlock language="typescript" title="multi-step.ts">
{`import * as tf from '@tensorflow/tfjs';

// Physical limits of the three features, from the same sensor spec the
// module-4 pipeline normalizes against. The hull sensors saturate at
// 2048 counts. "Frequency" is a zero-crossing count over a 64-sample
// window, and phase is an angle in radians.
const LIMITS = [
  { min: 0, max: 2048 },            // amplitude
  { min: 0, max: 63 },              // frequency
  { min: -Math.PI, max: Math.PI },  // phase
];

const clamp = (reading: number[]) =>
  reading.map((v, j) => Math.min(Math.max(v, LIMITS[j].min), LIMITS[j].max));

// Predict multiple steps ahead by feeding predictions back as input
async function forecastMultiStep(
  model: tf.LayersModel,
  seed: number[][],
  steps: number,
): Promise<number[][]> {
  const window = [...seed];
  const predictions: number[][] = [];

  for (let i = 0; i < steps; i++) {
    const nextValue = tf.tidy(() => {
      const input = tf.tensor3d([window.slice(-80)]);
      const pred = model.predict(input) as tf.Tensor;
      return Array.from(pred.dataSync());
    });
    // Clamp before the row goes back into the window. A fed-back forecast
    // is the one place an out-of-range value poisons every later step.
    // Step i + 1 reads this row as history, so an amplitude of -40 or
    // 3000 counts becomes the model's own input for the rest of the run.
    const bounded = clamp(nextValue);
    predictions.push(bounded);
    window.push(bounded);
  }

  return predictions;
}

// Forecast 47 steps ahead
const forecast = await forecastMultiStep(model, recentWindow, 47);
// The LSTM predicts a spike at step 47 of this one-second-step demo horizon.`}
</CodeBlock>

One unit check before anyone trusts a display. The demo above walks 47 one-second steps, under a minute of horizon. The bridge's 47-minute countdown runs on a different series, the pulse intervals, one value per pulse, where 47 minutes is about 38 steps at the current spacing. Read what one step means before you read a forecast, and when a short forecast lands, credit the signal's regularity before you credit the model.
