The model's architecture lives in `model.json`. The learned weights live in binary `.bin` shards alongside it. `tf.loadLayersModel()` fetches both over HTTP and assembles the model in memory. Like a font loader, it may fetch several files. It also builds a runnable model from them.

You will load a saved model and inspect the input and output shapes it expects.

## From files to a usable model

The deployed example at `/models/deep-scan/model.json` lists one weight shard,
`weights.bin`. Its three dense layers have 673 float32 parameters, occupying
2,692 weight bytes. The manifest and runtime add their own bytes. Other
exports can list more shards or use supported weight encodings.

| Stage | What the loader or your code does |
| --- | --- |
| Manifest | Read the topology and the `weightsManifest` groups. |
| Shards | Resolve each group's paths relative to the manifest URL and fetch every required weight file. |
| Await | Wait for the loader to construct the model. A Promise is not its input metadata. |
| Inspect | Copy the returned model's input/output shapes and count its layers. |
| Release | Dispose the inspected model after copying the plain metadata, including if inspection throws. |

<BridgeCallout bridge={frontmatter.concept.bridge} />

This inspection-only example loads once. The copied arrays survive disposal.
Its `[null, 3]` input means a variable number of rows with three features per
row. `[null, 1]` means one output per row. Neither shape tells you the feature
names, scaling, or what a score means. Those come from the model's contract.
Read the returned shapes instead of typing these example dimensions into your
Challenge function, because its simulated models can have different shapes.

<CodeBlock language="typescript" title="model-loading.ts">
{`import * as tf from '@tensorflow/tfjs';

const inspected = await tf.loadLayersModel('/models/deep-scan/model.json');
try {
  const inputShape = [...inspected.inputs[0].shape];
  const outputShape = [...inspected.outputs[0].shape];
  const layerCount = inspected.layers.length;
  console.log({ inputShape, outputShape, layerCount });
  // This deployed example: [null, 3], [null, 1], 3 layers.
  inspected.summary(); // 128 + 528 + 17 = 673 parameters
} finally {
  inspected.dispose();
}
// The model is released. The copied shape arrays describe what was loaded.`}
</CodeBlock>

The inspection helper owns this short-lived model. A dashboard that will call
`predict()` repeatedly keeps its loaded model alive until teardown. Disposing
that model after every reading would force the app to load another one.

This simplified float32 example shows the manifest and weight requests. The real loader also handles multiple shards and supported weight encodings:

## Exported files and their paths

The training module kept a model in memory. `model.save()` exports its architecture and learned weights so another app can load them. The following export examples assume a separate live trained `model` is in scope. The inspected model above has already been released. These exports write one JSON manifest and one weight file.

<CodeBlock language="typescript" title="export.ts">
{`// Node, with @tensorflow/tfjs-node installed: writes model.json and
// weights.bin into ./models/deep-scan/, the exact pair the loader wants.
await model.save('file://./models/deep-scan');

// Browser: this downloads two files, named off the prefix you pass.
// 'downloads://deep-scan' gives you deep-scan.json and
// deep-scan.weights.bin. Serve both with those names and load deep-scan.json.
// If you rename the weight file, update weightsManifest.paths inside the
// JSON too. Renaming the files alone leaves the loader requesting a missing shard.
await model.save('downloads://deep-scan');

// For this classifier, the weight shard holds 673 float32 values: 2,692 bytes.`}
</CodeBlock>

A model trained in Python arrives by a different route. `tensorflowjs_converter` can produce a LayersModel from a supported Keras export or a GraphModel from a supported SavedModel. Both use JSON and weight shards. Use `tf.loadGraphModel()` for a GraphModel and `tf.loadLayersModel()` for a LayersModel. Converters such as `tf2onnx` serve a different route to ONNX. Lesson 5 uses a small exporter for this course's exact dense network.

## A separate application cache

The following application example returns a live model for repeated predictions. Its caller owns that model and disposes it during teardown.

A URL load requests the manifest and weight files. HTTP or service-worker caching may serve those files without another full download. IndexedDB gives the app a model copy it can load explicitly.

DEEP SCAN’s float32 weights take only 2,692 bytes, excluding the manifest and runtime. The main benefit here is working when the compute-bay link fails. The IndexedDB copy can keep predictions running if the page, runtime and all other required files are also available offline. It also needs a versioning plan: later in this lesson, the cached model and retrained model disagree about a reading.

<CodeBlock language="typescript" title="model-caching.ts">
{`import * as tf from '@tensorflow/tfjs';

const MODEL_URL = '/models/deep-scan/model.json';
const CACHE_KEY = 'indexeddb://deep-scan-v1';

async function loadModelWithCache(): Promise<tf.LayersModel> {
  try {
    // Try loading from IndexedDB cache first
    const cached = await tf.loadLayersModel(CACHE_KEY);
    console.log('Loaded from cache');
    return cached;
  } catch {
    // Cache miss: fetch from server and save to IndexedDB
    console.log('Cache miss; fetching from server');
    const model = await tf.loadLayersModel(MODEL_URL);
    try {
      await model.save(CACHE_KEY);
    } catch (error) {
      // A quota or storage-permission failure must not discard a usable model.
      console.warn('Model ready, but unavailable offline:', error);
    }
    return model;
  }
}

// On a cache miss this fetches from the server. A cache hit loads the saved copy.
const model = await loadModelWithCache();

// Check what's cached
const savedModels = await tf.io.listModels();
console.log(savedModels);
// { 'indexeddb://deep-scan-v1': { dateSaved: '...', modelTopologyBytes: 1234, ... } }

// Shipping new weights means a new key: CACHE_KEY becomes
// 'indexeddb://deep-scan-v2', and nothing reads the v1 entry after that.
// After v2 is loaded and verified, removeModel frees the old bytes.
// Do not delete your current offline copy immediately after saving it.
// await tf.io.removeModel('indexeddb://deep-scan-v1').
// When this application no longer needs its model: model.dispose();`}
</CodeBlock>

Try the cache first. If it is missing, download the model and try to save a copy. A failed download prevents loading. A failed cache write does not: the downloaded model is already usable in memory. Users can clear browser storage, and the browser can evict it. Test both cache hits and misses.

When the weights change, use a new version in the cache key. Otherwise, users keep loading the old weights. Once you load and verify the new version, remove the unused old entry to free storage.

## Loading States in the UI

<CodeBlock language="typescript" title="loading-ui.ts">
{`import * as tf from '@tensorflow/tfjs';

type ModelState =
  | { status: 'idle' }
  | { status: 'loading'; progress: number }
  | { status: 'ready'; model: tf.LayersModel }
  | { status: 'error'; message: string };

async function loadWithProgress(
  url: string,
  onProgress: (state: ModelState) => void,
): Promise<tf.LayersModel> {
  onProgress({ status: 'loading', progress: 0 });

  try {
    const model = await tf.loadLayersModel(url, {
      onProgress: (fraction) => {
        // fraction goes from 0 to 1 as weight shards download
        onProgress({ status: 'loading', progress: fraction });
      },
    });

    onProgress({ status: 'ready', model });
    return model;
  } catch (err) {
    const message = err instanceof Error ? err.message : 'Failed to load model';
    onProgress({ status: 'error', message });
    throw err;
  }
}
