<Dialogue speaker="Ensign Demir" expression="breakthrough">
So the model is not one file at all. That's... exactly like a web font or a spritesheet, isn't it. I was fetching the spritesheet by the name of the folder.

The model's architecture lives in `model.json`; the learned weights live in binary `.bin` shards alongside it. `tf.loadLayersModel()` fetches both over HTTP and assembles the model in memory. Demir's font comparison holds for the network leg of the trip, and only for that leg.

## The Fetch Pattern You Already Know

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="model-loading.ts">
{`import * as tf from '@tensorflow/tfjs';

// Loading a model is a fetch with extra steps
// model.json contains the architecture (layers, shapes, activations)
// weights.bin contains the learned weights (Float32Array)
const model = await tf.loadLayersModel('/models/deep-scan/model.json');

// Inspect what we loaded, like checking an API response shape
console.log('Input shape:', model.inputs[0].shape);   // [null, 3]
console.log('Output shape:', model.outputs[0].shape);  // [null, 1]
model.summary();
// Layer (type)              Output shape       Param #
// dense_Dense1 (Dense)      [null, 32]         128
// dense_Dense2 (Dense)      [null, 16]         528
// dense_Dense3 (Dense)      [null, 1]          17
// Total params: 673. The architecture taped to the engineering board in
// module 2, carrying the weights module 3 trained: the same network,
// now an asset the dashboard fetches instead of a variable in a notebook.`}
</CodeBlock>

Under the hood, `tf.loadLayersModel()` does exactly what you'd do manually:

<CodeBlock language="typescript" title="under-the-hood.ts">
{`// What tf.loadLayersModel() does internally:

// 1. Fetch the manifest (architecture)
const manifest = await fetch('/models/deep-scan/model.json').then(r => r.json());
// manifest.modelTopology = layer config (Dense, activation, shapes)
// manifest.weightsManifest = list of .bin files and their tensor names

// 2. Fetch the weight binaries
const weightData = await fetch('/models/deep-scan/weights.bin')
  .then(r => r.arrayBuffer());
// Raw Float32 values: the numbers the network learned during training

// 3. Reconstruct the model from architecture + weights
// tf.loadLayersModel() handles all of this in one call`}
</CodeBlock>

<Dialogue speaker="ARIA">
The fetch is like a font. What resolves is not. A font resolves to bytes the renderer consumes once. tf.loadLayersModel resolves to a live LayersModel: a compute graph with predict and evaluate methods that holds GPU memory until you dispose it. You download it like an asset. You manage it like a process.
</Dialogue>

## Where the Two Files Come From

Module 3 trained this network in memory. `model.save()` is the step that turns it into the two files the loader fetches.

<CodeBlock language="typescript" title="export.ts">
{`// Node, with @tensorflow/tfjs-node installed: writes model.json and
// weights.bin into ./models/deep-scan/, the exact pair the loader wants.
await model.save('file://./models/deep-scan');

// Browser: this downloads two files, named off the prefix you pass.
// 'downloads://deep-scan' gives you deep-scan.json and
// deep-scan.weights.bin, so rename them before serving them at the URL
// above, or the loader hands you the same 404 this lesson opened with.
await model.save('downloads://deep-scan');

// Either route, weights.bin holds 673 float32 values: 2,692 bytes.`}
</CodeBlock>

A model trained in Python arrives by a different route. `tensorflowjs_converter` turns a Keras or SavedModel export into the same model.json plus shard layout, and `tf2onnx` produces the `.onnx` file lesson 5 loads.

## Caching with IndexedDB

Models run 5-50MB. You don't re-download that on every page load, for the same reason static assets sit behind a service worker.

<CodeBlock language="typescript" title="model-caching.ts">
{`import * as tf from '@tensorflow/tfjs';

const MODEL_URL = '/models/deep-scan/model.json';
const CACHE_KEY = 'indexeddb://deep-scan-v1';

async function loadModelWithCache(): Promise<tf.LayersModel> {
  try {
    // Try loading from IndexedDB cache first
    const cached = await tf.loadLayersModel(CACHE_KEY);
    console.log('Loaded from cache');
    return cached;
  } catch {
    // Cache miss: fetch from server and save to IndexedDB
    console.log('Cache miss; fetching from server');
    const model = await tf.loadLayersModel(MODEL_URL);
    await model.save(CACHE_KEY);  // saves to IndexedDB
    console.log('Saved to cache');
    return model;
  }
}

// Usage: first load fetches from network, subsequent loads hit cache
const model = await loadModelWithCache();

// Check what's cached
const savedModels = await tf.io.listModels();
console.log(savedModels);
// { 'indexeddb://deep-scan-v1': { dateSaved: '...', modelTopologyBytes: 1234, ... } }

// Clear cache when deploying a new model version
await tf.io.removeModel(CACHE_KEY);`}
</CodeBlock>

Check cache first, fall back to network, store for next time. And remove the cached entry when you ship a new model version, or users keep running the old weights.

## Loading States in the UI

<CodeBlock language="typescript" title="loading-ui.ts">
{`import * as tf from '@tensorflow/tfjs';

type ModelState =
  | { status: 'idle' }
  | { status: 'loading'; progress: number }
  | { status: 'ready'; model: tf.LayersModel }
  | { status: 'error'; message: string };

async function loadWithProgress(
  url: string,
  onProgress: (state: ModelState) => void,
): Promise<tf.LayersModel> {
  onProgress({ status: 'loading', progress: 0 });

  try {
    const model = await tf.loadLayersModel(url, {
      onProgress: (fraction) => {
        // fraction goes from 0 to 1 as weight shards download
        onProgress({ status: 'loading', progress: fraction });
      },
    });

    onProgress({ status: 'ready', model });
    return model;
  } catch (err) {
    const message = err instanceof Error ? err.message : 'Failed to load model';
    onProgress({ status: 'error', message });
    throw err;
  }
}

</CodeBlock>
