## Three Browser ML Runtimes, Three Jobs

By now you've seen TFJS and ONNX Runtime Web. Transformers.js is the third tool. They aren't competitors; they solve different problems.

<BridgeCallout bridge={frontmatter.concept.bridge} />

| Runtime | When to use | Cost shape |
|---|---|---|
| **TensorFlow.js** | You trained your own model and want to ship it | Your model size + your domain expertise |
| **ONNX Runtime Web** | Your team built a PyTorch model; you want it in the browser without Python | Conversion friction + op-set risk |
| **Transformers.js** | You need a well-known NLP/vision/audio task done well | 50–500MB model download per task |

The right answer depends on whether the task is **custom** (TFJS) or **commodity** (Transformers.js).

## Pipeline in Five Lines

<CodeBlock language="typescript" title="sentiment-pipeline.ts">
{`import { pipeline } from '@xenova/transformers';

// First call: downloads ~80MB model + tokenizer to IndexedDB.
// Subsequent calls: instant from cache.
const classifier = await pipeline('sentiment-analysis');

const result = await classifier('Diagnostic One flagged the methotrexate interaction.');
console.log(result);
// [{ label: 'POSITIVE', score: 0.9991 }]

// Batch inference: pass an array.
const reports = [
  'Sensor array is functioning within tolerance.',
  'Catastrophic failure on the port-side coupling.',
  'Signal classification: anomalous.',
];
const batched = await classifier(reports);
// [
//   { label: 'POSITIVE', score: 0.987 },
//   { label: 'NEGATIVE', score: 0.999 },
//   { label: 'NEGATIVE', score: 0.852 },
// ]`}
</CodeBlock>

## Tasks the Pipeline Handles Out of the Box

```
sentiment-analysis          NER (named entities)        question-answering
translation                 summarization               text-generation
image-classification        image-segmentation          image-to-text (caption)
zero-shot-classification    feature-extraction          automatic-speech-recognition
```

Each pipeline is one line. Each downloads a model file the first time and caches it. The library ships ONNX Runtime Web underneath; TFJS is not involved at all when you use Transformers.js.

## When NOT to Use Transformers.js

- **Your task is not in the standard list.** A custom regression on sensor readings has no pretrained pipeline. Train your own with TFJS.
- **Bandwidth-sensitive users.** A 200MB model on a 3G connection is a UX failure. Inspect model sizes at [huggingface.co/models](https://huggingface.co/models) before committing.
- **Strict latency budgets on cold start.** First-call latency includes model download. Pre-warm via service worker if you need cold-start guarantees.
- **You need fine-tuning.** Transformers.js runs models, it doesn't train them. Fine-tune in Python, export to ONNX, ship via Transformers.js.
