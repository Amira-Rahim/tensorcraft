## Three Browser ML Runtimes, Three Jobs

By now you've seen TFJS and ONNX Runtime Web. Transformers.js is the third tool. They aren't competitors; they solve different problems.

<BridgeCallout bridge={frontmatter.concept.bridge} />

| Runtime | When to use | Cost shape |
|---|---|---|
| **TensorFlow.js** | You trained your own model and want to ship it | Your model size + your domain expertise |
| **ONNX Runtime Web** | Your team built a PyTorch model; you want it in the browser without Python | Conversion friction + op-set risk |
| **Transformers.js** | You need a well-known NLP/vision/audio task done well | 50-500MB model download per task |

The right answer depends on whether the task is **custom** (TFJS) or **commodity** (Transformers.js).

## Pipeline in Ten Lines

<CodeBlock language="typescript" title="sentiment-pipeline.ts">
{`// The package moved from '@xenova/transformers' to the official
// '@huggingface/transformers' at v3; old tutorials cite the former.
import { pipeline } from '@huggingface/transformers';

// First call: downloads the model + tokenizer into the browser's Cache
// Storage (the Cache API). Size depends on dtype: v3 defaults to a
// quantized model in the browser (tens of MB), and forcing fp32 means 4
// bytes per weight, about 268MB for this ~67M-parameter sentiment model.
// Note the contrast with lesson 3 of this module: TFJS saves models to
// IndexedDB via the indexeddb:// scheme; Transformers.js uses a different
// browser store entirely.
// Subsequent calls: instant from cache.
const classifier = await pipeline('sentiment-analysis');

const result = await classifier('Starboard array cleared diagnostics ahead of schedule.');
console.log(result);
// [{ label: 'NEGATIVE', score: 0.9759 }]
// Good news, labeled NEGATIVE at high confidence. That is not a bug,
// and the last section of this lesson says what it is.

// Batch inference: pass an array.
const reports = [
  'Sensor array is functioning within tolerance.',
  'Catastrophic failure on the port-side coupling.',
  'Signal classification: anomalous.',
];
const batched = await classifier(reports);
// [
//   { label: 'POSITIVE', score: 0.9592 },
//   { label: 'NEGATIVE', score: 0.9997 },
//   { label: 'NEGATIVE', score: 0.9987 },
// ]
// Those are the quantized scores. Forcing fp32 gives 0.9117, 0.9997
// and 0.9984 on the same three lines: the scores move, the labels
// do not. Every score here was recorded on @huggingface/transformers
// 3.8.1 with the default model, run at dtype 'q8' (what the browser
// picks) and at 'fp32'. Read the q8 numbers loosely: int8 arithmetic
// shifts with the runtime that executes it, and the first batch score
// lands between 0.93 and 0.96 depending on the build, while the fp32
// scores match to six decimals across runtimes.`}
</CodeBlock>

## Tasks the Pipeline Handles Out of the Box

```
sentiment-analysis          NER (named entities)        question-answering
translation                 summarization               text-generation
image-classification        image-segmentation          image-to-text (caption)
zero-shot-classification    feature-extraction          automatic-speech-recognition
```

Each pipeline is one line. Each downloads a model file the first time and caches it. The library ships ONNX Runtime Web underneath; TFJS is not involved at all when you use Transformers.js.

That is also the seam between this path and the rest of the ship's work. A Transformers.js model runs as ONNX, so the TFJS tooling does not reach it: no walk over `model.layers`, no quantization flags on `tensorflowjs_converter`. Using those on a pretrained model means re-exporting it to TFJS layers first. DEEP SCAN was trained in TFJS and stays there.

Aboard the Archimedes the download comes from the ship's mirrored model archive, synced at the last relay pass; the live Hub is eleven light-minutes of latency away on a good day. The cache math is the same either way: one download, and every later call reads the copy already in the browser.

## When NOT to Use Transformers.js

- **Your task is not in the standard list.** A custom regression on sensor readings has no pretrained pipeline. Train your own with TFJS.
- **Bandwidth-sensitive users.** A 200MB model on a 3G connection is a UX failure. Inspect model sizes at [huggingface.co/models](https://huggingface.co/models) before committing.
- **Strict latency budgets on cold start.** First-call latency includes model download. Pre-warm via service worker if you need cold-start guarantees.
- **You need fine-tuning.** Transformers.js runs models, it doesn't train them. Fine-tune in Python, export to ONNX, ship via Transformers.js.
- **Your text does not look like the model's training text.** `pipeline('sentiment-analysis')` defaults to `Xenova/distilbert-base-uncased-finetuned-sst-2-english`, fine-tuned on SST-2 review sentences, and the crew's reports are operational logs. The runs above already show the cost. `Signal classification: anomalous.` came back NEGATIVE at 0.9987, and `Starboard array cleared diagnostics ahead of schedule.` came back NEGATIVE at 0.9759. One neutral line, one report of good news, both NEGATIVE above 0.97, and nothing threw. It is the failure mode lesson 4 gave you for mismatched preprocessing, arriving through the text instead. Label twenty real reports by hand and compare before you put the pipeline in front of Mirza.

## Challenge

The exercise injects pipeline output. It checks task selection and result handling without downloading pretrained weights. Actual download size, browser operator support and whether the model suits your text still require a real-model evaluation.

Sort the crew's status reports by classifier confidence. The harness stands in for the Transformers.js loader, so what you write is the call and the wiring around it: name the task, load it once, classify the whole batch in one call, sort by score. The names it takes, spelled the way the library spells them: `sentiment-analysis`, `ner`, `question-answering`, `translation`, `summarization`, `text-generation`, `image-classification`, `image-segmentation`, `image-to-text`, `zero-shot-classification`, `feature-extraction`, `automatic-speech-recognition`. These reports are text, which rules out the image and audio jobs. Of the text jobs, one takes nothing but the text and answers with a label and a confidence; the others answer with generated text, spans, vectors, or scores over candidate labels you have to supply yourself.
