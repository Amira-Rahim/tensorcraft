A 220× spread on identical code, and the only variable is which engine TF.js lands on. Installation is the part you already know; the new concept is **backends**: in the browser TF.js runs on WebGL (GPU), WebAssembly (CPU, optimized), or plain JavaScript (CPU, slow). On Node it binds to native TensorFlow instead (`@tensorflow/tfjs-node`), a separate package behind the same API.

## Backends: The Runtime Engine

Think of backends like rendering engines in browsers. Chrome uses Blink, Firefox uses Gecko: same web pages, different performance. TF.js backends work the same way:

<CodeBlock language="typescript" title="backends.ts">
{`import * as tf from '@tensorflow/tfjs';

// WebGL backend: uses the GPU via WebGL shaders
// Best for: most models, especially matrix-heavy operations
// Like using CSS transforms (GPU-accelerated) instead of top/left (CPU)
import '@tensorflow/tfjs-backend-webgl';

// WASM backend: compiled C++ running in WebAssembly
// Best for: smaller models, devices without good GPU, SIMD support
// Like using a Web Worker for heavy computation
import '@tensorflow/tfjs-backend-wasm';
import { setWasmPaths } from '@tensorflow/tfjs-backend-wasm';
setWasmPaths('/wasm/');  // point to your WASM binary files

// CPU backend: pure JavaScript, no acceleration
// Best for: nothing in production (fallback only)
// Like doing layout calculations in JS instead of CSS

// WebGPU backend: the compute-first successor to WebGL, fastest where
// the browser ships it (Chromium everywhere, Safari 26, and Firefox on
// Windows with macOS and Linux still behind a flag). Feature-detect with
// navigator.gpu rather than assuming, the way the ladder below does
// Like moving from canvas hacks to a purpose-built compute API
import '@tensorflow/tfjs-backend-webgpu';

// Newest first, WASM above the plain CPU kernels (lesson 5 ships on WASM),
// and fall through on both ways a rung can fail. A name that was never
// registered makes tf.setBackend throw; a registered backend that cannot
// START (a lost GPU context, a blocked WebGPU adapter) makes it resolve
// false instead of throwing. Ignore the boolean and the page runs
// somewhere else while your code believes it is on webgpu.
const ladder = navigator.gpu
  ? ['webgpu', 'webgl', 'wasm', 'cpu']
  : ['webgl', 'wasm', 'cpu'];
for (const name of ladder) {
  try {
    if (await tf.setBackend(name)) break;
  } catch {
    // not registered on this page: try the next rung
  }
}
await tf.ready();

// Or let TF.js choose. Its rule: the registered backend with the highest
// priority wins, webgpu (3) first, then webgl and wasm, which are BOTH
// registered at priority 2, so that tie goes to whichever package the page
// imported first, then cpu (1). The tie is why the ladder above is worth
// writing: a page that imports the wasm backend before the webgl one gets
// wasm on a machine with a perfectly good GPU, and nothing warns you.`}
</CodeBlock>

## Benchmarking Your Setup

Nazari would benchmark everything. You should too.

<CodeBlock language="typescript" title="benchmark.ts">
{`import * as tf from '@tensorflow/tfjs';

async function benchmarkBackend(backendName: string) {
  await tf.setBackend(backendName);
  await tf.ready();

  // Warm up: first operation is always slow (shader compilation for WebGL).
  // tf.tidy() frees everything the callback allocated, transpose included.
  // Disposing the matMul result and the input by hand misses that
  // intermediate: 1 tensor and 40,000 bytes still live afterwards.
  tf.tidy(() => {
    const w = tf.randomNormal([100, 100]);
    tf.matMul(w, w.transpose());
  });

  // Benchmark: matrix multiply (the core ML operation)
  const a = tf.randomNormal([256, 256]);
  const b = tf.randomNormal([256, 256]);

  const start = performance.now();
  let checksum: tf.Tensor | null = null;
  for (let i = 0; i < 100; i++) {
    const result = tf.matMul(a, b);
    if (i === 99) checksum = result;
    else result.dispose();  // always dispose to prevent memory leaks
  }
  // CRITICAL: read a result back before stopping the clock. GPU backends
  // queue kernels asynchronously; dispose() does not flush the queue, so
  // without this await you are timing how fast you can ENQUEUE work, not
  // how fast the GPU does it.
  await checksum!.data();
  const elapsed = performance.now() - start;

  checksum!.dispose();
  a.dispose();
  b.dispose();

  console.log(\`\${backendName}: \${(elapsed / 100).toFixed(2)}ms per matmul\`);
  // Representative shape (exact numbers vary by machine):
  // webgpu: fastest where available
  // webgl:  fast (GPU-accelerated)
  // wasm:   ~5-10x slower (SIMD-optimized CPU)
  // cpu:    slowest (pure JS)
}`}
</CodeBlock>
