ONNX (Open Neural Network Exchange) is ML's attempt at a web standard: a shared format that any compliant runtime can execute, regardless of which framework trained the model. It carries the same fine print every web standard does: "universal" means "universal where implemented."

// npm install onnxruntime-web
import * as ort from 'onnxruntime-web';

// Load an ONNX model (exported from PyTorch, TF, sklearn, etc.)
const session = await ort.InferenceSession.create('/models/deep-scan.onnx', {
  executionProviders: ['wasm'],  // 'wasm', or 'webgpu' for GPU (ORT
                                 // Web's WebGL EP is legacy)
});

// Check model inputs/outputs, like inspecting an API schema
console.log('Inputs:', session.inputNames);    // ['input']
console.log('Outputs:', session.outputNames);  // ['output']

// Create input tensor
const inputData = new Float32Array([0.5, 0.3, 0.7]);  // normalized signal
const inputTensor = new ort.Tensor('float32', inputData, [1, 3]);

// Run inference
const results = await session.run({ input: inputTensor });
const output = results.output;
console.log('Prediction:', output.data[0]);  // 0.847`}

## TF.js vs ONNX Runtime: Head-to-Head

<CodeBlock language="typescript" title="benchmark-comparison.ts">
{`import * as tf from '@tensorflow/tfjs';
import * as ort from 'onnxruntime-web';

interface BenchmarkResult {
  runtime: string;
  coldStartMs: number;
  avgInferenceMs: number;
  memoryMB: number;
}

// Benchmark TensorFlow.js
async function benchmarkTFJS(): Promise<BenchmarkResult> {
  const t0 = performance.now();
  const model = await tf.loadLayersModel('/models/deep-scan/model.json');
  const coldStartMs = performance.now() - t0;

  // Warm up
  const warmup = tf.tensor2d([[0.5, 0.3, 0.7]]);
  (model.predict(warmup) as tf.Tensor).dispose();
  warmup.dispose();

  // Sustained inference (100 iterations)
  const times: number[] = [];
  for (let i = 0; i < 100; i++) {
    const start = performance.now();
    const out = tf.tidy(() => {
      const input = tf.tensor2d([[Math.random(), Math.random(), Math.random()]]);
      return model.predict(input) as tf.Tensor;
    });
    // Read the result back INSIDE the timed region. WebGL queues kernels
    // asynchronously; without this await the clock measures enqueue time,
    // not execution time, and the "benchmark" flatters the GPU.
    await out.data();
    out.dispose();
    times.push(performance.now() - start);
  }

  return {
    runtime: 'TF.js (WebGL)',
    coldStartMs,
    avgInferenceMs: times.reduce((a, b) => a + b, 0) / times.length,
    memoryMB: tf.memory().numBytes / 1e6,  // 1e6 for MB, not 1024*1024 (MiB)
  };
}

// benchmarkONNX() is the SAME harness with three lines changed:
//
//   load:   await ort.InferenceSession.create('/models/deep-scan.onnx')
//           replaces tf.loadLayersModel(...)
//   input:  new ort.Tensor('float32', new Float32Array([...]), [1, 3])
//           replaces the tf.tensor2d call inside tf.tidy
//   run:    await session.run({ input }) replaces model.predict plus the
//           explicit readback await; session.run resolves when compute
//           finishes, and ORT Web's JS tensors are garbage-collected,
//           so the dispose bookkeeping goes too
//
// Everything else (warm-up, the 100-iteration loop, the averaging, the
// result shape with runtime: 'ONNX (WASM)') stays byte-identical. In a
// benchmark, any difference outside the thing being measured
// contaminates the measurement.

// Typical results for a small signal classifier (readback included,
// exact numbers vary by machine):
// TF.js (WebGL):  cold=340ms, inference=2.1ms, mem=0.8MB
// ONNX (WASM):    cold=180ms, inference=3.8ms, mem=1.2MB`}
</CodeBlock>

## When to Choose Which

| Factor | TF.js | ONNX Runtime Web |
|--------|-------|-------------------|
| **Ecosystem** | Largest, most tutorials | Growing fast |
| **GPU acceleration** | WebGL (mature) + WebGPU (fastest, Chromium) | WebGPU (its primary GPU path) |
| **Python interop** | Export from TF/Keras | Any framework via ONNX export |
| **Cold start** | Slower (WebGL shader compilation) | Faster (WASM) |
| **Sustained speed** | Faster (GPU shaders cached) | Good (SIMD-optimized WASM) |
| **Memory management** | Manual (tf.tidy/dispose) | Automatic (GC) |
| **Bundle size** | ~800KB JS | ~600KB JS + multi-MB `ort-wasm*.wasm` fetched at runtime |

For DEEP SCAN: TF.js wins on sustained inference (the dashboard runs continuously). ONNX wins on cold start (backup system that loads on demand). Nazari ships both, each where its cost shape wins.
