You have made this call before: does the work happen on the server or on the client? On the web it shows up as server-side vs client-side rendering, and the tradeoffs are the same: where does the computation happen, and what do you gain or lose by moving it to the client?

TensorFlow.js is not browser-only. `@tensorflow/tfjs-node` binds the same API to the native TensorFlow build and runs on a server, typically faster than any browser backend. This module goes to the browser because that is where DEEP SCAN has to land: the bridge dashboard, on the consoles the crew already reads.

## Where Inference Runs: Server or Client

<BridgeCallout bridge={frontmatter.concept.bridge} />

ML inference splits along the same line, with the same stakes of performance, privacy, and user experience:

<CodeBlock language="typescript" title="inference-comparison.ts">
{`// SERVER-SIDE INFERENCE, like SSR
// Data leaves the device, hits a server, waits for response
// (the server can be Node running this same model via @tensorflow/tfjs-node)
async function serverInference(signalData: number[]) {
  const response = await fetch('/api/classify', {
    method: 'POST',
    body: JSON.stringify({ signal: signalData }),
  });
  return response.json(); // { class: 'anomaly', confidence: 0.94 }
}

// CLIENT-SIDE INFERENCE, like CSR
// Data never leaves the browser. Model runs locally.
async function clientInference(signalData: number[]) {
  const inputTensor = tf.tensor2d([signalData]);
  const prediction = model.predict(inputTensor) as tf.Tensor;
  const result = await prediction.array();
  inputTensor.dispose();
  prediction.dispose();
  const p = result[0][0];   // sigmoid output: P(anomaly)
  // Confidence reports the verdict, not the raw sigmoid: p = 0.12 is
  // "noise, 0.88 confident". Lesson 4 builds this pipeline properly.
  return { class: p > 0.5 ? 'anomaly' : 'noise', confidence: p > 0.5 ? p : 1 - p };
}`}
</CodeBlock>

**When to choose client-side inference:**

| Factor | Server (SSR) | Browser (CSR) |
|--------|-------------|---------------|
| **Latency** | Network round-trip (50-500ms) | Local compute only (under 5ms for this model, benchmarked in lesson 5) |
| **Privacy** | Data leaves device | Data stays local |
| **Offline** | Requires connection | Works offline |
| **Model size** | Unlimited | ~50MB budget for this dashboard's cold load (lesson 6 ships 50-500MB models when the download itself is the product) |
| **Compute** | GPU clusters available | Device CPU/GPU only |
| **Cold start** | Warm server | Model must download first |

Nazari is right, though not because one round-trip misses the budget: a 180-millisecond hop to the ship's compute bay fits inside a second easily. Her objection is that the dashboard would then depend on that link staying up, reading after reading, for every hour of every watch.

## The Cost of Client-Side ML

Moving the computation client-side doesn't erase its costs; it changes their currency:

<CodeBlock language="typescript" title="browser-constraints.ts">
{`// Memory: browser tabs typically have 1-4GB limit
// A model with 10M parameters at float32 = 40MB just for weights:
// 10,000,000 x 4 bytes / 1e6 = 40 exactly. (Divide by 1e6, not
// 1024*1024: that gives 38.1 MiB, a different unit wearing MB's name.)
const modelSizeMB = (parameterCount * 4) / 1e6;
console.log(\`Model size: \${modelSizeMB}MB\`);

// Cold start: model must be downloaded and initialized
// This is like the "time to interactive" metric in the browser
const t0 = performance.now();
const model = await tf.loadLayersModel('/models/deep-scan/model.json');
const coldStartMs = performance.now() - t0;
console.log(\`Cold start: \${coldStartMs}ms\`);  // 200-2000ms depending on model

// Inference budget: 60fps = 16ms per frame
// Signal processing at 1Hz = 1000ms budget (comfortable)
// Real-time audio at 44.1kHz = 0.023ms budget (very tight)
const inferenceStart = performance.now();
const output = model.predict(input) as tf.Tensor;
await output.data();  // GPU kernels are queued; read a result back or you time the queue
const inferenceMs = performance.now() - inferenceStart;
output.dispose();
console.log(\`Inference: \${inferenceMs}ms\`);  // 0.9ms on WASM, 2.4ms on WebGL`}
</CodeBlock>

The good news: DEEP SCAN processes signals at 1Hz. With a 1000ms budget per inference, browser ML is more than fast enough.
