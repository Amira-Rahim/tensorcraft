Monitoring works the same way whatever you ship. You pick a budget for the numbers you care about: for example, Largest Contentful Paint under 2.5s in a browser or p99 response time under 200ms on a Node service. A measured baseline tells you how the system currently behaves; the budget sets what you will accept. Then you alert when a value drifts past it. Anomaly detection makes the same move: define what "normal" looks like, then flag whatever lands outside it.

You will define a baseline for normal readings and use z-scores to flag readings outside it.

## Modeling Normality

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="baseline-stats.ts">
{`// Step 1: Define "normal" from known-good data
// Like establishing performance baselines before deploying a change

interface SignalStats {
  mean: number;
  std: number;
  p5: number;   // 5th percentile
  p95: number;  // 95th percentile
}

function computeBaseline(normalAmplitudes: number[]): SignalStats {
  if (!normalAmplitudes.length || !normalAmplitudes.every(Number.isFinite)) {
    throw new Error('Expected finite, nonempty baseline readings');
  }
  const sorted = [...normalAmplitudes].sort((a, b) => a - b);
  const n = sorted.length;
  const mean = normalAmplitudes.reduce((s, v) => s + v, 0) / n;
  const std = Math.sqrt(normalAmplitudes.reduce((s, v) => s + (v - mean) ** 2, 0) / n);

  return {
    mean,
    std,
    p5: sorted[Math.ceil(n * 0.05) - 1], // nearest-rank percentiles
    p95: sorted[Math.ceil(n * 0.95) - 1],
  };
}

// Step 2: Flag deviations
function isAnomaly(value: number, baseline: SignalStats, sigmas: number = 3): boolean {
  if (![value, baseline.mean, baseline.std, sigmas].every(Number.isFinite) || baseline.std < 0 || sigmas < 0) {
    throw new Error('Invalid reading or threshold');
  }
  if (baseline.std === 0) return value !== baseline.mean; // exact-reading policy
  const zScore = Math.abs(value - baseline.mean) / baseline.std;
  return zScore > sigmas;  // beyond 3 standard deviations = anomaly
}

// Worked example using the mission's fictional baseline, not measured data.
// For your own detector, computeBaseline takes reviewed training rows only.
const baseline = { mean: 0.52, std: 0.15, p5: 0.28, p95: 0.76 };

console.log(isAnomaly(0.55, baseline));  // false: normal
console.log(isAnomaly(1.00, baseline));  // true: 3.2 sigmas, the most a spike can score
console.log(isAnomaly(0.00, baseline));  // true: 3.47 sigmas, the far end of the scale`}
</CodeBlock>

Amplitude arrives here already normalized: module 4 divides the hull sensor's count by its 2048-count full scale, so no reading can come in above 1.00. Against mean 0.52 and std 0.15, a channel pegged at full scale is 3.2 sigma out. A dead channel reading 0.00 is 3.47 sigma, and nothing on this feature reads past those two ends. The gate at 3 sigma therefore fires on amplitudes above 0.97 or below 0.07, the top three and the bottom seven hundredths of the 0-to-1 scale. That is a slice of the scale, not a flag rate. Measure the false-alarm rate on separate, reviewed normal readings. A bounded sensor distribution is not exactly Gaussian. The sigma count stays small however loud the event is. If a sigma count above 3.47 turns up on this feature, look for a units bug before you believe the reading.

<DerivationDrawer summary="When does a 3-sigma cutoff imply a probability?">
A z-score measures distance in units of standard deviation. Computing it does not require a Gaussian distribution. The claim that about 0.27% of normal readings exceed three sigmas does: it uses a Gaussian population and its true mean and standard deviation. Estimates from a small sample add uncertainty.

The Central Limit Theorem can justify a Gaussian approximation for sums under suitable conditions, such as independent contributions with finite variance. It does not make every sensor's readings Gaussian. Heavy tails, saturation, changing operating conditions and correlated effects can invalidate that approximation.

For a Gaussian channel, a two-sigma gate flags about 4.55% of readings. With 64 such channels the expected count is about 2.9 flags per reading, whether or not the channels are independent. Expectation adds. The probability of no flags is different: about 0.9545^64, or 5.1%, only if flags are independent. Shared disturbances can make flags arrive together, changing that distribution without changing its mean.

Measure both per-channel rates and the distribution of simultaneous flags on representative data before choosing a page policy. A cutoff is a decision rule; it is not a probability attached to an individual alert.
</DerivationDrawer>

## Precision vs Recall

The sigma count is a dial between two kinds of error, both of which you met in module 3's evaluation drawer: false positives (calm readings flagged, the wolf cried) and false negatives (real anomalies missed, the watch asleep). Loosen the dial to 2 sigma and you catch more anomalies at the price of more false alarms; tighten it to 4 and the alarms go quiet along with some of the real events. Nazari wants zero false positives, because each one is investigation time. Farah wants zero false negatives, because the signal is the mission. When the score distributions overlap, no threshold can eliminate both kinds of error. A perfectly separating sample can exist, but does not guarantee perfect future detection. The right one depends on which error costs more, and lesson 4 works that trade through with numbers. The two ratios that score any threshold are module 3's:

<CodeBlock language="typescript" title="precision-recall.ts">
{`interface DetectionResult {
  truePositives: number;   // real anomalies, flagged
  falsePositives: number;  // calm readings, flagged anyway
  falseNegatives: number;  // real anomalies, missed
}

// Of everything flagged, how much was real?
function precision(r: DetectionResult): number | null {
  const n = r.truePositives + r.falsePositives;
  return n === 0 ? null : r.truePositives / n;
}

// Of everything real, how much was flagged?
function recall(r: DetectionResult): number | null {
  const n = r.truePositives + r.falseNegatives;
  return n === 0 ? null : r.truePositives / n;
}`}
</CodeBlock>
