## Modeling Normality

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="baseline-stats.ts">
{`// Step 1: Define "normal" from known-good data
// Like establishing performance baselines before deploying a change

interface SignalStats {
  mean: number;
  std: number;
  p5: number;   // 5th percentile
  p95: number;  // 95th percentile
}

function computeBaseline(normalAmplitudes: number[]): SignalStats {
  const sorted = [...normalAmplitudes].sort((a, b) => a - b);
  const n = sorted.length;
  const mean = normalAmplitudes.reduce((s, v) => s + v, 0) / n;
  const std = Math.sqrt(normalAmplitudes.reduce((s, v) => s + (v - mean) ** 2, 0) / n);

  return {
    mean,
    std,
    p5: sorted[Math.floor(n * 0.05)],
    p95: sorted[Math.floor(n * 0.95)],
  };
}

// Step 2: Flag deviations
function isAnomaly(value: number, baseline: SignalStats, sigmas: number = 3): boolean {
  const zScore = Math.abs(value - baseline.mean) / baseline.std;
  return zScore > sigmas;  // beyond 3 standard deviations = anomaly
}

const baseline = computeBaseline(normalAmplitudes);
console.log('Baseline:', baseline);
// { mean: 0.52, std: 0.15, p5: 0.28, p95: 0.76 }

console.log(isAnomaly(0.55, baseline));  // false: normal
console.log(isAnomaly(1.00, baseline));  // true: 3.2 sigmas, the most a spike can score
console.log(isAnomaly(0.00, baseline));  // true: 3.47 sigmas, the far end of the scale`}
</CodeBlock>

Amplitude arrives here already normalized: module 4 divides the hull sensor's count by its 2048-count full scale, so no reading can come in above 1.00. Against mean 0.52 and std 0.15, a channel pegged at full scale is 3.2 sigma out. A dead channel reading 0.00 is 3.47 sigma, and nothing on this feature reads past those two ends. The gate at 3 sigma therefore fires on amplitudes above 0.97 or below 0.07, the top three and the bottom seven hundredths of the 0-to-1 scale. That is a slice of the scale, not a flag rate: on calm readings the gate fires about a quarter of one percent of the time. The sigma count stays small however loud the event is. If a sigma count above 3.47 turns up on this feature, look for a units bug before you believe the reading.

<DerivationDrawer summary="What the 3-sigma rule assumes, and when it lies">
**The z-score recipe is a stack of probability claims.** Dividing by the standard deviation and comparing to 3 asserts: readings follow a distribution, that distribution is roughly Gaussian (the bell curve), and its tails put probability 0.0027 beyond 3 sigma. The recipe works exactly as far as those claims hold.

**Why Gaussian is a reasonable default:** the Central Limit Theorem. A reading that sums many small independent physical effects gets pushed toward the bell curve no matter what shape the individual parts have. Sensor noise usually qualifies.

**Two standard ways production data breaks it.** Heavy tails: when rare large effects dominate, 3-sigma events stop being rare and the detector cries wolf. Correlation: channels mounted on the same hull move together, so their noise does not average away and the effective spread is wider than any per-channel std reports.

**Per-channel thresholds also compound.** Loosen the dial to 2 sigma and each channel trips 4.6% of the time on calm data. Across 64 channels, a fully dark board then has probability 0.954⁶⁴ ≈ 0.05: the calm state has a few channels lit. On a calm reading, expect about 3 lit channels (64 × 0.046 = 2.9). Both numbers multiply the per-channel rate as if the channels tripped independently, which the paragraph above says hull-mounted channels do not. Correlation leaves that average alone and wrecks the spread around it. Simulate 64 channels that share half their noise variance and the board goes fully dark about a third of the time instead of about 5%. The median calm reading lights 1 channel rather than 3, and one reading in a hundred lights more than 25. So judge the count of lit channels against the expectation, rather than treating each lit channel as its own alarm, and expect that count to swing far wider than 2.9 suggests.
</DerivationDrawer>

## Precision vs Recall

The sigma count is a dial between two kinds of error, both of which you met in module 3's evaluation drawer: false positives (calm readings flagged, the wolf cried) and false negatives (real anomalies missed, the watch asleep). Loosen the dial to 2 sigma and you catch more anomalies at the price of more false alarms; tighten it to 4 and the alarms go quiet along with some of the real events. Nazari wants zero false positives, because each one is investigation time. Farah wants zero false negatives, because the signal is the mission. A threshold that satisfies both does not exist. The right one depends on which error costs more, and lesson 4 works that trade through with numbers. The two ratios that score any threshold are module 3's:

<CodeBlock language="typescript" title="precision-recall.ts">
{`interface DetectionResult {
  truePositives: number;   // real anomalies, flagged
  falsePositives: number;  // calm readings, flagged anyway
  falseNegatives: number;  // real anomalies, missed
}

// Of everything flagged, how much was real?
function precision(r: DetectionResult): number {
  return r.truePositives / (r.truePositives + r.falsePositives);
}

// Of everything real, how much was flagged?
function recall(r: DetectionResult): number {
  return r.truePositives / (r.truePositives + r.falseNegatives);
}`}
</CodeBlock>
