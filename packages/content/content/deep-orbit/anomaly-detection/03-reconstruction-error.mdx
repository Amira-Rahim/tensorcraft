The autoencoder learns patterns from normal signals. Its error score measures how well it rebuilds each reading. You get one number per reading, so Farah's question still needs a separate check: which feature contributed most?

You will measure reconstruction error and inspect which features contributed to a missed anomaly.

## Measure the reconstruction error

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="reconstruction-error.ts">
{`import * as tf from '@tensorflow/tfjs';

// Compute reconstruction error for each sample
function computeAnomalyScores(
  autoencoder: tf.LayersModel,
  signals: tf.Tensor2D,
): number[] {
  return tf.tidy(() => {
    const reconstructed = autoencoder.predict(signals) as tf.Tensor2D;
    // Average the squared differences across features to get one MSE per sample.
    // Unlike git diff, this score does not identify individual changes.
    // It combines all eleven features into one number.
    const errors = tf.mean(tf.square(tf.sub(signals, reconstructed)), 1);
    return Array.from(errors.dataSync());
  });
}

// Tiny helper for the printouts below (Math has no built-in mean)
const mean = (xs: number[]) => xs.reduce((a, b) => a + b, 0) / xs.length;

// Integration sketch: supply the fitted autoencoder and separate,
// normalized normalTestData and anomalousData tensors. Caller owns them.
const normalScores = computeAnomalyScores(autoencoder, normalTestData);
console.log('Normal, mean error:', mean(normalScores));
console.log('Normal, max error:', Math.max(...normalScores));

// Anomalous signal: high reconstruction error
const anomalyScores = computeAnomalyScores(autoencoder, anomalousData);
console.log('Probe, error:', anomalyScores[0]);
// The story's normal maximum 0.5 and probe score 6.2 are fictional.
// Your fitted model will produce its own scores; no ratio is guaranteed.`}

## A Detector Can Miss

Consider an encoder that keeps only the first coordinate and a decoder that puts zero back in the second. Even if normal training inputs had their first coordinate between -1 and 1, this mapping also reconstructs a distant input exactly.

<CodeBlock language="javascript" title="reconstruction-counterexample.js">
{`const encode = ([x, y]) => x;
const decode = (x) => [x, 0];
const mse = (input) => {
  const rebuilt = decode(encode(input));
  return input.reduce((sum, value, i) => sum + (value - rebuilt[i]) ** 2, 0) / input.length;
};
const distantAnomalyError = mse([1000, 0]); // 0: missed despite its distance
const ordinaryNoisyError = mse([0, 0.2]);  // 0.02: an ordinary sensor variation
// A cutoff of 0.01 misses the anomaly and flags the ordinary variation.`}
</CodeBlock>

This is a constructed mapping, not a trained benchmark. It disproves the guarantee that an unseen input must reconstruct badly. The incident exercise below asks you to inspect a detector that missed a confirmed anomaly.

## Check the error for each feature

<CodeBlock language="typescript" title="feature-errors.ts">
{`import * as tf from '@tensorflow/tfjs';

// Which features contribute most to the anomaly?
// This map is Farah's actual answer, and she wants it computed
// before she signs off on any alert.
function featureErrors(
  autoencoder: tf.LayersModel,
  signal: tf.Tensor2D,
  featureNames: string[],
): { feature: string; error: number }[] {
  return tf.tidy(() => {
    const reconstructed = autoencoder.predict(signal) as tf.Tensor2D;
    const errors = tf.square(tf.sub(signal, reconstructed));
    const perFeature = errors.arraySync()[0] as number[];

    return featureNames.map((name, i) => ({
      feature: name,
      error: perFeature[i],
    })).sort((a, b) => b.error - a.error);
  });
}

const analysis = featureErrors(autoencoder, anomalyTensor, [
  'amplitude', 'frequency', 'phase',
  'fft_0', 'fft_1', 'fft_2', 'fft_3', 'fft_4', 'fft_5', 'fft_6', 'fft_7',
]);

console.log('Top contributors:');
// Fictional mission output, not values produced by the code above:
// fft_5: 64.12  ← the 72 Hz-centered bin nearest the 73.4 Hz component, 90x the amplitude row
// fft_6: 2.89
// amplitude: 0.71
// Everything else: < 0.1
// (these rounded components give a mean near 6.2 across eleven features)

// Even with all eleven inputs z-scored to mean 0 and std 1, their
// normal reconstruction errors can differ. A feature that is hard to
// rebuild may rank highly on normal readings too. Compare each error
// with that feature's usual normal error before interpreting the ranking.
function relativeFeatureErrors(
  autoencoder: tf.LayersModel,
  signal: tf.Tensor2D,
  normalData: tf.Tensor2D,
  featureNames: string[],
): { feature: string; ratio: number }[] {
  if (signal.shape[0] !== 1 || normalData.shape[0] === 0 || featureNames.length !== signal.shape[1]) {
    throw new Error('Expected one probe and a nonempty baseline with matching features');
  }
  return tf.tidy(() => {
    const perFeature = tf.square(
      tf.sub(signal, autoencoder.predict(signal) as tf.Tensor2D),
    );
    const normalPerFeature = tf.mean(
      tf.square(tf.sub(normalData, autoencoder.predict(normalData) as tf.Tensor2D)),
      0,
    );
    // Explicit regularization: cap amplification of near-zero baseline error.
    // Inspect those features separately; this epsilon depends on score units.
    const ratios = tf.div(perFeature, tf.maximum(normalPerFeature, 1e-8)).arraySync()[0] as number[];
    return featureNames
      .map((name, i) => ({ feature: name, ratio: ratios[i] }))
      .sort((a, b) => b.ratio - a.ratio);
  });
}
// The incident exercise uses absolute errors and matching absolute-error
// baselines. This example uses squared errors in both parts of the ratio.
`}
</CodeBlock>

Squared errors show how much each feature adds to MSE. Error ratios show how large each error is compared with its usual size. Check both, but remember that neither tells you the physical cause. The incident exercise uses absolute errors rather than squared errors. Compare them with absolute-error baselines so the units match.
