Gzip reconstructs the original bytes exactly. An autoencoder learns a compressed representation and tries to rebuild the input from it. A narrow bottleneck encourages it to use regularities in the training examples. We measure the difference between input and reconstruction as an anomaly score.

That score is a heuristic, a rule we must test on data. The bottleneck does not guarantee that unfamiliar inputs reconstruct badly. Normal inputs can also reconstruct poorly if the model has not learned their variation. Evaluate both misses and false alarms before using the score to wake anyone.

## Encoder → Bottleneck → Decoder

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="autoencoder.ts">
{`import * as tf from '@tensorflow/tfjs';

// Build an autoencoder for signal anomaly detection
const inputDim = 11;  // 3 raw features + 8 FFT features

// ENCODER: compress 11 features → 4 (the bottleneck)
const encoder = tf.sequential();
encoder.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [inputDim] }));
encoder.add(tf.layers.dense({ units: 16, activation: 'relu' }));
encoder.add(tf.layers.dense({ units: 4, activation: 'relu' }));  // bottleneck

// DECODER: reconstruct 4 → 11
const decoder = tf.sequential();
decoder.add(tf.layers.dense({ units: 16, activation: 'relu', inputShape: [4] }));
decoder.add(tf.layers.dense({ units: 32, activation: 'relu' }));
decoder.add(tf.layers.dense({ units: inputDim }));  // reconstruct original

// Full autoencoder: input → encoder → decoder → reconstruction
// (a model is a layer in TFJS, so the two halves stack directly)
const autoencoder = tf.sequential();
autoencoder.add(encoder);  // 11 → 4
autoencoder.add(decoder);  // 4 → 11

// Keeping the halves as their own models pays off later:
// encoder.predict(signal) lets you inspect the 4-number bottleneck directly

// Train to reconstruct its own input: input = label
autoencoder.compile({ optimizer: 'adam', loss: 'meanSquaredError' });`}
</CodeBlock>

Those eleven numbers describe one extraction window, not a whole archive capture. In the archive a capture is the 33-second block, 256 Hz across 64 channels; the window is 64 consecutive samples of one channel, a quarter of a second. Lesson 5 uses the same word for the window whose eleven features the autoencoder rebuilds, and the number beside it says which is meant. Two different 64s: samples here, hull sensors in lesson 1's drawer. The difference decides how much of a training set a recurring event touches. The pulse DEEP SCAN hunts comes back on its 73.4-second clock, so it lands in nearly half the 33-second captures and in about one quarter-second window in seventy, the 412 rows of 28,800 the epilogue below counts.

## Training on Normal Data Only

<CodeBlock language="typescript" title="training.ts">
{`import * as tf from '@tensorflow/tfjs';

// KEY INSIGHT: train ONLY on normal signals
// The autoencoder learns to compress and reconstruct normal patterns
// Some anomalies may still reconstruct well; test for those misses

// normalSignals: shape [1000, 11]: 1000 normal signal readings. A reduced
// demo slice: the epoch lines below are its numbers, not the ship's own fit
// over the eleven days of archive.
const history = await autoencoder.fit(normalSignals, normalSignals, {
  epochs: 100,
  batchSize: 32,
  validationSplit: 0.2,
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      if (epoch % 20 === 0) {
        console.log(
          \`Epoch \${epoch}: loss=\${logs?.loss.toFixed(6)} \` +
          \`val_loss=\${logs?.val_loss.toFixed(6)}\`
        );
      }
    },
  },
});
// Epoch 0:  loss=1.002725 val_loss=0.906331
// Epoch 20: loss=0.132932 val_loss=0.139485
// Epoch 40: loss=0.116131 val_loss=0.127430
// Epoch 60: loss=0.110304 val_loss=0.124273
// Epoch 80: loss=0.107359 val_loss=0.120210
// (the % 20 callback prints epochs 0 through 80; with epochs: 100 the
// loop ends after epoch 99, so no line for 100 ever appears)

// Epoch 0 is the no-information baseline, not a first guess that happens
// to be poor. Module 5 z-normalized all eleven features to mean 0 and
// std 1, so a model answering zero for every feature scores a squared
// error near 1.0. The number tfjs prints for epoch 0 is the average
// across that epoch's 25 batches, and 25 updates do not move an untrained
// network far off that. Every row below it is the model beating the
// baseline.

// Read the val_loss column. validationSplit holds back the last 200 of
// these readings and the model never fits them, so val_loss is the only
// number here that says anything about readings it has not seen. Above,
// val_loss runs 5% to 13% above loss from epoch 20 on, which is
// what a model that learned the structure looks like. Loss falling while
// val_loss stalls several times higher is the other outcome: the model
// memorized the 800 rows it trained on. That autoencoder scores its own
// training normals low and every unseen calm reading high, so it
// manufactures false alarms instead of finding anomalies.`}
</CodeBlock>
