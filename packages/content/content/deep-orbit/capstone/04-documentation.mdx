## Model Card

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="model-card.ts">
{`// A Model Card is structured documentation for an ML model
// Think of it as package.json + README + CHANGELOG for your model

interface ModelCard {
  name: string;
  version: string;
  description: string;
  author: string;

  // Training details
  training: {
    dataset: string;
    datasetSize: number;
    features: string[];
    trainTestSplit: string;
    epochs: number;
    optimizer: string;
  };

  // Performance metrics
  performance: {
    accuracy: number;
    benchmarkedOn: string;   // which evaluation produced the number above
    precision: number;
    recall: number;
    f1Score: number;
    inferenceMs: number;   // the classifier alone
    pipelineMs: number;    // the whole classify() call, end to end
    weightBytes: number;    // this model's weight file
    bundleSizeMB: number;   // everything the dashboard downloads to run it
  };

  // What the model cannot do
  limitations: string[];

  // How to use it
  usage: {
    inputFormat: string;
    outputFormat: string;
    exampleCode: string;
  };
}

const deepScanCard: ModelCard = {
  name: 'DEEP SCAN Signal Classifier',
  version: '1.0.0',
  description: 'Classifies deep space radio signals into 5 categories: pulsar, quasar, noise, interference, anomaly.',
  author: 'Ensign Demir, Archimedes',

  training: {
    dataset: 'Sector 7-G Signal Archive (11 days, one reading per 33-second window)',
    datasetSize: 28_800,
    features: ['amplitude', 'zeroCrossings', 'phase', 'FFT bin magnitudes (8 fixed bins)'],
    trainTestSplit: '80/10/10 (train/val/test)',
    epochs: 50,
    optimizer: 'Adam (lr=0.001)',
  },

  performance: {
    accuracy: 0.918,
    benchmarkedOn: 'the pruning review holdout',
    precision: 0.92,
    recall: 0.91,
    f1Score: 0.915,
    inferenceMs: 0.035,  // the eleven-feature classifier alone at the dashboard station, one
                         // backend, readback inside the clock (module 10)
    pipelineMs: 5,       // the whole classify() call on WebGPU, 15 on WebGL: feature extraction,
                         // the classifier and the readback, which is what the monitor times
    weightBytes: 3_988,  // measured off weights.bin, not estimated: 997 float32
    bundleSizeMB: 85,    // the whole download, quantized: this classifier
                         // plus the pretrained language component
  },

  limitations: [
    'Trained on Sector 7-G captures only; accuracy may drop in other sectors',
    'Anomaly class has lowest recall: 21 of the 25 labelled anomalies in the holdout, 84%; rare signals may be misclassified as noise',
    'Requires exactly 64 samples per capture (0.25 seconds of one channel at 256 Hz); the 8 FFT bins and the zero-crossing scale are defined at that length, so shorter bursts cannot be classified',
    'WebGPU backend required for the 5 ms end-to-end path; the pipeline falls back to 15 ms on WebGL. The classifier itself was timed in microseconds on one backend, which is not a figure for all of them',
    'Not validated on signals below -20 dB SNR (signal-to-noise ratio; the signal is one tenth the amplitude of the noise)',
  ],

  usage: {
    inputFormat: 'Float32Array of exactly 64 raw signal samples; the pipeline extracts the 11 features and applies the saved training statistics itself',
    outputFormat: '{ label: string, confidence: number, isAnomaly: boolean }',
    exampleCode: 'const result = await deepScan.classify(signalData);',
  },
};`}
</CodeBlock>

Two sizes and two latencies, because each pair answers two questions. `weightBytes` is this model's own
weight file, and it is 3,988 bytes: the 997 float32 weights of the eleven-feature, five-class network module 10 retrained. `bundleSizeMB` is everything the bridge
dashboard downloads before it can classify anything, and almost none of that is
the classifier. The mass is the pretrained language component behind the report
pipeline, which is what the optimization sprint in module 10 was actually
measuring. Write the bundle figure on the classifier's card and the next person
who reads it optimizes the wrong network. The latencies split the same way: `inferenceMs` is the classifier alone, 0.035 ms with the readback inside the clock, the figure module 10's cache ledger was built on. `pipelineMs` is the whole `classify()` call the bridge dashboard makes, feature extraction and readback included, 5 ms on WebGPU and 15 on WebGL, which is what lesson 3's monitor times. Put the 5 on the classifier's line and someone will one day spend a week trying to make a microsecond call faster.

The input contract is worth reading twice, because two different 64s run through
this course. An archive row is a 33-second capture, 256 Hz across 64 channels:
540,672 samples, a little over two megabytes at float32. The classifier's input is
a 64-sample window taken from one of those channels, a quarter of a second at
256 Hz. That window length sets the rest of the contract: 8 FFT bins 4 Hz wide,
and a zero-crossing count that cannot exceed 63. Both numbers are real. Neither
one is the other.

<Epilogue>

The runbook's first draft comes together in the dead hours of the night watch, and its single assigned reviewer returns comments within ninety seconds.

<Dialogue speaker="ARIA" expression="deadpan">
Three of the four procedures parse as condition and action. The first instructs the operator to retrain "if drift is high." I do not have an intuition for "high." I have thresholds. Please provide one.
</Dialogue>

Demir does not pick a number. He goes and measures one: score drift over 180 fixed 100-sample windows from the calm week before deployment, then read the 99th percentile off that distribution. It lands at 0.5. The rewritten procedure carries the window size with it. On calm data the distance between two sample means shrinks as the windows grow, and the same detector sits near 0.22 on a 500-sample window. The entry reads: drift above 0.5 on a 100-sample window, hand-label a hundred recent captures, retrain. The finished document reads less like documentation and more like a will, which he supposes is the point: if he is not here to run DEEP SCAN, this is the part of him that is. He signs it at an interval reading of 31.6 seconds, because ARIA timestamps reviews in pulses now, the way other systems use dates. Tomorrow they deploy.

</Epilogue>
