{`// A Model Card is structured documentation for an ML model
// Think of it as package.json + README + CHANGELOG for your model

interface ModelCard {
  name: string;
  version: string;
  description: string;
  author: string;

  // Training details
  training: {
    dataset: string;
    datasetSize: number;
    features: string[];
    trainTestSplit: string;
    epochs: number;
    optimizer: string;
  };

  // Performance metrics
  performance: {
    accuracy: number;
    benchmarkedOn: string;   // which evaluation produced the number above
    precision: number;
    recall: number;
    f1Score: number;
    inferenceMs: number;
    modelSizeMB: number;
  };

  // What the model cannot do
  limitations: string[];

  // How to use it
  usage: {
    inputFormat: string;
    outputFormat: string;
    exampleCode: string;
  };
}

const deepScanCard: ModelCard = {
  name: 'DEEP SCAN Signal Classifier',
  version: '1.0.0',
  description: 'Classifies deep space radio signals into 5 categories: pulsar, quasar, noise, interference, anomaly.',
  author: 'Ensign Demir, Archimedes',

  training: {
    dataset: 'Sector 7-G Signal Archive (11 days, one reading per 33-second window)',
    datasetSize: 28_800,
    features: ['amplitude', 'zeroCrossings', 'phase', 'FFT bin magnitudes (8 fixed bins)'],
    trainTestSplit: '80/10/10 (train/val/test)',
    epochs: 50,
    optimizer: 'Adam (lr=0.001)',
  },

  performance: {
    accuracy: 0.918,
    benchmarkedOn: 'the pruning review holdout',
    precision: 0.92,
    recall: 0.91,
    f1Score: 0.915,
    inferenceMs: 5,
    modelSizeMB: 85,   // weights.bin on disk; 42 MB gzipped over the wire
  },

  limitations: [
    'Trained on Sector 7-G captures only; accuracy may drop in other sectors',
    'Anomaly class has lowest recall (84%); rare signals may be misclassified as noise',
    'Requires exactly 64 samples per capture (0.25 seconds of one channel at 256 Hz); the 8 FFT bins and the zero-crossing scale are defined at that length, so shorter bursts cannot be classified',
    'WebGPU backend required for <10ms inference; falls back to 15ms on WebGL',
    'Not validated on signals below -20 dB SNR (signal-to-noise ratio; the signal is one tenth the amplitude of the noise)',
  ],

  usage: {
    inputFormat: 'Float32Array of exactly 64 raw signal samples; the pipeline extracts the 11 features and applies the saved training statistics itself',
    outputFormat: '{ label: string, confidence: number, isAnomaly: boolean }',
    exampleCode: 'const result = await deepScan.classify(signalData);',
  },
};`}

<Epilogue>

The runbook's first draft comes together in the dead hours of the night watch, and its single assigned reviewer returns comments within ninety seconds.

<Dialogue speaker="ARIA" expression="deadpan">
Three of the four procedures parse as condition and action. The first instructs the operator to retrain "if drift is high." I do not have an intuition for "high." I have thresholds. Please provide one.
</Dialogue>

Demir does not pick a number. He goes and measures one: score drift over 180 fixed 100-sample windows from the calm week before deployment, then read the 99th percentile off that distribution. It lands at 0.5. Module 7 computed a percentile the same way and then moved off it, because it had labeled anomalies to sweep against and a false alarm with a price on it. Drift has neither, so the percentile is where this number stops. The rewritten procedure carries the window size with it. On calm data the distance between two sample means shrinks as the windows grow, and the same detector sits near 0.22 on a 500-sample window. The entry reads: drift above 0.5 on a 100-sample window, hand-label a hundred recent captures, retrain. The finished document reads less like documentation and more like a will, which he supposes is the point: if he is not here to run DEEP SCAN, this is the part of him that is. He signs it at an interval reading of 31.6 seconds, because ARIA timestamps reviews in pulses now, the way other systems use dates. Tomorrow they deploy.

</Epilogue>
