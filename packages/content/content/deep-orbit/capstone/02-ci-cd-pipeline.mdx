## ML-Aware CI/CD

One file, three jobs. The first is the web CI Demir already knows.

{`name: DEEP SCAN CI/CD

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

The second job is the ML half, and it runs only if the first one passed. Same file, same `jobs:` block, one level of indentation in.

<CodeBlock language="yaml" title="deploy.yml · jobs.validate-model">
{`  validate-model:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci

      # Model artifacts: the models/ directory, restored from the CI
      # cache, which the training rig seeds after every retrain. Almost
      # all of it is the report pipeline's pretrained language component,
      # 85 MB of weights once the uint8 pass has run and too big for git.
      # The signal classifier ships beside it in the same directory, its
      # own 3,988-byte weight file.
      - name: Restore model artifact
        uses: actions/cache@v4
        with:
          path: models/
          key: deep-scan-model

      # ML-specific: validate model accuracy
      - name: Validate model accuracy
        run: |
          node scripts/validate-model.js \\
            --model models/deep-scan-v1/model.json \\
            --test-data data/holdout.json \\
            --min-accuracy 0.90

      # ML-specific: benchmark inference speed and weight footprint.
      # Pointed at the bundle's language component, not at the classifier:
      # module 10 profiled 84,994,664 of the bundle's weights into that
      # one model, and the classifier's 997 run in microseconds.
      # A hosted runner has no GPU, so this pins the wasm backend, where
      # the optimization profile put DEEP SCAN at 45 ms mean, 112 ms P95.
      # Gate the P95, not the mean: one call in twenty runs that slow and
      # the mean hides it. The operator on watch sees the slow one.
      # The footprint budget covers the float32 tensors the runtime keeps
      # resident once that model is loaded, which is 340 MB for this graph.
      - name: Benchmark inference
        run: |
          node scripts/benchmark.js \\
            --model models/report-lang-v1/model.json \\
            --max-p95-ms 150 \\
            --max-resident-weights-mb 400`}
</CodeBlock>

The third job is the deploy. It waits on both jobs above and runs only on `main`. Its first half snapshots what is live, builds, records the digest of what is about to go up, and publishes.

<CodeBlock language="yaml" title="deploy.yml · jobs.deploy, publish">
{`  deploy:
    runs-on: ubuntu-latest
    needs: [test, validate-model]
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - name: Restore model artifact
        uses: actions/cache@v4
        with:
          path: models/
          key: deep-scan-model

      # Rollback needs bytes to roll back TO, and the cache only holds the
      # candidate. Copy whatever is live right now, before we overwrite it.
      - name: Snapshot the live artifact
        run: |
          base=https://\${{ github.repository_owner }}.github.io/deep-scan-signal-classifier
          mkdir -p models/previous/deep-scan-v1
          for f in model.json weights.bin; do
            curl -fsSL "$base/models/deep-scan-v1/$f" -o "models/previous/deep-scan-v1/$f" || {
              echo "Nothing live yet; this run has no rollback target"
              rm -rf models/previous
              break
            }
          done

      - run: npm run build

      # The digest of the weight file this run is shipping. Every check
      # below compares against this, never against a file name or a URL.
      - name: Digest the candidate artifact
        id: candidate
        run: |
          sum=$(sha256sum models/deep-scan-v1/weights.bin | cut -d' ' -f1)
          echo "sha256=$sum" >> "$GITHUB_OUTPUT"
          echo "Publishing weights.bin sha256=$sum"

      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: \${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist`}
</CodeBlock>

The publish is not the end of the job. The rest of it proves which bytes went live, grades those bytes, and puts the old ones back if either step fails.

<CodeBlock language="yaml" title="deploy.yml · jobs.deploy, verify and roll back">
{`      # That action returns once its push to gh-pages lands. Pages builds
      # and propagates afterward, so the public URL keeps serving the old
      # weights for a while. Poll until the live bytes are the bytes we
      # published, and fail this step if they never are.
      - name: Wait for the candidate to go live
        id: propagate
        continue-on-error: true
        run: |
          url=https://\${{ github.repository_owner }}.github.io/deep-scan-signal-classifier/models/deep-scan-v1/weights.bin
          for i in $(seq 1 60); do
            if curl -fsSL "$url" -o live.bin; then
              live=$(sha256sum live.bin | cut -d' ' -f1)
            else
              live=unavailable
            fi
            if [ "$live" = "\${{ steps.candidate.outputs.sha256 }}" ]; then
              echo "Live bytes match the candidate after $i checks"
              exit 0
            fi
            sleep 10
          done
          echo "Pages never served the candidate digest; not grading a stale artifact"
          exit 1

      # Only now is there an identified artifact to grade. --expect-digest
      # re-reads the live weights and exits non-zero on a mismatch, so an
      # edge that flips back mid-run fails the gate instead of passing it.
      - name: Smoke-test live deployment
        id: smoke
        if: steps.propagate.outcome == 'success'
        continue-on-error: true
        run: |
          node scripts/validate-model.js \\
            --model https://\${{ github.repository_owner }}.github.io/deep-scan-signal-classifier/models/deep-scan-v1/model.json \\
            --test-data data/holdout.json \\
            --min-accuracy 0.90 \\
            --expect-digest \${{ steps.candidate.outputs.sha256 }}

      # A stalled propagation and a failed gate both roll back.
      - name: Roll back model artifact
        if: steps.propagate.outcome == 'failure' || steps.smoke.outcome == 'failure'
        run: |
          test -d models/previous/deep-scan-v1 || {
            echo "Bad model is live and there is no snapshot to restore"
            exit 1
          }
          rm -rf models/deep-scan-v1
          cp -r models/previous/deep-scan-v1 models/deep-scan-v1
          npm run build
          npx gh-pages -d dist
          exit 1`}
</CodeBlock>

Four steps in that file carry the rollback objective. The snapshot copies the artifact that is live, before the publish overwrites it. The digest step records the sha256 of the bytes about to go up. The wait step then polls the public URL until it serves those exact bytes, and only after that does the smoke test re-run the accuracy gate. On failure the snapshot goes back up and the run stays red, because a rollback that goes green in silence tells nobody a bad model ever shipped. Restore the directory, not one file: `model.json` holds only the topology, and the weights sit in `weights.bin` beside it, so copying the JSON alone would leave the bad weights serving under an older graph.

The order is doing real work there. `peaceiris/actions-gh-pages@v4` finishes when its push to the gh-pages branch returns, and the Pages build that serves those files runs afterward. A curl fired the instant the publish step ends will usually read the previous artifact, score it, and pass. Hang rollback on that pass alone and the new weights stay live, never graded. Comparing digests is what closes the hole. File size will not do it: two builds of one architecture at the same precision produce weight files of identical length.

## Validation Scripts

<CodeBlock language="typescript" title="validate-model.ts · identify the bytes">
{`// Model accuracy gate: blocks deployment if accuracy drops.
// tfjs-node, not @tensorflow/tfjs: the browser build registers the http
// loader and nothing else, and this file runs under Node against a path
// on disk. A local path is not a URL, so plain tfjs throws
// "Failed to parse URL" before it loads anything.
import * as tf from '@tensorflow/tfjs-node';
import { createHash } from 'node:crypto';
import { resolve } from 'node:path';

// The five classes in the order the training labels were encoded, so an
// index off the score vector reads back as the name the holdout uses.
const CLASSES = ['pulsar', 'quasar', 'noise', 'interference', 'anomaly'];

interface ValidationResult {
  accuracy: number;
  passed: boolean;
  details: { total: number; correct: number; failures: string[] };
}

// Hash the weight shards model.json names, in the order it names them.
// A file name and a URL cannot say which artifact is live. The bytes can.
// This one runs against the deployed https URL, which is the only spelling
// fetch() takes; the local gate below has no live artifact to identify.
async function fetchWeightDigest(modelUrl: string): Promise<string> {
  const manifest = await (await fetch(modelUrl)).json();
  const dir = modelUrl.slice(0, modelUrl.lastIndexOf('/'));
  const hash = createHash('sha256');
  for (const group of manifest.weightsManifest) {
    for (const file of group.paths) {
      const res = await fetch(\`\${dir}/\${file}\`);
      if (!res.ok) throw new Error(\`weight shard \${file}: HTTP \${res.status}\`);
      hash.update(Buffer.from(await res.arrayBuffer()));
    }
  }
  return hash.digest('hex');
}`}
</CodeBlock>

Two spellings reach this script and only one of them is a URL. The workflow's validate-model job passes `models/deep-scan-v1/model.json`, a path in the checkout; the smoke test passes the deployed `https://` address. `tf.loadLayersModel` takes a URL and picks a loader by scheme, so the local form has to be widened into a `file://` URL, which is the loader `tfjs-node` adds and the browser build does not have.

<CodeBlock language="typescript" title="validate-model.ts · score it">
{`async function validateModel(
  modelPath: string,
  testDataPath: string,
  minAccuracy: number,
  expectedDigest?: string
): Promise<ValidationResult> {
  // Identify the bytes before scoring them. tf.loadLayersModel() does not
  // check the HTTP status of a weight shard, so a 404 page of the right
  // length loads as a model and predicts a constant.
  if (expectedDigest) {
    const live = await fetchWeightDigest(modelPath);
    if (live !== expectedDigest) {
      throw new Error(
        \`Digest mismatch: expected \${expectedDigest}, live is \${live}\`
      );
    }
  }

  const modelUrl = /^https?:/.test(modelPath)
    ? modelPath
    : \`file://\${resolve(modelPath)}\`;
  const model = await tf.loadLayersModel(modelUrl);
  const testData = await loadTestData(testDataPath);

  let correct = 0;
  const failures: string[] = [];

  for (const sample of testData) {
    // predict() is synchronous and hands back a tensor of five class
    // scores, not a verdict. Read the winning index off it, and read it
    // inside tidy: the row, the scores and the argMax are three tensors
    // per sample, so a 100-row holdout otherwise leaves 300 behind.
    const label = tf.tidy(() => {
      const scores = model.predict(tf.tensor2d([sample.input])) as tf.Tensor;
      return CLASSES[scores.argMax(-1).dataSync()[0]];
    });
    if (label === sample.expectedLabel) {
      correct++;
    } else {
      failures.push(
        \`Expected \${sample.expectedLabel}, got \${label}\`
      );
    }
  }

  const accuracy = correct / testData.length;
  return {
    accuracy,
    passed: accuracy >= minAccuracy,
    details: { total: testData.length, correct, failures: failures.slice(0, 10) },
  };
}`}
</CodeBlock>

And the invocation the workflow's validate-model step runs. `--expect-digest` is absent there and present on the smoke test, which is the whole difference between grading an artifact and grading whichever artifact answered.

<CodeBlock language="typescript" title="validate-model.ts · run it">
{`function flag(name: string): string | undefined {
  const i = process.argv.indexOf(name);
  return i === -1 ? undefined : process.argv[i + 1];
}

const result = await validateModel(
  flag('--model') ?? 'models/deep-scan-v1/model.json',
  flag('--test-data') ?? 'data/holdout.json',
  Number(flag('--min-accuracy') ?? 0.90),
  flag('--expect-digest')
);

console.log(\`Accuracy: \${(result.accuracy * 100).toFixed(1)}%\`);
console.log(\`Gate: \${result.passed ? 'PASSED ✓' : 'FAILED ✗'}\`);

if (!result.passed) {
  console.error('Model accuracy below threshold; blocking deployment');
  process.exit(1);
}`}
</CodeBlock>

The function that reads a cache key, `hashFiles()`, is what makes her order work and also what rules out the obvious version of it. It hashes files already in the workspace, so it cannot hash the 85 MB bundle the restore step has not fetched yet. The digest file the training rig commits is in the checkout the moment the job starts, which is why the key reads that file and not the weights.

## Challenge

Write the validation gate the merge decision reads: accuracy against a floor, and an honest answer when the batch it was handed cannot be scored.

<Exercise slug="ci-cd-gate" />

The gate checks the artifact. Now produce one. Nazari's hash-pin order has a quiet prerequisite: bytes to hash, and `model.save()` is where they come from. It will save to anything that implements a handler, including plain memory. Nothing touches a filesystem or a network, and you end up holding the serialized model: topology, weight specs, and the weight bytes the digest is computed over. Prove the export path on the bench copy of DEEP SCAN before anyone points it at the real 85 MB build.
