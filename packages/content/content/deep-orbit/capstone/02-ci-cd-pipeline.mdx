## ML-Aware CI/CD

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="yaml" title="deploy.yml">
{`name: DEEP SCAN CI/CD

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      # Standard web app steps
      - run: npm ci
      - run: npm run lint
      - run: npm run typecheck
      - run: npm test

  validate-model:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci

      # Model artifact: 42 MB of weights, too big for git. Restored from
      # the CI cache; the training rig seeds it after every retrain.
      - name: Restore model artifact
        uses: actions/cache@v4
        with:
          path: models/
          key: deep-scan-model

      # ML-specific: validate model accuracy
      - name: Validate model accuracy
        run: |
          node scripts/validate-model.js \\
            --model models/deep-scan-v1.json \\
            --test-data data/holdout.json \\
            --min-accuracy 0.90

      # ML-specific: benchmark inference speed
      - name: Benchmark inference
        run: |
          node scripts/benchmark.js \\
            --model models/deep-scan-v1.json \\
            --max-inference-ms 20 \\
            --max-memory-mb 50

  deploy:
    runs-on: ubuntu-latest
    needs: [test, validate-model]
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: \${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist

      # Rollback on failure: re-run the accuracy gate against the LIVE
      # deployment. If it fails, restore the previous model artifact,
      # republish, and keep the run red so the failure pages someone.
      - name: Smoke-test live deployment
        id: smoke
        continue-on-error: true
        run: |
          node scripts/validate-model.js \\
            --model https://deep-scan.pages.dev/models/deep-scan-v1.json \\
            --test-data data/holdout.json \\
            --min-accuracy 0.90
      - name: Roll back model artifact
        if: steps.smoke.outcome == 'failure'
        run: |
          cp models/previous/deep-scan-v1.json models/deep-scan-v1.json
          npm run build
          npx gh-pages -d dist
          exit 1`}
</CodeBlock>

The last two steps are the rollback objective made concrete: the smoke test re-runs the accuracy gate against what actually deployed, and on failure the previous model artifact is restored and republished while the workflow stays red. A rollback that quietly succeeds is how a bad model stays shipped.

## Validation Scripts

<CodeBlock language="typescript" title="validate-model.ts">
{`// Model accuracy gate: blocks deployment if accuracy drops

interface ValidationResult {
  accuracy: number;
  passed: boolean;
  details: { total: number; correct: number; failures: string[] };
}

async function validateModel(
  modelPath: string,
  testDataPath: string,
  minAccuracy: number
): Promise<ValidationResult> {
  const model = await loadModel(modelPath);
  const testData = await loadTestData(testDataPath);

  let correct = 0;
  const failures: string[] = [];

  for (const sample of testData) {
    const prediction = await model.predict(sample.input);
    if (prediction.label === sample.expectedLabel) {
      correct++;
    } else {
      failures.push(
        \`Expected \${sample.expectedLabel}, got \${prediction.label}\`
      );
    }
  }

  const accuracy = correct / testData.length;
  return {
    accuracy,
    passed: accuracy >= minAccuracy,
    details: { total: testData.length, correct, failures: failures.slice(0, 10) },
  };
}

// Usage in CI
const result = await validateModel(
  'models/deep-scan-v1.json',
  'data/holdout.json',
  0.90
);

console.log(\`Accuracy: \${(result.accuracy * 100).toFixed(1)}%\`);
console.log(\`Gate: \${result.passed ? 'PASSED ✓' : 'FAILED ✗'}\`);

if (!result.passed) {
  console.error('Model accuracy below threshold; blocking deployment');
  process.exit(1);
}`}
</CodeBlock>

## Challenge

Write a model validation gate for CI/CD.

<Exercise slug="ci-cd-gate" />

The gate checks the artifact. Now produce one. Nazari's hash-pin order has a quiet prerequisite: bytes to hash, and `model.save()` is where they come from. It will save to anything that implements a handler, including plain memory. Nothing touches a filesystem or a network, and you end up holding the serialized model: topology, weight specs, and the weight bytes the cache key is a hash of. Prove the export path on the bench copy of DEEP SCAN before anyone points it at the real 42 MB build.

<Exercise slug="export-model-artifact" />

<RecallPrompt question="Why does a passing CI workflow not guarantee you tested the model you are about to ship?" answer="Because the workflow only tests whatever artifact its steps resolve, and a cache keyed by a fixed name or path can resolve to a stale one. CI caches CAN pin content (GitHub Actions keys support hashFiles() over the artifact). But if the key omits the model's content hash, a weight file from a previous training run satisfies the cache hit and passes every accuracy gate, measuring a model that no longer exists. Version weights separately and key the cache on the artifact's hash." />

  question="What do ML model gates add to a standard web CI pipeline, and what do they share with failing unit tests?"
