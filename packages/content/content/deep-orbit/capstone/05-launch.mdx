## Deploy and Verify

Two deployment shapes appear in this lesson. The verification suite below is the full gate. The other is the hot canary from the decision above: ship to ONE console, watch it against live data for a fixed interval, then roll fleet-wide only if it holds. Canaries trade a slice of your window for a bounded blast radius; the suite trades time for certainty. Production teams run both, in that order.

<CodeBlock language="typescript" title="deploy.ts">
{`// Deployment verification: smoke test the live system

async function verifyDeployment(baseUrl: string): Promise<boolean> {
  console.log('=== DEEP SCAN Deployment Verification ===');
  console.log('');

  // 1. Check model loads
  console.log('1. Loading model...');
  const modelUrl = \`\${baseUrl}/models/deep-scan-v1/model.json\`;
  const response = await fetch(modelUrl);
  if (!response.ok) {
    console.error('✗ Model failed to load:', response.status);
    return false;
  }
  console.log('✓ Model loaded successfully');

  // 2. Check inference works
  console.log('2. Running test inference...');
  const testSignal = new Float32Array(80).fill(0).map(() => Math.random() * 2 - 1);
  const result = await pipeline.classify(testSignal);
  if (!result.label || result.confidence < 0) {
    console.error('✗ Inference returned invalid result');
    return false;
  }
  console.log(\`✓ Inference works: \${result.label} (\${(result.confidence * 100).toFixed(1)}%)\`);

  // 3. Check performance
  console.log('3. Benchmarking...');
  const times: number[] = [];
  for (let i = 0; i < 20; i++) {
    const input = new Float32Array(80).fill(0).map(() => Math.random() * 2 - 1);
    const t0 = performance.now();
    await pipeline.classify(input);
    times.push(performance.now() - t0);
  }
  const avgMs = times.reduce((a, b) => a + b) / times.length;
  console.log(\`✓ Avg inference: \${avgMs.toFixed(1)}ms\`);

  console.log('');
  console.log('=== Deployment verified ===');
  return true;
}`}
</CodeBlock>

<RecallPrompt question="How does rolling back a deployed model differ from rolling back a deployed web app?" answer="Rolling back a web app restores the prior build artifact and the user gets the previous page: the system state is fully described by those bytes. Rolling back a model restores the prior weights, but drift accumulates from the training cutoff, not the deploy time. The prior weights were calibrated to a data distribution that may have moved further away since they were trained, so a rollback does not guarantee the model is safe to run again." />
