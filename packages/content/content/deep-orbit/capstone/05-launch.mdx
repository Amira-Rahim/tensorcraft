      function decomposeIntervals(intervals) {
        const ratios = [];
        for (let i = 0; i < intervals.length - 1; i++) {
          ratios.push(intervals[i + 1] / intervals[i]);
        }
        return ratios;
      }

      function isFibonacciTrain(ratios) {
        const fibonacciRatios = [1, 2, 1.5, 5 / 3, 1.6, 1.625];
        // The reading's first ratio may be the 1:1 opener or start at the 2;
        // align on length from the tail, where the train converges on phi.
        const expected = fibonacciRatios.slice(
          fibonacciRatios.length - ratios.length,
        );
        if (expected.length !== ratios.length) return false;
        return ratios.every(
          (r, i) => Math.abs(r - expected[i]) / expected[i] <= 0.02,
        );
      }

      function classifyAnomaly(reading) {
        const { mean, variance } = tf.tidy(() => {
          const m = tf.moments(tf.tensor1d(reading.window));
          return {
            mean: m.mean.dataSync()[0],
            variance: m.variance.dataSync()[0],
          };
        });
        const std = Math.sqrt(variance);
        const z = std === 0 ? 0 : (reading.actual - mean) / std;

        const verdicts = {
          statistical: Math.abs(z) > 3,
          autoencoder: reading.reconstructionError > reading.reconThreshold,
          lstm:
            Math.abs(reading.predicted - reading.actualForecast) >
            reading.predTolerance,
        };
        const votes = Object.values(verdicts).filter(Boolean).length;
        const isAnomaly = votes >= 2;

        const ratios = decomposeIntervals(reading.intervals);
        const fibonacciTrain = isFibonacciTrain(ratios);

        return {
          votes,
          isAnomaly,
          ratios,
          fibonacciTrain,
          classification:
            isAnomaly && fibonacciTrain
              ? "confirmed-anomaly"
              : isAnomaly
                ? "anomaly"
                : "noise",
          scoreDelta:
            Math.round((reading.ensembleScore - reading.module3Score) * 1000) /
            1000,
        };
      }

Two model directories ship and only one of them is the classifier. `deep-scan-v1` is the eleven-feature, five-class network module 10 retrained: a topology file and 997 weights, about seven kilobytes together. `report-lang-v1` is the report pipeline's pretrained language component, and it is what the 85 MB counts. The model card in the last lesson keeps those two sizes on separate lines for the same reason this config does. A reader who sees 85 MB beside the classifier goes and optimizes the wrong network.

## Deploy and Verify

Two deployment shapes appear in this lesson. The verification suite below is the full gate. The other is the hot canary from the decision above: ship to ONE console, watch it against live data for a fixed interval, then roll fleet-wide only if it holds. Canaries trade a slice of your window for a bounded blast radius; the suite trades time for certainty. Production teams run both: the suite first, then the canary.

<CodeBlock language="typescript" title="deploy.ts">
{`// Deployment verification: smoke test the live system

async function verifyDeployment(baseUrl: string): Promise<boolean> {
  console.log('=== DEEP SCAN Deployment Verification ===');
  console.log('');

  // 1. Check model loads
  console.log('1. Loading model...');
  const modelUrl = \`\${baseUrl}/models/deep-scan-v1/model.json\`;
  let response: Response;
  try {
    response = await fetch(modelUrl);
  } catch (error) {
    // The failure that has no status to read: DNS does not resolve, the
    // host never answers, the request is refused. Letting it through
    // ends the run with no report at all, and the operator is left
    // guessing which check died.
    console.error('✗ Model fetch failed:', (error as Error).message);
    return false;
  }
  if (!response.ok) {
    console.error('✗ Model failed to load:', response.status);
    return false;
  }
  console.log('✓ Model loaded successfully');

  // 2. Score the labeled probe that shipped with the build. Random input
  // would only prove the file parses: a mangled preprocessing path still
  // returns a label and a confidence for noise. Known inputs with known
  // answers are the only check that can see the input path is wrong.
  console.log('2. Scoring the labeled probe...');
  const probe: { input: number[]; label: string }[] = await (
    await fetch(\`\${baseUrl}/data/validation-sample.json\`)
  ).json();
  let correct = 0;
  for (const sample of probe) {
    const { label } = await pipeline.classify(new Float32Array(sample.input));
    if (label === sample.label) correct++;
  }
  // A floor, not the benchmark. The card claims 91.8% and the probe is
  // 100 rows, so a healthy deploy falls under 80 about five times in a
  // hundred thousand runs; five-way chance on mangled input lands near 20.
  const FLOOR = 80;
  if (correct < FLOOR) {
    console.error(\`✗ Probe accuracy \${correct}/\${probe.length}, floor \${FLOOR}\`);
    return false;
  }
  console.log(\`✓ Probe accuracy: \${correct}/\${probe.length}\`);

  // 3. Check performance. Nothing reads the labels here, only the clock,
  // but the samples still have to be raw ADC counts: the extractor takes
  // amplitude as the largest magnitude in the window and normalizes it
  // against 0 to 2048. Values in [-1, 1] would time the pipeline on input
  // that looks already normalized, the same confusion the labeled probe
  // above is there to catch.
  console.log('3. Benchmarking...');
  const times: number[] = [];
  for (let i = 0; i < 20; i++) {
    const input = new Float32Array(64)
      .fill(0)
      .map(() => Math.random() * 4096 - 2048);
    const t0 = performance.now();
    await pipeline.classify(input);
    times.push(performance.now() - t0);
  }
  const avgMs = times.reduce((a, b) => a + b) / times.length;
  console.log(\`✓ Avg inference: \${avgMs.toFixed(1)}ms\`);

  console.log('');
  console.log('=== Deployment verified ===');
  return true;
}`}
</CodeBlock>

## The Interval Train, in Ratios

Farah's decomposition handed the crew a sequence, not a test. The sequence is the sub-pulse gaps, 1, 1, 2, 3, 5, 8, 13, each gap the sum of the two before it. What a classifier can check is the sequence divided through: each gap over the gap before it, which drops the units and leaves six numbers.

<CodeBlock language="text" title="interval-ratios.txt">
{`gaps      1     1     2     3     5     8     13
divide          1/1   2/1   3/2   5/3   8/5   13/8
ratios          1.0   2.0   1.5   1.667 1.6   1.625`}
</CodeBlock>

Three properties of that list are what the finale exercise grades.

Dividing removes the scale. Farah's capture was in seconds and the sequence is unitless, and both decompose to the same six ratios. That is the reason the calibration overlay lined up at all.

The ratios converge. They land above and below 1.618 by turns and the miss narrows each step, so the tail of the list is the part that identifies the pattern and the front is the part a capture can lose. A recording that starts mid-train has no 1:1 opener in it, which means a short ratio list is compared against the end of the full list rather than the beginning.

Measured seconds do not divide exactly. Even in the archive's rounded slice, 11.7 over 7.2 comes back as 1.6249999999999998, and a live capture misses by more than that, so a match is a band around each expected ratio rather than an equality. The width of that band is a false-alarm decision like every other cutoff in module 7: too tight and the real train is rejected by rounding, too loose and a metronome starts qualifying.
