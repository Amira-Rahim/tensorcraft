{`interface PredictionLog {
  timestamp: number;
  confidence: number;
  latencyMs: number;
  inputFeatures: number[];
  label: string;
}

class ModelMonitor {
  readonly logs: PredictionLog[] = [];
  private baselineFeatures: number[][] = [];

  constructor(baselineData: number[][]) {
    this.baselineFeatures = baselineData;
  }

  log(prediction: PredictionLog): void {
    this.logs.push(prediction);
    this.checkAlerts(prediction);
  }

  // Confidence tracking, like error rate monitoring
  get avgConfidence(): number {
    const recent = this.logs.slice(-100);
    return recent.reduce((sum, p) => sum + p.confidence, 0) / recent.length;
  }

  // Latency percentiles, like response time monitoring
  getLatencyPercentile(p: number): number {
    const sorted = this.logs.slice(-1000)
      .map(l => l.latencyMs)
      .sort((a, b) => a - b);
    return sorted[Math.floor(sorted.length * p / 100)];
  }

  // Data drift detection, unique to ML monitoring
  computeDrift(recentInputs: number[][]): number {
    const baselineMean = this.computeMean(this.baselineFeatures);
    const recentMean = this.computeMean(recentInputs);

    // Simple drift: Euclidean distance between feature means.
    // Assumes features are z-scored first (the foundations rule):
    // on raw scales the 73-Hz frequency term would drown the phase
    // term and this one number would mean nothing.
    // A mean vector only sees a shift in level. Two windows with the
    // same means and twice the spread score 0.0 here, and so does one
    // that split into two modes at the same average.
    let sumSqDiff = 0;
    for (let i = 0; i < baselineMean.length; i++) {
      sumSqDiff += (baselineMean[i] - recentMean[i]) ** 2;
    }
    return Math.sqrt(sumSqDiff);
  }

  private computeMean(data: number[][]): number[] {
    const featureCount = data[0].length;
    const means = new Array(featureCount).fill(0);
    for (const row of data) {
      for (let i = 0; i < featureCount; i++) {
        means[i] += row[i] / data.length;
      }
    }
    return means;
  }

  private checkAlerts(prediction: PredictionLog): void {
    if (prediction.confidence < 0.5) {
      console.warn('⚠ Low confidence prediction:', prediction.label);
    }
    if (prediction.latencyMs > 50) {
      console.warn('⚠ Slow inference:', prediction.latencyMs, 'ms');
    }
  }
}

// Usage
const monitor = new ModelMonitor(trainingFeatures);

// After each prediction
monitor.log({
  timestamp: Date.now(),
  confidence: 0.94,
  latencyMs: 5.2,
  inputFeatures: signalFeatures,
  label: 'pulsar',
});

console.log('Avg confidence:', monitor.avgConfidence.toFixed(3));
console.log('P95 latency:', monitor.getLatencyPercentile(95).toFixed(1), 'ms');`}
</CodeBlock>

## Drift Detection

<CodeBlock language="typescript" title="drift.ts">
{`// Data drift: when production data diverges from training data
// Like monitoring API response shapes: if they change, your app breaks

interface DriftReport {
  driftScore: number;
  isSignificant: boolean;
  features: { name: string; baselineMean: number; currentMean: number; shift: number }[];
}

function detectDrift(
  baseline: number[][],
  current: number[][],
  // 0.5 is not a universal number. It is the 99th percentile of this
  // detector's own score over 180 known-calm 100-sample windows. Module 7
  // computed that percentile too and then walked away from it: it had
  // labeled anomalies, so its cutoff came from an F1 sweep and the cost of
  // a false alarm. Drift has no labels to sweep, so here the percentile is
  // where the number stops.
  // It is only valid at that window size. On calm data the distance
  // between two sample means shrinks as the windows grow: the same
  // detector sits near 0.22 on a 500-sample window. Change the window
  // and you have to measure the number again.
  threshold: number = 0.5
): DriftReport {
  // The model's REAL input vector (module 5's fixed-bin design): 3 raw
  // features + 8 fixed FFT bins. Drift checks watch what the model eats.
  const featureNames = [
    'amplitude', 'zeroCrossings', 'phase',
    'fft_0', 'fft_1', 'fft_2', 'fft_3', 'fft_4', 'fft_5', 'fft_6', 'fft_7',
  ];
  const features = featureNames.map((name, i) => {
    const baselineMean = baseline.reduce((s, r) => s + r[i], 0) / baseline.length;
    const currentMean = current.reduce((s, r) => s + r[i], 0) / current.length;
    return {
      name,
      baselineMean,
      currentMean,
      shift: Math.abs(currentMean - baselineMean),
    };
  });

  // This is a distance between means, not a comparison of distributions.
  // Production drift monitors score each feature with a
  // Kolmogorov-Smirnov statistic (the largest gap between the two
  // cumulative distributions) or a population stability index (both
  // windows bucketed the same way, then compared bucket by bucket).
  // Both read a change in spread or shape that the mean vector misses.
  const driftScore = Math.sqrt(features.reduce((s, f) => s + f.shift ** 2, 0));

  return {
    driftScore,
    isSignificant: driftScore > threshold,
    features,
  };
}

const drift = detectDrift(trainingData, recentSignals);
if (drift.isSignificant) {
  console.error('🚨 Data drift detected! Score:', drift.driftScore.toFixed(3));
  console.log('Drifted features:', drift.features
    .filter(f => f.shift > 0.1)
    .map(f => f.name)
  );
  // Trigger retraining alert
}`}
</CodeBlock>

Accuracy is missing from that dashboard, and it is missing for a reason. A production prediction arrives with no label attached. The monitor records that DEEP SCAN called a window `pulsar` at 0.94 confidence, and nothing in the stream says whether that was right. Confidence and drift are proxies for an accuracy nobody can read live. The lag between a prediction and the label that would grade it is the label feedback delay, and here a label means Nazari at a console working through the capture by hand.

That also bounds what "retrain" can mean. Retraining on drifted inputs needs labels for the drifted inputs, so the first real step after a drift alert is somebody hand-labeling a sample of recent captures. A drift score tells you the training set is out of date. It does not produce the replacement.

The other distribution worth watching sits on the output side. `this.logs` already holds a label and a confidence for every prediction, so two counts fall out of it for free: the share of verdicts landing in each of the five classes, and the histogram of confidences. When `noise` climbs from 60 percent of verdicts to 85, or the confidence histogram slides down a tenth, the model's behavior has moved even if every input feature mean sat still. Prediction-side drift needs no labels either, which is the reason to keep it next to the input-side check.
