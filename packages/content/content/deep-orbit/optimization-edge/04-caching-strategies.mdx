      The first decision is what counts as the same input, which is the

      are rounded, and `decimals` is how wide you make the bucket. Watch what

      their sum or their mean, hands [0.9, 0.1] and [0.1, 0.9] the same key.

## Inference Caching

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="inference-cache.ts">
{`class InferenceCache<T> {
  private cache = new Map<string, { result: T; timestamp: number }>();
  private readonly maxSize: number;
  private readonly ttlMs: number;
  private readonly hashInput: (input: number[]) => string;
  private hits = 0;
  private misses = 0;

  // The key function comes in from outside on purpose. Rounding the values
  // before joining them is what lands near-identical signals on one entry,
  // and how far to round is not a decision this class can make for you:
  // round too little and every repeat misses, too much and two signals that
  // should have stayed apart are served one verdict between them. Writing
  // that function, and keeping the values in their own places while you do,
  // is the Challenge below.
  constructor(
    hashInput: (input: number[]) => string,
    maxSize: number = 1000,
    ttlMs: number = 60000,
  ) {
    this.hashInput = hashInput;
    this.maxSize = maxSize;
    this.ttlMs = ttlMs;
  }

  get(input: number[]): T | null {
    const key = this.hashInput(input);
    const entry = this.cache.get(key);
    if (!entry) {
      this.misses++;
      return null;
    }
    if (Date.now() - entry.timestamp > this.ttlMs) {
      this.cache.delete(key);
      this.misses++;
      return null;
    }
    // True LRU: a Map iterates in insertion order, so delete + re-set
    // moves this key to the back of the eviction line. Without it you have
    // built FIFO, which evicts your hottest entry because it arrived first.
    this.cache.delete(key);
    this.cache.set(key, entry);
    this.hits++;
    return entry.result;
  }

  set(input: number[], result: T): void {
    const key = this.hashInput(input);
    // Re-setting an existing key must refresh its recency (the same
    // delete-then-set trick get() uses) and must NOT evict a stranger:
    // the size isn't growing.
    if (this.cache.has(key)) {
      this.cache.delete(key);
    } else if (this.cache.size >= this.maxSize) {
      // Map's first key = least recently used (get() refreshes position)
      const lru = this.cache.keys().next().value;
      if (lru) this.cache.delete(lru);
    }
    this.cache.set(key, { result, timestamp: Date.now() });
  }

  get hitRate(): number {
    return this.hits / (this.hits + this.misses) || 0;
  }
}

// Usage. signalKey rounds the way the Challenge's decimals = 2 does. The
// TTL is six hours, past the end of the watch, because the repeats this
// cache is built for arrive about a hundred seconds apart: on a 30-second
// clock nearly every entry expires before its repeat comes back, and most
// of the 40 percent below goes with it.
const signalKey = (input: number[]) => input.map(v => Math.round(v * 100) / 100).join(',');
const cache = new InferenceCache<string>(signalKey, 500, 6 * 60 * 60 * 1000);

function cachedClassify(signal: number[]): string {
  const cached = cache.get(signal);
  if (cached) return cached;

  const result = classify(model, signal);
  cache.set(signal, result);
  return result;
}

// After the overnight run: 4,110 lookups, 1,644 hits. cache.hitRate reads 0.40.

// Mean cost per served call = hitRate * hit + (1 - hitRate) * classify.
// Both terms are measured on one backend, readback inside the clock. A
// classification on the eleven-feature classifier ran 0.035 ms per call,
// timed one call at a time across 20 runs of 200. A hit is the whole
// cheap path: dataSync, round the values, join the key, read the Map,
// and over 200,000 hits against a 500-entry cache that path ran
// 0.0013 ms, of which the Map read itself was 0.00004.
const effectiveMs = 0.4 * 0.0013 + 0.6 * 0.035;
console.log(effectiveMs.toFixed(4));  // 0.0215

// 0.035 ms to 0.0215 is the hit rate and nothing more. A cache never makes
// a call faster; it removes calls. Put the night through it and the whole
// saving is 1,644 hits at 0.0337 ms each, which is 55 milliseconds between
// midnight and morning.
//
// The 45 ms in this module's first lesson is not this call. It belongs to
// the 85-million-parameter language component behind the report pipeline.
// A cache in front of THAT call is worth building. The pattern was never
// wrong here; the call it was pointed at was.`}
</CodeBlock>

Notice what `InferenceCache<string>` holds: the verdict, not the tensor it came out of. Cache the tensor instead and 50 cached predictions leave 50 tensors resident with nothing to release them, in the module that opened on a dashboard running out of memory. Sharing the handle is the other half of it. Whoever disposes the returned tensor first turns every later hit on that key into `Tensor is disposed.`

Keep the ledger honest on both sides while you read that. On the credit side this cache removes 40 percent of the classifier's forward passes, worth 55 milliseconds a night. On the debit side it creates a second copy of every verdict the model has ever given, with its own expiry rules and its own ways of being wrong, and the next page you get will be about that copy. A cache earns its place when the call behind it costs enough to pay for the invalidation you just signed up for. Time the call first.
