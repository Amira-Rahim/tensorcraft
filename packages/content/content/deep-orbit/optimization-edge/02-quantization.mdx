<Dialogue speaker="Chief Nazari">
Every weight is a 32-bit float: 4 bytes. Your model has 85 million weights. That's 340 MB just for the numbers. Store them as 8-bit integers and the file is 85 MB. One quarter the download, one quarter the disk. Don't promise me faster inference; the runtime decodes them back to floats at load. Promise me a file that fits.
</Dialogue>

Two ledgers, one knife. The 85 million weights are the whole DEEP SCAN bundle, and almost all of them belong to the pretrained language component from the report pipeline; the crew's own trained models ride along at under a megabyte. The uint8 pass goes across everything, so the accuracy row tracks the one part of the bundle with a scoreboard: the classifier, at 94.2 after this week's retrain (78 after the spectrogram re-annotation, 87 with the FFT features, 94.2 with five modules of sequence features).

That retrain also changed the classifier's shape, and the change deserves a paragraph rather than a footnote. Farah's catalog labels finally landed, and the binary anomaly-or-noise gate became a five-way sort: pulsar, quasar, noise, interference, anomaly. Two things move when a classifier grows past two classes. The output layer becomes five units under a softmax, module 8's arithmetic, so the five scores become five probabilities that sum to 1 and the verdict is whichever is largest. And the loss becomes categorical cross-entropy: module 3's log of the probability the model gave the right answer, read from whichever of the five columns holds the true label, with labels one-hot encoded so each reading's target is four zeros and a one.

Quantize the whole bundle, and the scoreboard reports what the knife took in the one place the loss can be measured.

The converter does not force that. `--quantize_uint8` takes a value, a comma-separated list of weight-name patterns, which is why you often see it written as `--quantize_uint8='*'` when you mean every layer. Narrow the pattern and the language weights go to uint8 while the whole classifier stays at float32. The classifier is under a megabyte, so holding it out costs under a megabyte of the 255 MB the pass takes off the bundle. The crew did not narrow it. The classifier was mid-retrain that week, with its layer names still moving, so any pattern they wrote would have gone stale by the next build.

The technique runs exactly as deep as Nazari's arithmetic. If you've ever converted a 2 MB PNG to a 200 KB WebP and squinted at the invisible difference, you know the trade. Store each weight in one byte instead of four and the file lands at 85 MB; the cost is roughly a point of accuracy. The dashboard that died at 0249 has 512 MB of RAM and went down parsing a 340 MB weight file; cutting that file to 85 MB is the first and largest payment on the debt.

## Precision Reduction

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="quantization.ts">
{`import * as tf from '@tensorflow/tfjs';

// Float32: full precision (default)
// 1.2345678 → stored as 4 bytes
// Model size: 85M params × 4 bytes = 340 MB

// Uint16 storage: 2 bytes per weight, 65,536 levels (0-65535) across the range
// (an affine integer mapping, not IEEE float16)
// File size: 85M params × 2 bytes = 170 MB

// Uint8 storage: 1 byte per weight, 256 levels (coarse, usually OK)
// File size: 85M params × 1 byte = 85 MB

// Simulate quantization effect
function quantizeWeights(weights: Float32Array, bits: 8 | 16): { quantized: number[]; scale: number; zeroPoint: number } {
  // (teaching scale: on a real model's millions of weights, spread
  // arguments overflow the stack; use a loop or tf.min()/tf.max())
  const min = Math.min(...weights);
  const max = Math.max(...weights);
  const range = max - min;
  const levels = (1 << bits) - 1;  // 255 steps between 256 levels for 8-bit
  const scale = range / levels;
  const zeroPoint = Math.round(-min / scale);

  const quantized = Array.from(weights).map(w =>
    Math.round((w - min) / scale)
  );

  return { quantized, scale, zeroPoint };
}

// Dequantize back to float
function dequantize(quantized: number[], scale: number, zeroPoint: number): number[] {
  return quantized.map(q => (q - zeroPoint) * scale);
}

// The error between original and quantized weights is small
// Accuracy typically drops < 2% for 8-bit quantization`}
</CodeBlock>

## Saving Quantized Models

<CodeBlock language="bash" title="quantize-on-export.sh">
{`# Quantization happens at EXPORT time, in the converter, not in
# model.save(). TFJS's save() writes float32, full stop; there is no
# quantization option on it. The tensorflowjs_converter (a one-time
# Python CLI step, the only Python in this course) rewrites the weight
# files and records the scheme in the weights manifest:

tensorflowjs_converter \\
  --input_format=tfjs_layers_model \\
  --output_format=tfjs_layers_model \\
  --quantize_uint16 \\
  ./model-f32/model.json ./model-q16/

# --quantize_uint8 for the 4x version. At load time in the browser,
# tf.loadLayersModel() reads the manifest and dequantizes back to
# float32 automatically; your inference code does not change.

# Size comparison for DEEP SCAN:
# float32 (no quantization):  340 MB, accuracy: 94.2%
# uint16  (--quantize_uint16): 170 MB, accuracy: 94.0% (-0.2%)
# uint8   (--quantize_uint8):   85 MB, accuracy: 93.0% (-1.2%)`}
</CodeBlock>

One thing to be clear about before Nazari makes you be clear about it: TensorFlow.js decodes quantized weights back to float32 when the model loads. Loading is where the size shows up: the runtime holds the downloaded file buffer and the decoded float32 tensors at the same time, so a 340 MB file peaks near 680 MB, over the dashboard's 512 MB budget, while an 85 MB file peaks near 425 MB and survives. Once the load finishes, the resident weights are 340 MB either way, so nothing about the running model got smaller. The math of inference runs at the same speed as before; nothing in the browser executes on integer hardware. What you bought is a 4x smaller download, a smaller disk cache, and a load spike the dashboard can survive. Runtimes like TFLite do run int8 kernels on integer silicon; in the browser, quantization is a storage format, not an execution mode.
