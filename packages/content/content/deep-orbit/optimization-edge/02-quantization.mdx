  - level: guidance
    content: |
      There is no tf.quantize() in TFJS, so the mapping is arithmetic you
      write yourself. Three decisions decide whether the report is a
      measurement or a story.

      The first is which tensors are in scope. A weight list holds kernels
      and biases, the biases here keep full precision, and what tells the two
      apart is how many dimensions the tensor has.

      The second is where the price shows up. Squeezing a weight onto one of
      256 buckets is what saves the byte, and coming back out of the bucket
      is what the runtime does for you at load. So the floats that come back
      out have to go onto the model before the second prediction pass.
      Otherwise you have measured the original model twice. Zero changed
      predictions is a valid result, but only after testing the decoded weights.

      The third is the grid. Every tensor gets its own, measured from its own
      smallest and largest value. One tensor carrying a value far out from
      the rest would otherwise widen the buckets of every other tensor in the
      model. That widening is the failure mode this exercise is built around.
      A wider bucket permits a larger rounding error. The decoded value is
      q * scale + min, so a small weight does not necessarily round to zero.
  - level: solution
    content: |
      interface QuantizedKernel {
        quantized: number[];
        scale: number;
        min: number;
        shape: number[];
      }

      interface QuantizationReport {
        kernels: QuantizedKernel[];
        maxWeightError: number;
        predictionsChanged: number;
      }

      async function quantizeModel(
        model: any,
        captures: number[][]
      ): Promise<QuantizationReport> {
        const input = tf.tensor2d(captures);
        const before = Array.from(await model.predict(input).argMax(1).data());

        const isKernel = (w: any) => w.shape.length === 2;
        const kernels: QuantizedKernel[] = [];
        let maxWeightError = 0;

        const rebuilt = model.getWeights().map((w: any) => {
          if (!isKernel(w)) return w;
          const values = Array.from(w.dataSync()) as number[];
          const min = values.reduce((a, b) => Math.min(a, b));
          const max = values.reduce((a, b) => Math.max(a, b));
          const scale = (max - min) / 255;
          const quantized = values.map(v => scale === 0 ? 0 : Math.round((v - min) / scale));
          const restored = quantized.map(q => q * scale + min);
          const error = restored.reduce((worst, v, i) => Math.max(worst, Math.abs(v - values[i])), 0);
          maxWeightError = Math.max(maxWeightError, error);
          kernels.push({ quantized, scale, min, shape: w.shape });
          return tf.tensor(restored, w.shape);
        });

        model.setWeights(rebuilt);

        const after = Array.from(await model.predict(input).argMax(1).data());
        const predictionsChanged = after.filter((v, i) => v !== before[i]).length;

        return { kernels, maxWeightError, predictionsChanged };
      }

That retrain also changed the classifier's shape, and the change deserves a paragraph rather than a footnote. Farah's catalog labels finally landed, and the binary anomaly-or-noise gate became a five-way sort: pulsar, quasar, noise, interference, anomaly. Two things move when a classifier grows past two classes. The output layer becomes five units under a softmax, module 8's arithmetic, so the five scores become five probabilities that sum to 1 and the verdict is whichever is largest. And the loss becomes categorical cross-entropy: module 3's negative log of the probability the model gave the right answer, read from whichever of the five columns holds the true label, with labels one-hot encoded so each reading's target is four zeros and a one. The minus sign is what makes it a loss rather than a score. A true-class probability of 0.01 costs 4.605. Get that probability to 0.99 and the cost falls to 0.010.

The pass covers every weight in the bundle, and only one part of the bundle has an accuracy score, so the classifier is where the cost shows up.

The converter does not force a whole-bundle pass. `--quantize_uint8` takes an optional value, a comma-separated list of weight-name patterns, with wildcards for a family of names such as `conv/*/weights`. With no value it covers every weight, which is how the command below is written. Narrow the pattern and the language weights go to uint8 while the whole classifier stays at float32. The classifier is under a megabyte, so holding it out costs under a megabyte of the 255 MB the pass takes off the bundle. The crew did not narrow it. The classifier was mid-retrain that week, with its layer names still moving, so any pattern they wrote would have gone stale by the next build.

The technique runs exactly as deep as Nazari's arithmetic. If you've ever converted a 2 MB PNG to a 200 KB WebP and squinted at the invisible difference, you know the trade. Store each weight in one byte instead of four and the file lands at 85 MB. The rule of thumb people quote for the accuracy cost is about a point. Nazari does not take rules of thumb, and neither does this lesson: the figure that goes on the board is the one the holdout prints. The dashboard that died at 0249 has 512 MB of RAM and went down parsing a 340 MB weight file, so cutting that file to 85 MB is the first and largest payment on the debt.

## Precision Reduction

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="quantization.ts">
{`import * as tf from '@tensorflow/tfjs';

// Float32: full precision (default)
// 1.2345678 → stored as 4 bytes
// Model size: 85M params × 4 bytes = 340 MB

// Uint16 storage: 2 bytes per weight, 65,536 levels (0-65535) across the range
// (an affine integer mapping, not IEEE float16)
// File size: 85M params × 2 bytes = 170 MB

// Uint8 storage: 1 byte per weight, 256 levels (coarse, usually OK)
// File size: 85M params × 1 byte = 85 MB

// Simulate quantization effect
function quantizeWeights(weights: Float32Array, bits: 8 | 16): { quantized: number[]; scale: number; min: number } {
  // (teaching scale: on a real model's millions of weights, spread
  // arguments overflow the stack; use a loop or tf.min()/tf.max())
  const min = Math.min(...weights);
  const max = Math.max(...weights);
  const range = max - min;
  const levels = (1 << bits) - 1;  // 255 steps between 256 levels for 8-bit
  const scale = range / levels;

  const quantized = Array.from(weights).map(w =>
    scale === 0 ? 0 : Math.round((w - min) / scale)
  );

  // scale and min are the two numbers a TensorFlow.js weight manifest
  // stores for a quantized tensor. There is no zero point in this scheme.
  return { quantized, scale, min };
}

// Dequantize back to float: the exact arithmetic tfjs runs at load time
// (io_utils: value * scale + min), so the floats the model runs are these.
function dequantize(quantized: number[], scale: number, min: number): number[] {
  return quantized.map(q => q * scale + min);
}

// What this costs is one measurement away, and nothing here can tell you:
// the error on any single weight is at most half a bucket, but whether that
// moves a verdict depends on how close that verdict was. Score the decoded
// build against the trained one and read the difference.`}
</CodeBlock>

## Saving Quantized Models

<CodeBlock language="bash" title="quantize-on-export.sh">
{`# Quantization happens at EXPORT time, in the converter, not in
# model.save(). TFJS's save() writes float32, full stop; there is no
# quantization option on it. The tensorflowjs_converter (a one-time
# Python CLI step, alongside the tf2onnx export module 4 mentioned;
# nothing else in this course leaves JavaScript) rewrites the weight
# files and records the scheme in the weights manifest:

tensorflowjs_converter \\
  --input_format=tfjs_layers_model \\
  --output_format=tfjs_layers_model \\
  --quantize_uint16 \\
  ./model-f32/model.json ./model-q16/

# --quantize_uint8 for the 4x version. At load time in the browser,
# tf.loadLayersModel() reads the manifest and dequantizes back to
# float32 automatically; your inference code does not change.

# Size and accuracy for DEEP SCAN. The accuracy column is the classifier's,
# scored on the same holdout at every precision:
# float32 (no quantization):  340 MB, accuracy: 94.2%
# uint16  (--quantize_uint16): 170 MB, accuracy: 94.2%
# uint8   (--quantize_uint8):   85 MB, accuracy: 94.2%`}
</CodeBlock>

Read that accuracy column twice, because it is a measurement and not a rounding. The score sits at 94.2 before the pass and 94.2 after it, at both precisions. The width of one bucket is why. The widest weight tensor in this classifier spans 2.29, so uint8 lays 255 steps across that and one step comes out 0.0090 wide; the largest gap between a trained weight and the float the runtime decodes back is half a step, measured 0.0045 on this classifier. uint16 puts the step at 0.000035 and that largest gap at 0.000017. Nothing this classifier decides turns on a difference that small. Score 10,000 held-out captures instead of the usual slice and uint16 still moves no verdict at all, while uint8 moves three.

<Dialogue speaker="Dr. Farah">
Then write it the narrow way. Quantization cost this classifier nothing on this holdout. That is not a property of quantization, and the sentence stops being true the week the model changes.
</Dialogue>

One thing to be clear about before Nazari makes you be clear about it: TensorFlow.js decodes quantized weights back to float32 when the model loads. Loading is where the size shows up: the runtime holds the downloaded file buffer and the decoded float32 tensors at the same time, so a 340 MB file peaks near 680 MB, over the dashboard's 512 MB budget, while an 85 MB file peaks near 425 MB and survives. Once the load finishes, the resident weights are 340 MB either way, so nothing about the running model got smaller. The math of inference runs at the same speed as before, because no TensorFlow.js backend runs a model's weights as integers: by the time any op sees a weight, the loader has already decoded it to float32. What you bought is a 4x smaller download, a smaller disk cache, and a load spike the dashboard can survive. Runtimes like TFLite do run int8 compute kernels on integer silicon; in the browser, quantization is a storage format, not an execution mode. Two different things go by kernel here: a compute kernel is the routine that runs an operation on a backend, and a dense layer's kernel is its weight matrix, which is the one the exercise below quantizes.
