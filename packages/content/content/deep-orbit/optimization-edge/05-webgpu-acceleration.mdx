<Dialogue speaker="Dr. Farah">
That analogy survives about one paragraph of scrutiny. Web Workers keep the language and memory model you already trust; WebGPU replaces both — new shader language, new memory semantics, drivers you don't control. Trust the shape of the win. Don't trust the cost of entry.
</Dialogue>

Nazari isn't wrong about the triangles. WebGL runs tensor math by smuggling it through a graphics pipeline: data as textures, math as fragment shaders, overhead on every op. WebGPU's compute shaders run matrix multiplications and parallel reductions directly — which is most of what inference is.

<CodeBlock language="typescript" title="webgpu-setup.ts">
{`import * as tf from '@tensorflow/tfjs';

async function initBestBackend(): Promise<string> {
  // Try WebGPU first (fastest)
  if ('gpu' in navigator) {
    try {
      await tf.setBackend('webgpu');
      await tf.ready();
      return 'webgpu';
    } catch {
      console.log('WebGPU not available, falling back');
    }
  }

  // Fall back to WebGL (widely supported)
  try {
    await tf.setBackend('webgl');
    await tf.ready();
    return 'webgl';
  } catch {
    console.log('WebGL not available, falling back');
  }

  // Last resort: WASM (always works)
  await tf.setBackend('wasm');
  await tf.ready();
  return 'wasm';
}

const backend = await initBestBackend();
console.log('Using backend:', backend);

// Benchmark results for DEEP SCAN (42MB optimized model):
// WebGPU:  ~5ms per inference   (3x faster than WebGL)
// WebGL:   ~15ms per inference  (GPU via graphics API)
// WASM:    ~35ms per inference  (CPU, SIMD optimized)
// CPU:     ~120ms per inference (pure JavaScript)`}
</CodeBlock>
