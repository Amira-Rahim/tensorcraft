WebGL was designed for 3D graphics. ML inference works on it, but it's like using `<canvas>` to render a spreadsheet. WebGPU is designed for general-purpose GPU compute: matrix multiplications, parallel reductions, and the tensor operations that ML inference actually needs.

## WebGPU Backend

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="webgpu-setup.ts">
{`import * as tf from '@tensorflow/tfjs';

async function initBestBackend(): Promise<string> {
  // Try WebGPU first (fastest)
  if ('gpu' in navigator) {
    try {
      await tf.setBackend('webgpu');
      await tf.ready();
      return 'webgpu';
    } catch {
      console.log('WebGPU not available, falling back');
    }
  }

  // Fall back to WebGL (widely supported)
  try {
    await tf.setBackend('webgl');
    await tf.ready();
    return 'webgl';
  } catch {
    console.log('WebGL not available, falling back');
  }

  // Last resort: WASM (always works)
  await tf.setBackend('wasm');
  await tf.ready();
  return 'wasm';
}

const backend = await initBestBackend();
console.log('Using backend:', backend);

// Benchmark results for DEEP SCAN (42MB optimized model):
// WebGPU:  ~5ms per inference   (3x faster than WebGL)
// WebGL:   ~15ms per inference  (GPU via graphics API)
// WASM:    ~35ms per inference  (CPU, SIMD optimized)
// CPU:     ~120ms per inference (pure JavaScript)`}
</CodeBlock>
