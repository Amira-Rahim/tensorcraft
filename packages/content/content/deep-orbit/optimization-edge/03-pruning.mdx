      interface Classifier {
        getWeights: () => any[];
        setWeights: (weights: any[]) => void;
        predict: (input: any) => any;
      }

      interface LevelReport {
        sparsity: number;
        perClass: (number | null)[];
      }

      async function pruneAndScore(
        model: Classifier,
        samples: number[][],
        labels: number[],
        levels: number[],
      ): Promise<LevelReport[]> {
        if (levels.some((level) => !Number.isFinite(level) || level < 0 || level > 1))
          throw new Error('Invalid sparsity');
        const original = model.getWeights().map((w) => w.clone());
        const isKernel = (w: any) => w.shape.length === 2;
        const ranked = original
          .filter(isKernel)
          .flatMap((w) => Array.from(w.dataSync()).map(Math.abs))
          .sort((a, b) => a - b);

        const classCount = Math.max(...labels) + 1;
        const input = tf.tensor2d(samples);
        const report: LevelReport[] = [];

        try {
          for (const sparsity of levels) {
            const threshold = sparsity === 1 ? Infinity : ranked[Math.floor(ranked.length * sparsity)];
            const pruned = original.map((w) =>
              isKernel(w)
                ? tf.tensor(
                    Array.from(w.dataSync()).map((v) => (Math.abs(v) < threshold ? 0 : v)),
                    w.shape,
                  )
                : w,
            );
            try {
              model.setWeights(pruned);
            } finally {
              pruned.forEach((w, i) => {
                if (w !== original[i]) w.dispose();
              });
            }

            const prediction = tf.tidy(() => model.predict(input).argMax(1));
            let predicted;
            try {
              predicted = await prediction.data();
            } finally {
              prediction.dispose();
            }
            const correct = new Array(classCount).fill(0);
            const total = new Array(classCount).fill(0);
            labels.forEach((label, i) => {
              total[label] += 1;
              if (predicted[i] === label) correct[label] += 1;
            });

            report.push({
              sparsity,
              perClass: correct.map((hits, c) => (total[c] === 0 ? null : hits / total[c])),
            });
          }

          return report;
        } finally {
          try { model.setWeights(original); }
          finally { original.forEach((w) => w.dispose()); input.dispose(); }
        }
      }

## The cutoff and its class-level cost

The required experiment uses a supplied eleven-input, twelve-hidden-unit, five-class classifier. Pool the magnitudes of its two kernels, containing 132 and 60 weights, before selecting a cutoff. Biases stay outside that pool. The activity displays the first twelve positions of the first kernel and the checked reference results for the whole model.

For requested sparsity `s`, sort all 192 magnitudes and select position `floor(192 * s)`. Zero weights strictly below that cutoff. Keep ties at the cutoff, so the achieved zero fraction can differ from the request. Level zero preserves the weights. Level one zeroes every kernel position.

Read recall as `correct / support` for each class. The supplied labeled set contains forty synthetic captures per class. Its unpruned anomaly recall is `39 / 40`. At requested sparsities 0.3, 0.6, and 0.8, the checked reference keeps 38, 28, and zero of those forty anomaly cases correct. These are model measurements on an authored fixture, separate from the fictional mission's six anomalies.

A class absent from another labeled set has zero support and `null` recall. Zero would falsely claim that the model missed known examples. Check every class: full pruning can leave biases that always choose one class and give it perfect recall while failing the others.

Clone the original weights once. Start every level from those originals, and restore them in `finally`, including if a prediction fails. Comparing a second level against already-pruned weights would answer a different question.

{`import * as tf from '@tensorflow/tfjs';

function pruneWeights(weights: number[], sparsity: number): number[] {
  if (!Number.isFinite(sparsity) || sparsity < 0 || sparsity > 1 || !weights.every(Number.isFinite)) throw new Error('Invalid pruning inputs');
  if (!weights.length) return [];
  if (sparsity === 1) return weights.map(() => 0);
  // Sort by absolute value to find the threshold
  const sorted = weights.map(Math.abs).sort((a, b) => a - b);
  const threshold = sorted[Math.floor(sorted.length * sparsity)];

  // Zero out weights below threshold
  return weights.map(w => Math.abs(w) < threshold ? 0 : w);
}

// Example: request 60% sparsity, then read what you actually got.
const original = [0.5, -0.01, 0.002, -0.8, 0.003, 0.7, -0.001, 0.6];
const pruned = pruneWeights(original, 0.6);
console.log(pruned);
// [0.5, 0, 0, -0.8, 0, 0.7, 0, 0.6]
// 4 of 8 weights remain (4 pruned, those closest to zero:
// 60% of 8 rounds down to a cut of 4)

// Hold the result to tree-shaking's promise: same probe input,
// both weight sets, "nobody notices the difference."
const probe = new Array(original.length).fill(1);
const dot = (ws: number[]) => ws.reduce((sum, w, i) => sum + w * probe[i], 0);
console.log(dot(original).toFixed(3));  // 0.994
console.log(dot(pruned).toFixed(3));    // 1.000

// Sparsity levels for DEEP SCAN, one accuracy per level, scored on the
// natural mix of captures:
// 30% requested: 93.8% accuracy (vs 94.2% baseline)
// 60% requested: 91.8% accuracy
// 80% requested: 91.6% accuracy
// 90% requested: 71.2% accuracy
// These aggregate figures alone cannot approve any pruning level.`}

The output changed from 0.994 to 1.000. Tree-shaking should preserve a program's behavior, so Demir's analogy has already failed. The four removed weights contributed -0.006 to this output.

A small change on this input does not tell us what will happen on others. A small weight can multiply a large activation, and removing several weights can have a combined effect. Test representative data.

With **magnitude pruning**, we rank weights by absolute value and set the smallest to zero. This is unstructured pruning, so every tensor keeps its original shape.

For the model, rank all kernel weights together. Do not rank each layer separately. A layer with mostly small weights may lose many more connections than a layer with large weights.

Leave biases unchanged. Each Dense output unit has one bias and `inputWidth` kernel weights. The bias sets the unit's offset. Each kernel weight scales one input.

Read the accuracy table carefully. Its held-out data follows the mix of arriving captures: 6 labeled anomalies and 500 examples of each ordinary class. These six anomalies are separate from the six used in retraining.

Anomalies make up only 0.3 percent of this evaluation set. Losing every correct anomaly prediction changes overall accuracy by just 0.3 percentage points. Most visible changes in that column therefore come from the common classes. Even an unchanged total can hide a serious rare-class failure.

Compare recall for each class to see what the total hides. An evaluation set with equal class counts would also give a different overall result. The exercise asks you to report per-class recall: for each true class, the share of its readings the model labels correctly.

This run shows why Demir needed a per-class report. It does not prove that rare signals always depend on small weights.

Dense magnitude pruning keeps every weight slot, including zeroed values. With unchanged shapes and dtypes, the TFJS weight payload retains its size. Its dense manifest has no list of nonzero indexes. Repeated stored codes may compress well, but measure the result. An affine uint8 code representing zero need not be byte 0.

Structured pruning removes complete units or channels and changes tensor shapes. It can reduce storage and computation, but the resulting model still needs evaluation. Fine-tuning may recover quality. Some models fail to recover their earlier quality. This lesson uses unstructured pruning.

<DerivationDrawer summary="Why use weight size to estimate importance?">
A useful importance measure would estimate the change in loss when we set a weight to zero. Near a particular weight vector, a second-order approximation is:

```
Delta L ≈ g^T Delta w + 0.5 Delta w^T H Delta w
```

Here g is the gradient and H is the Hessian, including interactions between weights. If we remove only weight i, the approximation becomes `-g_i*w_i + 0.5*H_ii*w_i^2`. Near a stationary point the first term may be small. Training does not guarantee that condition.

Ranking only by magnitude ignores both curvature and interactions. Test this practical heuristic by measuring the resulting model. A small weight can still matter. The rare-class failures in the scenario do not establish a measured curvature explanation.
</DerivationDrawer>

<DerivationDrawer summary="Another way to compress a matrix: low-rank approximation">
A matrix may have an accurate low-rank approximation. For `W = U Sigma V^T`, keeping the largest k singular values gives the best rank-k approximation in Frobenius and spectral norm. The omitted singular values determine matrix approximation error. Task accuracy still needs evaluation.

A 512-by-512 matrix stores 262,144 numbers. At k = 40, storing both factors and 40 singular values takes 41,000 numbers, about 6.4 times fewer. This is useful only if the approximation preserves the behavior you need. There is no guarantee that a trained matrix has a small enough rank.

LoRA uses low-rank matrices for a different purpose: it trains an update while freezing the base weights. It does not replace the base matrix with its truncated SVD or automatically shrink the base model at inference.
</DerivationDrawer>
