## How Wrong Are We?

0.52 against a true label of 1.0 means the network is off by 0.48. Square that and you get 0.23, and averaging the squares across every prediction in a batch gives you mean squared error: one number that answers Farah's question. If you've written `expect(actual).toBe(expected)`, you've used the same idea before. A loss function is an assertion that returns a distance instead of a pass/fail.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="loss-functions.ts">
{`import * as tf from '@tensorflow/tfjs';

// Actual labels (ground truth)
const labels = tf.tensor([1, 0, 1, 0, 1]);

// Network predictions (untrained, pretty bad)
const predictions = tf.tensor([0.6, 0.4, 0.3, 0.7, 0.8]);

// Mean Squared Error: average of (prediction - label)^2
const mse = tf.losses.meanSquaredError(labels, predictions);
console.log('MSE:', mse.dataSync()); // 0.268

// Binary Crossentropy: better for classification (0 or 1).
// sigmoidCrossEntropy expects raw logits (pre-sigmoid outputs), not probabilities
const logits = tf.tensor([0.4, -0.4, -0.8, 0.8, 1.4]);
const bce = tf.losses.sigmoidCrossEntropy(labels, logits);
console.log('BCE:', bce.dataSync()); // ~0.718

// Perfect predictions → loss approaches 0
const perfect = tf.tensor([1, 0, 1, 0, 1]);
const perfectLoss = tf.losses.meanSquaredError(labels, perfect);
console.log('Perfect MSE:', perfectLoss.dataSync()); // 0`}
</CodeBlock>

One naming trap before the rest of the module builds on this. A **logit** is the number a neuron emits before any sigmoid touches it: unbounded, positive or negative, the raw weighted sum from module 2. `tf.losses.sigmoidCrossEntropy` takes logits and applies the sigmoid itself. The compile option you will use in lesson 4, `loss: 'binaryCrossentropy'`, takes probabilities, the numbers a sigmoid output layer has already produced. They are the same loss reached from two ends. Your task already picked cross-entropy, so what is left to pick is the form, and the last layer decides that. A sigmoid output layer hands you probabilities, so you call `binaryCrossentropy`. A last layer with no sigmoid hands you logits, so you call `sigmoidCrossEntropy`. Mix them up and nothing throws; the network learns the wrong thing quietly, which is the category of bug this course hunts hardest.

The rest of this module is machinery for making that one number smaller: gradients to find the direction, backprop to compute them fast, the loop to keep stepping.

<DerivationDrawer summary="MSE and cross-entropy from first principles">
**Why squared error?** MSE squares each error so positive and negative errors don't cancel, AND so large errors are penalized more than small ones (a 0.4 error counts 4× more than a 0.2 error). The formula:

`MSE = (1/n) Σ (yᵢ - ŷᵢ)²`

**Why cross-entropy for classification?** The usual answer is "MSE's gradient goes flat near 0 and 1." That answer is wrong, and it is worth being precise about why, because the real reason is more useful.

`BCE = -(1/n) Σ [ yᵢ log(ŷᵢ) + (1-yᵢ) log(1-ŷᵢ) ]`

Take the label `y = 1` and a model that confidently predicts `ŷ = 0.01`. MSE's gradient **with respect to the prediction** is `2(ŷ - y) = -1.98`: not flat, and in fact the biggest it ever gets. Nothing is wrong with MSE's own slope.

What flattens is the sigmoid you put in front of it. Backprop multiplies by `σ'(z) = ŷ(1-ŷ)`, and at `ŷ = 0.01` that factor is `0.0099`. So the gradient that actually reaches the weights is:

- MSE + sigmoid: `2(ŷ - y) · ŷ(1-ŷ) = -1.98 × 0.0099 = -0.0196`
- BCE + sigmoid: the `log` and the `σ'` cancel exactly, leaving `ŷ - y = -0.99`

Fifty times more signal, for the same wrongness. Cross-entropy's advantage is not that its curve is steeper; it is that its derivative is **built to cancel the sigmoid's**, so a confidently wrong prediction reaches the weights at full strength instead of being multiplied by a number near zero. This factor is the saturation you met by name in `neural-networks/02`: a sigmoid pushed into its tail goes flat, and 0.0099 is what flat costs.

Note where the advantage lives, because the intuition runs backwards from most explanations. At the decision boundary (`ŷ = 0.5`) the two are nearly the same: `-0.25` vs `-0.5`, a factor of 2. The gap only opens as the model gets *more confidently wrong*: 5.6× at `ŷ = 0.1`, 50× at `ŷ = 0.01`. Cross-entropy is not for the boundary. It is for the disaster.
</DerivationDrawer>
