## How Wrong Are We?

A prediction of 0.52 against a label of 1.0 has an error of 0.48. Square it and you get about 0.23. Average those squared errors across the batch to get **mean squared error**, or MSE.

A test assertion such as `expect(actual).toBe(expected)` tells you pass or fail. A loss gives training a number to reduce. Some losses are not mathematical distances. Compare losses on the same examples using the same rule. A lower training loss alone does not prove the model works on new data.

<CodeBlock language="typescript" title="loss-functions.ts">
{`import * as tf from '@tensorflow/tfjs';

// Actual labels (ground truth)
const labels = tf.tensor([1, 0, 1, 0, 1]);

// Network predictions (untrained, pretty bad)
const predictions = tf.tensor([0.6, 0.4, 0.3, 0.7, 0.8]);

// Mean Squared Error: average of (prediction - label)^2
const mse = tf.losses.meanSquaredError(labels, predictions);
console.log('MSE:', mse.dataSync()); // 0.268

// Binary crossentropy: a common objective for binary labels (0 or 1).
// sigmoidCrossEntropy expects raw logits (pre-sigmoid outputs), not probabilities
const logits = tf.tensor([0.4, -0.4, -0.8, 0.8, 1.4]);
const bce = tf.losses.sigmoidCrossEntropy(labels, logits);
console.log('BCE:', bce.dataSync()); // ~0.718

// Perfect predictions → loss approaches 0
const perfect = tf.tensor([1, 0, 1, 0, 1]);
const perfectLoss = tf.losses.meanSquaredError(labels, perfect);
console.log('Perfect MSE:', perfectLoss.dataSync()); // 0
tf.dispose([labels, predictions, mse, logits, bce, perfect, perfectLoss]);`}
</CodeBlock>

A **logit** is the raw score before sigmoid. It can be negative or positive, with no fixed upper or lower bound. Binary cross-entropy has two API forms:

- `tf.losses.sigmoidCrossEntropy` takes logits and applies sigmoid itself.
- `loss: 'binaryCrossentropy'` takes probabilities already produced by a sigmoid output layer. You will use it in lesson 4.

Choose the form that matches what the output represents. Do not pass probabilities to the logits API, because it would apply sigmoid again. An unfamiliar activation name is not enough information to choose.

The rest of this module is machinery for making that one number smaller: gradients to find the direction, backprop to compute them fast, the loop to keep stepping.

<DerivationDrawer summary="MSE and cross-entropy from first principles">
Three symbols run through this drawer. Σ means add up one term per row in the batch, ŷ (say y-hat) is the model's prediction against the true label y, and a prime mark means the slope of that function, so `σ'` is the slope of the sigmoid.

**Why squared error?** MSE squares each error so positive and negative errors don't cancel, AND so large errors are penalized more than small ones (a 0.4 error counts 4× more than a 0.2 error). The formula:

`MSE = (1/n) Σ (yᵢ - ŷᵢ)²`

**Why cross-entropy for classification?** The usual answer is "MSE's gradient goes flat near 0 and 1." That answer is wrong, and it is worth being precise about why, because the real reason is more useful.

`BCE = -(1/n) Σ [ yᵢ log(ŷᵢ) + (1-yᵢ) log(1-ŷᵢ) ]`

Take the label `y = 1` and a model that confidently predicts `ŷ = 0.01`. MSE's gradient **with respect to the prediction** is `2(ŷ - y) = -1.98`: not flat, close to the largest magnitude it reaches for predictions in [0, 1]. Nothing is wrong with MSE's own slope.

What flattens is the sigmoid you put in front of it. Backprop multiplies by `σ'(z) = ŷ(1-ŷ)`, and at `ŷ = 0.01` that factor is `0.0099`. So the gradient that actually reaches the weights is:

- MSE + sigmoid: `2(ŷ - y) · ŷ(1-ŷ) = -1.98 × 0.0099 = -0.0196`
- BCE + sigmoid: the `log` and the `σ'` cancel exactly, leaving `ŷ - y = -0.99`

Here, the BCE derivative with respect to the output logit is about fifty times larger. In the ideal, unclipped calculation, the final sigmoid derivative cancels out.

Earlier operations still affect the weight gradients. Hidden layers can therefore still have very small or zero gradients. A stable logits API also avoids taking logs of probabilities rounded to zero or one.

Note where the advantage lives, because the intuition runs backwards from most explanations. At the decision boundary (`ŷ = 0.5`) the two are nearly the same: `-0.25` vs `-0.5`, a factor of 2. The gap only opens as the model gets *more confidently wrong*: 5.6× at `ŷ = 0.1`, 50× at `ŷ = 0.01`.
</DerivationDrawer>
