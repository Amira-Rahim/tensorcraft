The method Demir reached for needs no new math, which is exactly why he reached for it: nudge one weight, rerun the network, see how the loss moved. You know how to do that already. So before this lesson hands you anything, do it his way and watch what it costs.

## The Method You Already Have

One weight, one question: if I move this a little, does the loss go down? Nothing stops you from asking it 673 times.

<CodeBlock language="typescript" title="gradient-by-nudging.ts">
{`// Numeric gradient: nudge one weight, rerun, compare. No calculus.
const EPS = 1e-3;

function nudgedLoss(w: tf.Variable, index: number): number {
  const values = w.dataSync().slice();
  values[index] += EPS;
  w.assign(tf.tensor(values, w.shape));
  const loss = computeLoss();          // one full forward pass
  values[index] -= EPS;
  w.assign(tf.tensor(values, w.shape)); // restore the weight
  return loss;
}

const base = computeLoss();             // forward pass 0
// gradient ≈ how much the loss moved, per unit of nudge
const grad = (nudgedLoss(w1, 0) - base) / EPS;`}
</CodeBlock>

It works. It is also a forward pass **per parameter, per training step**: 673 extra forward passes to update the network once, thousands of steps per training run. On the engineering rig that's 27 seconds per step; a run that takes minutes with the backward pass stretches past thirty hours. The method is correct at a cost nothing can pay, and removing that cost is the reason this lesson exists.

<Dialogue speaker="ARIA" expression="deadpan">
Estimating the gradient for each of 673 parameters one nudge at a time costs 673 additional forward passes. I have now watched you pay that price once. There exists a procedure that computes all 673 derivatives exactly in one backward sweep, at a cost of roughly two forward passes. It has a name.
</Dialogue>

## Working Backwards

The name is **backpropagation**. A call chain already runs in two directions: the calls go down, `main` into `readFile` into `parseRow`, and when `parseRow` throws, the error comes back up the same path it came down, every frame adding its line to the trace. Backpropagation has that same two-pass shape. The forward pass runs input to output computing the loss, then the backward pass runs output back to input, each layer folding what it receives into the gradient it hands to the layer below.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="backpropagation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Build a simple network with trackable weights
const w1 = tf.variable(tf.randomNormal([3, 4]));  // layer 1 weights
const b1 = tf.variable(tf.zeros([4]));              // layer 1 bias
const w2 = tf.variable(tf.randomNormal([4, 1]));   // layer 2 weights
const b2 = tf.variable(tf.zeros([1]));              // layer 2 bias

const input = tf.tensor2d([[0.5, 0.8, 0.2]]);
const label = tf.tensor2d([[1]]);

// Forward pass + loss computation + automatic backprop
const { value: loss, grads } = tf.variableGrads(() => {
  // Forward: input → layer1 → relu → layer2 (raw logits)
  // sigmoidCrossEntropy applies the sigmoid itself, so feed it logits
  const hidden = tf.relu(input.matMul(w1).add(b1));
  const logits = hidden.matMul(w2).add(b2);
  return tf.losses.sigmoidCrossEntropy(label, logits).mean() as tf.Scalar;
});

// grads now contains gradients for ALL 4 variables
console.log('Loss:', loss.dataSync()[0]);
console.log('w1 gradient shape:', grads[w1.name].shape); // [3, 4]
console.log('w2 gradient shape:', grads[w2.name].shape); // [4, 1]

// Each gradient tells us: "adjust this weight by this much"`}
</CodeBlock>

No magic involved: `tf.variableGrads()` records every operation during the forward pass, then computes gradients for all variables by applying the chain rule backwards. The drawer below walks the exact multiplication chain by hand. You never have to implement it manually, but you can.

<DerivationDrawer summary="Chain rule applied to a 2-layer network, by hand">
**The chain rule:** if `y = f(g(x))`, then `dy/dx = f'(g(x)) · g'(x)`. For a 2-layer network:

```
z₁ = w₁·x + b₁          ← layer 1 pre-activation
a₁ = ReLU(z₁)            ← layer 1 activation
z₂ = w₂·a₁ + b₂          ← layer 2 pre-activation
ŷ  = σ(z₂)               ← layer 2 output (sigmoid)
L  = ½(ŷ - y)²           ← loss
```

**Goal:** compute `∂L/∂w₁` (gradient of loss w.r.t. layer-1 weights). Apply chain rule from L back to w₁:

```
∂L/∂w₁ = ∂L/∂ŷ · ∂ŷ/∂z₂ · ∂z₂/∂a₁ · ∂a₁/∂z₁ · ∂z₁/∂w₁
       = (ŷ - y)  · σ'(z₂)  ·   w₂    ·  ReLU'(z₁)  ·  x
```

Each factor is local to one layer. `tf.variableGrads()` builds the computational graph during forward pass, then walks it backward multiplying these local derivatives. **That backward walk is the entire algorithm**: there is no other magic. The "1 backward pass" claim above is exactly this multiplication chain.

**Vanishing gradients = the chain product collapsing.** If `σ'(z₂) ≈ 0.1`, `ReLU'(z₁) ∈ {0,1}`, and you have 20 layers, the product can be `0.1²⁰ ≈ 10⁻²⁰`. The early-layer weights stop updating. Residual connections add `+1` to each link in the chain to prevent this collapse.
</DerivationDrawer>
