## One weight and two loss values

Demir first checks the methods on the supplied scalar test loss, `loss = w²`.
The diagram above uses that same calculation. This test checks the gradient
methods before he applies them to the network. It contains no sensor readings
and trains no model.

At `w = 2`, the loss is `4`. At `w = 2.001`, it is about `4.004001`.
The change in loss divided by the change in weight is about `4.001`.
That number estimates the local slope, also called the **gradient**. A
positive slope means a small increase in this weight raises the loss.

<CodeBlock language="typescript" title="scalar-slope.ts">
{`// Compare two nearby weights without changing a model.
const sampleWeights = tf.tensor1d([2, 2.001]);
const sampleLosses = sampleWeights.square();
const values = sampleLosses.dataSync();
const estimate = (values[1] - values[0]) / 0.001;
console.log(estimate); // approximately 4.001, with float32 rounding

tf.dispose([sampleWeights, sampleLosses]);`}
</CodeBlock>

This **forward finite difference** needs two loss values. A large nudge gives
a rough estimate. A very small one can lose accuracy when you subtract nearly
equal floating-point numbers.

The challenge measures a loss function that reads a variable. To nudge that
variable safely, save its original value and use `assign()` to change it.
Restore it in a `finally` block, which runs even if the measurement throws.
`tf.tidy()` can release temporary tensors, but it cannot undo an assignment.

<CodeBlock language="typescript" title="temporary-weight.ts">
{`const probe = tf.tidy(() => tf.variable(tf.scalar(2)));
const savedWeight = probe.dataSync()[0];

try {
  tf.tidy(() => probe.assign(tf.scalar(savedWeight + 0.001)));
  console.log(probe.dataSync()[0]); // the temporary weight
} finally {
  tf.tidy(() => probe.assign(tf.scalar(savedWeight)));
  console.log(probe.dataSync()[0]); // 2 again
  probe.dispose();
}`}
</CodeBlock>

In your numerical function, measure the original loss before the `try`, then
measure the changed loss inside it. Move only the selected variable. Keep the
other variables fixed so the loss change belongs to that one nudge.

## The same slope from the calculation

For `loss = w × w`, the weight appears twice. Each path contributes `w` to
the slope, giving `w + w`. At `w = 2`, the gradient is `4`. The
**chain rule** combines local slopes along a calculation. Backpropagation
multiplies them along each path, then adds contributions where paths meet.
The diagram compares that gradient with the nearby-value estimate.

**Backpropagation** applies the chain rule backward through the operations
recorded during the forward calculation. TensorFlow.js can do this for you:

<CodeBlock language="typescript" title="automatic-slope.ts">
{`const testWeight = tf.tidy(() => tf.variable(tf.scalar(2)));
const result = tf.variableGrads(() => testWeight.square());

console.log(result.value.dataSync()[0]); // loss: 4
console.log(result.grads[testWeight.name].dataSync()[0]); // gradient: 4
console.log(testWeight.dataSync()[0]); // weight: still 2

tf.dispose([result.value, ...Object.values(result.grads), testWeight]);`}
</CodeBlock>

`value` holds the scalar loss tensor. `grads` maps variable names to gradient
tensors. Use `grads[variable.name]` to find the matching gradient. Call
`tf.variableGrads()` again when the weight or loss function changes so the
result describes the new calculation.

Computing these gradients leaves the weights unchanged. An optimizer, or
your own update code, uses them in a separate step.

The backward direction may remind you of an error traveling from `parseRow`
through `readFile` to `main`. An exception transfers program control.
Backpropagation combines derivatives through a recorded calculation.

## Several weights from one recorded calculation

The challenge also supplies `sin(a) + b² + c × a`, with three variables.
Here, `a` affects both the sine and the product. Its gradient must include
both paths. Your automatic function must handle this changed loss without
assuming that every variable is squared.

One call records that loss calculation and returns all three gradients.
Your numerical function measures the base and nudged loss separately for
each variable, so three estimates need at least six forward calculations.
The two result tables show the gradients and counts from your actual code.
The numerical estimates may differ slightly because of the nudge and float32
rounding.

Demir's network has 673 parameters. If he shares one base loss, nudging each
parameter still needs 673 additional forward passes. Backpropagation reuses
one forward calculation and computes the gradients in a backward sweep.
Those counts explain the repeated work. Elapsed time also depends on the
calculation and backend.

<ConceptReference summary="The same gradient call in a two-layer network">

This supporting example builds a separate small network with random weights.
It uses the same `value` and `grads` return structure. The scalar and
three-variable comparisons above cover the coding task's required behavior.

<CodeBlock language="typescript" title="backpropagation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Build a simple network with trackable weights
const w1 = tf.tidy(() => tf.variable(tf.randomNormal([3, 4])));  // layer 1 weights
const b1 = tf.tidy(() => tf.variable(tf.zeros([4])));              // layer 1 bias
const w2 = tf.tidy(() => tf.variable(tf.randomNormal([4, 1])));   // layer 2 weights
const b2 = tf.tidy(() => tf.variable(tf.zeros([1])));              // layer 2 bias

const input = tf.tensor2d([[0.5, 0.8, 0.2]]);
const label = tf.tensor2d([[1]]);

// Forward pass + loss computation + automatic backprop
const { value: loss, grads } = tf.variableGrads(() => {
  // Forward: input to layer1 to relu to layer2 (raw logits)
  // sigmoidCrossEntropy applies the sigmoid itself, so feed it logits
  const hidden = tf.relu(input.matMul(w1).add(b1));
  const logits = hidden.matMul(w2).add(b2);
  return tf.losses.sigmoidCrossEntropy(label, logits) as tf.Scalar;
});

// grads now contains gradients for ALL 4 variables
console.log('Loss:', loss.dataSync()[0]);
console.log('w1 gradient shape:', grads[w1.name].shape); // [3, 4]
console.log('w2 gradient shape:', grads[w2.name].shape); // [4, 1]

// Gradients give local slopes. The optimizer uses them to choose updates.
tf.dispose([input, label, loss, ...Object.values(grads), w1, b1, w2, b2]);`}
</CodeBlock>

</ConceptReference>

The derivation below expands the chain rule for a two-layer scalar network. It also explains why some long products of derivatives become very small.

<DerivationDrawer summary="Chain rule applied to a 2-layer network, by hand">
**The chain rule:** if `y = f(g(x))`, then `dy/dx = f'(g(x)) · g'(x)`. For a two-layer scalar example (one unit per layer):

```
z₁ = w₁·x + b₁          (layer 1 pre-activation)
a₁ = ReLU(z₁)            (layer 1 activation)
z₂ = w₂·a₁ + b₂          (layer 2 pre-activation)
ŷ  = σ(z₂)               (layer 2 output, sigmoid)
L  = ½(ŷ - y)²           (loss)
```

**Goal:** compute `∂L/∂w₁` (gradient of loss w.r.t. layer-1 weights). Apply chain rule from L back to w₁:

```
∂L/∂w₁ = ∂L/∂ŷ · ∂ŷ/∂z₂ · ∂z₂/∂a₁ · ∂a₁/∂z₁ · ∂z₁/∂w₁
       = (ŷ - y)  · σ'(z₂)  ·   w₂    ·  ReLU'(z₁)  ·  x
```

Each factor is local to one layer. `tf.variableGrads()` builds the computational graph during the forward pass, then walks it backward multiplying these local derivatives. This is the backward pass referred to above.

**Vanishing gradients** occur when repeated derivative factors make early gradients very small. Twenty factors near 0.1 multiply to about 10⁻²⁰. For vectors, the derivatives are matrices called **Jacobians**. Backpropagation multiplies them and adds contributions from different paths. Small factors can still weaken the result.

A residual block, `y = x + F(x)`, adds a direct path from input to output. Its Jacobian is `I + J_F`, where `I` is the identity matrix. This can help gradients pass through, but does not guarantee they will never vanish or grow too large.
</DerivationDrawer>
