## The Learning Loop

`setImmediate(loop)` gives you a loop only because each callback queues the next one: do a pass, check the exit condition, re-schedule, with the event loop free for other work in between. Training has that same self-rescheduling shape, plus one problem a drain loop never has. Nothing hands training its last iteration.

<CodeBlock language="typescript" title="training-loop.ts">
{`import * as tf from '@tensorflow/tfjs';

// Prepare the model (from previous lesson)
const model = tf.sequential();
model.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [3] }));
model.add(tf.layers.dense({ units: 16, activation: 'relu' }));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
model.compile({ optimizer: 'adam', loss: 'binaryCrossentropy', metrics: ['accuracy'] });

// Synthetic practice data, not spacecraft measurements. Each class has
// three bounded features drawn from different distributions. Clipping
// enforces this fixture's chosen range; min-max scaling alone does not
// stop future observations from falling outside a fitted range.
const { trainX, trainY } = tf.tidy(() => {
const calm = tf.clipByValue(tf.concat([
  tf.randomNormal([50, 1], 0.17, 0.10, 'float32', 7),
  tf.randomNormal([50, 1], 0.81, 0.10, 'float32', 8),
  tf.randomNormal([50, 1], 0.23, 0.10, 'float32', 9),
], 1), 0, 1);
const flagged = tf.clipByValue(tf.concat([
  tf.randomNormal([50, 1], 0.84, 0.10, 'float32', 41),
  tf.randomNormal([50, 1], 0.18, 0.10, 'float32', 42),
  tf.randomNormal([50, 1], 0.78, 0.10, 'float32', 43),
], 1), 0, 1);
const xs = tf.concat([calm, flagged]);
const ys = tf.concat([tf.zeros([50, 1]), tf.ones([50, 1])]);

// Shuffle once: validationSplit takes the LAST rows, and a validation
// set with one class cannot assess both classes. This random split is
// suitable for this independent synthetic fixture. Real time series need
// a time/group split before any training-only shuffle.
const order = Array.from(tf.util.createShuffledIndices(100));
const trainX = xs.gather(order);
const trainY = ys.gather(order);
return { trainX, trainY };
});

// THE TRAINING LOOP: model.fit() handles everything
const history = await model.fit(trainX, trainY, {
  epochs: 50,             // iterate over dataset 50 times
  batchSize: 32,          // process 32 samples at a time
  validationSplit: 0.2,   // hold out 20% for validation
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      if (epoch % 10 === 0) {
        console.log(\`Epoch \${epoch}: loss=\${logs?.loss.toFixed(4)}, acc=\${logs?.acc.toFixed(4)}\`);
      }
    },
  },
});

// Inspect history.history.loss and history.history.val_loss for YOUR run.
// Initialization and shuffling are random; exact scores are not promised.
// Keep model, trainX and trainY for the next two blocks.
`}
</CodeBlock>

These deliberately separated clusters make a small training exercise tractable. They do not represent the full range of a real stream. A high score on another draw from the same generator shows performance on that generator, not on spacecraft telemetry or unknown anomalies.

<DerivationDrawer summary="Why identical code lands on different losses: the loss landscape">
**Loss is a surface over weight space.** A network with n weights defines `L(w)`: one loss value for every point in n-dimensional weight space. Training is descent on that surface, and the epoch trace above is an altitude log.

**Convex vs non-convex.** On a convex objective, every local minimum is global. Ordinary least-squares and unregularized logistic regression have convex objectives, but stable optimization still depends on step sizes, feature scaling and other assumptions. Convexity alone does not guarantee that any gradient-descent run converges. Neural networks give that up: stacking layers with nonlinear activations folds the bowl into many basins separated by ridges and flats.

**Why reruns can disagree.** Initialization, row shuffling and backend arithmetic can change the path. Record those settings when comparing experiments. A different result does not, by itself, identify a particular basin or training defect.

**Saddles and flat regions can also slow training.** A saddle curves upward in some directions and downward in others. Small gradients can occur near saddles or in other flat regions, but a stalled loss trace does not identify which geometry caused it. Adam uses running gradient statistics to adjust updates; it does not guarantee escape or convergence.
</DerivationDrawer>

Three of the four settings in the `fit()` call above are dials. `epochs` is how many passes over the data. `batchSize` is how many rows the optimizer sees before it updates the weights, 32 here and by default, so one weight update per batch. `validationSplit` is the fraction held back so the run is checked against rows it never trained on. `epochs` is the judgment call: more passes mean more learning, up to a point.

Demir gives the run 500 epochs because he does not know when to stop. A larger budget buys more updates, but their value has to be measured. Validation monitoring makes the stopping rule explicit rather than treating an epoch count as proof of learning.

The fix is a callback that watches the validation loss and halts when it stops improving, so the loop stops itself instead of trusting your epoch guess:

<CodeBlock language="typescript" title="early-stopping.ts">
{`// Continues training-loop.ts. A new model starts a separate experiment;
// fitting the existing model would continue from its current weights.
const rerun = tf.sequential();
rerun.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [3] }));
rerun.add(tf.layers.dense({ units: 16, activation: 'relu' }));
rerun.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
rerun.compile({ optimizer: 'adam', loss: 'binaryCrossentropy', metrics: ['accuracy'] });

// Corrupt six TRAINING labels to explore noisy supervision. The final
// 20 rows used for validation remain untouched. Conflicting nearby
// examples do not impose a hard loss floor: a flexible model can memorize
// individual rows. A plateau or halt is an observation, not a guarantee.
const labels = trainY.arraySync();
for (const i of [3, 17, 29, 41, 52, 68]) labels[i] = [1 - labels[i][0]];

const noisyY = tf.tensor2d(labels);
const stopped = await rerun.fit(trainX, noisyY, {
  epochs: 500,            // an upper bound now, not a target
  validationSplit: 0.2,
  callbacks: tf.callbacks.earlyStopping({
    monitor: 'val_loss',  // stop when the HELD-OUT loss stops falling
    patience: 5,          // give it 5 epochs of no improvement first
  }),
});
console.log('Epochs completed:', stopped.epoch.length);
noisyY.dispose();
rerun.dispose();
// Keep the first model and clean tensors for evaluation in lesson 5.
`}
</CodeBlock>

Early stopping leaves the final epoch's weights in place in TFJS 4.22.0. With `minDelta: 0` and `patience: 5`, it stops after five epochs that fail to improve the best monitored value, unless the budget ends first. It does not prove convergence or overfitting. This version does not implement `restoreBestWeights: true`. To retain the best checkpoint, clone its weight tensors when validation improves, restore them after fitting, and dispose the snapshots.

<DerivationDrawer summary="The 7-step loop that fit() hides, and what Adam changes in step 4">
**`model.fit()` is a wrapper around this loop.** Sampling mini-batches instead of the whole dataset is what makes it stochastic gradient descent: each batch is a random sample, so each gradient is only an estimate of the true one. Without early stopping, the inner update runs `epochs × ceil(trainingRows / batchSize)` times, including a partial final batch. Validation rows are excluded:

```
for epoch in 1..N:
  shuffle(trainX, trainY)
  for batch in chunks(trainX, batchSize):
      // 1. Forward pass: predictions ŷ (y-hat) for this batch
      ŷ = model.forward(batch.x)

      // 2. Loss: how wrong on this batch
      L = lossFn(ŷ, batch.y)

      // 3. Backward pass: gradients via chain rule
      ∇w = backward(L, model.params)

      // 4. Update: step opposite to gradient
      for w in model.params:
          w := w - learningRate * ∇w[w]

      // 5. Log batch metrics
  // 6. End-of-epoch: validate on heldout set
  if val_loss not improving for K epochs:   // K = patience, typically 5-10
      // 7. Stop early
      break
```

**Step 4 is the one line `optimizer` swaps out.** Under a plain `optimizer: 'sgd'` that line is exactly the rule above. Under `optimizer: 'adam'`, which both networks in this lesson and the exercise below use, it is not. The learning rate lives on the optimizer, so it belongs to `compile()`, and `fit()` silently ignores a `learningRate` option. Both nets here pass the optimizer as a bare string, so each takes its default rate. That is why lesson 2's most important knob appears nowhere in this lesson's code.

**What Adam changes.** It tracks moving averages of gradients and squared gradients, corrects their initial bias, and divides the first by the square root of the second plus a small stabilizer. The base learning rate still scales the update. TFJS defaults Adam to 0.001; use `tf.train.adam(lr)` to choose another value. Adaptation does not guarantee stable steps or escape from flat regions.

**Why mini-batches?** They trade memory, throughput and gradient variability. Full-batch training uses the full training objective per update; single-example updates use one row. Neither is universally worse. Try batch sizes that fit the model and device, then compare learning and throughput. There is no universal 32-512 range that saturates every GPU.

**Why shuffle?** For independent examples, it reduces dependence on file ordering. It must preserve features and labels together. Do not shuffle across train/validation boundaries or destroy the temporal order inside a sequence.
</DerivationDrawer>
