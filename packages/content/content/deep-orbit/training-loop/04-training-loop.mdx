## The Learning Loop

`setImmediate(loop)` gives you a loop only because each callback queues the next one: do a pass, check the exit condition, re-schedule, with the event loop free for other work in between. Training has that same self-rescheduling shape, plus one problem a drain loop never has. Nothing hands training its last iteration.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="training-loop.ts">
{`import * as tf from '@tensorflow/tfjs';

// Prepare the model (from previous lesson)
const model = tf.sequential();
model.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [3] }));
model.add(tf.layers.dense({ units: 16, activation: 'relu' }));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
model.compile({ optimizer: 'adam', loss: 'binaryCrossentropy', metrics: ['accuracy'] });

// Training data: 100 labeled readings, three features each:
// [amplitude, frequency, phase], each min-max normalized against the
// range its own sensor can produce, so amplitude 1.00 means the hull
// sensor pegged at its full 2048 counts. These 100 rows are hand-picked
// clean examples from the flag log, 50 per label, which is why every
// channel arrives as two tight clusters rather than one spread.
// Flagged windows run hot on amplitude and phase and LOW on frequency
// (frequency here is a zero-crossing count, and a clean tone crosses
// zero far less often than broadband noise); calm periods are the
// mirror image. The seeds make the DATA reproducible. A net trained on
// pure noise could still memorize it. Its training loss would fall
// while the held-out loss sat at 0.693, the coin-flip number. Reading
// that pair is what this lesson teaches.
//
// clipByValue is doing real work here. A normal draw has no bounds, and
// on these seeds six of the 150 calm values land outside [0, 1]: one
// negative amplitude, two negative phases, and three frequencies above
// 1.00, the highest at 1.0387. Read back through the min-max range,
// 1.0387 means 65 zero crossings in a window that can only hold 63.
// Clip every column to [0, 1] and the synthetic rows obey the same
// limits the sensors do.
const calm = tf.clipByValue(tf.concat([
  tf.randomNormal([50, 1], 0.17, 0.10, 'float32', 7),
  tf.randomNormal([50, 1], 0.81, 0.10, 'float32', 8),
  tf.randomNormal([50, 1], 0.23, 0.10, 'float32', 9),
], 1), 0, 1);
const flagged = tf.clipByValue(tf.concat([
  tf.randomNormal([50, 1], 0.84, 0.10, 'float32', 41),
  tf.randomNormal([50, 1], 0.18, 0.10, 'float32', 42),
  tf.randomNormal([50, 1], 0.78, 0.10, 'float32', 43),
], 1), 0, 1);
const xs = tf.concat([calm, flagged]);
const ys = tf.concat([tf.zeros([50, 1]), tf.ones([50, 1])]);

// Shuffle once: validationSplit takes the LAST rows, and a validation
// set that is all flagged windows validates nothing.
const order = Array.from(tf.util.createShuffledIndices(100));
const trainX = xs.gather(order);
const trainY = ys.gather(order);

// THE TRAINING LOOP: model.fit() handles everything
const history = await model.fit(trainX, trainY, {
  epochs: 50,             // iterate over dataset 50 times
  batchSize: 32,          // process 32 samples at a time
  validationSplit: 0.2,   // hold out 20% for validation
  callbacks: {
    onEpochEnd: (epoch, logs) => {
      if (epoch % 10 === 0) {
        console.log(\`Epoch \${epoch}: loss=\${logs?.loss.toFixed(4)}, acc=\${logs?.acc.toFixed(4)}\`);
      }
    },
  },
});

// One real run. Weight init is random, so reruns differ: across 800
// reruns of this block, epoch-10 accuracy landed anywhere from 0.45 to
// 1.00, hit 1.00 by epoch 30 in 758 of the 800, and epoch-40 loss ran
// from 0.10 to 0.49.
// Epoch 0:  loss=0.7384, acc=0.4625
// Epoch 10: loss=0.6593, acc=0.9250
// Epoch 20: loss=0.5682, acc=1.0000
// Epoch 30: loss=0.4427, acc=1.0000
// Epoch 40: loss=0.2954, acc=1.0000
// Accuracy tops out before loss finishes falling: the net finds the
// boundary first, then spends the remaining epochs getting confident
// about it.`}

Two clean ends of the flag log are not a sample of the stream, and the amplitude column is where that shows. No training row lands between 0.38 and 0.65. Module 7 measures the archive's normal amplitude at mean 0.52 with a standard deviation of 0.15, which puts about two thirds of calm readings inside that empty band. Frequency and phase carry the label anyway. An amplitude pegged at full scale on an otherwise calm reading came back at a median 0.45, under the 0.5 line, though 72 of the 200 runs put it above. The empty band costs something exactly once, on the reading in lesson 5 that sits mid-scale on all three channels at once.

<DerivationDrawer summary="Why identical code lands on different losses: the loss landscape">
**Loss is a surface over weight space.** A network with n weights defines `L(w)`: one loss value for every point in n-dimensional weight space. Training is descent on that surface, and the epoch trace above is an altitude log.

**Convex vs non-convex.** A convex surface is a bowl: every local minimum is the global minimum, and gradient descent converges to it from any starting point. Linear and logistic regression have convex losses, which is why they never need a rerun. Neural networks give that up: stacking layers with nonlinear activations folds the bowl into many basins separated by ridges and flats.

**That is why the 800 reruns disagree.** Random initialization drops each run at a different point on the same landscape. Different basin, different descent path, different epoch-10 accuracy (the 0.45 to 1.00 spread above). No code changed between runs; only the starting coordinates did.

**Saddle points outnumber local minima in high dimensions.** A saddle curves up in some directions and down in others; the Hessian (the matrix of second derivatives) classifies the point by the sign of its curvature along each direction: all positive for a minimum, mixed for a saddle. A true local minimum needs upward curvature in all n directions at once, and with thousands of weights that coincidence gets rarer with every added dimension. What actually stalls training is the near-zero gradient on the plateaus around saddles. Momentum-based optimizers like Adam carry enough velocity to coast across them, which is one reason `optimizer: 'adam'` is the house default.
</DerivationDrawer>

**Key parameters:**
- **epochs**: How many times to iterate over the full dataset. More epochs = more learning (up to a point).
- **batchSize**: How many samples to process before updating weights. 32 is a good default.
- **validationSplit**: Fraction of data held out to check for overfitting.

"Up to a point" is the whole problem: nothing in the loop tells you where the point is. Demir's first run was not the curve above. Reasoning from drain loops, where another pass always means less backlog, he set `epochs: 500` to be safe and went for coffee. Forty minutes later both curves read about 0.0004, down from a validation loss near 0.14 at epoch 50. That run is the better model, and he could not have known it would be. Ten times the compute bought a gain nobody was watching for, on an epoch count picked before the first epoch ran. A drain loop can run to exhaustion because the queue length is the exit test. Training has no queue to empty, so 500 stays a guess until something reads the curve and decides.

The fix is a callback that watches the validation loss and halts when it stops improving, so the loop stops itself instead of trusting your epoch guess:

<CodeBlock language="typescript" title="early-stopping.ts">
{`// Two setup notes, both load-bearing. First, a FRESH network: \`model\`
// is already trained, so re-fitting it starts partway down the loss
// curve and halts sooner. Over 60 runs of each, the re-fit stopped at a
// median epoch 47 where a fresh network took 99, and 11 of the 60
// re-fits stopped inside the first 10 epochs. Roughly half the run.
// That is enough for the halt epoch to report where the weights
// started rather than anything about this data.
const rerun = tf.sequential();
rerun.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [3] }));
rerun.add(tf.layers.dense({ units: 16, activation: 'relu' }));
rerun.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
rerun.compile({ optimizer: 'adam', loss: 'binaryCrossentropy', metrics: ['accuracy'] });

// Second, something for the callback to fire ON. On the clean synthetic
// clusters above, validation loss just keeps creeping down (under 0.001
// after 500 epochs) and the run never halts. The archive is not that clean:
// its labels come from the flag log, and a few are wrong. Flip six of
// the first eighty labels to simulate that. Six contradictory rows put a
// floor under both curves, since no setting of the weights can satisfy
// them and their neighbors at once. validationSplit takes the LAST 20
// rows, which stay clean, so that floor on val_loss is the price of the
// bad rows rather than a broken split.
const labels = trainY.arraySync();
for (const i of [3, 17, 29, 41, 52, 68]) labels[i] = [1 - labels[i][0]];

await rerun.fit(trainX, tf.tensor2d(labels), {
  epochs: 500,            // an upper bound now, not a target
  validationSplit: 0.2,
  callbacks: tf.callbacks.earlyStopping({
    monitor: 'val_loss',  // stop when the HELD-OUT loss stops falling
    patience: 5,          // give it 5 epochs of no improvement first
  }),
});
// The halt epoch is data- and init-dependent. Across 150 runs of this
// block the callback fired between epoch 66 and epoch 184, median 105,
// on a val_loss between 0.05 and 0.30, with the middle eight tenths
// inside 0.07 to 0.12. One of those 150 stopped at epoch 102 on
// val_loss 0.081, and that is the run the epilogue records. Now read
// WHAT tripped it. The validation curve here does not climb, it
// flattens: at the halt, val_loss sat a median 0.0013 above its own
// best, and 0.0045 above it at the 90th percentile, while the training
// loss was still a median 0.259, which is nowhere near memorized.
// patience counts epochs that fail to BEAT the best score so far, and a
// plateau fails that test the same way a climb does. So the callback
// only tells you the run stopped improving. Whether that is convergence
// or overfitting is a question the gap between the two curves answers,
// which is why you read both.`}
</CodeBlock>

Early stopping ends the run without rewinding it. The weights left in the model are the halt-epoch weights, `patience` epochs past the best val_loss. Across 150 runs of this block the halt landed exactly five epochs past the best score every single time, on a val_loss between 0.0000 and 0.0113 above it, median 0.0013. TFJS 4.22 has no undo for that: `tf.callbacks.earlyStopping({ restoreBestWeights: true })` throws `restoreBestWeights = True is not implemented in EarlyStopping yet`. If you want the best weights and not just the halt, clone `model.getWeights()` in `onEpochEnd` whenever val_loss improves and set them back after `fit` resolves.

<DerivationDrawer summary="The 7-step loop that fit() hides, and what Adam changes in step 4">
**`model.fit()` is a wrapper around this loop.** Sampling mini-batches instead of the whole dataset is what makes it stochastic gradient descent: each batch is a random sample, so each gradient is only an estimate of the true one. The inner update (steps 1-4) runs `epochs × (datasetSize / batchSize)` times:

```
for epoch in 1..N:
  shuffle(trainX, trainY)
  for batch in chunks(trainX, batchSize):
      // 1. Forward pass: predictions ŷ (y-hat) for this batch
      ŷ = model.forward(batch.x)

      // 2. Loss: how wrong on this batch
      L = lossFn(ŷ, batch.y)

      // 3. Backward pass: gradients via chain rule
      ∇w = backward(L, model.params)

      // 4. Update: step opposite to gradient
      for w in model.params:
          w := w - learningRate * ∇w[w]

      // 5. Log batch metrics
  // 6. End-of-epoch: validate on heldout set
  if val_loss not improving for K epochs:   // K = patience, typically 5-10
      // 7. Stop early
      break
```

**Step 4 is the one line `optimizer` swaps out.** Under `optimizer: 'sgd'`, which is what the exercise below compiles with, that line is exactly the rule above. Under `optimizer: 'adam'`, which both networks in this lesson use, it is not. The learning rate lives on the optimizer, so it belongs to `compile()`, and `fit()` silently ignores a `learningRate` option. Both nets here pass the optimizer as a bare string, so each takes its default rate. That is why lesson 2's most important knob appears nowhere in this lesson's code.

**What Adam puts in step 4 instead.** Adam keeps two running averages per weight: `m` over recent gradients and `v` over recent squared gradients. The step is `m` divided by the square root of `v`, scaled by the learning rate. The `m` term is momentum, so a weight whose gradient keeps pointing one way builds speed and coasts over the flats around saddles. The `sqrt(v)` division sizes each weight's step against that weight's own recent gradients, so a parameter with tiny gradients still moves and one with huge gradients does not bolt. Both averages start at zero and get rescaled early to correct that bias, which leaves the first step roughly one learning rate wide whatever the gradient measures. On `L = w²` at `w = 3` the gradient is 6, and one default Adam step moves `w` by 0.00100; the plain rule at the same rate would move it 0.006. TensorFlow.js defaults Adam to a learning rate of 0.001, and `tf.train.adam(lr)` is how you set your own.

**Why mini-batch (not full-batch or single-sample)?** Full-batch is exact but uses too much memory and takes one step per epoch. Single-sample (true SGD) is noisy and underuses GPU parallelism. Mini-batches of 32-512 are the empirical sweet spot: enough samples for a smooth gradient estimate, small enough to fit in memory, large enough to saturate the GPU.

**Why shuffle each epoch?** Without shuffling, the model sees batches in the same order every epoch, which biases learning toward whatever pattern is in the file order. Shuffle breaks the correlation between adjacent batches.
</DerivationDrawer>
