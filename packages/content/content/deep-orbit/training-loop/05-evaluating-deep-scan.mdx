## The Final Test

Ninety-five percent training accuracy, sixty percent on signals the network has never seen. That gap is the most common failure in ML, and nothing in the training logs warns you about it: the model memorized its homework instead of learning the subject. Evaluation on held-out data exists to catch exactly this, the way E2E tests catch what unit tests can't: code that passes against fixtures and fails against reality.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="evaluation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Assume model is trained from previous lesson

// Test data: a held-out slice of the archive, labeled, and NEVER seen
// during training. It must be real readings with real labels: random
// tensors cannot measure anything, because random labels contain no
// pattern to be right about.
const testX = tf.tensor2d([
  [0.82, 0.14, 0.77],  // flagged window, confirmed anomalous
  [0.11, 0.86, 0.19],  // calm-period reading
  [0.74, 0.22, 0.68],  // flagged window
  [0.15, 0.79, 0.24],  // calm-period reading
  [0.68, 0.31, 0.66],  // flagged window
  [0.09, 0.91, 0.13],  // calm-period reading
  [0.71, 0.18, 0.72],  // flagged window
  [0.21, 0.74, 0.28],  // calm-period reading
]);
const testY = tf.tensor2d([[1], [0], [1], [0], [1], [0], [1], [0]]);

// Evaluate: returns [loss, accuracy] (matches compile metrics)
const [testLoss, testAccuracy] = model.evaluate(testX, testY) as tf.Tensor[];
console.log('Test Loss:', testLoss.dataSync()[0].toFixed(4));
console.log('Test Accuracy:', (testAccuracy.dataSync()[0] * 100).toFixed(1) + '%');
// The crew's run printed 94.0% on the full held-out slice. Yours will
// differ: training starts from random weights, so two honest runs never
// match to the decimal. What must match is the story the gap tells.

// Make predictions on new signals
const newSignals = tf.tensor2d([
  [0.9, 0.1, 0.8],   // possibly anomalous
  [0.1, 0.9, 0.2],   // probably normal
  [0.5, 0.5, 0.5],   // archive sample 7741: Farah's calibration ghost
]);

const predictions = model.predict(newSignals) as tf.Tensor;
const results = predictions.dataSync();
results.forEach((prob, i) => {
  console.log(\`Signal \${i + 1}: \${(prob * 100).toFixed(1)}% anomalous\`);
});
// The bridge run printed:
//   Signal 1: 87.3% anomalous
//   Signal 2: 12.1% anomalous
//   Signal 3: 51.8% anomalous  ← sample 7741. Neither normal nor alarm.`}
</CodeBlock>

One entry for the strangest page of the ship's ledger: back before this network had seen a single label, an untrained build scored sample 7741 at 0.998, and a brand-new reinitialization, fresh random numbers and all, scored it 0.997. Nobody explained it then and nobody explains it now. But notice what training did: the certain machine became an uncertain one. Untrained, it had an opinion; trained, it refuses to commit at 51.8. Whatever else the loss curve bought, it bought honesty about the one reading the crew cannot label.

**Interpreting results:**
- **Training accuracy > Test accuracy** → The model is memorizing (overfitting). You need more data, less complexity, or regularization.
- **Both accuracies low** → The model can't learn the pattern (underfitting). You need more layers, more units, or more training.
- **Both accuracies high** → Ship it.

<DerivationDrawer summary="Why accuracy alone is not enough: precision, recall, F1">
**Accuracy** = `(TP + TN) / (TP + TN + FP + FN)`. This breaks under class imbalance: if 99% of signals are normal, predicting "normal" for everything scores 99% accuracy and zero useful detections.

**Precision** = `TP / (TP + FP)`: of all signals you flagged as anomalous, what fraction actually were?

**Recall** (sensitivity) = `TP / (TP + FN)`: of all true anomalies, what fraction did you catch?

**Tradeoff:** lowering the decision threshold (default 0.5) increases recall (catch more anomalies) but lowers precision (more false alarms). Raising it does the opposite. There is no free lunch. Pick based on the cost asymmetry of false positives vs false negatives in your domain.

**F1 score** = `2 · (precision · recall) / (precision + recall)`: harmonic mean. Use when you need a single number that punishes either extreme. For DEEP SCAN, missing a true anomaly might cost a ship. False alarms cost crew time. The right metric depends on which cost you're willing to absorb.

**ROC and PR curves** plot precision-recall (or TPR-FPR) across all thresholds. Reporting one accuracy number from one threshold hides this entire surface.
</DerivationDrawer>
