## The Final Test

In software engineering, you don't trust code that only passes unit tests — you need E2E tests against real scenarios. Model evaluation is the same: testing on data the model never saw during training.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="evaluation.ts">
{`import * as tf from '@tensorflow/tfjs';

// Assume model is trained from previous lesson

// Test data — NEVER seen during training
const testX = tf.randomNormal([50, 3]);
const testY = tf.randomUniform([50, 1]).round();

// Evaluate: returns [loss, accuracy] (matches compile metrics)
const [testLoss, testAccuracy] = model.evaluate(testX, testY) as tf.Tensor[];
console.log('Test Loss:', testLoss.dataSync()[0].toFixed(4));
console.log('Test Accuracy:', (testAccuracy.dataSync()[0] * 100).toFixed(1) + '%');

// Make predictions on new signals
const newSignals = tf.tensor2d([
  [0.9, 0.1, 0.8],   // possibly anomalous
  [0.1, 0.9, 0.2],   // probably normal
  [0.5, 0.5, 0.5],   // ambiguous
]);

const predictions = model.predict(newSignals) as tf.Tensor;
const results = predictions.dataSync();
results.forEach((prob, i) => {
  console.log(\`Signal \${i + 1}: \${(prob * 100).toFixed(1)}% anomalous\`);
});
// Signal 1: 87.3% anomalous
// Signal 2: 12.1% anomalous
// Signal 3: 51.8% anomalous`}
</CodeBlock>

**Interpreting results:**
- **Training accuracy > Test accuracy** → The model is memorizing (overfitting). You need more data, less complexity, or regularization.
- **Both accuracies low** → The model can't learn the pattern (underfitting). You need more layers, more units, or more training.
- **Both accuracies high** → Ship it.
