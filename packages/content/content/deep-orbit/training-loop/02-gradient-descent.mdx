If you've ever written an easing loop, you have already written this lesson. Every loop that runs `pos += (target - pos) * 0.1` is doing gradient descent on the loss `(target - pos)² / 2`. The derivative of that loss with respect to `pos` is `-(target - pos)`, and stepping opposite the derivative, scaled by 0.1, reproduces the lerp line character for character. Run both from `pos = 2` toward `target = 10` and each lands on 2.8: the easing line because it was written that way, `tf.variableGrads` because it measured the slope (-8) and subtracted a tenth of it. What this lesson adds is only the part lerp never needed: where the slope comes from when nobody can tell you the target.

## Finding Downhill

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="gradient-descent.ts">
{`import * as tf from '@tensorflow/tfjs';

// Simple example: find the x that minimizes (x - 3)^2
let x = tf.variable(tf.scalar(0)); // start at 0
const learningRate = 0.1;

for (let step = 0; step < 20; step++) {
  // Compute loss and gradient
  const { value: loss, grads } = tf.variableGrads(() => {
    return x.sub(3).square() as tf.Scalar; // loss = (x - 3)^2
  });

  // Update x: move opposite to gradient direction
  const grad = grads[x.name];
  x.assign(x.sub(grad.mul(learningRate)));

  if (step % 5 === 0) {
    console.log(\`Step \${step}: x=\${x.dataSync()[0].toFixed(3)}, loss=\${loss.dataSync()[0].toFixed(3)}\`);
  }
}
// Step 0:  x=0.600, loss=9.000
// Step 5:  x=2.214, loss=0.966
// Step 10: x=2.742, loss=0.104
// Step 15: x=2.916, loss=0.011
// (x prints after the update, loss is measured before it)`}
</CodeBlock>

That slope arrives without anyone writing a derivative. `tf.variableGrads` records the operations your loss function runs and replays that recording backwards to get it. The name for the trick is autograd, short for automatic differentiation. The next lesson takes it apart.

Read that trace as distances rather than positions. Each row sits five steps after the one before it, and the distance covered shrinks: 1.614, then 0.528, then 0.174. Nothing in the loop asks it to slow down. The slope of `(x - 3)²` shrinks as x nears 3, and each step is a tenth of the slope, so descent slows near the minimum instead of overshooting it.

**Learning rate** is a hyperparameter: a setting you pick by hand rather than a weight the model learns, and the one that matters most. Lerp factors carry the same intuition, and the easing loop is small enough to check the numbers on. Each frame leaves `|1 - r|` of the distance still to cover, so `pos = 2` running toward `target = 10` at 0.001 needs 6,682 frames to close the gap to 0.01.

Overshooting is not the same as diverging. At 1.5 the element jumps past the target to 14, then halves its error on every frame after and arrives in ten. Divergence starts at 2.0, which leaves the element bouncing between 18 and 2 forever, and 2.5 grows the error by half again per frame: 22, then -8, then 37.

The threshold belongs to the loss rather than to the rate. The descent above minimizes `(x - 3)²` instead of half of it, so every slope it reads is twice as steep and its own threshold sits at 1.0. The 1.5 that settles the easing loop in ten frames sends x to 9, then -9, then 27.

<DerivationDrawer summary="Why the gradient is the steepest-ascent direction">
**The gradient is a vector of partial derivatives.** For loss `L(w₁, w₂, ..., wₙ)`:

`∇L = [ ∂L/∂w₁, ∂L/∂w₂, ..., ∂L/∂wₙ ]`

Each `∂L/∂wᵢ` answers: "if I nudge wᵢ by ε, how much does L change?" The vector of all these answers points in the direction where L grows fastest. **Subtracting it walks you toward where L shrinks fastest.**

**Why the update rule `w := w - η·∇L`?** The Taylor expansion of L around the current point, which is the straight-line approximation of the loss right where you are standing:

`L(w + Δw) ≈ L(w) + ∇L · Δw`

To minimize the linear approximation, pick Δw opposite to ∇L. The learning rate η scales the step:
- η too large → that straight line stops describing the real curve, so the step lands past the minimum
- η too small → many steps to converge
- Adaptive optimizers (Adam, RMSprop) tune η per-parameter using gradient history.
</DerivationDrawer>
