An easing loop such as `pos += (target - pos) * 0.1` moves a value toward a known target. It is also gradient descent on the loss `(target - pos)² / 2`.

Start at `pos = 2` with `target = 10`. The loss slope is -8. Subtract a tenth of that slope and the next position is 2.8, the same result as the easing line.

For a network, we know the labels but not the best weights. Calculating the loss slope tells us which direction to try.

## Finding Downhill

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="gradient-descent.ts">
{`import * as tf from '@tensorflow/tfjs';

// Simple example: find the x that minimizes (x - 3)^2
const x = tf.tidy(() => tf.variable(tf.scalar(0))); // start at 0
const learningRate = 0.1;

for (let step = 0; step < 20; step++) {
  tf.tidy(() => {
  // Compute loss and gradient
  const { value: loss, grads } = tf.variableGrads(() => {
    return x.sub(3).square() as tf.Scalar; // loss = (x - 3)^2
  });

  // Update x: move opposite to gradient direction
  const grad = grads[x.name];
  x.assign(x.sub(grad.mul(learningRate)));

  if (step % 5 === 0) {
    console.log(\`Step \${step}: x=\${x.dataSync()[0].toFixed(3)}, loss=\${loss.dataSync()[0].toFixed(3)}\`);
  }
  });
}
// Step 0:  x=0.600, loss=9.000
// Step 5:  x=2.214, loss=0.966
// Step 10: x=2.742, loss=0.104
// Step 15: x=2.916, loss=0.011
// (x prints after the update, loss is measured before it)
x.dispose();`}
</CodeBlock>

`tf.variableGrads` calculates the slope without you writing the derivative. It records the loss calculation, then works backward through its operations. This is called **automatic differentiation**, or autograd. The next lesson explains it.

Each row in the trace is five steps after the previous row. The distance covered gets smaller: 1.614, then 0.528, then 0.174.

The loop does not change the learning rate. The slope of `(x - 3)²` gets smaller as x approaches 3. Each update is a tenth of that slope, so the steps also get smaller.

The **learning rate** scales each update. It is a **hyperparameter**, a setting you choose rather than a weight this optimizer learns.

In the easing example, rate `r` leaves `|1 - r|` of the remaining distance after each frame. A rate of 0.001 moves very slowly: starting at `pos = 2` toward `target = 10` takes 6,682 frames to get within 0.01.

Overshooting is not the same as diverging. At 1.5 the element jumps past the target to 14, then halves its error each frame and comes within 0.01 of the target in ten frames. At 2.0 it stops converging and bounces between 18 and 2. Above 2.0 the error grows: at 2.5 the positions are 22, -8 and 37.

The threshold belongs to the loss rather than to the rate. The descent above minimizes `(x - 3)²` instead of half of it, so every slope it reads is twice as steep and its own threshold sits at 1.0. The 1.5 that settles the easing loop in ten frames sends x to 9, then -9, then 27.

<DerivationDrawer summary="Why the gradient is the steepest-ascent direction">
**The gradient is a vector of partial derivatives.** For loss `L(w₁, w₂, ..., wₙ)`:

`∇L = [ ∂L/∂w₁, ∂L/∂w₂, ..., ∂L/∂wₙ ]`

Each partial derivative asks what happens to the loss if just one weight changes. For a small change ε, the loss changes by about ε times that derivative.

For a differentiable loss, the gradient points toward the steepest local increase at a fixed Euclidean step length. Its negative points toward local decrease if the gradient is nonzero. The step still needs to be small enough.

**Why the update rule `w := w - η·∇L`?** The Taylor expansion of L around the current point, which is the straight-line approximation of the loss right where you are standing:

`L(w + Δw) ≈ L(w) + ∇L · Δw`

To minimize the linear approximation, pick Δw opposite to ∇L. The learning rate η scales the step:
- η too large → the local approximation may be poor at the proposed point, and the step can raise the loss
- η too small → many steps to converge
- Adaptive optimizers such as Adam scale updates using gradient history; their base learning rate remains a setting.
</DerivationDrawer>
