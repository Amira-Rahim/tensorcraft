Three operations cover almost everything Nazari just asked for: add two tensors, multiply them element by element, and matMul rows into columns. Each is a single call that the GPU executes across the entire tensor at once. The logic will feel familiar if you've chained `Array.map()` and `reduce()` over a list; what changes is the execution model, where one op covers millions of elements in parallel.

## Element-wise Operations

<BridgeCallout bridge={frontmatter.concept.bridge} />

When you write `arr.map((x, i) => x + arr2[i])`, you're doing element-wise addition. TensorFlow.js does the same thing, but across any number of dimensions and on the GPU:

<CodeBlock language="typescript" title="tensor-ops.ts">
{`import * as tf from '@tensorflow/tfjs';

const sensor1 = tf.tensor([1, 2, 3]);
const sensor2 = tf.tensor([4, 5, 6]);

// Element-wise operations: same as map + zip
const sum = tf.add(sensor1, sensor2);     // [5, 7, 9]
const product = tf.mul(sensor1, sensor2); // [4, 10, 18]
const diff = tf.sub(sensor2, sensor1);    // [3, 3, 3]

// Chaining with method syntax
const result = sensor1.add(sensor2).mul(tf.scalar(2));
// [10, 14, 18]`}
</CodeBlock>

## Matrix Multiplication, and Its One Rule

`matMul` is different from `mul`. It doesn't multiply matching positions; it multiplies **rows into columns**: every row of the left tensor dot-producted with every column of the right. That gives it one inflexible shape rule:

**`[m, n] × [n, p] → [m, p]`: the inner dimensions must match.**

The left tensor's column count must equal the right tensor's row count. When they don't, you flip one with `transpose()`, which swaps a tensor's rows and columns, turning `[3, 2]` into `[2, 3]`:

<CodeBlock language="typescript" title="matmul.ts">
{`// weights: [3, 2], input: [3, 1]
const weights = tf.tensor2d([[1, 2], [3, 4], [5, 6]]);  // [3, 2]
const input = tf.tensor2d([[1], [1], [1]]);               // [3, 1]

// weights.matMul(input) would throw:
//   [3, 2] × [3, 1]: inner dims 2 ≠ 3. No deal.

// transpose() flips [3, 2] → [2, 3]. Now the rule is satisfied:
//   [2, 3] × [3, 1] → [2, 1] ✓
const output = weights.transpose().matMul(input);
output.print();
// [[9],     ← 1+3+5: first column of weights, summed against input
//  [12]]    ← 2+4+6: second column`}
</CodeBlock>

Why care? Every layer of every neural network you'll build is essentially `matMul(input, weights) + bias`. The shape rule above is the single most common source of errors in ML code. You'll meet `Error: inner dimensions must match` again, and now you know exactly what it's complaining about.
