## Averaging and amplifying the readings

Demir wanted to multiply each reading by its matching gain, the number that
controls how much to amplify it. That is **element-wise multiplication**,
written `mul`. He used `matMul` instead. Matrix multiplication has a different
shape rule, and `[1, 64] × [1, 64]` does not meet it.

Use the same two-channel passes as the visual. Add matching values, divide by
2 to average them, then multiply the average by the gain. Each operation
creates a tensor. `tf.tidy()` releases the temporary tensors when its
synchronous callback finishes. That callback must finish without `await`.
TensorFlow.js keeps the tensors you return for later use:

<CodeBlock language="typescript" title="merge-two-passes.ts">
{`const pass1 = tf.tensor2d([[2, 10], [4, 12], [6, 14]]);
const pass2 = tf.tensor1d([4, 8]);
const gain = 2;

const { merged, boosted } = tf.tidy(() => {
  const merged = pass1.add(pass2).div(2);
  const boosted = merged.mul(gain);
  return { merged, boosted };
});
// merged:  [[3, 9], [4, 10], [5, 11]]
// boosted: [[6, 18], [8, 20], [10, 22]]
tf.dispose([pass1, pass2, merged, boosted]);`}
</CodeBlock>

**Broadcasting** lets one row apply to several rows. TensorFlow.js compares
the shapes from right to left. Each pair of sizes must match, or one must be 1.
Here, the `[2]` row applies to every row in `[3, 2]`. A scalar is a single
number, so a scalar gain applies to every reading.

Return both results from `tf.tidy()` and dispose of them after use. Averaging
can reduce noise when the errors are independent and average to zero. It
does not fix every kind of error.

## Weighted channel sums

Matrix multiplication multiplies pairs of values and adds the products.
Its shape rule is `[m, n] × [n, p] → [m, p]`: the middle sizes must match.
In the exercise, each row of `block` holds a set of readings. Each row of
`mix` holds weights for combining those channels. Transpose `mix` so those
weights become columns:

<CodeBlock language="typescript" title="weighted-channel-mix.ts">
{`// block: [readings, channels], mix: [banks, channels]
const mixed = tf.tidy(() => block.matMul(mix.transpose()));
// result: [readings, banks]; its caller disposes it after use`}
</CodeBlock>

Check axis meanings before transposing. Matching dimensions alone cannot tell
you whether a multiplication combines the intended channels. Speed
depends on the workload and backend. These checks show whether your calculations
and shapes are correct.

<ConceptReference summary="Reference: the original amplifier and matrix products">

### The shape error

Here is the code that produced the error. Demir wanted to multiply each of the 64 readings by its own gain factor.

<CodeBlock language="typescript" title="amplify-broken.ts">
{`import * as tf from '@tensorflow/tfjs';

// channelGains: 64 amplification factors. latestReadings: 64 raw values.
const gains = tf.tensor2d([channelGains]);      // shape [1, 64]
const readings = tf.tensor2d([latestReadings]); // shape [1, 64]

// BROKEN: this is not the multiplication you want.
const amplified = gains.matMul(readings);
// Error in matMul: inner shapes (64) and (1) of Tensors with
// shapes 1,64 and 1,64 and transposeA=false and transposeB=false
// must match.`}
</CodeBlock>

`matMul` needs the left tensor's column count to match the right tensor's row count. Here those counts are 64 and 1. Demir only wanted to multiply matching positions, so he needs `mul` instead.

### The element-wise calculation

<BridgeCallout bridge={frontmatter.concept.bridge} />

When you write `arr.map((x, i) => x + arr2[i])`, you're doing element-wise addition. `tf.mul`, `tf.add`, and `tf.sub` do the same kind of calculation on tensors. Their shapes must follow the broadcasting rules. `gains.mul(readings)` is the one-word fix for the broken amplifier:

<CodeBlock language="typescript" title="tensor-ops.ts">
{`import * as tf from '@tensorflow/tfjs';

// The amplifier from amplify-broken.ts, repaired: matching positions,
// so matMul's inner-dimension rule does not apply. The shapes still
// have to be broadcast-compatible.
const amplified = gains.mul(readings);    // [1, 64], gain[i] * reading[i]

const sensor1 = tf.tensor([1, 2, 3]);
const sensor2 = tf.tensor([4, 5, 6]);

// Element-wise operations: same as map + zip
const sum = tf.add(sensor1, sensor2);     // [5, 7, 9]
const product = tf.mul(sensor1, sensor2); // [4, 10, 18]
const diff = tf.sub(sensor2, sensor1);    // [3, 3, 3]

// Chaining with method syntax
const result = tf.tidy(() => sensor1.add(sensor2).mul(2));
// [10, 14, 18]
tf.dispose([amplified, gains, readings, sensor1, sensor2, sum, product, diff, result]);`}
</CodeBlock>

Broadcasting compares shapes from right to left. Each pair of sizes must match, or one must be 1. A missing leading axis also acts like size 1.

For example, `.mul(tf.scalar(2))` doubles every value. Subtracting two column means, shape `[2]`, from five rows, shape `[5, 2]`, subtracts the same pair from each row. A size mismatch that meets this rule is valid for an element-wise operation. Matrix multiplication follows its own rule.

Tensor operations are not automatically faster than JavaScript loops. Call overhead and readback can dominate a small array. Acceleration depends on the workload and backend. Measure the version you intend to run. This lesson checks shape rules. You would need runtime measurements to compare speed.

### When to use matMul

Dense layers compute weighted sums. `matMul` computes them for every row of its left input against every column of its right input. Element-wise multiplication alone leaves the products unsummed. The matrix operation has a shape rule:

**`[m, n] × [n, p] → [m, p]`: the inner dimensions must match.**

The left tensor's column count must equal the right tensor's row count. If a matrix stores the intended axes in the opposite order, transpose it. A shape error can also mean missing features or an incorrect layout. Transposing until code runs can silently change the computation. Here, rows and columns need to swap:

<CodeBlock language="typescript" title="matmul.ts">
{`// weights: [3, 2], input: [3, 1]
const weights = tf.tensor2d([[1, 2], [3, 4], [5, 6]]);  // [3, 2]
const input = tf.tensor2d([[1], [1], [1]]);               // [3, 1]

// weights.matMul(input) would throw:
//   [3, 2] × [3, 1]: inner dims 2 ≠ 3. No deal.

// transpose() flips [3, 2] to [2, 3]. Now the rule is satisfied:
//   [2, 3] × [3, 1] to [2, 1] ✓
const output = tf.tidy(() => weights.transpose().matMul(input));
output.print();
// [[9],: 1+3+5: first column of weights, summed against input
//  [12]]: 2+4+6: second column
tf.dispose([weights, input, output]);`}
</CodeBlock>

A dense layer, which you will build next, starts with `matMul(input, weights) + bias`. The same shape rule will help you check its inputs and weights. The time-based models in module 6 use it too.

<DerivationDrawer summary="Why the inner dimensions must match">
A matrix turns a list of numbers into another list, one weighted sum per output. Its shape says which sizes: a `[2, 3]` matrix reads three numbers and emits two.

Use `weights.transpose()` from above: `[[1, 3, 5], [2, 4, 6]]`. Try inputs that select one column at a time:

- `[1, 0, 0]` selects the first column: `[1, 2]`.
- `[0, 1, 0]` selects the second: `[3, 4]`.
- `[0, 0, 1]` selects the third: `[5, 6]`.

Each input scales one column. Add the scaled columns to get the output. For `[1, 1, 1]`, all three columns contribute equally: `[1 + 3 + 5, 2 + 4 + 6]`. That gives the `[[9], [12]]` printed above.

When two matrix operations run back to back, the first output must fit the next input. For column-vector inputs, a matrix produces one value per row and reads one value per column. The connecting sizes must match. In `[m, n] × [n, p]`, that shared size is `n`.
</DerivationDrawer>


</ConceptReference>
