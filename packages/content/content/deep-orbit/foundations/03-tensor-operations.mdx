## Matching sensors across neighboring moments

Demir wanted to multiply each reading by its matching gain, the number that
controls how much to amplify it. That is **element-wise multiplication**,
written `mul`. He used `matMul` instead. Matrix multiplication has a different
shape rule, and `[1, 64]` times `[1, 64]` does not meet it.

<StoryPassage>

Demir reopens the three moments Farah checked. He keeps sensors A and B in
the order listed in the recording header, leaving C and D aside for now.
Nazari points to the first two rows and waits for the calculation.

</StoryPassage>

The earlier excerpt contains these values:

| Local moment | Sensor A | Sensor B |
| --- | --- | --- |
| 1 | 2 | 20 |
| 2 | 3 | 18 |
| 3 | 4 | 16 |

These are fictional recorded readings from the same selection used in Tensor
Shapes. The header gives their order. It supplies no physical unit here, so
we keep them as readings without adding one.

Demir makes two overlapping views. The first holds moments 1 and 2. The
second holds moments 2 and 3. Matching positions now pair the same sensor at
neighboring moments. Averaging each pair smooths this short sequence. It also
changes the readings, so the raw recording stays available.

<CodeBlock language="typescript" title="merge-two-passes.ts">
{`// Columns stay in header order: sensor A, then sensor B.
const pass1 = tf.tensor2d([[2, 20], [3, 18]]); // moments 1 and 2
const pass2 = tf.tensor2d([[3, 18], [4, 16]]); // moments 2 and 3
const gain = 2;

const { merged, boosted } = tf.tidy(() => {
  const merged = pass1.add(pass2).div(2);
  const boosted = merged.mul(gain);
  return { merged, boosted };
});
console.log(merged.arraySync());  // [[2.5, 19], [3.5, 17]]
console.log(boosted.arraySync()); // [[5, 38], [7, 34]]
// Keep these tensors for the bank calculation below.`}
</CodeBlock>

Follow sensor A through the first pair: `(2 + 3) / 2 = 2.5`.
Gain `2` gives `5`. Sensor B uses `(20 + 18) / 2`, then the same gain.
The gain is a dimensionless setting chosen for this example. Doubling a value
also doubles any error in it. This example establishes no noise reduction
from independent repeated measurements.

Each operation creates a tensor. `tf.tidy()` releases temporary tensors when
its synchronous callback finishes. That callback must finish without `await`.
TensorFlow.js keeps the tensors in the returned object, so you can use
`boosted` in the next calculation and dispose of both results afterward.

## One channel-bank sum

Nazari also wants to inspect channels together. A **bank** is one supplied
set of channel weights. Bank 0 keeps A, Bank 1 keeps B, and Bank 2 adds A
and B. These fixed settings help you check the calculation. They make no
claim about which sensors detect an anomaly.

Matrix multiplication computes a **dot product** for each output: multiply
each channel by its weight, then add the products. The first boosted row is
`[5, 38]`. Bank 2 uses `[1, 1]`, so its score is `5 * 1 + 38 * 1 = 43`.
Element-wise `mul` produces the separate products. `matMul` also sums them.

| Tensor | Row meaning | Column meaning | Shape |
| --- | --- | --- | --- |
| `boosted` | Neighboring-moment pair | Sensor A, B | `[2, 2]` |
| `mix` | Bank 0, 1, 2 | Sensor A, B | `[3, 2]` |
| `mix.transpose()` | Sensor A, B | Bank 0, 1, 2 | `[2, 3]` |
| `mixed` | Neighboring-moment pair | Bank 0, 1, 2 | `[2, 3]` |

Transpose puts each bank's weights in a column. The multiplication then has
matching sensor axes: `[2, 2]` times `[2, 3]` produces `[2, 3]`.

<CodeBlock language="typescript" title="weighted-channel-mix.ts">
{`// Continue with boosted from merge-two-passes.ts.
const mix = tf.tensor2d([[1, 0], [0, 1], [1, 1]]);
const mixed = tf.tidy(() => boosted.matMul(mix.transpose()));
console.log(mixed.arraySync()); // [[5, 38, 43], [7, 34, 41]]

tf.dispose([pass1, pass2, merged, boosted, mix, mixed]);`}
</CodeBlock>

In the activity, select **Channel-bank sums**, then choose an output row and
column. The highlighted sensor values and weights show every contributor to
that score. Check their meanings as well as their counts. The general matrix
rule is `[m, n]` times `[n, p]` produces `[m, p]`, where the shared `n` counts
the values in each dot product.

## Broadcasting one reference row

<StoryPassage>

Demir keeps the first moment beside the chart as a fixed reference. He checks
what the same merge function does when he reuses that row for both outputs.

</StoryPassage>

This case blends each row with the first moment. It is a chosen comparison,
not another capture of those moments. The reference has shape `[2]`: A's
reading `2`, then B's reading `20`.

<CodeBlock language="typescript" title="broadcast-recording-reference.ts">
{`const earlier = tf.tensor2d([[2, 20], [3, 18]]); // moments 1 and 2
const reference = tf.tensor1d([2, 20]); // moment 1, reused
const blended = tf.tidy(() => earlier.add(reference).div(2));
console.log(blended.arraySync()); // [[2, 20], [2.5, 19]]
tf.dispose([earlier, reference, blended]);`}
</CodeBlock>

**Broadcasting** lets that one row apply to both rows. TensorFlow.js compares
shapes from right to left. Each pair of sizes must match, or one must be `1`.
A missing leading axis acts like size `1`. Here, `[2]` matches the last axis
of `[2, 2]`. The result keeps shape `[2, 2]`.

Select **Fixed first-moment reference** in the activity. Trace sensor B in
the second output row: `(18 + 20) / 2 = 19` at gain `1`. The same reference
value reaches each row, while A and B keep their own columns. A scalar gain
has one value and applies to every result.

### The shape error

Here is the code that produced the error. Demir wanted to multiply each of the 64 readings by its own gain factor.

<CodeBlock language="typescript" title="amplify-broken.ts">
{`import * as tf from '@tensorflow/tfjs';

// channelGains: 64 amplification factors. latestReadings: 64 raw values.
const gains = tf.tensor2d([channelGains]);      // shape [1, 64]
const readings = tf.tensor2d([latestReadings]); // shape [1, 64]

// BROKEN: this operation requires matching inner dimensions.
const amplified = gains.matMul(readings);
// Error in matMul: inner shapes (64) and (1) of Tensors with
// shapes 1,64 and 1,64 and transposeA=false and transposeB=false
// must match.`}
</CodeBlock>

`matMul` needs the left tensor's column count to match the right tensor's row count. Here those counts are 64 and 1. Demir only wanted to multiply matching positions, so he needs `mul` instead.

### Extra element-wise operations

The short arrays below are separate toy inputs for comparing addition,
subtraction, and multiplication. They do not come from the recording.

<BridgeCallout bridge={frontmatter.concept.bridge} />

When you write `arr.map((x, i) => x + arr2[i])`, you're doing element-wise addition. `tf.mul`, `tf.add`, and `tf.sub` do the same kind of calculation on tensors. Their shapes must follow the broadcasting rules. `gains.mul(readings)` is the one-word fix for the broken amplifier:

<CodeBlock language="typescript" title="tensor-ops.ts">
{`import * as tf from '@tensorflow/tfjs';

// The amplifier from amplify-broken.ts, repaired: matching positions,
// so matMul's inner-dimension rule does not apply. The shapes still
// have to be broadcast-compatible.
const amplified = gains.mul(readings);    // [1, 64], gain[i] * reading[i]

const sensor1 = tf.tensor([1, 2, 3]);
const sensor2 = tf.tensor([4, 5, 6]);

// Element-wise operations: same as map + zip
const sum = tf.add(sensor1, sensor2);     // [5, 7, 9]
const product = tf.mul(sensor1, sensor2); // [4, 10, 18]
const diff = tf.sub(sensor2, sensor1);    // [3, 3, 3]

// Chaining with method syntax
const result = tf.tidy(() => sensor1.add(sensor2).mul(2));
// [10, 14, 18]
tf.dispose([amplified, gains, readings, sensor1, sensor2, sum, product, diff, result]);`}
</CodeBlock>

Broadcasting compares shapes from right to left. Each pair of sizes must match, or one must be 1. A missing leading axis also acts like size 1.

For example, `.mul(tf.scalar(2))` doubles every value. Subtracting two column means, shape `[2]`, from five rows, shape `[5, 2]`, subtracts the same pair from each row. A size mismatch that meets this rule is valid for an element-wise operation. Matrix multiplication follows its own rule.

Tensor operations are not automatically faster than JavaScript loops. Call overhead and readback can dominate a small array. Acceleration depends on the workload and backend. Measure the version you intend to run. This lesson checks shape rules. You would need runtime measurements to compare speed.

### A matrix example with three inputs

This separate toy example uses three inputs and two outputs to make the
inner-dimension rule visible with different sizes.

Dense layers compute weighted sums. `matMul` computes them for every row of its left input against every column of its right input. Element-wise multiplication alone leaves the products unsummed. The matrix operation has a shape rule:

**`[m, n]` times `[n, p]` produces `[m, p]`: the inner dimensions must match.**

The left tensor's column count must equal the right tensor's row count. If a matrix stores the intended axes in the opposite order, transpose it. A shape error can also mean missing features or an incorrect layout. Transposing until code runs can silently change the computation. Here, rows and columns need to swap:

<CodeBlock language="typescript" title="matmul.ts">
{`// weights: [3, 2], input: [3, 1]
const weights = tf.tensor2d([[1, 2], [3, 4], [5, 6]]);  // [3, 2]
const input = tf.tensor2d([[1], [1], [1]]);               // [3, 1]

// weights.matMul(input) would throw:
//   [3, 2] × [3, 1]: inner dims 2 ≠ 3. No deal.

// transpose() flips [3, 2] to [2, 3]. Now the rule is satisfied:
//   [2, 3] × [3, 1] to [2, 1] ✓
const output = tf.tidy(() => weights.transpose().matMul(input));
output.print();
// [[9],: 1+3+5: first column of weights, summed against input
//  [12]]: 2+4+6: second column
tf.dispose([weights, input, output]);`}
</CodeBlock>

A dense layer, which you will build next, starts with `matMul(input, weights) + bias`. The same shape rule will help you check its inputs and weights. The time-based models in module 6 use it too.

<DerivationDrawer summary="Why the inner dimensions must match">
A matrix turns a list of numbers into another list, one weighted sum per output. Its shape says which sizes: a `[2, 3]` matrix reads three numbers and emits two.

Use `weights.transpose()` from above: `[[1, 3, 5], [2, 4, 6]]`. Try inputs that select one column at a time:

- `[1, 0, 0]` selects the first column: `[1, 2]`.
- `[0, 1, 0]` selects the second: `[3, 4]`.
- `[0, 0, 1]` selects the third: `[5, 6]`.

Each input scales one column. Add the scaled columns to get the output. For `[1, 1, 1]`, all three columns contribute equally: `[1 + 3 + 5, 2 + 4 + 6]`. That gives the `[[9], [12]]` printed above.

When two matrix operations run back to back, the first output must fit the next input. For column-vector inputs, a matrix produces one value per row and reads one value per column. The connecting sizes must match. In `[m, n] × [n, p]`, that shared size is `n`.
</DerivationDrawer>


</ConceptReference>
