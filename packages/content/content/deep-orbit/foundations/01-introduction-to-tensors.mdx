You've worked with arrays your entire career: API responses, byte buffers, pixel data. A tensor stores its numbers much the way a `Float32Array` does: flat, typed, contiguous. TensorFlow.js adds shape tracking, numerical operations on a selected backend, and an explicit disposal lifecycle. A backend is the implementation that runs those operations on the CPU or GPU.

## What Is a Tensor?

For the default float32 dtype, the CPU backend stores values in a `Float32Array`. Other dtypes use different storage. On WebGL the same values live in a GPU texture instead, which the JavaScript garbage collector cannot see, and that is where the memory rules further down come from.

<BridgeCallout bridge={frontmatter.concept.bridge} />

Shape is the piece you'll reach for most: it's what separates a `[2, 3]` matrix from the six numbers underneath it, and the first thing to check when an op refuses to run.

<CodeBlock language="typescript" title="tensors-are-arrays.ts">
{`import * as tf from '@tensorflow/tfjs';

// A scalar (0D tensor), just a single number
const scalar = tf.scalar(42);
console.log(scalar.rank);  // 0

// A vector (1D tensor), like a regular array
const vector = tf.tensor1d([1, 2, 3, 4, 5]);
console.log(vector.rank);  // 1

// A matrix (2D tensor), like an array of arrays
const matrix = tf.tensor2d([[1, 2], [3, 4], [5, 6]]);
console.log(matrix.rank);  // 2

// You can always get the data back as a JavaScript array
const jsArray = await vector.array();
console.log(jsArray);  // [1, 2, 3, 4, 5]

// Three tensors are alive at this point, and dropping the variables would
// not free them. Release them before the next block starts counting.
scalar.dispose();
vector.dispose();
matrix.dispose();`}
</CodeBlock>

One difference to internalize early: you can iterate a `Float32Array` directly, but a tensor's data lives on the backend. Call `await t.array()` (or `dataSync()`) to pull the values back into JavaScript.

## The Part Garbage Collection Won't Do For You

Dispose tensors when you finish with them, on every backend. `tf.memory().numTensors` counts tensors that have not been disposed. It is useful for detecting unexpected growth, but it is not a browser-process memory measurement.

GPU resources need explicit cleanup. CPU values use JavaScript-managed storage, but relying on garbage collection leaves TFJS's bookkeeping behind and makes code unsafe when it switches backends. Initialization, intentional caches and retained model weights can also raise the count; growth alone does not identify a leak.

Two tools fix this:

<CodeBlock language="typescript" title="tensor-memory.ts">
{`// Tool 1: dispose(), manual and surgical
const reading = tf.tensor1d([0.3, 0.7, 0.1]);
console.log(tf.memory().numTensors);  // 1
reading.dispose();                     // GPU memory released
console.log(tf.memory().numTensors);  // 0

// Tool 2: tf.tidy(), automatic, for everything intermediate.
// Every tensor created inside the callback is disposed when it
// returns, EXCEPT the one you return.
const result = tf.tidy(() => {
  const a = tf.tensor1d([1, 2, 3]);   // disposed automatically
  const b = tf.tensor1d([4, 5, 6]);   // disposed automatically
  return a.add(b);                     // survives: it's the return value
});

console.log(await result.array()); // [5, 7, 9]
result.dispose(); // a returned tensor outlives tidy, so the caller owns it`}
</CodeBlock>

`tf.tidy()` runs a synchronous callback and disposes its temporary tensors. Do not pass it an async function. Return a tensor you need to read asynchronously, await its data outside the callback, then dispose it. Unlike a React effect cleanup, tidy finishes as soon as the callback returns.
