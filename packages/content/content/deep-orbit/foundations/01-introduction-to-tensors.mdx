## Keep the packet, read the result

Use the same five-reading excerpt you just inspected. A tensor holds numeric
values and their **shape**. `[5]` means one axis with five values; its **rank**
(the number of axes) is 1. A matrix has two axes, so its rank is 2.

Demir needs a copy of the readings before releasing the tensor. TensorFlow.js,
imported as `tf`, provides the operations below.

<CodeBlock language="typescript" title="inspect-a-packet.ts">
{`const streamValues = [0.12, 0.94, 0.31, 0.88, 0.47];
const reading = tf.tensor(streamValues);

// Copy out the information before releasing the tensor.
const shape = reading.shape;                       // [5]
const values = Array.from(reading.dataSync());      // the five readings
const total = tf.tidy(() => reading.sum().dataSync()[0]); // approximately 2.72

reading.dispose();`}
</CodeBlock>

`dataSync()` reads the tensor into typed JavaScript storage. `Array.from()`
copies that into the plain array the exercise asks for. Float32 storage can
round a decimal slightly; the order and shape stay the same.

`sum()` makes a temporary tensor. The synchronous `tf.tidy()` callback reads
its number and releases that temporary. `reading.dispose()` then releases the
original tensor. The copied `shape`, `values`, and `total` remain available.
Do not put an async callback inside `tf.tidy()`.

<ConceptReference summary="Reference: tensor ranks, backend storage, and cleanup">

A backend is the implementation that runs operations on the CPU or GPU. With the default float32 dtype, the CPU backend uses `Float32Array` storage; other dtypes use other storage. WebGL stores values in GPU textures. Read values back before ordinary JavaScript iteration, and dispose tensors on every backend.

<CodeBlock language="typescript" title="tensors-are-arrays.ts">
{`import * as tf from '@tensorflow/tfjs';

// A scalar (0D tensor), just a single number
const scalar = tf.scalar(42);
console.log(scalar.rank);  // 0

// A vector (1D tensor), like a regular array
const vector = tf.tensor1d([1, 2, 3, 4, 5]);
console.log(vector.rank);  // 1

// A matrix (2D tensor), like an array of arrays
const matrix = tf.tensor2d([[1, 2], [3, 4], [5, 6]]);
console.log(matrix.rank);  // 2

// You can always get the data back as a JavaScript array
const jsArray = await vector.array();
console.log(jsArray);  // [1, 2, 3, 4, 5]

// Three tensors are alive at this point, and dropping the variables would
// not free them. Release them before the next block starts counting.
scalar.dispose();
vector.dispose();
matrix.dispose();`}
</CodeBlock>


### Keeping repeated runs small

Dispose tensors when you finish with them, on every backend. `tf.memory().numTensors` counts tensors that have not been disposed. It is useful for detecting unexpected growth, but it is not a browser-process memory measurement.

GPU resources need explicit cleanup. CPU values use JavaScript-managed storage, but relying on garbage collection leaves TFJS's bookkeeping behind and makes code unsafe when it switches backends. Initialization, intentional caches and retained model weights can also raise the count; growth alone does not identify a leak.

Use a cleanup scope for temporary tensors and dispose anything you retain:

<CodeBlock language="typescript" title="tensor-memory.ts">
{`// Tool 1: dispose(), explicit cleanup
const reading = tf.tensor1d([0.3, 0.7, 0.1]);
console.log(tf.memory().numTensors);  // compare with the count before creating reading
reading.dispose();                     // release its backend resources
console.log(tf.memory().numTensors);  // back to the earlier count if nothing else changed

// Tool 2: tf.tidy(), automatic, for everything intermediate.
// Every tensor created inside the callback is disposed when it
// returns, EXCEPT the one you return.
const result = tf.tidy(() => {
  const a = tf.tensor1d([1, 2, 3]);   // disposed automatically
  const b = tf.tensor1d([4, 5, 6]);   // disposed automatically
  return a.add(b);                     // survives: it's the return value
});

console.log(await result.array()); // [5, 7, 9]
result.dispose(); // a returned tensor outlives tidy, so the caller owns it`}
</CodeBlock>

`tf.tidy()` runs a synchronous callback and disposes its temporary tensors. Do not pass it an async function. Return a tensor you need to read asynchronously, await its data outside the callback, then dispose it. Unlike a React effect cleanup, tidy finishes as soon as the callback returns.
