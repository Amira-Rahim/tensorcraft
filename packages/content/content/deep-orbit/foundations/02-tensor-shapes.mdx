## Use the layout in JavaScript

An **axis** is one direction in a tensor. The grid has two axes: rows and
columns. Here, rows represent moments and columns represent sensors. The
recording header establishes that meaning; the shape `[3, 4]` only gives
the counts.

The **rank** counts the axes. A flat list has one axis, so it has rank 1.
This grid has two axes, so it has rank 2. An axis is also called a
**dimension**.

Here are the same practice readings from the activity. Read the list from
left to right, with sensors A, B, C, and D recorded at each moment:

<CodeBlock language="typescript" title="arrange-readings.ts">
{`import * as tf from '@tensorflow/tfjs';

const flat = tf.tensor1d([2, 20, 5, 8, 3, 18, 7, 8, 4, 16, 6, 9]);

// One row per moment, with sensors A, B, C, D in the columns.
const grid = flat.reshape([3, 4]);
console.log(grid.arraySync());
// [[2, 20, 5, 8],
//  [3, 18, 7, 8],
//  [4, 16, 6, 9]]

// Read the second moment as a regular JavaScript array.
const step1 = grid.arraySync()[1];
console.log(step1); // [3, 18, 7, 8]

// The chart needs one row per sensor, with moments in order.
const bySensor = grid.transpose();
console.log(bySensor.arraySync());
// [[2, 3, 4],     // Sensor A
//  [20, 18, 16],  // Sensor B
//  [5, 7, 6],     // Sensor C
//  [8, 8, 9]]     // Sensor D

// Clean up after using the results.
tf.dispose([flat, grid, bySensor]);`}
</CodeBlock>

`reshape([3, 4])` starts a new row every four values. It keeps the values in
their original order. A reshape must keep the same number of values:
`3 × 4 = 12`.

`arraySync()` reads the tensor into regular JavaScript arrays. For this grid,
it returns one array per row. JavaScript counts from zero, so `[1]` selects
the second row. Use `grid.arraySync()[1]`, not `grid[1]`, to read that row.

For this two-dimensional grid, `transpose()` turns each column into a row.
The result has shape `[4, 3]`: four sensors, with three readings per sensor
in time order.

Reshaping `grid` to `[4, 3]` also gives four rows of three, but its first row
would be `[2, 20, 5]`. Those values come from three different sensors. The
shape is valid, but that row cannot show how sensor A changed over time.

### Shapes can have more than two axes

A shape lists the size of each axis, in order. A list of ten values has shape
`[10]`. A grid with three rows and four columns has shape `[3, 4]`.

A **batch** is a group of examples processed together. For 32 color images,
the shape might be `[32, 224, 224, 3]`:

- `32` images.
- `224` pixels high per image.
- `224` pixels wide per image.
- `3` color channels per pixel: red, green, and blue.

This is a **channel-last** layout because the color channels come last.
Other systems may put them in a different position. The image format tells
you which axis represents height, width, or color channels.

For readings over time, `[32, 5, 3]` could mean 32 examples, each with five
moments and three measurements per moment. Those measurements are called
**features**. These are possible meanings, not information stored in the
shape itself.

### Reshape, transpose, and memory

Reshape follows the tensor's existing value order, reading across each row
before moving to the next. This is called **row-major order**.

In this TensorFlow.js exercise, reshape reuses the original tensor's data in
memory. The tests check that you reshape the supplied `flat` tensor rather
than create a new one from copied values. The JavaScript array returned by
`arraySync()` is a separate copy.

The worked example disposes of its tensors after reading the results.
In the challenge, keep `grid` and `bySensor` for the tests. `step1` is a
regular JavaScript array and does not need `dispose()`.

With more than two axes, you can give transpose an explicit axis order. For
example, `tensor.transpose([1, 0, 2])` exchanges the first two axes and
leaves the third in place. Without an argument, TensorFlow.js reverses the
axis order. Check what each axis represents before choosing that order.

</ConceptReference>
