## Farah’s plan in JavaScript

Demir’s selection has 12 readings. Three rows of four give the grid a
**shape** of `[3, 4]`. Each row holds one moment, and each column follows
one sensor.

Rows and columns are the grid’s two **axes**. We also call an axis a
**dimension**. The number of axes is the **rank**: this grid has rank 2.
The original list has just one axis, so it has rank 1.

<StoryPassage>

Farah brings the 12 selected readings over to JavaScript. The full recording
stays in the archive while you arrange them.

</StoryPassage>

<CodeBlock language="typescript" title="arrange-readings.ts">
{`import * as tf from '@tensorflow/tfjs';

const flat = tf.tensor1d([2, 20, 5, 8, 3, 18, 7, 8, 4, 16, 6, 9]);

// Keep sensors A, B, C, D in that order in each row.
const grid = flat.reshape([3, 4]);
console.log(grid.arraySync());
// [[2, 20, 5, 8],
//  [3, 18, 7, 8],
//  [4, 16, 6, 9]]

// Read the second row. JavaScript starts counting at 0.
const step1 = grid.arraySync()[1];
console.log(step1); // [3, 18, 7, 8]

// Give each sensor its own row, from the first reading to the last.
const bySensor = grid.transpose();
console.log(bySensor.arraySync());
// [[2, 3, 4],     // Sensor A
//  [20, 18, 16],  // Sensor B
//  [5, 7, 6],     // Sensor C
//  [8, 8, 9]]     // Sensor D

// Release the tensors when you are done with them.
tf.dispose([flat, grid, bySensor]);`}
</CodeBlock>

Farah needs four readings in each row. `reshape([3, 4])` takes the list in
order and starts a new row after every four values. The operation keeps all 12 readings: `3 × 4 = 12`.

`arraySync()` copies the tensor's values into nested JavaScript arrays.
`grid.arraySync()[1]` reads the second row. `grid[1]` does not index a tensor.

After the reshape, Farah can see all four sensors at each time. Her chart
needs a different view: one sensor per row. `transpose()` turns the columns
into rows. The shape becomes `[4, 3]`: four sensors, with three readings each.

`reshape([4, 3])` also makes four rows, but its first row is `[2, 20, 5]`.
That mixes readings from sensors A, B, and C. `transpose()` gives sensor A
its own row: `[2, 3, 4]`. The two results have the same shape, but only one
keeps each sensor’s readings together.

<ConceptReference summary="Optional: images, extra axes, and memory">

### The same idea works for images

A shape gives the size of each axis, in order. A list of ten values has
shape `[10]`. A grid with three rows and four columns has shape `[3, 4]`.

You can also group images into a **batch** to process them together.
Suppose you have 32 color images, each 224 pixels high and 224 pixels wide.
Their shape could be `[32, 224, 224, 3]`:

- `32` images.
- `224` pixels high per image.
- `224` pixels wide per image.
- `3` color channels per pixel: red, green, and blue.

Here, the color channels come last, giving us a **channels-last** layout. Other models expect `[32, 3, 224, 224]`, with color channels before
height and width. Prepare the images in the order your model expects.

For another example, `[32, 5, 3]` could hold 32 short recordings. Each covers
five points in time, with three measurements at each point. Those
measurements are **features**. The data’s format defines what each axis represents.

### What happens to the data in memory?

Reshape uses **row-major order**: it reads across each row before moving down to the next. It makes new rows from that sequence. It does
not work out which readings belong to a sensor.

Here, TensorFlow.js lets `reshape()` reuse the data already stored in
`flat`. The exercise checks that `grid` reuses the data in `flat` through `reshape()`. Creating a tensor from copied values would allocate separate data. The arrays from `arraySync()` are separate
JavaScript copies.

The example above releases its tensors after reading the results. In the
challenge, keep `grid` and `bySensor` so the tests can check them. `step1`
is a regular JavaScript array, so it does not need `dispose()`.

### Swapping axes in a bigger tensor

With more than two axes, you can tell `transpose()` which order you want.
Axes use zero-based indexes.
`tensor.transpose([1, 0, 2])` puts the second axis first and the first axis
second. The third stays where it is. With no argument, TensorFlow.js reverses
all the axes. Check what each axis means before choosing an order.

</ConceptReference>
