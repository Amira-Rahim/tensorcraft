## Assembly Required

Assemble the network and call `model.predict()`. Prediction does not require compilation. `compile()` configures the optimizer, loss and metrics used by training; it does not fit or reset the weights. A newly initialized model can emit confident scores without having learned anything useful.

Hidden units need a way to learn different features. Identical initialization can preserve symmetry: units start with the same computation and can receive identical updates. Random kernel weights are a common way to break that symmetry. In this TFJS dense layer, the defaults are Glorot-normal kernel initialization and zero biases. `kernelInitializer` and `biasInitializer` can change them.

Glorot chooses the draw's scale using the layer's input and output widths. That aims to control signal variance under assumptions about the inputs and activations. It does not guarantee that every signal stays well-scaled or that no unit saturates. Training behavior still needs observation.

<CodeBlock language="typescript" title="complete-network.ts">
{`import * as tf from '@tensorflow/tfjs';

// 1. Create the model
const model = tf.sequential();

// 2. Add layers (like registering each stage of the pipeline)
model.add(tf.layers.dense({
  units: 32,
  activation: 'relu',
  inputShape: [3],     // 3 sensor inputs
}));
model.add(tf.layers.dense({ units: 16, activation: 'relu' }));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

// 3. Configure training. predict() already works on the initialized weights.
model.compile({
  optimizer: 'adam',              // how to update weights
  loss: 'binaryCrossentropy',    // how to measure error
  metrics: ['accuracy'],          // what to track
});

// 4. Verify with summary. TFJS names layers className + counter
// (dense_Dense1, not dense_1) and prints four columns:
model.summary();
// __________________________________________________________________________________________
// Layer (type)                Input Shape               Output shape              Param #
// ==========================================================================================
// dense_Dense1 (Dense)        [[null,3]]                [null,32]                 128
// __________________________________________________________________________________________
// dense_Dense2 (Dense)        [[null,32]]               [null,16]                 528
// __________________________________________________________________________________________
// dense_Dense3 (Dense)        [[null,16]]               [null,1]                  17
// ==========================================================================================
// Total params: 673
// Trainable params: 673
// Non-trainable params: 0
// __________________________________________________________________________________________

// 5. Test with a prediction
const testInput = tf.tensor2d([[0.5, 0.8, 0.2]]);
const prediction = model.predict(testInput) as tf.Tensor;
console.log('Initial prediction:', prediction.dataSync());
tf.dispose([testInput, prediction]);
model.dispose();`}
</CodeBlock>

`optimizer: 'adam'` names the algorithm that adjusts weights during training, and Adam uses moving estimates of gradients and their squares to scale parameter updates. You still choose its base learning rate. `loss: 'binaryCrossentropy'` sets how error gets measured. Binary crossentropy is a common loss for a binary probability model. Mean squared error, MSE, is a common regression loss. The task, output format and costs still determine the appropriate objective. `metrics: ['accuracy']` only adds a number to the training log, the share of predictions that came out correct. It does not change what the model learns.

## Challenge

Assemble and compile the complete DEEP SCAN signal classifier, then measure what compiling bought. You build it twice, sweep both copies over the same 120 readings while both are still untrained, train one of them, and sweep that one again. The `fit()` call is written out for you in the instructions; module 3 is where it gets taken apart.

The practice model differs from the bridge build in both input width and layer sizes. It reads 8 features through 24/12/1 units: `(8 × 24 + 24) + (24 × 12 + 12) + (12 + 1) = 529` parameters. Its synthetic batch adds five noise features to the three class-dependent ones. Compare its own before/after outputs; do not compare its parameter count as if only the input width changed. Module 3 returns to the bridge’s 3-input, 32/16/1 stack with 673 parameters.
