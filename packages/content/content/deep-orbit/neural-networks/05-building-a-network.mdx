## The rehearsal's inputs and layers

The challenge supplies 120 generated rows, each with eight dimensionless
features. The first three are amplitude, zero-crossing, and phase proxies.
Their distributions differ between the two generated groups. Five extra
practice features use the same noise distribution for both groups.

The generator assigns label 0 to rows 0-59 and label 1 to rows 60-119.
These are practice targets, separate from the ship's measurements and sample
7741. This batch also differs from the two-feature normalization task.

Define `buildClassifier()` to create a new Sequential model and add these
dense layers in order. Compile it before returning it. Each call must create
its own model and weights. Assigning `second = model` gives two names to the
same object and cannot provide an untrained comparison.

| Layer | Input features | Units | Activation | Weights and biases |
| --- | --- | --- | --- | --- |
| First hidden | 8 | 24 | ReLU | `8 * 24 + 24 = 216` |
| Second hidden | 24 | 12 | ReLU | `24 * 12 + 12 = 300` |
| Output | 12 | 1 | Sigmoid | `12 * 1 + 1 = 13` |

Each model has `216 + 300 + 13 = 529` parameters. Each layer keeps one kernel
tensor, its weights, and one bias tensor. The three layers therefore have six
weight tensors in total. The complete bridge example below shows the same
construction calls with its separate three-feature configuration.

Hidden units need different starting points so they can learn different features. If all their weights start the same, they can keep receiving the same updates. Random starting weights help avoid this. These TensorFlow.js dense layers use Glorot-normal weights and zero biases by default. Change those settings with `kernelInitializer` and `biasInitializer`.

Glorot sets the size of the random weights using the layer's input and output
counts. This helps keep values from growing or shrinking too much as they
pass through layers. Check the actual values and loss during training.

## Compilation configures the next training call

Call `compile()` on each model inside `buildClassifier()`. For a model named
`network`, the configuration is:

<CodeBlock language="typescript" title="compile-rehearsal.ts">
{`network.compile({
  optimizer: 'adam',
  loss: 'binaryCrossentropy',
  metrics: ['accuracy'],
});`}
</CodeBlock>

These options have different jobs:

- `optimizer: 'adam'` chooses how to adjust the weights. Adam uses recent gradients and their squares to scale the updates. It also has a base learning rate.
- `loss: 'binaryCrossentropy'` measures the error for this binary target and sigmoid output. A different task or output format can need another loss.
- `metrics: ['accuracy']` logs the share of predictions that are correct. It does not choose the training updates.

Compilation does not fit or reset the weights. `predict()` already works once
the layers are built, including before compilation. A confident initial score
does not establish that the model has learned anything useful.

## Initial weights and both untrained sweeps

A **sweep** runs every row through one model and collects one score per row.
Build both copies before training. Copy the first model's starting values into
plain arrays so you can keep that state after its weights change.

<CodeBlock language="typescript" title="initial-rehearsal.ts">
{`// buildClassifier creates and compiles a fresh model on each call.
const model = buildClassifier();
const second = buildClassifier();

const initialWeights = model.getWeights().map(
  weight => Array.from(weight.dataSync())
);

function scoresOf(network) {
  return tf.tidy(() => {
    const predictions = network.predict(readings) as tf.Tensor;
    return Array.from(predictions.dataSync());
  });
}

const sweepOne = scoresOf(model);
const sweepTwo = scoresOf(second);`}
</CodeBlock>

`initialWeights` holds six number arrays in kernel/bias order, with 529 values
altogether. Keep it before `fit()`. Each sweep holds 120 numbers because the
output layer returns one score for each of the 120 rows.

`tf.tidy()` releases the prediction tensor after the callback copies its
values. It returns the plain array. Both models remain untrained here, with
zero optimizer updates. Independent random weights can give different starting
scores. Those scores can also coincide, so a difference is not a requirement.

## One fit on the first model

<CodeBlock language="typescript" title="train-first-rehearsal.ts">
{`const history = await model.fit(readings, labels, {
  epochs: 50,
  batchSize: 16,
});
const trainedSweep = scoresOf(model);
const secondAgain = scoresOf(second);`}
</CodeBlock>

An **epoch** is one pass through the training rows. Here, each epoch uses
eight batches: seven groups of 16 and a final group of 8. Completing all
50 epochs applies 400 optimizer updates to the first model. The second model
receives no `fit()` call and stays at its own starting weights.

`await` keeps the final sweep after training finishes. Compare `trainedSweep`
with `sweepOne` row by row. `secondAgain` should still match `sweepTwo`, since
its model has not changed. The `history` object contains this fit's measured
loss and metrics. Module 3 explains how those updates work.

In the Concept activity, inspect each stage and its settings. The schedule
calculation predicts update counts. It supplies no prediction values or loss.
Even an equal update count can describe a different run: 100 epochs at batch
size 32 also gives 400 updates, but the challenge requests 50 epochs at 16.

## The separate bridge configuration

The bridge architecture has three inputs, 32 and 16 hidden units, and one
sigmoid output: 673 parameters. The complete example below builds a fresh,
untrained copy. Its `[0.5, 0.8, 0.2]` test row is an illustrative input with
no capture ID or label. It is separate from the eight-feature rehearsal.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="complete-network.ts">
{`import * as tf from '@tensorflow/tfjs';

// 1. Create the model
const model = tf.sequential();

// 2. Add layers (like registering each stage of the pipeline)
model.add(tf.layers.dense({
  units: 32,
  activation: 'relu',
  inputShape: [3],     // 3 input features in this bridge configuration
}));
model.add(tf.layers.dense({ units: 16, activation: 'relu' }));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

// 3. Configure training. predict() already works on the initialized weights.
model.compile({
  optimizer: 'adam',              // how to update weights
  loss: 'binaryCrossentropy',    // how to measure error
  metrics: ['accuracy'],          // what to track
});

// 4. Verify with summary. TFJS names layers className + counter
// (such as dense_Dense1) and prints four columns:
model.summary();
// __________________________________________________________________________________________
// Layer (type)                Input Shape               Output shape              Param #
// ==========================================================================================
// dense_Dense1 (Dense)        [[null,3]]                [null,32]                 128
// __________________________________________________________________________________________
// dense_Dense2 (Dense)        [[null,32]]               [null,16]                 528
// __________________________________________________________________________________________
// dense_Dense3 (Dense)        [[null,16]]               [null,1]                  17
// ==========================================================================================
// Total params: 673
// Trainable params: 673
// Non-trainable params: 0
// __________________________________________________________________________________________

// 5. Test with a prediction
const testInput = tf.tensor2d([[0.5, 0.8, 0.2]]);
const prediction = model.predict(testInput) as tf.Tensor;
console.log('Initial prediction:', prediction.dataSync());
tf.dispose([testInput, prediction]);
model.dispose();`}
</CodeBlock>
