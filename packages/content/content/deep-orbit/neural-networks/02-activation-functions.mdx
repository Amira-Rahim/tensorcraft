Any numeric score can be compared with a threshold. A sigmoid adds a useful range, from 0 to 1, but it does not choose the threshold or make an untrained score trustworthy. Activations also serve another purpose: they let hidden layers represent functions that a single weighted sum cannot.

You will apply ReLU, an activation function that turns negative values into zero and keeps positive values.

## What a Linear Stack Cannot Add

A matrix multiplication plus a bias is called an **affine** transformation. It scales and combines inputs, then adds a constant. Stacking these calculations still gives one affine transformation. To represent more kinds of patterns, the stack needs a nonlinear operation.

<CodeBlock language="typescript" title="collapse.ts">
{`import * as tf from '@tensorflow/tfjs';

// Two affine layers, with hand-picked numbers so the check is repeatable.
tf.tidy(() => {
  const w1 = tf.tensor2d([[2, -1], [0.5, 3]]);
  const b1 = tf.tensor1d([0.1, -0.2]);
  const w2 = tf.tensor2d([[1], [2]]);
  const b2 = tf.tensor1d([0.3]);
  const xs = tf.tensor2d([[0, 0], [1, 2], [-1, 0.5]]);
  const stacked = xs.matMul(w1).add(b1).matMul(w2).add(b2);
  const W = w1.matMul(w2);
  const b = b1.reshape([1, 2]).matMul(w2).add(b2);
  const combined = xs.matMul(W).add(b);
  console.log(stacked.sub(combined).abs().max().dataSync()[0]);
  // Near zero, subject to float32 rounding. Same affine computation.
});`}
</CodeBlock>

A **nonlinear** activation changes that restriction. ReLU is `Math.max(0, x)`. It keeps positive values and replaces negative values with zero. Two ReLU units can form `relu(x) + relu(-x)`, which equals `Math.abs(x)`. No single affine function matches that V-shaped function across both negative and positive inputs.

Adding ReLU permits nonlinear behavior; it does not guarantee it. If all relevant inputs keep the same units active, the network can act affinely over that region. Other network operations can also introduce nonlinearity. Here we are discussing a stack of dense layers.

<CodeBlock language="typescript" title="activations.ts">
{`import * as tf from '@tensorflow/tfjs';

tf.tidy(() => {
  const raw = tf.tensor1d([-2, -1, 0, 1, 2]);
  console.log(tf.relu(raw).arraySync());    // [0, 0, 0, 1, 2]
  console.log(tf.sigmoid(raw).arraySync()); // about [0.12, 0.27, 0.5, 0.73, 0.88]
  console.log(tf.tanh(raw).arraySync());    // about [-0.96, -0.76, 0, 0.76, 0.96]
});`}
</CodeBlock>

For finite real inputs, sigmoid lies strictly between 0 and 1 and tanh between -1 and 1. Floating-point implementations can round to an endpoint. ReLU has no upper bound.

## A Score and an Alert Are Different

For the two scores Nazari read out, sigmoid gives about 0.485 and 0.739. A threshold of 0.5 alerts on the second. Thresholding the original scores at zero gives the same decisions. The sigmoid changes the score scale, not the ordering.

Sigmoid is often used for a model with two possible classes. A score of 0.8 is not automatically a reliable 80% probability. To earn that meaning, about 80% of comparable examples scored 0.8 should belong to the positive class. Checking this agreement is called **calibration**. Test it on data like the model will see in use.

**ReLU** is a common hidden-layer choice. Its derivative, the local rate of change, is 1 for a positive input and 0 for a negative one. That derivative does not shrink a positive branch's gradient by itself; the rest of the network still affects the gradient.

**Sigmoid** commonly supplies a binary output score. **Tanh** supplies a bounded signed value, useful when that range fits the model. Range is one consideration; training behavior and the loss function matter too. Module 3 connects those choices to parameter updates.

<DerivationDrawer summary="Why sigmoid is bounded, and what logistic regression adds">
Write the mathematical sigmoid as `1 / (1 + exp(-z))` for a finite real score `z`. The exponential is positive, so the denominator is greater than one. At zero, the output is 0.5. As z increases, the output approaches one; as z decreases, it approaches zero.

The symmetry `sigmoid(-z) = 1 - sigmoid(z)` follows by multiplying numerator and denominator by `exp(z)`. This is an arithmetic identity, not a statement about prediction reliability. JavaScript's `Math.exp` has finite precision and can overflow or underflow; use the library operation for tensor work.

A learned weighted sum followed by sigmoid is a binary logistic-regression model. It is a useful baseline before adding hidden layers. “Regression” in its name does not mean its output task is predicting an unrestricted continuous quantity.
</DerivationDrawer>

## When Gradients Become Small

A ReLU unit that stays negative on the training examples receives zero gradient through that activation. It can remain inactive, a problem called **dying ReLU**. This is not a claim that every currently negative unit is permanently dead.

Sigmoid's derivative becomes small in its tails, called **saturation**. Repeated small factors can weaken gradients through hidden layers. The full gradient also depends on the loss and other operations; a confident wrong sigmoid output does not automatically mean the model cannot learn from it.
