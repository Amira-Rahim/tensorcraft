## Breaking the Collapse

Without activation functions, a neural network is stacked linear transformations, and stacked linear maps multiply out to a single matrix: ten layers of pure matrix math collapse into one. Activations break the collapse. They are the only place the network gets to bend. Do not take that on faith; it is a claim you can run.

<CodeBlock language="typescript" title="collapse.ts">
{`import * as tf from '@tensorflow/tfjs';

// Three stages of lesson 1's arithmetic with the activations left out,
// at the widths module 3's classifier will use: 3 in, 32, 16, 1 out.
const w1 = tf.randomNormal([3, 32], 0, 0.25), b1 = tf.randomNormal([32], 0, 0.25);
const w2 = tf.randomNormal([32, 16], 0, 0.25), b2 = tf.randomNormal([16], 0, 0.25);
const w3 = tf.randomNormal([16, 1], 0, 0.25), b3 = tf.randomNormal([1], 0, 0.25);
const stack = (x: tf.Tensor) =>
  x.matMul(w1).add(b1).matMul(w2).add(b2).matMul(w3).add(b3);

// Multiply the three weight matrices into one and fold the biases along.
const W = w1.matMul(w2).matMul(w3);                                   // [3, 1]
const b = b1.reshape([1, 32]).matMul(w2).add(b2).matMul(w3).add(b3);  // [1, 1]
const single = (x: tf.Tensor) => x.matMul(W).add(b);

const xs = tf.randomUniform([200, 3]);
console.log(stack(xs).sub(single(xs)).abs().max().dataSync()[0]);
// Under 1e-6 on every one of 3,000 fresh draws, 1.2e-7 on a typical one:
// float32 rounding, not a difference. 673 numbers, and they answer
// exactly like 3 weights and 1 bias.

// Bend each hidden stage and the shortcut stops working.
const bent = (x: tf.Tensor) =>
  tf.relu(tf.relu(x.matMul(w1).add(b1)).matMul(w2).add(b2)).matMul(w3).add(b3);
console.log(bent(xs).sub(single(xs)).abs().max().dataSync()[0]);
// About 0.6 on a typical draw, anywhere from 0.04 to 3 over 3,000 of them,
// and no single matrix closes it.`}
</CodeBlock>

The stack holds 673 numbers and answers exactly like lesson 1's neuron, three weights and one bias, and those four are computed from all 673 rather than picked out of them. That is what collapse means, and it is arithmetic, not a training failure. Put relu between the stages and the shortcut breaks, because `Math.max(0, x)` is not a multiplication, so no matrix does what it does. Every stage lesson 3 stacks is worth something only because of that bend.

<CodeBlock language="typescript" title="activations.ts">
{`import * as tf from '@tensorflow/tfjs';

const raw = tf.tensor([-2, -1, 0, 1, 2]);

// ReLU: max(0, x), the most popular activation
const relu = tf.relu(raw);        // [0, 0, 0, 1, 2]

// Sigmoid: squash to (0, 1), good for probabilities
const sigmoid = tf.sigmoid(raw);   // [0.12, 0.27, 0.5, 0.73, 0.88]

// Tanh: squash to (-1, 1), centered version of sigmoid
const tanh = tf.tanh(raw);         // [-0.96, -0.76, 0, 0.76, 0.96]

// JS equivalent of ReLU:
const jsRelu = [-2, -1, 0, 1, 2].map(x => Math.max(0, x));
// [0, 0, 0, 1, 2]: identical!`}
</CodeBlock>

## Answering the Board

Her two numbers are not a bug in the neuron. With the lesson-1 weights `[0.4, -0.2, 0.6]` and a bias of 0.1, three features between 0 and 1 can only score between -0.10 and 1.10, so both of her readings sit near the edges of what that neuron can say. The trouble is that those edges belong to those three weights. Change one weight and the edges move, and training in module 3 rewrites every one of them.

Run Nazari's two readings through the sigmoid and her question answers itself:

<CodeBlock language="typescript" title="board-verdicts.ts">
{`import * as tf from '@tensorflow/tfjs';

const board = tf.tensor([-0.06, 1.04]);  // the two scores Nazari read out
tf.sigmoid(board).print();               // [0.4850045, 0.73885]

// Both land inside (0, 1), where a 0.5 threshold means something.
// Minus 0.06 comes back 0.485, a no. 1.04 comes back 0.739, a yes.
// Those two started near the range on the luck of hand-picked
// weights. The bound owes nothing to that luck and holds for any
// score at all:
tf.sigmoid(tf.tensor([-11, 600])).print();  // [0.0000167, 1]

// -11 squashes to 0.0000167: a no, four zeros deep.
// 600 comes back as exactly 1: the curve is so flat out there that
// float32 has no digits left to hedge with. A yes.`}
</CodeBlock>

One word about what "yes" means, because the module has used it two ways. Lesson 1's neuron was hand-set to split the calibration tones because they were the only labeled data aboard, so high meant tone A: a two-class warm-up. Nazari's board asks a different question of the same number. From here on, high means anomalous, the reading the crew wants a human to look at, and low means the stream looks like the catalog. Same sigmoid, same threshold, one label.

Placement falls out of the ranges. ReLU stays in the hidden layers, where the outputs feed more math. Its slope is exactly 1 for every positive input, so the learning signal you meet in module 3 passes through undiminished, and it is the cheapest of the three to compute. Sigmoid takes the output slot when the question is yes/no, because (0, 1) reads as a probability. Tanh takes it when values need to swing negative.

<DerivationDrawer summary="Sigmoid's math, and the classical model built from it">
**Why sigmoid lands strictly inside (0, 1).** The formula is `sigmoid(z) = 1 / (1 + Math.exp(-z))`, where `z` is the raw pre-activation score. `Math.exp(-z)` is positive for every `z`, so the denominator is always bigger than 1 and the division always lands strictly between 0 and 1. At `z = 0`, `Math.exp(0) = 1` and the output is exactly 0.5, which is why the sigmoid line in the code above shows 0.5 in the middle slot. Push `z` positive and `Math.exp(-z)` shrinks toward zero, pulling the output toward 1; push `z` negative and the denominator blows up, pushing the output toward 0. The endpoints are approached, never reached: 600 printed as exactly 1 above only because float32 ran out of digits, not because the math got there.

**The curve is symmetric around 0.5.** `sigmoid(-z) = 1 - sigmoid(z)`: write `1 - sigmoid(z)` as `Math.exp(-z) / (1 + Math.exp(-z))`, multiply top and bottom by `Math.exp(z)`, and you are left with `1 / (Math.exp(z) + 1)`, which is `sigmoid(-z)`. Check it against the printed values: `sigmoid(-1)` is 0.27, and `1 - sigmoid(1)` is `1 - 0.73 = 0.27`. A no is exactly as confident as the mirror-image yes.

**A sigmoid on a weighted sum is a complete model by itself.** Take a single neuron's weighted sum (each input times its weight, plus a bias), put sigmoid in the output slot, and you have **logistic regression**: the classical baseline worth beating before you add a single hidden layer. The name is a trap: despite the word regression, it is a classifier, and module 3 draws the line between the two properly.
</DerivationDrawer>

## When Activations Die

Each choice has a failure mode with a name. A ReLU neuron whose weighted sum stays negative outputs zero forever and stops learning: the dying ReLU. A sigmoid pushed hard into either tail goes flat and stops responding: saturation. Both failures show up the same way, as a gradient near zero. That quantity is what module 3 builds, and it is where the crew catches both of these.
