## A score before and after ReLU

The previous lesson's arithmetic example produced `0.26`. ReLU passes that
positive score through unchanged. A negative score becomes zero. Each
position follows the same rule: `Math.max(0, score)`.

Use the activity's **Five-score diagnostic** to check the same inputs as the
challenge: `[-2, -0.5, 0, 1.5, 3]`. These are supplied test values, separate
from the calibration-tone recordings. Select a position to compare its
value before and after the activation.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="activations.ts">
{`import * as tf from '@tensorflow/tfjs';

tf.tidy(() => {
  const raw = tf.tensor1d([-2, -0.5, 0, 1.5, 3]);
  console.log(tf.relu(raw).arraySync());    // [0, 0, 0, 1.5, 3]
  console.log(tf.sigmoid(raw).arraySync()); // about [0.119, 0.378, 0.5, 0.818, 0.953]
  console.log(tf.tanh(raw).arraySync());    // about [-0.964, -0.462, 0, 0.905, 0.995]
});`}
</CodeBlock>

The first two scores become `0`. Zero stays `0`. ReLU keeps `1.5` and `3`
unchanged, including their positions. It also preserves the tensor's shape.
A two-dimensional input stays two-dimensional:

<CodeBlock language="typescript" title="relu-keeps-shape.ts">
{`tf.tidy(() => {
  const raw = tf.tensor2d([[-1, 2], [0.5, -0.25]]);
  const activated = raw.relu();
  console.log(activated.shape);       // [2, 2]
  console.log(activated.arraySync()); // [[0, 2], [0.5, 0]]
});`}
</CodeBlock>

Select **Large-positive diagnostic** in the activity. The supplied inputs
include `6.5` and `2 ** 126`, about `8.5e37`. ReLU keeps both unchanged.
It has no upper limit. ReLU6, a different activation that clips at `6`,
would change both values and fail this task.

and mapping over them breaks the gradient connection training will need.

## Why hidden layers need a nonlinear step

An **affine** transformation scales and combines inputs, then adds a bias.
A dense layer with no activation does this. Stack several such layers and
their matrices and biases still combine into one affine transformation.
Extra layers alone cannot escape that restriction.

ReLU is **nonlinear**. Its rule changes at zero. Two units can calculate
`relu(x) + relu(-x)`, which equals `Math.abs(x)`. At inputs `-1`, `0`, and
`1`, that gives `1`, `0`, and `1`: a V shape. One straight affine rule cannot
match both sides of that V. ReLU lets Farah's hidden layers represent
patterns a single weighted sum cannot.

Adding ReLU permits that behavior. It does not guarantee a useful learned
pattern. If the same units stay active throughout the inputs you check,
the network can still act affinely over that region.

## Output ranges and alert decisions

Switch the activity to sigmoid or tanh and inspect the same position.
For finite real inputs, mathematical sigmoid lies strictly between `0` and
`1`. Tanh lies strictly between `-1` and `1`. Floating-point calculations can
round to an endpoint. ReLU keeps positive values without a ceiling.

For Nazari's scores of `-0.06` and `1.04`, sigmoid gives about `0.485` and
`0.739`. A threshold of `0.5` alerts on the second. Comparing the original
scores with zero gives the same two decisions. Sigmoid changes the scale
while keeping the order. The threshold is a separate setting.

A score of `0.8` does not establish a reliable 80% probability. Among
comparable examples scored near `0.8`, about 80% should belong to the
positive class for that interpretation to hold. Checking this agreement is
**calibration**. Use labeled data like the model will see in practice.

ReLU is a common hidden-layer choice. Its derivative, the local rate of
change, is `1` for positive inputs and `0` for negative inputs. The full
training gradient also depends on the rest of the network. Sigmoid often
supplies a binary output score. Tanh supplies a bounded signed value.
The loss function and training behavior also matter when choosing an activation.

### Two affine layers in one calculation

This separate numerical example checks the matrix-composition claim above.
The hand-picked inputs and weights make the equality repeatable. They do
not come from the calibration recordings.

<CodeBlock language="typescript" title="collapse.ts">
{`import * as tf from '@tensorflow/tfjs';

// Two affine layers, with hand-picked numbers so the check is repeatable.
tf.tidy(() => {
  const w1 = tf.tensor2d([[2, -1], [0.5, 3]]);
  const b1 = tf.tensor1d([0.1, -0.2]);
  const w2 = tf.tensor2d([[1], [2]]);
  const b2 = tf.tensor1d([0.3]);
  const xs = tf.tensor2d([[0, 0], [1, 2], [-1, 0.5]]);
  const stacked = xs.matMul(w1).add(b1).matMul(w2).add(b2);
  const W = w1.matMul(w2);
  const b = b1.reshape([1, 2]).matMul(w2).add(b2);
  const combined = xs.matMul(W).add(b);
  console.log(stacked.sub(combined).abs().max().dataSync()[0]);
  // Near zero, subject to float32 rounding. Same affine computation.
});`}
</CodeBlock>

### A unit that stays inactive

A ReLU unit that stays negative on the training examples receives zero
gradient through that activation. It can remain inactive, a problem called
**dying ReLU**. A negative value on one example does not establish that it
will stay inactive.

Sigmoid's derivative becomes small in its tails, called **saturation**.
Repeated small factors can weaken gradients through hidden layers. The full
gradient also depends on the loss and other operations. A confident wrong
sigmoid output does not by itself establish that the model cannot learn.

<DerivationDrawer summary="Sigmoid bounds and logistic regression">
Write the mathematical sigmoid as `1 / (1 + exp(-z))` for a finite real score `z`. The exponential is positive, so the denominator is greater than one. At zero, the output is 0.5. As z increases, the output approaches one. As z decreases, it approaches zero.

The symmetry `sigmoid(-z) = 1 - sigmoid(z)` follows by multiplying numerator and denominator by `exp(z)`. This identity describes the arithmetic. Prediction reliability still needs evaluation. JavaScript's `Math.exp` has finite precision and can overflow or underflow. Use the library operation for tensor work.

A learned weighted sum followed by sigmoid is a binary logistic-regression model. It is a useful baseline before adding hidden layers. Despite its name, logistic regression performs classification. Its sigmoid output gives a score between 0 and 1.
</DerivationDrawer>

</ConceptReference>
