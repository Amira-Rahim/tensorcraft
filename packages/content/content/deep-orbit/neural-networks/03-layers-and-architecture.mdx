## The three-layer network

The **bridge classifier** has three dense layers. The first has 32 units.
The second has 16. The last has one sigmoid unit that returns a score.
It has 673 **trainable parameters**, the weights and biases training can change.

This model expects three prepared features per example. A feature is one
number the model reads about that example. Those three input slots summarize
a capture. They are separate from the ship's 64 sensor channels and from the
number of examples in a batch. This lesson checks the architecture and its
parameter count. It does not establish feature extraction or event labels.

For the extraction discussed later, 64 consecutive samples from one channel
cover a quarter of a second at 256 samples per second. Those 64 samples
describe a time window, while 64 channels describe the sensor array.

Like a middleware chain, each layer reads the previous layer's result, changes it, and passes it on.

A **dense layer** with 32 units contains 32 neurons. Each reads all three inputs using its own weights and bias. ReLU then acts on each of the 32 scores.

The next layer has 16 neurons, each reading those 32 outputs. Its ReLU outputs go to the final neuron. The activations let the stack represent nonlinear patterns. Without them, all these layers would still combine into one affine calculation.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="layer-architecture.ts">
{`import * as tf from '@tensorflow/tfjs';

// Node: compose middleware
// app.use(parseBody);      // reads the raw request
// app.use(extractFields);  // transforms it
// app.use(sendResponse);   // produces the result

// ML: compose layers
const model = tf.sequential();

// First hidden stage: 3 features in, 32 units out
model.add(tf.layers.dense({
  units: 32,
  activation: 'relu',
  inputShape: [3],     // 3 features in
}));

// Second hidden stage: 32 in, 16 out
model.add(tf.layers.dense({
  units: 16,
  activation: 'relu',
}));

// Output layer: binary classification
model.add(tf.layers.dense({
  units: 1,
  activation: 'sigmoid', // bounded binary score. Evaluate before trusting it
}));

model.summary(); // prints layer shapes and parameter counts
model.dispose();`}
</CodeBlock>

## Each layer's share of the count

Every dense unit has one weight per input and one bias. A layer with `inputs`
incoming values and `units` outputs therefore has `(inputs * units) + units`
parameters. Count the bridge classifier's layers separately:

| Bridge layer | Inputs per example | Units | Weights | Biases | Subtotal |
| --- | --- | --- | --- | --- | --- |
| First hidden layer | 3 | 32 | 96 | 32 | 128 |
| Second hidden layer | 32 | 16 | 512 | 16 | 528 |
| Output layer | 16 | 1 | 16 | 1 | 17 |

The total is `128 + 528 + 17 = 673`. The second layer reads the first layer's
32 outputs, so its weight count is `32 * 16`. The number of original features
does not carry through unchanged to every layer.

Only the first layer needs `inputShape`. Later layers get their input count from the previous layer's output. Change the first input shape to `[8]` while keeping 32/16/1 units, and the count becomes 833.

Sending more examples through the same model does not create more weights.
A batch with 20 examples and a batch with one example use the same parameters.
Batch size affects how much data moves through each layer at once.

## The challenge's separate practice stack

The challenge uses a **four-feature practice model** with 16, 8, and 1 units.
The first two layers use ReLU, and the last uses sigmoid.
It is a separate configuration from the bridge classifier. No capture values,
physical units, or labels accompany its four input slots.

| Practice layer | Inputs per example | Units | Weights | Biases | Subtotal |
| --- | --- | --- | --- | --- | --- |
| First hidden layer | 4 | 16 | 64 | 16 | 80 |
| Second hidden layer | 16 | 8 | 128 | 8 | 136 |
| Output layer | 8 | 1 | 8 | 1 | 9 |

This total is `80 + 136 + 9 = 225`. If only the input width changes, the
first layer gains 16 weights for each extra feature. Its biases and both
later layers stay the same. For any positive width, the total is
`16 * width + 161`.

Here is the same calculation for six input features. It creates no model
or tensor:

<CodeBlock language="javascript" title="parameter-quote.js">
{`const featureWidth = 6;
const units = [16, 8, 1];
let incoming = featureWidth;
const layerCounts = units.map((outgoing) => {
  const count = incoming * outgoing + outgoing;
  incoming = outgoing;
  return count;
});
const quotedParams = layerCounts.reduce((total, count) => total + count, 0);
console.log(layerCounts);  // [112, 136, 9]
console.log(quotedParams); // 257`}
</CodeBlock>

In the activity, choose the bridge or practice configuration. Change its input
width, then select a layer to inspect the weights and biases that contribute

Nonlinear activations let these stacks represent patterns that a single
affine calculation cannot. Parameter count describes the model's size.
Training and evaluation must establish whether its predictions are useful.

<ConceptReference summary="Optional: why nonlinear layers can represent XOR">

### What the network can represent

The stack has 673 parameters. The first lesson's neuron has four: three weights and one bias. More layers can represent patterns that one neuron cannot.

Consider two inputs that can each be 0 or 1. Flag a case only when exactly one input is 1. The four cases are `[0, 0]`, `[0, 1]`, `[1, 0]`, and `[1, 1]`, with labels 0, 1, 1, and 0. Plot them at the corners of a square. One weighted sum and a threshold can only draw one straight dividing line. No such line separates these labels.

This XOR task demonstrates a capacity limit of one affine score with a threshold. More parameters alone do not prove better predictions. The arrangement and nonlinearities matter.

Two ReLU units followed by a sum can represent XOR on binary inputs. You can check this construction without training:

<CodeBlock language="javascript" title="xor-capacity.js">
{`const relu = (x) => Math.max(0, x);
const xor = (a, b) => relu(a - b) + relu(b - a);
const cases = [[0, 0], [0, 1], [1, 0], [1, 1]];
const outputs = cases.map(([a, b]) => xor(a, b)); // [0, 1, 1, 0]
// For a sigmoid output, sigmoid(20 * (xor(a, b) - 0.5)) gives
// the same classes at threshold 0.5. These weights are chosen by hand.`}
</CodeBlock>

Representing a function and learning its weights are different questions. This construction answers the first. A training experiment must answer the second separately. A model can represent a solution yet fail to learn it with a particular initialization and training schedule.

This example shows what the layers can represent. It does not test the spacecraft data. In module 5, you’ll give the network eleven features per reading so it can learn from more aspects of the signal.

</ConceptReference>
