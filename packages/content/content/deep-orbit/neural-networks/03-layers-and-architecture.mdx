## Stages All the Way Down

Three dense layers, 673 trainable parameters. That's the whole system Nazari just asked for: a 32-unit stage reading the three features from lesson 1, a 16-unit stage that finds patterns in what the first stage produces, and a single sigmoid unit for the verdict. Those three are amplitude, frequency, and phase, each mapped to 0-1 against the range its own sensor can physically produce. Module 4 quotes those ranges when the browser pipeline has to apply them. Nazari's sixty-four channels do not arrive as sixty-four inputs. Extraction summarizes a capture into those three numbers before the model sees anything, off a 64-sample window, a quarter second of one channel at 256 Hz. That window is a different sixty-four from the stream's sixty-four channels. The composition logic is a middleware chain: each stage takes what the previous stage produced, transforms it, and hands the result on.

Say exactly what a stage is, because "finds patterns" describes the result, not the mechanism. A dense layer with 32 units is 32 copies of the lesson-1 neuron, plus the activation lesson 1 left out. Every one of them reads the same 3 inputs through its own weights and bias. That gives 32 weighted sums, and the layer's relu runs on each one before the next stage sees it. The 16-unit stage is 16 more neurons, and its inputs are those 32 relu outputs. They vote on combinations of the first stage's votes, and the verdict neuron votes on combinations of theirs. Lesson 2 already told you why the activation between stages is not optional. Without it, three stages of weighted sums multiply out to one weighted sum, and the stack would know exactly as much as a single neuron.

<CodeBlock language="typescript" title="layer-architecture.ts">
{`import * as tf from '@tensorflow/tfjs';

// Node: compose middleware
// app.use(parseBody);      ← takes the raw request
// app.use(extractFields);  ← transforms it
// app.use(sendResponse);   ← produces the result

// ML: compose layers
const model = tf.sequential();

// First hidden stage: 3 features in, 32 units out
model.add(tf.layers.dense({
  units: 32,
  activation: 'relu',
  inputShape: [3],     // 3 features in
}));

// Second hidden stage: 32 in, 16 out
model.add(tf.layers.dense({
  units: 16,
  activation: 'relu',
}));

// Output layer: binary classification
model.add(tf.layers.dense({
  units: 1,
  activation: 'sigmoid', // output 0-1 probability
}));

model.summary(); // prints layer shapes and parameter counts`}
</CodeBlock>

Two numbers price a dense layer: how many values arrive, and how many units read them. The layer holds one weight for every incoming value on every unit, plus one bias per unit: `(inputs * units) + units`. Run that down the three stages above and you get Nazari's 673. On the first layer the arriving width is whatever `inputShape` declares, so that setting carries a price too. Every later layer inherits its width from the stage before it, which is why only the first one declares anything. Leave the units at 32/16/1 and change `inputShape` to `[8]`, and the same stack quotes 833.

Demir's first stack ran 96, then 32, then 1: 3,521 parameters, on a 96-unit first stage he picked because it looked like a serious number. Nazari read the quote, said nothing, and went back to her console. The 32/16/1 above is the third version he brought her.

## What the Count Buys

The stack costs 673 parameters. The lesson-1 neuron, three weights and a bias, costs 4. Here is the smallest case where that difference decides the answer rather than the speed. A reading carries two normalized inputs, so there are four cases to label: 0 and 0, 0 and 1, 1 and 0, 1 and 1. The label fires when exactly one of the two reads high, which makes the middle two 1 and the outer two 0. Plot the four on a square, one axis per input. One weighted sum plus a threshold draws a single straight line on that square. No straight line puts the two cases labeled 1 on one side and the two labeled 0 on the other.

Two calls in the block below are not yours to worry about yet. `compile()` picks how the weights get adjusted and how error is measured, and `fit()` runs the adjusting; lesson 5 wires the first one, and module 3 takes both apart. Read the two console lines, not the setup.

<CodeBlock language="typescript" title="one-stage-vs-two.ts">
{`import * as tf from '@tensorflow/tfjs';

const xs = tf.tensor2d([[0, 0], [0, 1], [1, 0], [1, 1]]);
const ys = tf.tensor2d([[0], [1], [1], [0]]);  // 1 when exactly one reads high

// One sigmoid unit, no hidden stage: 3 parameters.
const flat = tf.sequential();
flat.add(tf.layers.dense({ units: 1, activation: 'sigmoid', inputShape: [2] }));
flat.compile({ optimizer: tf.train.adam(0.05), loss: 'binaryCrossentropy' });
await flat.fit(xs, ys, { epochs: 3000 });
console.log(Array.from((flat.predict(xs) as tf.Tensor).dataSync()));
// all four within a hundredth of 0.50, every run

// One 16-unit relu stage in front of the same output unit: 65 parameters.
const staged = tf.sequential();
staged.add(tf.layers.dense({ units: 16, activation: 'relu', inputShape: [2] }));
staged.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));
staged.compile({ optimizer: tf.train.adam(0.05), loss: 'binaryCrossentropy' });
await staged.fit(xs, ys, { epochs: 3000 });
console.log(Array.from((staged.predict(xs) as tf.Tensor).dataSync()));
// all four within 0.0003 of 0, 1, 1, 0 on all but about one run in sixty`}
</CodeBlock>

A hundred runs of the flat model, three hundred of the staged one. The one-unit version answered 0.50 on every point, every run, to within a hundredth, which is as close as a single straight line gets. The staged version got all four right, within 0.0003, on 295 of its 300 runs, on 62 more parameters; the other five answered 0.5 on two of the points, which is the failure the next paragraph is about.

An 8-unit stage would be cheaper and it is not enough: in a hundred runs of it, eight came back answering 0.5 on two of the four points, which is the flat model's answer, because too many of its eight relu units died during training. Dead units on their own are not the exception. 98 of those hundred runs ended with at least one, and 92 of the hundred got all four points right anyway: a working 8-unit run carries 3 dead units at the median, and the 16-unit stage above carries 6 dead of its 16 at the median and still missed only five times in 300 runs. What decides a run is how many units die against the width of the stage.

No reading this ship extracts needs a boundary that shape yet; module 5 widens a reading to eleven features, and stages are what read combinations of them.
