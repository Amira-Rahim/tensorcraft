## The diagnostic input contract

The challenge supplies two practice rows, `[1, 2]` and `[3, 4]`. Each has two
feature slots with no physical units or capture provenance. They are
diagnostic inputs, separate from the bridge classifier's three features.

Build one dense layer with three units. Keep its default **linear activation**,
which leaves each weighted sum unchanged. Its kernel, the weight matrix, has
shape `[2, 3]`: one row per input feature and one column per output unit.
The bias has shape `[3]`, one value per unit. That is `2 * 3 + 3 = 9` parameters.

| Value | Shape | Meaning |
| --- | --- | --- |
| Two input rows | `[2, 2]` | Two examples, two features each |
| Kernel | `[2, 3]` | Two input weights for each of three units |
| Bias | `[3]` | One bias per unit, reused for each example |
| Output | `[2, 3]` | Three unit outputs for each input row |

<CodeBlock language="javascript" title="diagnostic-forward.js">
{`const diagnostic = tf.sequential();
diagnostic.add(tf.layers.dense({ units: 3, inputShape: [2] }));
const twoRows = tf.tensor2d([[1, 2], [3, 4]]);
const outputs = diagnostic.predict(twoRows);
console.log(outputs.shape); // [2, 3]
console.log(outputs.arraySync()); // values depend on the initial weights`}
</CodeBlock>

One `predict()` call returns outputs for the whole batch. Return that tensor
from your `forward(batch)` function. Repeated calls for individual rows add
work and fail the challenge's batch contract. A copied or cloned output also
fails its returned-tensor identity check.

The default kernel starts with random weights, and the default biases start
at zero. Do not replace those initializers in the challenge. A linear output
can be negative or greater than one. These three outputs are weighted sums,
with no established class or probability meaning.

## One captured unit's calculation

Read the weights from this same model. For the second input row, unit 3 uses
the third kernel column. Its calculation is `3 * weight1 + 4 * weight2 + bias`.
The indexes below start at zero:

<CodeBlock language="javascript" title="inspect-diagnostic-unit.js">
{`// Continue with diagnostic, twoRows, and outputs from above.
const [kernel, bias] = diagnostic.getWeights();
const weights = kernel.arraySync();
const biases = bias.arraySync();
const selectedRow = twoRows.arraySync()[1];
const unit = 2;
const products = selectedRow.map((value, feature) => value * weights[feature][unit]);
const manual = products.reduce((total, value) => total + value, biases[unit]);
const captured = outputs.arraySync()[1][unit];
console.log(products, biases[unit], manual, captured);`}
</CodeBlock>

The captured value comes from `predict()`. The manual value comes from the
same input, kernel column, and bias. Compare them with a small numerical
tolerance because TensorFlow.js and JavaScript can round differently.
Reading these weights does not train the model. Keep the model alive while
using its weight tensors.

After your challenge run, inspect **Your first forward pass** and **Weights
used for this forward pass**. They contain your actual outputs and the weights
used to calculate them. Choose a row and unit, then check that dot product. Random starting
weights change the numbers across runs, so a supplied reference value cannot
stand in for your result.

## One reading and larger batches

A single `[2]` reading needs a leading batch axis. `expandDims(0)` makes its
shape `[1, 2]` without changing either feature value. The same operation works
for any flat width. The resulting width must still match the chosen model.

<CodeBlock language="javascript" title="diagnostic-batches.js">
{`const flatReading = tf.tensor1d([5, 6]);
const oneRow = flatReading.expandDims(0);
const oneOutput = diagnostic.predict(oneRow);
console.log(oneRow.shape, oneOutput.shape); // [1, 2], [1, 3]

// The same model accepts three rows without changing its weights.
const threeRows = tf.tensor2d([[1, 2], [3, 4], [5, 6]]);
const threeOutputs = diagnostic.predict(threeRows);
console.log(threeOutputs.shape); // [3, 3]

tf.dispose([twoRows, outputs, flatReading, oneRow, oneOutput, threeRows, threeOutputs]);
diagnostic.dispose();`}
</CodeBlock>

The first axis counts examples. The second counts features at the input and
units at the output. The model keeps its nine parameters when the batch grows.
The challenge checks other batch lengths and verifies that adding an axis
preserves all values.

### Data through the three-layer bridge model

The bridge classifier uses the earlier three-input 32/16/1 architecture.
This supplied demonstration row `[0.5, 0.8, 0.2]` is an illustrative input,
with no capture record or known event label. It does not continue the
two-feature diagnostic batch.

The forward pass applies each layer in order. Demir's model needs a batch axis at the start, even when he sends it one reading.


<CodeBlock language="typescript" title="forward-pass.ts">
{`import * as tf from '@tensorflow/tfjs';

const model = tf.sequential();
model.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [3] }));
model.add(tf.layers.dense({ units: 16, activation: 'relu' }));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

// Forward pass: push one normalized reading through the network
const sensorReading = tf.tensor2d([[0.5, 0.8, 0.2]]);  // shape: [1, 3]

// predict() runs the full forward pass
const prediction = model.predict(sensorReading) as tf.Tensor;
console.log(prediction.shape);     // [1, 1]
console.log(prediction.dataSync()); // untrained score. The value depends on initialization

// Shape flow: [1, 3] to [1, 32] to [1, 16] to [1, 1]. Only the last axis changes.

// The feed hands over one reading at a time, flat. Give it the axis:
const flat = tf.tensor1d([0.5, 0.8, 0.2]); // shape: [3], which predict() rejects
const batched = flat.expandDims(0);        // shape: [1, 3]: a stack of one
const singlePrediction = model.predict(batched) as tf.Tensor; // runs`}
</CodeBlock>

This model expects a batch axis even for one reading, giving shape `[1, 3]`. A `[3]` tensor lacks that axis. The first number counts readings. The second counts features.

Use `expandDims(0)` to add a leading axis to the flat reading. `reshape([1, 3])` also works when you know its width. Before changing a shape, compare what the error expected with what the model received. Here, the missing batch axis caused the failure.

## Calculating a forward pass

`predict()` runs the same calculations you have learned. `getWeights()` returns six tensors for these three layers: a weight matrix and a bias for each layer. Multiply by the weights, add the bias, apply the activation, then pass the result to the next layer.

<CodeBlock language="typescript" title="by-hand.ts">
{`// Continues forward-pass.ts: same model, same reading.
tf.tidy(() => {
  // Read the model's existing weights. Do not change or dispose the model.
  const [w1, b1, w2, b2, w3, b3] = model.getWeights();
  const h1 = sensorReading.matMul(w1).add(b1).relu();  // [1, 32]
  const h2 = h1.matMul(w2).add(b2).relu();             // [1, 16]
  const out = h2.matMul(w3).add(b3).sigmoid();         // [1, 1]
  console.log(h1.shape, h2.shape, out.shape);
  console.log(out.sub(prediction).abs().max().dataSync()[0]);
  // Check a numerical tolerance. Fused kernels/backends may round differently.
});
tf.dispose([sensorReading, prediction, flat, batched, singlePrediction]);
model.dispose();`}
</CodeBlock>

These operations express the same computation for this dense network. Compare results using a suitable floating-point tolerance. Backends can round the same calculation differently. `predict()` manages its internal temporaries and returns output tensors that the caller owns. A hand-written chain also needs temporary-tensor cleanup, which the `tf.tidy()` block supplies.

</ConceptReference>
