At 0940, Demir's first network demo stops on a shape error. The model expects batches shaped `[rows, 3]`; he passes a flat `[3]` tensor. In TFJS 4.22.0, the input adapter expands that vector to `[3, 1]`, which still does not match. Three features have become three rows of one feature.

Commander Mirza leaves four minutes into the demo. Demir needs eleven more to find the missing batch axis. He had treated a reading like an event object: one item arrives, one handler receives it. The model's input contract says otherwise.

## Data Flows Forward

The forward pass itself is the simple part: data enters the first layer, gets transformed, and flows on until it reaches the output. The part that bit Demir is the shapes.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="forward-pass.ts">
{`import * as tf from '@tensorflow/tfjs';

const model = tf.sequential();
model.add(tf.layers.dense({ units: 32, activation: 'relu', inputShape: [3] }));
model.add(tf.layers.dense({ units: 16, activation: 'relu' }));
model.add(tf.layers.dense({ units: 1, activation: 'sigmoid' }));

// Forward pass: push one normalized reading through the network
const sensorReading = tf.tensor2d([[0.5, 0.8, 0.2]]);  // shape: [1, 3]

// predict() runs the full forward pass
const prediction = model.predict(sensorReading) as tf.Tensor;
console.log(prediction.shape);     // [1, 1]
console.log(prediction.dataSync()); // untrained score; the value depends on initialization

// Shape flow: [1, 3] → [1, 32] → [1, 16] → [1, 1]. Only the last axis changes.

// The feed hands over one reading at a time, flat. Give it the axis:
const flat = tf.tensor1d([0.5, 0.8, 0.2]); // shape: [3], which predict() rejects
const batched = flat.expandDims(0);        // shape: [1, 3]: a stack of one
const singlePrediction = model.predict(batched) as tf.Tensor; // runs`}
</CodeBlock>

Every input carries a batch dimension, even a batch of one: `[1, 3]`, not `[3]`. The network accepts stacked readings, and a single reading is a stack of height one. The runtime controls how that work executes. `expandDims(0)` adds that axis to a flat reading, and `reshape([1, 3])` does the same job when you already know the width. Read the error’s expected and actual shapes before changing the data. In this example, the missing axis explains the failure.

## The Same Pass, by Hand

`predict()` runs nothing you have not already written. `getWeights()` hands back the six tensors the three stages hold, in order: a weight matrix and a bias vector for each stage. Multiply, add the bias, bend, hand the result to the next stage.

<CodeBlock language="typescript" title="by-hand.ts">
{`// Continues forward-pass.ts: same model, same reading.
tf.tidy(() => {
  // Read the model's existing weights; do not change or dispose the model.
  const [w1, b1, w2, b2, w3, b3] = model.getWeights();
  const h1 = sensorReading.matMul(w1).add(b1).relu();  // [1, 32]
  const h2 = h1.matMul(w2).add(b2).relu();             // [1, 16]
  const out = h2.matMul(w3).add(b3).sigmoid();         // [1, 1]
  console.log(h1.shape, h2.shape, out.shape);
  console.log(out.sub(prediction).abs().max().dataSync()[0]);
  // Check a numerical tolerance; fused kernels/backends may round differently.
});
tf.dispose([sensorReading, prediction, flat, batched, singlePrediction]);
model.dispose();`}
</CodeBlock>

These operations express the same computation for this dense network. Expect agreement within a suitable floating-point tolerance, not bit-for-bit equality on every backend. `predict()` manages its internal temporaries and returns output tensors that the caller owns. A hand-written chain also needs temporary-tensor cleanup, which the `tf.tidy()` block supplies.
