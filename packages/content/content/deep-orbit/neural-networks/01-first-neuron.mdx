## Every contribution to one score

A neuron multiplies each input by a weight, adds those products, then adds a
bias. The bias is a constant offset. The result here is one score, before
an activation function or an alert threshold.

Use the same arithmetic check in the activity and code: inputs
`[0.5, 0.8, 0.2]`, weights `[0.4, -0.2, 0.6]`, and bias `0.1`.
These are supplied dimensionless example values. They do not identify a
measurement from tone A, tone B, or the unknown signal.

Select an input in the activity. Follow its value and matching weight into
its product, then the running sum. Input 2 contributes `0.8 * -0.2 = -0.16`.
That lowers the sum. The three products are `0.20`, `-0.16`, and `0.12`,
which total `0.16`. Add bias `0.1` to get `0.26`.

The `Array.reduce()` expression below computes the same score.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="first-neuron.ts">
{`import * as tf from '@tensorflow/tfjs';

// The same supplied arithmetic check as the activity.
const inputs = tf.tensor1d([0.5, 0.8, 0.2]);
const weights = tf.tensor1d([0.4, -0.2, 0.6]);
const bias = tf.scalar(0.1);

// The neuron computation: weighted sum + bias
const output = tf.tidy(() => tf.dot(inputs, weights).add(bias));
console.log(output.dataSync()); // Float32Array(1) [ 0.2600000202655792 ]

// Compare with the reduce() equivalent:
const jsInputs = [0.5, 0.8, 0.2];
const jsWeights = [0.4, -0.2, 0.6];
const jsOutput = jsInputs.reduce((sum, x, i) => sum + x * jsWeights[i], 0.1);
console.log(jsOutput); // approximately 0.26. JS and float32 rounding may differ
tf.dispose([inputs, weights, bias, output]);`}
</CodeBlock>

`tf.dot()` multiplies matching positions and adds the products. For these
one-dimensional inputs and weights, it returns a scalar tensor with shape
`[]` and rank `0`. Adding a scalar bias keeps that shape.

The calculation stays in tensor operations so training can later calculate
its gradients. `tf.tidy()` releases the temporary dot-product tensor and
keeps the returned score. Read the score outside the calculation, then
dispose of the inputs, weights, bias, and output when you finish with them.
In the challenge, keep the output available for the checks.

## A weight and its contribution

A weight's sign tells you how this score changes when its input increases.
The second weight is `-0.2`, so raising input 2 lowers the score. Its
magnitude tells you how much the score changes for a one-unit change in
that input. The input's scale defines what one unit means. Change that
weight to `+0.2` in the activity. Its contribution becomes `+0.16`,
and the final score rises from `0.26` to `0.58`. The inputs and bias stay
the same.

The contribution for one reading is **input times weight**. Input 3 has
the largest weight, `0.6`, but contributes `0.2 * 0.6 = 0.12`.
Input 1 contributes `0.5 * 0.4 = 0.20`. A larger weight can still produce
a smaller contribution when its input is smaller.

The bias shifts the final score by the amount you add. A decision threshold
is a separate rule that can later compare that score with a cutoff. Neither
the arithmetic score nor its sign establishes a class label.

<ConceptReference summary="Optional: sensitivity in a larger network">

A weight's magnitude describes how much this neuron's score changes for a
one-unit change in its input. Compare that sensitivity in the input's own
scale. Different physical units or scaling rules change what one unit means.

A weight near zero makes this neuron respond only a little to a one-unit
change in that input. Other neurons can still use the feature. Later layers
and activations also affect a network's final result. A weight alone cannot
establish whether a feature causes an event.

Training changes the parameters from labeled examples. This lesson checks
the calculation with supplied weights. Module 3 introduces those updates.

</ConceptReference>
