## The Simplest Learning Machine

A neuron takes inputs, multiplies each by a weight, sums the products, adds a bias, and emits one number. You've written this exact pattern with `Array.reduce()`.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="first-neuron.ts">
{`import * as tf from '@tensorflow/tfjs';

// A neuron with 3 inputs
const inputs = tf.tensor([0.5, 0.8, 0.2]);   // sensor readings
const weights = tf.tensor([0.4, -0.2, 0.6]);  // hand-picked weights
const bias = tf.scalar(0.1);                   // threshold offset

// The neuron computation: weighted sum + bias
const output = tf.tidy(() => tf.dot(inputs, weights).add(bias));
console.log(output.dataSync()); // Float32Array(1) [ 0.2600000202655792 ]

// Compare with the reduce() equivalent:
const jsInputs = [0.5, 0.8, 0.2];
const jsWeights = [0.4, -0.2, 0.6];
const jsOutput = jsInputs.reduce((sum, x, i) => sum + x * jsWeights[i], 0.1);
console.log(jsOutput); // approximately 0.26; JS and float32 rounding may differ
tf.dispose([inputs, weights, bias, output]);`}
</CodeBlock>

Each weight scales its own input: a positive weight pushes the output up, a negative one pushes against it. The bias adds a constant to the output. If you later compare that output with a threshold, changing the bias moves the decision boundary.

## Reading the Weights

Those three numbers are hand-picked so the arithmetic stays followable; training will overwrite every one of them in module 3. These weights are easy to interpret because this is one affine function. In a deeper network, later weights and activations also affect the final output. Practice the local reading here, on inputs that mean amplitude, frequency, and phase.

Sign is direction. Weight 0.4 on amplitude: louder pushes the verdict up, moderately. Weight -0.2 on frequency says this neuron treats higher frequency as mild evidence AGAINST. Run the flip to feel it: change `-0.2` to `+0.2` in the code above and the same reading scores 0.58 instead of 0.26, identical evidence now arguing for the other side.

Magnitude is sensitivity, not importance. A weight says how much the output moves per unit of that input, so the vote an input casts is weight times input. Run the row: amplitude contributes `0.5 * 0.4 = 0.20`, frequency `0.8 * -0.2 = -0.16`, phase `0.2 * 0.6 = 0.12`. Per unit of phase, 0.6 is the loudest coefficient here. Phase still cast the smallest vote of the three in size, 0.12 against 0.20 and 0.16, because it read low on this sample. Because all three features were mapped onto the same 0-1 scale, the weights are comparable to each other as per-unit sensitivities. What they cannot tell you is which input drove one particular reading; that is the vote, and the vote changes with the sample.

A small coefficient gives this unit low sensitivity to that input in its current units. It does not prove that the feature is globally unimportant, unnecessary or causally unrelated to the target.
