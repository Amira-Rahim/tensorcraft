      function ensembleGain(members, actual) {
        const mae = (values) =>
          values.reduce((sum, v, i) => sum + Math.abs(v - actual[i]), 0) /
          actual.length;

        const perMember = Object.create(null);
        for (const member of members) {
          perMember[member.name] = mae(member.predictions);
        }

        const blended = actual.map(
          (_, i) =>
            members.reduce((sum, m) => sum + m.predictions[i], 0) / members.length,
        );
        const ensemble = mae(blended);

        // Multiplying every inverse-square weight by minError^2 cancels
        // during normalization and avoids overflow for very small errors.
        const minError = Math.min(...members.map(member => member.heldOutError));
        const inverseSquaredError = members.map(
          (member) => (minError / member.heldOutError) ** 2,
        );
        const total = inverseSquaredError.reduce((sum, v) => sum + v, 0);
        const weights = Object.create(null);
        members.forEach((member, i) => {
          weights[member.name] = inverseSquaredError[i] / total;
        });

        const weightedBlend = actual.map((_, i) =>
          members.reduce((sum, m) => sum + m.predictions[i] * weights[m.name], 0),
        );
        const weighted = mae(weightedBlend);

        const best = Math.min(...Object.values(perMember));
        return { perMember, ensemble, weights, weighted, beatsBest: ensemble < best };
      }

<Dialogue speaker="Ensign Demir">
The LSTM is great at short-range patterns. The attention model catches long-range dependencies. The Kalman filter smooths the noise off the level. Why choose one when we can combine all three?
</Dialogue>

<Dialogue speaker="Dr. Farah">
Because all three run on every input. An ensemble isn't a router that picks the right specialist. Every model runs, so total computation grows. Elapsed time also depends on whether the hardware can run them concurrently. Different errors may partly cancel, but a shared mistake survives the blend.
</Dialogue>

`Promise.all([svcA(x), svcB(x), svcC(x)])` is the shape that carries over: one input, three calls that all run, one bill that is the sum of the three. What does not carry over is the reason you fan out. Services can answer the same or different questions. An ensemble needs predictions about the same target, time and units. A third model must justify its compute cost through measured accuracy, robustness or another explicit requirement.

You will combine forecasts using weights based on earlier errors, then compare the result with the best individual model.

  validatePredictions(predictions);
  const n = predictions.length;
  const dim = predictions[0].prediction.length;

    }
  }

// Weighted averaging: use validation-derived blend coefficients
function weightedEnsemble(predictions: ModelPrediction[]): number[] {
  validatePredictions(predictions);
  // Scale before summing so finite, large weights do not overflow.
  const largestWeight = Math.max(...predictions.map(p => p.weight));

    for (let i = 0; i < dim; i++) {
      result[i] += p.prediction[i] * weight;
    }
  }
  return result;

The `weight` field is a blend coefficient we choose from validation results, not a probability the model reports. Here `e_i` is MAE on a prior held-out week, with each channel's errors divided by its range. We use `w_i = (1 / e_i^2) / sum_j (1 / e_j^2)`. This is an inverse-squared-error heuristic. Squared MAE is not error variance, so the rule has no minimum-variance guarantee. The example errors 0.045, 0.038 and 0.058 produce weights near 0.333, 0.467 and 0.200. Compare that blend with equal weighting on a separate evaluation week. The exercise supplies strictly positive errors; a real implementation must define what to do with zero or invalid scores.

## Why Ensembles Work

Averaging helps when members make errors that partly cancel. Different architectures, seeds or training samples may create that diversity, but do not guarantee it. Bagging trains members on random resamples of the training data. For this time series, any resampling must preserve the temporal structure needed by the model. In the story's held-out week, the equal blend scores MAE 0.036. We cannot predict that MAE by dividing the mean member MAE by sqrt(3); the variance calculation below describes a different quantity.

Compare the blend's 0.036 with 0.038, the best member on the same week. For equal-weight averaging under MAE, the blend's error cannot exceed the arithmetic mean of the members' MAEs, and it can tie it. That bound does not promise a win over the best member. Choose members and weights on validation data, then report the selected system on a final untouched period.

<DerivationDrawer summary="Where the sqrt(N) error cut comes from, and the correlation floor">
**A variance calculation with explicit assumptions.** Model each member's error on a given input as a random variable `eᵢ` with variance `σ²`, the same spread for every member. The ensemble averages predictions, so its error is the mean of the N member errors.

**Variance of a sum runs through covariance.** For two variables, `Var(x + y) = Var(x) + Var(y) + 2·Cov(x, y)`; the covariance term measures how the two move together. Write each pairwise covariance through the correlation `ρ = Cov(eᵢ, eⱼ) / σ²`. Summing the N member errors picks up one `σ²` per member plus one `ρσ²` per ordered pair, and there are `N(N-1)` ordered pairs:

`Var(sum of the N errors) = Nσ² + N(N-1)·ρσ²`

**Averaging divides variance by N².** Divide through and regroup:

`Var(ensemble error) = σ²/N + ((N-1)/N)·ρσ² = ρσ² + (1-ρ)·σ²/N`

**Read the two terms.** `(1-ρ)·σ²/N` is the part averaging can cancel; it dies as members are added. For a fixed nonnegative correlation, `ρσ²` is the variance floor as N grows. At `ρ = 0` the formula collapses to `σ²/N`: the standard deviation falls by sqrt(N). This does not give a general formula for MAE. At `ρ = 0.5`, three members give `0.5σ² + 0.5σ²/3 ≈ 0.667σ²`: a variance cut of one third, where independent members would have delivered two thirds. And the formula is about variance only; shared bias, like every member training on the same mislabeled batch, passes through the average untouched.
</DerivationDrawer>
