<Dialogue speaker="Ensign Demir">
The LSTM is great at short-range patterns. The attention model catches long-range dependencies. The Kalman filter smooths the noise off the level. Why choose one when we can combine all three?
</Dialogue>

<Dialogue speaker="Dr. Farah">
Because all three run on every input. An ensemble isn't a router that picks the right specialist. Every model fires every time, and you pay the sum of their inference costs. If the compute budget covers that, then yes: each model has blind spots, and the ensemble covers them.
</Dialogue>

`Promise.all([svcA(x), svcB(x), svcC(x)])` is the shape that carries over: one input, three calls that all run, one bill that is the sum of the three. What does not carry over is the reason you fan out. Three services hand back three different pieces of an answer. Three models hand back three answers to the same question, and the only thing that makes the third one worth paying for is that it is wrong in places the other two are right.

{`import * as tf from '@tensorflow/tfjs';

interface ModelPrediction {
  modelName: string;
  prediction: number[];
  confidence: number;
}

// Simple averaging: each model gets equal vote
function averageEnsemble(predictions: ModelPrediction[]): number[] {
  const n = predictions.length;
  const dim = predictions[0].prediction.length;
  const result = new Array(dim).fill(0);

  for (const p of predictions) {
    for (let i = 0; i < dim; i++) {
      result[i] += p.prediction[i] / n;
    }
  }
  return result;
}

// Weighted averaging: trust the members that scored better last week
function weightedEnsemble(predictions: ModelPrediction[]): number[] {
  const totalConf = predictions.reduce((s, p) => s + p.confidence, 0);
  const dim = predictions[0].prediction.length;
  const result = new Array(dim).fill(0);

  for (const p of predictions) {
    const weight = p.confidence / totalConf;
    for (let i = 0; i < dim; i++) {
      result[i] += p.prediction[i] * weight;
    }
  }
  return result;
}

A forecaster has no trust number of its own, as lesson 3 said, so the `confidence` field is not something the member reports. You measure it: score each member on a week of held-out readings it never trained on, then weight by inverse variance. Every error below is a fraction of its channel's range rather than a raw figure, so a miss in counts and a miss in radians can go into one score. For a member whose held-out error is `e_i`, `w_i = (1 / e_i^2) / sum_j (1 / e_j^2)`. When member errors are independent, that is the weighting with the lowest blend variance, and it falls out of the same algebra as the drawer below. Held-out errors of 0.045, 0.038 and 0.058 give `1 / e^2` values of 494, 693 and 297, so the three confidences above are 0.333, 0.467 and 0.200. Rescore them after the signal drifts, or you are weighting today's blend by who was right last month.

## Why Ensembles Work

Each member fails in its own place. The LSTM reads short patterns and misses long-range drift. The attention model reads long range and can overfit a small archive. The Kalman filter smooths noise off the level and assumes the level holds still between readings. Average three answers whose mistakes land in different places and the mistakes partly cancel. With fully uncorrelated errors the typical ensemble error shrinks by a factor of sqrt(N), and the drawer below shows how far short of that a realistic correlation falls. On that same held-out week the plain average of the three scored MAE 0.036. Uncorrelated errors would have bought 0.028. The attention member runs on an LSTM encoder of its own, so part of its error is the LSTM's error.

That 0.036 counts as a win because it beats 0.038, the best single member. It would not count for beating 0.047, which is the mean of the three member scores. Scoring an ensemble against that mean proves nothing: the error of the averaged prediction can never exceed the mean of the members' errors, so every ensemble clears that bar. An ensemble that lands between its members did worse than one member would have done alone, at three times the inference cost. You only see that if you score every member on the same held-out week. That is the challenge below.

<DerivationDrawer summary="Where the sqrt(N) error cut comes from, and the correlation floor">
**The sqrt(N) claim above has fine print, and the fine print is one formula.** Model each member's error on a given input as a random variable `eᵢ` with variance `σ²`, the same spread for every member. The ensemble averages predictions, so its error is the mean of the N member errors.

**Variance of a sum runs through covariance.** For two variables, `Var(x + y) = Var(x) + Var(y) + 2·Cov(x, y)`; the covariance term measures how the two move together. Write each pairwise covariance through the correlation `ρ = Cov(eᵢ, eⱼ) / σ²`. Summing the N member errors picks up one `σ²` per member plus one `ρσ²` per ordered pair, and there are `N(N-1)` ordered pairs:

`Var(sum of the N errors) = Nσ² + N(N-1)·ρσ²`

**Averaging divides variance by N².** Divide through and regroup:

`Var(ensemble error) = σ²/N + ((N-1)/N)·ρσ² = ρσ² + (1-ρ)·σ²/N`

**Read the two terms.** `(1-ρ)·σ²/N` is the part averaging can cancel; it dies as members are added. `ρσ²` does not contain N: it is a floor that no ensemble size removes. At `ρ = 0` the formula collapses to `σ²/N`, the sqrt(N) cut in typical error. At `ρ = 0.5`, three members give `0.5σ² + 0.5σ²/3 ≈ 0.667σ²`: a variance cut of one third, where independent members would have delivered two thirds. And the formula is about variance only; shared bias, like every member training on the same mislabeled batch, passes through the average untouched.
</DerivationDrawer>
