const smooth = (alpha: number) =>

A small alpha trusts history and lags the drift. A large alpha trusts the newest reading and inherits its noise. That tradeoff depends on the process and the cost of lag. A tuned EMA can be a useful baseline; a Kalman model makes the uncertainty assumptions explicit.

</Dialogue>

A Kalman filter can calculate that weight from an uncertainty model. It predicts a value and its uncertainty, then uses the new measurement to update both. The weight is called the Kalman gain. Whether it is trustworthy depends on the model and noise assumptions we give it.

## Predict, Then Correct

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="kalman-filter.ts">
{`// Scalar random-walk state model: x(t) = x(t-1) + process noise.
// Measurement z(t) = x(t) + measurement noise. Q and R are VARIANCES.

interface KalmanState {
  estimate: number;      // current best guess
  variance: number;      // uncertainty in our estimate
}

class KalmanFilter {
  private state: KalmanState;
  private processNoise: number;      // variance of process noise per update
  private measurementNoise: number;  // variance of measurement noise

  constructor(initial: number, processNoise: number, measurementNoise: number) {
    if (![initial, processNoise, measurementNoise].every(Number.isFinite) || processNoise < 0 || measurementNoise <= 0) throw new Error('Invalid filter parameters');
    this.state = { estimate: initial, variance: 1 };
    this.processNoise = processNoise;
    this.measurementNoise = measurementNoise;
  }

  update(measurement: number): KalmanState {
    if (!Number.isFinite(measurement)) throw new Error('Invalid measurement');
    // PREDICT: where do we think the state is?
    const predicted = this.state.estimate;
    const predictedVariance = this.state.variance + this.processNoise;

    // UPDATE: how much to trust the new measurement?
    const gain = predictedVariance / (predictedVariance + this.measurementNoise);
    // gain ≈ 0: trust prediction (measurement is noisy)
    // gain ≈ 1: trust measurement (prediction is uncertain)

    // CORRECT: blend prediction with measurement
    this.state = {
      estimate: predicted + gain * (measurement - predicted),
      variance: (1 - gain) * predictedVariance,
    };

    return { ...this.state };
  }
}

// Track the anomaly timing interval, sampled once per day: each day's
// first cycle, eight days of log. Initialize from the first reading, then
// update on subsequent readings. The initial variance is a chosen prior.
const kf = new KalmanFilter(73.1, 0.1, 1.0);

const measurements = [73.1, 72.9, 73.0, 72.6, 72.7, 72.3, 72.4, 72.0];
for (const m of measurements.slice(1)) {
  const state = kf.update(m);
  console.log(\`Measurement: \${m.toFixed(1)}, Estimate: \${state.estimate.toFixed(2)}\`);
}
// Estimate walks 73.1 → 72.43 while the readings end at 72.0: the
// filter is absorbing the noise and trailing the trend, not following
// it. The per-day shrink gets read off the raw log, not off this line.`}
</CodeBlock>

This filter tracks one number, the current level. It does not track how fast that level changes. As the gain settles, it behaves like an EMA with a fixed alpha and falls behind a steady trend.

For a correctly specified linear model, a Gaussian initial state and independent zero-mean Gaussian noise, the Kalman estimate minimizes mean squared estimation error. Our noisy mission log does not by itself verify those assumptions.

The final estimate differs from the final reading by 0.43. Demir's alpha-0.8 EMA differs by only 0.08. Smoother output does not prove greater accuracy because we do not know the true value without noise.

Here process variance is 0.1 and measurement variance is 1. By the eighth reading, the gain is close to its limiting value of 0.27. To track the downward trend directly, the filter would need a second state: change per day. The drawer below explains the gain calculation.

<DerivationDrawer summary="Why this gain gives the lowest updated uncertainty">
The update blends prediction and measurement: `estimate = prediction + K(z - prediction)`. The Kalman gain minimizes the variance of that blend under the assumptions below.

```
Prediction uncertainty:   P   (variance of the prediction)
Measurement uncertainty:  R   (variance of the sensor)

Blend:  x̂ = (1-K)·prediction + K·z
For unbiased prediction and measurement errors with zero covariance, the blend's error variance is
        V(K) = (1-K)²·P + K²·R
```

Minimize over K: differentiate and set to zero.

```
dV/dK = -2(1-K)·P + 2K·R = 0
      → K·(P + R) = P
      → K = P / (P + R)
```

The code uses that same formula: `predictedVariance / (predictedVariance + measurementNoise)`. If the sensor is nearly perfect, R → 0 and K → 1, so the update follows the measurement. If sensor uncertainty is very large, R → ∞ and K → 0, so it keeps the prediction.

This is Demir's changing alpha. The filter recalculates it as corrections reduce P. If the model and noise statistics stay constant, the gain can settle at a constant value. Using that settled gain is a valid design choice.

With this random-walk model and fixed noise variances, P and the gain settle. For process noise 0.1 and measurement noise 1, the limiting gain is about 0.27. The early gains are 0.52, 0.38, and 0.33 as each measurement reduces the assumed uncertainty.

Once settled, the filter behaves like an EMA with a chosen alpha. It still falls behind a steady trend. To track that trend directly, add a second state for the change per day. A two-state constant-velocity filter runs these calculations on `[interval, change-per-day]` instead of one number.
</DerivationDrawer>
