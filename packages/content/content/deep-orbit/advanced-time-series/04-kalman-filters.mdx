> **PULSE INTERVAL LOG · first cycle of each of the last eight days (seconds):** 73.1 · 72.9 · 73.0 · 72.6 · 72.7 · 72.3 · 72.4 · 72.0

Read the column both ways. The noise says the numbers wander; the trend says they only wander downhill. Before this lesson names its subject, try to track that drift with a tool you already own.

Demir's first move is the one every JavaScript engineer makes when a value jitters: exponential moving average, `smoothed = alpha * new + (1 - alpha) * old`, the same trick as smoothing a scroll position. Run it on the log above with two different alphas and the problem introduces itself:

<CodeBlock language="typescript" title="ema-two-alphas.ts">
{`const log = [73.1, 72.9, 73.0, 72.6, 72.7, 72.3, 72.4, 72.0];

const smooth = (alpha: number) =>
  log.reduce((s, x) => alpha * x + (1 - alpha) * s);

smooth(0.2); // 72.57: beautifully smooth, but 0.57 s behind a signal
             // that has already reached 72.0. It lags the drift.
smooth(0.8); // 72.08: right on the drift, but the estimate now bounces
             // with every noisy reading it was supposed to absorb.`}
</CodeBlock>

A small alpha trusts history and lags the drift. A large alpha trusts the newest reading and inherits its noise. On a drifting signal no single constant gets both right, and hand-picking alpha per signal, forever, is not an engineering answer.

What I actually want is an alpha that adjusts itself. Trust the measurement more when my estimate is shaky. Trust my estimate more when the measurements are noisy.
</Dialogue>

## Predict, Then Correct

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="kalman-filter.ts">
{`// 1D Kalman Filter: optimal smoothing under noise

interface KalmanState {
  estimate: number;      // current best guess
  variance: number;      // uncertainty in our estimate
}

class KalmanFilter {
  private state: KalmanState;
  private processNoise: number;      // how much the true value changes between steps
  private measurementNoise: number;  // how noisy our measurements are

  constructor(initial: number, processNoise: number, measurementNoise: number) {
    this.state = { estimate: initial, variance: 1 };
    this.processNoise = processNoise;
    this.measurementNoise = measurementNoise;
  }

  update(measurement: number): KalmanState {
    // PREDICT: where do we think the state is?
    const predicted = this.state.estimate;
    const predictedVariance = this.state.variance + this.processNoise;

    // UPDATE: how much to trust the new measurement?
    const gain = predictedVariance / (predictedVariance + this.measurementNoise);
    // gain ≈ 0: trust prediction (measurement is noisy)
    // gain ≈ 1: trust measurement (prediction is uncertain)

    // CORRECT: blend prediction with measurement
    this.state = {
      estimate: predicted + gain * (measurement - predicted),
      variance: (1 - gain) * predictedVariance,
    };

    return { ...this.state };
  }
}

// Track the anomaly timing interval, sampled once per day: each day's
// first cycle, eight days of log. Initial estimate = day one's first
// cycle; the 73.4 s module-5 measurement is already history.
const kf = new KalmanFilter(73.1, 0.1, 1.0);

const measurements = [73.1, 72.9, 73.0, 72.6, 72.7, 72.3, 72.4, 72.0];
for (const m of measurements) {
  const state = kf.update(m);
  console.log(\`Measurement: \${m.toFixed(1)}, Estimate: \${state.estimate.toFixed(2)}\`);
}
// The filter smoothly tracks the downward drift: 73.1 → 72.44
// SHRINKING by roughly a sixth of a second per day. Speeding up.`}
</CodeBlock>

<DerivationDrawer summary="Where the gain formula comes from: minimize the posterior variance">
The update blends prediction and measurement: `estimate = prediction + K(z - prediction)`. Why THAT K and not a hand-picked alpha? Because K is the value that minimizes the variance of the blended estimate.

```
Prediction uncertainty:   P   (variance of the prediction)
Measurement uncertainty:  R   (variance of the sensor)

Blend:  x̂ = (1-K)·prediction + K·z
Since the two sources are independent, the blend's variance is
        V(K) = (1-K)²·P + K²·R
```

Minimize over K: differentiate and set to zero.

```
dV/dK = -2(1-K)·P + 2K·R = 0
      → K·(P + R) = P
      → K = P / (P + R)
```

That is line-for-line the `gain` in the code above: `predictedVariance / (predictedVariance + measurementNoise)`. Sanity-check the endpoints: a perfect sensor (R → 0) gives K → 1, trust the measurement; a useless sensor (R → ∞) gives K → 0, keep the prediction. Demir's "alpha that adjusts itself" is this quotient, recomputed every step as P shrinks with each correction. The EMA's fixed alpha is what you get if you freeze this formula and hope the uncertainties never change.

One honesty note the bridge has earned: with a constant-state model like this one, P settles and the gain converges (to about 0.27 with these Q and R), so after a handful of updates the filter behaves like an EMA with a well-chosen alpha, and it lags a steady drift the same way. What the adaptive gain buys is the burn-in and principled noise handling; it buys no immunity to trends. Tracking the drift itself takes a state with velocity in it: the 2-state constant-velocity Kalman, which is exactly this machinery run on `[interval, change-per-cycle]` instead of a single number. The crew's filter is the honest first rung, not the whole ladder.
</DerivationDrawer>
