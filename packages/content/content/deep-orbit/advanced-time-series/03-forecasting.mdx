## Multi-Step Forecasting

<CodeBlock language="typescript" title="forecasting.ts">
{`import * as tf from '@tensorflow/tfjs';

// The rolling loop from module 6, lesson 5: predict one step, clamp it,
// append it, slide the window, repeat. What matters this time is what its
// error does as the horizon grows.

// Same sensor spec module 6 clamped against: amplitude in counts,
// "frequency" as a zero-crossing count over a 64-sample window, phase in
// radians.
const LIMITS = [
  { min: 0, max: 2048 },
  { min: 0, max: 63 },
  { min: -Math.PI, max: Math.PI },
];

// The step of module 6's version that is easiest to drop, and the module-6
// exercise fails a submission for dropping it. This model reads and writes
// the per-channel z-scores it was trained on, so a limit in counts is not a
// limit its output can be compared against. MEAN and STD are the three
// per-channel statistics saved at training time; every limit moves into the
// model's space through them, and the clamp happens there.
const { mean: MEAN, std: STD } = savedScaler;
const bounds = LIMITS.map((limit, j) => ({
  min: (limit.min - MEAN[j]) / STD[j],
  max: (limit.max - MEAN[j]) / STD[j],
}));

const clamp = (reading: number[]) =>
  reading.map((v, j) => Math.min(Math.max(v, bounds[j].min), bounds[j].max));

async function forecast(
  model: tf.LayersModel,
  seed: number[][],
  horizon: number,
  windowSize: number,
): Promise<number[][]> {
  const window = [...seed];
  const predictions: number[][] = [];

  for (let step = 0; step < horizon; step++) {
    const nextValue = tf.tidy(() => {
      const input = tf.tensor3d([window.slice(-windowSize)]);
      const pred = model.predict(input) as tf.Tensor;
      return Array.from(pred.dataSync());
    });

    // Clamp before the row re-enters the window. Step + 1 reads it as
    // history, so one out-of-range value rides the rest of the run.
    const bounded = clamp(nextValue);
    predictions.push(bounded);
    window.push(bounded);
  }

  return predictions;
}

// Forecast 100 steps ahead. Step 1 is one model call from real data; step
// 100 is one model call from 99 of the model's own guesses. There is no
// trust number in this function because the model does not have one. A
// real interval comes from replaying old forecasts and measuring, at each
// horizon separately, how far they landed from what actually arrived.
const predictions = await forecast(model, recentWindow, 100, 80);`}

## Non-Stationarity: When Predictions Fail

A forecasting model assumes one thing above all: that the statistics it learned still hold. Non-stationary means they do not. The mean, the variance, or in this case the period drifts while the model keeps predicting from the shape it fit last week, so its error grows in one direction instead of scattering around zero.

Two different things make forecast error grow, and it is easy to read one as the other. Along a horizon, error compounds because step 100 stands on 99 of the model's own guesses. That happens on a signal that never changes at all. Drift is a change in the series itself between one week and the next. To measure drift, hold the horizon fixed at one step. Re-seed the window from the readings that actually arrived and score each prediction against the next real one. Then compare this period's errors against an earlier period's.

<CodeBlock language="typescript" title="non-stationary.ts">
{`// The forecast says the anomaly repeats at step 50
// It arrives at step 47: three steps EARLY
// The model was wrong. Why?

// NON-STATIONARY DATA: the statistical properties change over time
// The signal's timing is DRIFTING; it's not perfectly periodic
// Like a website's traffic patterns shifting after a redesign

// One prediction per reading that actually arrived. The window is re-seeded
// from real data every step, so no prediction ever feeds back into the next
// one and every error below costs exactly one model call.
function predictOneStepAhead(
  model: tf.LayersModel,
  observed: number[][],
  windowSize: number,
): number[][] {
  const predictions: number[][] = [];

  for (let t = windowSize; t < observed.length; t++) {
    predictions.push(tf.tidy(() => {
      const input = tf.tensor3d([observed.slice(t - windowSize, t)]);
      const pred = model.predict(input) as tf.Tensor;
      return Array.from(pred.dataSync());
    }));
  }

  return predictions;
}

// Detection: score those one-step errors along the clock, then compare the
// most recent stretch against the errors before it.
// Never pass a rollout in here. A rollout's error grows with the horizon by
// construction, so this function would report drift on a signal that has not
// changed at all.
function detectDrift(
  oneStepPredicted: number[][],
  actual: number[][],
  recentPeriod: number,
): { driftDetected: boolean; driftMagnitude: number } {
  const errors: number[] = [];
  for (let i = 0; i < actual.length; i++) {
    const err = actual[i].reduce(
      (sum, v, j) => sum + (v - oneStepPredicted[i][j]) ** 2,
      0,
    );
    errors.push(err);
  }

  // This period's errors against the earlier ones
  const recent = errors.slice(-recentPeriod);
  const historical = errors.slice(0, -recentPeriod);
  // No baseline, no comparison. Without this the mean of an empty slice is
  // NaN, driftMagnitude comes back NaN, and the function answers "no drift"
  // on a stream where drift cannot be measured at all.
  if (historical.length === 0) {
    throw new Error('drift needs a baseline: give it more readings than recentPeriod');
  }
  const recentMean = recent.reduce((a, b) => a + b, 0) / recent.length;
  const histMean = historical.reduce((a, b) => a + b, 0) / historical.length;

  return {
    driftDetected: recentMean > histMean * 2,  // errors doubled
    driftMagnitude: recentMean / histMean,
  };
}

// Observations only, never a forecast. The last 200 errors are this period;
// everything before them is the baseline they are judged against.
const oneStep = predictOneStepAhead(model, observedReadings, 80);
const drift = detectDrift(oneStep, observedReadings.slice(80), 200);`}
</CodeBlock>

## What Compounding Looks Like When It Shows

Compounding needs two things: a model whose output moves, and a series where a small error now makes a larger one next step. Put the same two arms on a series like that and the columns separate.

<CodeBlock language="typescript" title="error-by-horizon.ts">
{`// The same two functions on a feedback series instead of a sine: 900
// readings of x -> 3.9 * x * (1 - x) with noise of 0.002 added at every
// step. One channel, so LIMITS is the single row this series needs,
// { min: 0, max: 1 }; the series is already inside it, so MEAN is 0, STD
// is 1 and the clamp is the limit row itself. The window is 10 rather
// than 80, and both functions
// read that width from their arguments rather than holding one.
// Two runs of that loop starting a hair apart end up nowhere near each
// other, which is the property a rollout has to survive. A 32-unit LSTM,
// 250 epochs on the first 300 readings, the other 600 held back.
const rollout = await forecast(model, past, 16, 10);
const replay = predictOneStepAhead(model, [...past.slice(-10), ...arrived], 10);

// Mean absolute error at each horizon, over 16-step forecasts started from
// 30 different points in the held-back stretch:
// horizon   rollout   replay
//    1       0.017     0.017
//    2       0.020     0.014
//    3       0.036     0.013
//    4       0.058     0.017
//    5       0.086     0.012
//    6       0.170     0.011
//    7       0.204     0.015
//    8       0.282     0.013
//   12       0.313     0.013
//   16       0.270     0.013`}
</CodeBlock>

The replay column has no trend. Every prediction in it starts from readings that arrived, so what it reports at horizon 16 is still a one-step error, the same kind of number it reported at horizon 1. The rollout column starts on that same number and then grows by about half again per step, because the model is reading its own output back in and this series pulls small differences apart. It levels off near 0.3 because 0.336 is the average distance between any two unrelated readings here, which is about what a rollout scores once it has stopped tracking and is only wandering inside the same range. That is not a ceiling. A rollout that settles on a constant near the edge of the range does worse: a flat forecast at 0 scores 0.594 on this series. Nothing about the model changed between the two columns, only what it read before each prediction.

That rollout column is the probability cone the prefetch analogy at the top of this lesson promised, measured at each horizon separately instead of assumed. The model hands you a point. The rollout column tells you how wide to draw around it, horizon by horizon.

## Challenge

Train the one-step model yourself, then cover the same stretch twice: once feeding the forecast back into itself, once re-seeded from the readings that arrived. One channel, no clamp. Do not expect the two arms to separate by much on this run. Twenty epochs on a few dozen windows buys a model that has learned the level and little of the shape, and a rollout that settles onto a level stops compounding, because its own output is close to what it would have predicted next anyway. Compounding bites when the model is good enough for its output to move.
