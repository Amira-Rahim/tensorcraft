The previous lesson took its query from the sequence. Here, learned scorer weights act as the same query for every window. Each reading supplies both the features to score and the values to blend.

You will add position information to an attention scorer and use its weights to summarize a sequence.

## Position-aware scoring before pooling

The exercise starts with a rank-2 `[T, d]` sequence and a supplied `[d+1, 1]`
scorer. Its moderate probe uses rows `[[0, 4], [0.25, 2], [0.5, 0]]` and scorer
coefficients `[1, 0, 0.5]`. Positions `[0, 0.5, 1]` produce scores `[0, 0.5, 1]`.
The table connects each reading to its contribution:

| Step | Position | Score | Softmax weight | First-feature contribution |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | about 0.1863 | 0 |
| 1 | 0.5 | 0.5 | about 0.3072 | about 0.0768 |
| 2 | 1 | 1 | about 0.5065 | about 0.2532 |

<CodeBlock language="typescript" title="position-score-trace.ts">
{`const positionalExample = tf.tidy(() => {
  const rows = tf.tensor2d([[0, 4], [0.25, 2], [0.5, 0]]);
  const positions = tf.linspace(0, 1, 3).reshape([3, 1]);
  const extended = tf.concat([rows, positions], 1);
  const coefficients = tf.tensor2d([[1], [0], [0.5]]);
  const stepScores = extended.matMul(coefficients).reshape([3]);
  const shares = tf.softmax(stepScores);
  const pooled = shares.reshape([1, 3]).matMul(rows).squeeze([0]);
  return { scores: Array.from(stepScores.dataSync()), weights: Array.from(shares.dataSync()), summary: Array.from(pooled.dataSync()) };
});
console.log(positionalExample);`}
</CodeBlock>

The summary is about `[0.3300, 1.3597]`. Position affects scores but never
becomes a summary feature. For one step, position is zero. Flatten the scores
across time, and remove only the summary's batch axis. Keep d=1 as shape `[1]`.
The caller owns the original input tensors and both returned tensors. Tidy
should dispose only your intermediate allocations.

The separate batched examples below use retained Dense scorer layers. They
show integration and capture limits, with no promise that untrained weights
match the exercise's supplied coefficients. Actual tensors support these
operations. A SymbolicTensor in a layer-construction graph requires an
appropriate custom layer or differentiable training composition.

## Temporal Attention Layer

<BridgeCallout bridge={frontmatter.concept.bridge} />

<ConceptReference summary="Reference: a separate batched feature-only scorer">

<CodeBlock language="typescript" title="temporal-attention.ts">
{`import * as tf from '@tensorflow/tfjs';

// Create the scorer once and keep it between calls.
// Train it with the encoder and prediction head under one loss,
// using a manual optimizer.minimize loop over the full forward pass.
// This function does not work inside model.compile/model.fit as written.
// There scorer.apply returns a SymbolicTensor without tensor methods:
// "TypeError: scores.squeeze is not a function".
// tf.softmax or tf.sum would also reject that symbolic value.
//
// The code below only runs the forward pass. Its weights need training
// before they can mean anything. Creating a new layer on every call
// would replace its learned weights with new random ones.
const scorer = tf.layers.dense({ units: 1 });

// Temporal attention: score each time step's importance
function temporalAttention(
  sequence: tf.Tensor3D,  // [batch, timeSteps, features]
): { attended: tf.Tensor2D; weights: tf.Tensor2D } {
  return tf.tidy(() => {
    // Project each step to a scalar importance score
    const scores = scorer.apply(sequence) as tf.Tensor;
    const squeezed = scores.squeeze([2]) as tf.Tensor2D;  // [batch, timeSteps]

    // Softmax over time axis: which steps take the weight?
    const weights = tf.softmax(squeezed, 1);  // [batch, timeSteps]

    // Weighted sum: combine time steps by importance
    const expanded = weights.expandDims(2);  // [batch, timeSteps, 1]
    const weighted = tf.mul(sequence, expanded);
    const attended = tf.sum(weighted, 1) as tf.Tensor2D;  // [batch, features]

    return { attended, weights };
  });
}

// The weights tell the story:
// weights = [0.01, 0.01, ..., 0.12, 0.01, ..., 0.15, ...]
//                                ^                 ^
//                             step 4            step 78
// The model focuses on the initial spike and the frequency shift,
// 74 steps apart inside the 80-step window`}
</CodeBlock>

</ConceptReference>

Keep three counts separate. A dashboard time step is one reading, arriving once per second. The first and last timestamps in an 80-reading window are 79 seconds apart.

In the earlier capture, the spike is at `4 s`. The shift starts at timestamp `77.4 s`, so step 78 is the first one-second reading that includes it. Those displayed steps are 74 positions apart. The raw timestamps give the more precise gap: `77.4 - 4 = 73.4 s`. The 80-step window holds both events.

A 64-sample capture means something else: 64 samples from one channel at 256 Hz, covering a quarter of a second. We calculate each reading's three features from that capture. The ship's 64 sensor channels are a separate count again. They count the streams. The sampling rate and sample count determine the duration.

## Interpreting Attention Weights

<CodeBlock language="typescript" title="interpret-attention.ts">
{`// Attention weights have an explicit time axis that is convenient to plot
// You can show the crew exactly WHERE the model put its weight.
// Why it decided is a separate question the weights do not settle.

interface AttentionInsight {
  timeStep: number;
  weight: number;
  reading: number[];
}

function topAttentionSteps(
  weights: number[],
  readings: number[][],
  topK: number = 5,
): AttentionInsight[] {
  return weights
    .map((weight, i) => ({ timeStep: i, weight, reading: readings[i] }))
    .sort((a, b) => b.weight - a.weight)
    .slice(0, topK);
}

// The story supplies these fictional readings. The untrained layer above does not produce them.
// These use raw units: amplitude 0 to 2048 hull counts, frequency as a
// zero-crossing count from 0 to 63 over 64 samples, and phase in radians.
// Step 78: weight=0.15, reading=[635, 40, 1.57]: frequency shift
// Step 4:  weight=0.12, reading=[1980, 37, 0.23]: amplitude spike
// Step 40: weight=0.09, reading=[1065, 37, 0.89]: mid-pattern
// A crossing count does not uniquely identify frequency. Phase, offset,
// mixtures, noise, and window length affect it. Check the FFT and waveform.
// Removing a step tests sensitivity but can create unrealistic inputs.
// That test alone does not prove a physical cause or explain the prediction.
`}
</CodeBlock>

## Applied: Attention Over a Live Ring Buffer

The heatmaps above assume the model receives the whole window. The bridge only has the data its capture buffer saved. To save storage, it is tempting to keep readings near the predicted event and discard the rest, as a virtualized list keeps only nearby rows on screen.

Here is what happens when part of the window is missing:

<ConceptReference summary="Reference: apply that batched scorer to a truncated buffer">

<CodeBlock language="typescript" title="ring-buffer-attention.ts">
{`// One full capture cycle from the ring buffer: 80 steps, 3 features.
// Integration sketch: bufferWindow supplies one recorded window.
const full = bufferWindow();                       // [1, 80, 3]
const { attended, weights } = temporalAttention(full);
console.log(full.shape, weights.shape, attended.shape);
// [1, 80, 3] [1, 80] [1, 3]
console.log(tf.tidy(() => weights.sum().dataSync()[0]).toFixed(3));
// 1.000

// The virtualized buffer: the same cycle, but only the 48 steps around
// the PREDICTED onset were kept. The real onset arrived early, at what
// used to be step 4, and fell off the leading edge.
const kept = full.slice([0, 32, 0], [1, 48, 3]);   // [1, 48, 3]
const clipped = temporalAttention(kept);
console.log(kept.shape, clipped.weights.shape, clipped.attended.shape);
// [1, 48, 3] [1, 48] [1, 3]
console.log(tf.tidy(() => clipped.weights.sum().dataSync()[0]).toFixed(3));
// 1.000
tf.dispose([full, attended, weights, kept, clipped.attended, clipped.weights]);
// Dispose scorer at the end of the workflow.`}
</CodeBlock>

</ConceptReference>

Both weight sums are 1. That normalization says nothing about confidence or missing observations. The pooled outputs also have the same shape, [1, 3], although their values can differ. An output-shape check alone will not detect a truncated input. Validate window length, timestamps and capture metadata before inference, and preserve the missing-data status for the operator.

## Putting the Position Back

The scorer above only sees feature values. If you reorder the same readings, each weight follows its reading and the weighted sum stays the same. It cannot tell whether a spike came before or after a frequency shift.

Give it position information too. This example adds one feature: each step's position scaled to [0, 1]. Transformers can use learned position vectors, relative scores, or rotations. Our extra column is a simpler version.

<ConceptReference summary="Reference: a separate batched position-aware scorer">

<CodeBlock language="typescript" title="positional-feature.ts">
{`// [batch, T, 3] -> [batch, T, 4]: the fourth feature is position / (T - 1)
function withPosition(sequence: tf.Tensor3D): tf.Tensor3D {
  return tf.tidy(() => {
    const [batch, T] = sequence.shape;
    const pos = tf.linspace(0, 1, T).reshape([1, T, 1]).tile([batch, 1, 1]);
    return tf.concat([sequence, pos], 2) as tf.Tensor3D;
  });
}

// A dense layer builds its weight matrix on first call, so the 3-input
// scorer above cannot be handed 4 inputs. Positional attention gets its own.
const positionalScorer = tf.layers.dense({ units: 1 });

function positionalAttention(sequence: tf.Tensor3D): { attended: tf.Tensor2D; weights: tf.Tensor2D } {
  return tf.tidy(() => {
    // Position informs WHERE to look. The pooled value is still the readings.
    const scores = (positionalScorer.apply(withPosition(sequence)) as tf.Tensor).squeeze([2]) as tf.Tensor2D;
    const weights = tf.softmax(scores, 1);                                  // [batch, T]
    const attended = tf.sum(tf.mul(sequence, weights.expandDims(2)), 1) as tf.Tensor2D;  // [batch, 3]
    return { attended, weights };
  });
}

// Before: a window and its reversal pooled to the same summary.
// After: the scorer can learn "late steps matter more" (or early ones),
// because lateness is now a number it multiplies by a weight.`}
</CodeBlock>

</ConceptReference>

Sinusoidal encodings are one approach used in the original Transformer. Learned positions and relative or rotary schemes are other choices. Our linear position column only lets the scorer favor earlier or later steps. It is not a full transformer position mechanism.
