## Temporal Attention Layer

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="temporal-attention.ts">
{`import * as tf from '@tensorflow/tfjs';

// The scoring function is MODULE STATE, created once: it trains as part
// of the model. A fresh layer inside the function would score every call
// with brand-new random weights, and the heatmap below would be noise.
const scorer = tf.layers.dense({ units: 1 });

// Temporal attention: score each time step's importance
function temporalAttention(
  sequence: tf.Tensor3D,  // [batch, timeSteps, features]
): { attended: tf.Tensor2D; weights: tf.Tensor2D } {
  return tf.tidy(() => {
    // Project each step to a scalar importance score
    const scores = scorer.apply(sequence) as tf.Tensor;
    const squeezed = scores.squeeze([2]) as tf.Tensor2D;  // [batch, timeSteps]

    // Softmax over time axis: which steps matter most?
    const weights = tf.softmax(squeezed, 1);  // [batch, timeSteps]

    // Weighted sum: combine time steps by importance
    const expanded = weights.expandDims(2);  // [batch, timeSteps, 1]
    const weighted = tf.mul(sequence, expanded);
    const attended = tf.sum(weighted, 1) as tf.Tensor2D;  // [batch, features]

    return { attended, weights };
  });
}

// The weights tell the story:
// weights = [0.01, 0.01, ..., 0.12, 0.01, ..., 0.15, ...]
//                                ^                 ^
//                             step 4            step 77
// The model focuses on the initial spike and the frequency shift,
// 73 steps apart inside the 80-step window`}
</CodeBlock>

## Interpreting Attention Weights

<CodeBlock language="typescript" title="interpret-attention.ts">
{`// Attention weights are interpretable, unlike LSTM hidden state
// You can show the crew EXACTLY why the model made its prediction

interface AttentionInsight {
  timeStep: number;
  weight: number;
  reading: number[];
}

function topAttentionSteps(
  weights: number[],
  readings: number[][],
  topK: number = 5,
): AttentionInsight[] {
  return weights
    .map((weight, i) => ({ timeStep: i, weight, reading: readings[i] }))
    .sort((a, b) => b.weight - a.weight)
    .slice(0, topK);
}

// For the anomalous signal:
// Step 77: weight=0.15, reading=[0.31, 37, 1.57]  ← frequency shift
// Step 4:  weight=0.12, reading=[1.82, 37, 0.23]  ← amplitude spike
// Step 40: weight=0.09, reading=[0.95, 37, 0.89]  ← mid-pattern
// (middle feature is the zero-crossing count: ~37 for the 73.4 Hz line
//  in this window, steady across the steps the model locked onto)`}
</CodeBlock>

## Applied: Attention Over a Live Ring Buffer

The heatmaps above assume the model gets the whole window. On the bridge array it gets whatever the capture buffer kept, and storage is tight enough that the tempting move is the frontend one: virtualize. Keep the steps around the predicted event, drop the rest, let a viewport stand in for the sequence.

Attention has a failure mode built exactly for that trick, and four tensor shapes are enough to see it:

<CodeBlock language="typescript" title="ring-buffer-attention.ts">
{`// One full capture cycle from the ring buffer: 80 steps, 3 features.
const full = bufferWindow();                       // [1, 80, 3]
const { attended, weights } = temporalAttention(full);
console.log(full.shape, weights.shape, attended.shape);
// [1, 80, 3] [1, 80] [1, 3]
console.log(weights.sum().dataSync()[0].toFixed(3));
// 1.000

// The virtualized buffer: the same cycle, but only the 48 steps around
// the PREDICTED onset were kept. The real onset arrived early, at what
// used to be step 4, and fell off the leading edge.
const kept = full.slice([0, 32, 0], [1, 48, 3]);   // [1, 48, 3]
const clipped = temporalAttention(kept);
console.log(kept.shape, clipped.weights.shape, clipped.attended.shape);
// [1, 48, 3] [1, 48] [1, 3]
console.log(clipped.weights.sum().dataSync()[0].toFixed(3));
// 1.000`}
</CodeBlock>

Read the two sums together: 1.000 and 1.000. Softmax spends its entire budget on whatever the buffer kept, every time, so the truncated window produces a heatmap exactly as normalized and exactly as confident as the full one. The pooled outputs match too, [1, 3] from both windows, so nothing downstream can tell an 80-step capture from a 48-step one by shape. The weights map where the model looked; a step the buffer virtualized away is simply off the map, with no residual mass, no warning, no NaN. When a capture comes back missing its onset, the model will attend beautifully to what remains and never once complain.
