Like CSS :focus. Instead of styling every element equally, you highlight just the one that's active. Attention highlights the time steps that are most relevant to the current prediction.

Attention is the soft version of that move: it scores every time step for relevance, then spends most of its weight where the score is high and a little everywhere else. ## The Query-Key-Value Framework

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="attention-basics.ts">
{`import * as tf from '@tensorflow/tfjs';

// Attention in three steps:
// 1. Query: "What am I looking for?"
// 2. Keys: "Here are the candidates"
// 3. Values: "Here's the information at each candidate"

// Score = how well each key matches the query
// Weight = softmax(score): normalize to probabilities
// Output = weighted sum of values: focus on high-weight positions

// softmax, in case this is your first meeting: exponentiate every
// score, then divide by the sum, turning any scores into positive
// weights that add to 1. Three numbers, worked:
//   softmax([2, 1, 0]) = [e^2, e^1, e^0] / (e^2 + e^1 + e^0)
//                      = [7.39, 2.72, 1.00] / 11.11
//                      = [0.665, 0.245, 0.090]
// Bigger score, bigger share, and no step ever gets exactly 0 or 1:
// the weight is always shared.

function simpleAttention(
  query: tf.Tensor2D,   // [1, dim]: what we're looking for
  keys: tf.Tensor2D,    // [seqLen, dim]: candidates at each time step
  values: tf.Tensor2D,  // [seqLen, dim]: information at each time step
): { output: tf.Tensor; weights: tf.Tensor } {
  return tf.tidy(() => {
    // Score each key against the query
    const scores = tf.matMul(query, keys, false, true);  // [1, seqLen]

    // Normalize to probabilities
    const weights = tf.softmax(scores, 1);  // [1, seqLen]

    // Weighted sum of values
    const output = tf.matMul(weights, values);  // [1, dim]

    return { output, weights };
  });
}

// The weights tell you WHERE the model is "looking"
// High weight at step 4 and step 77 = those steps matter most
// This is interpretable, unlike LSTM hidden state`}
</CodeBlock>

The worked softmax is the part that vetoes the :focus picture, and it does so with three numbers. Scores of [2, 1, 0] went in; weights of [0.665, 0.245, 0.090] came out. The winner holds two thirds, and the two losers still hold a third between them. No step "has focus" while the rest have nothing; every step owns a share, and the shares always total 1.

<Dialogue speaker="Dr. Farah">
:focus lands on one element. Softmax never does, and the arithmetic you just ran is the proof: every step gets a weight, most of them near zero, none of them zero. Keep your picture, but read the weights as a budget, not a spotlight.
</Dialogue>

## LSTM vs Attention

<CodeBlock language="typescript" title="comparison.ts">
{`// LSTM processes sequentially:
// step 1 → step 2 → step 3 → ... → step 80
// Information must pass through EVERY intermediate step
// Long-range dependencies degrade (even with gates)

// Attention processes in parallel:
// [step 1, step 2, ..., step 80] → score ALL at once
// Direct connection between ANY two steps
// No degradation over distance

// Speed comparison for 80-step sequences:
// LSTM:      80 sequential operations (can't parallelize)
// Attention: 1 matrix multiply (fully parallelizable on GPU)
// The hybrid below keeps the sequential LSTM encoder, so it buys the
// DISTANCE fix, not the wall-clock one; pure-attention stacks buy both.

// Build an attention-enhanced model. tf.layers has no attention layer,
// so we compose the real mechanism from ops: an LSTM encodes the window
// (returnSequences keeps ALL 80 step outputs, because attention needs
// every candidate), and simpleAttention from above decides which steps
// the prediction actually listens to.
const encoder = tf.sequential();
encoder.add(tf.layers.lstm({
  units: 32,
  returnSequences: true,   // [1, 80, 32]: one output per time step
  inputShape: [80, 3],
}));
const head = tf.layers.dense({ units: 3 });

function predictWithAttention(window: tf.Tensor3D): tf.Tensor {
  return tf.tidy(() => {
    const encoded = encoder.apply(window) as tf.Tensor;   // [1, 80, 32]
    const steps = encoded.squeeze([0]) as tf.Tensor2D;    // [80, 32]
    const query = steps.slice([79, 0], [1, 32]);          // latest step asks
    const { output, weights } = simpleAttention(query, steps, steps);
    // weights: [1, 80]: read them to see WHERE the model looked.
    // High weight at step 4 and step 77 = the direct connection the
    // plain LSTM could not hold across the distance.
    return head.apply(output) as tf.Tensor;               // [1, 3]
  });
}

// Production transformers drop the recurrent encoder entirely and use
// attention end to end; this hybrid is the honest TFJS version of the
// same idea, and it is all this module's problem needs.`}
</CodeBlock>
