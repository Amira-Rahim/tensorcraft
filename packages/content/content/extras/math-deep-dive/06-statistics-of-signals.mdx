<Dialogue speaker="Instructor">
In Anomaly Detection you flagged any reading more than 3 standard deviations from a channel's mean. It works. But why 3? Why standard deviations? That recipe is actually a stack of probability claims: that a channel's readings follow a distribution, that the distribution is roughly Gaussian, and that Gaussian tails (the far edges of the curve) assign tiny probability past 3 sigma. Gaussian is the bell curve formally called the Normal distribution: two names for one shape, and no relation to 'normal' meaning non-anomalous. This lesson unpacks the stack, because when detection misbehaves in production, the broken piece is almost always one of those claims.
</Dialogue>

## A Reading Is a Random Variable

Ask a telemetry channel for its next value and you cannot say what number comes back, only which numbers are plausible. That object, a quantity whose individual outcomes are unpredictable but whose long-run pattern is stable, is a **random variable**. Frontend code is full of them: request latency, time-to-interactive, the number of retries before a flaky endpoint answers.

<BridgeCallout bridge={frontmatter.concept.bridge} />

A random variable is **discrete** when its outcomes are countable (retry counts: 0, 1, 2, ...) and **continuous** when outcomes fill a range (latency: any positive number of milliseconds). The distinction decides which kind of distribution describes it.

## Histograms Grow Up: PMF and PDF

A discrete random variable is fully described by its **probability mass function (PMF)**: a table mapping each outcome to its probability, all entries summing to 1. A normalized histogram of enough observations converges to it.

<CodeBlock language="typescript" title="empirical-pmf.ts">
{`// Retries observed across 1,000 requests
const retryCounts = [0, 0, 1, 0, 2, 0, 1, 0, 0, 3 /* ... */];

function empiricalPmf(samples: number[]): Map<number, number> {
  const counts = new Map<number, number>();
  for (const s of samples) counts.set(s, (counts.get(s) ?? 0) + 1);
  const pmf = new Map<number, number>();
  for (const [value, count] of counts) pmf.set(value, count / samples.length);
  return pmf;  // probabilities, summing to 1
}`}
</CodeBlock>

A continuous random variable cannot have a PMF: the probability of latency being *exactly* 137.2941... ms is zero. Instead it has a **probability density function (PDF)**. Density is not probability; it is probability per unit of width. Only areas under the PDF are probabilities, and the total area is 1. This is why a PDF can exceed 1 without contradiction: a Normal distribution (introduced below) with sigma = 0.1 peaks near 4, and that is a density, not a chance.

## Expectation and Variance, from the Distribution Side

You have computed means and variances of *samples* since Foundations. The distribution-side versions are what those estimate:

<CodeBlock language="typescript" title="expectation.ts">
{`// Expected value: probability-weighted average over ALL outcomes
// E[X] = sum(x_i * p_i)          (discrete)
function expectedValue(values: number[], probs: number[]): number {
  return values.reduce((s, x, i) => s + x * probs[i], 0);
}

// Variance: expected squared distance from the mean
// Var[X] = E[(X - E[X])^2]
function distVariance(values: number[], probs: number[]): number {
  const mu = expectedValue(values, probs);
  return values.reduce((s, x, i) => s + (x - mu) ** 2 * probs[i], 0);
}

// A die: E = 3.5, Var = 2.9167
const faces = [1, 2, 3, 4, 5, 6];
const fair = Array(6).fill(1 / 6);
console.log(expectedValue(faces, fair));  // 3.5
console.log(distVariance(faces, fair));   // 2.9166...`}
</CodeBlock>

The sample mean estimates E[X]; the sample variance estimates Var[X]. One wrinkle worth naming: the sample variance measures deviations from the sample's own mean, and that mean sits closer to its data than the true E[X] does. The squared deviations therefore come out systematically a little small, so dividing by n underestimates Var[X]. Dividing by n - 1 instead is the standard correction for that bias, which is why pandas and many calculators default to it. For [2, 4, 6] the divide-by-n version gives 8/3, about 2.667, while the n - 1 version gives 4. This course grades the divide-by-n (population) formula throughout, for consistency with tf.moments and numpy; the pandas lesson in the Python Bridge module shows the numeric cost of mixing the two.

Every loss function you have minimized is an expectation estimated by an average over training examples: MSE (mean squared error, from the Training Loop module) is E[(prediction - truth)^2] with the expectation replaced by a mean over the batch. That substitution, average-for-expectation, is the single most used move in machine learning.

## Three Distributions That Cover Most of ML

**Uniform(a, b): total ignorance over a range.** Every value between a and b is equally dense. `Math.random()` samples Uniform(0, 1); weight initializers draw from scaled uniforms precisely because before training there is no reason to prefer one direction over another.

**Normal(mu, sigma): the shape of accumulated noise.** Symmetric, bell-curved, fully described by its center and spread. Its density is `pdf(x) = exp(-((x - mu) ** 2) / (2 * sigma ** 2)) / (sigma * Math.sqrt(2 * Math.PI))`. Plug in x = mu and sigma = 0.1: the exponential is exp(0) = 1, so the peak is the coefficient alone, 1 / (0.1 * sqrt(2 * PI)) = 3.989, the peak near 4 from the PDF section. Sensor noise and measurement error tend Normal, and after enough training so do a model's residuals (the leftover errors, prediction minus truth), for a reason the next section makes precise. The 3-sigma rule is a fact about THIS distribution: it puts probability about 0.0027 outside mu plus or minus 3 sigma. Quote "3 sigma catches 99.7%" and you are implicitly claiming your data is Gaussian.

**Binomial(n, p): counting successes in independent tries.** Flip n independent coins that each land heads with probability p; the count of heads is Binomial. The workhorse question it answers for a detector: if each of 64 channels independently has a 5% chance of tripping its threshold on a calm reading, how many trips should one sweep of the whole board produce?

<CodeBlock language="typescript" title="binomial.ts">
{`// P(exactly k successes in n tries) = C(n, k) * p^k * (1-p)^(n-k)
function binomialProbability(n: number, k: number, p: number): number {
  let c = 1;  // C(n, k), built iteratively to avoid factorial overflow
  for (let i = 0; i < k; i++) c = (c * (n - i)) / (i + 1);
  return c * p ** k * (1 - p) ** (n - k);
}

// 64 channels, each 5% likely to trip on calm data:
console.log(binomialProbability(64, 0, 0.05));  // 0.0375: all-quiet is RARE
// Expected trips on one perfectly calm sweep of the board: n * p = 3.2 channels
// A calm board should show a few lit channels. Zero lit is itself unusual.`}
</CodeBlock>

That 0.0375 is worth staring at: on a fully calm signal, a completely dark board happens less than 4% of the time. A detector that treats *any* tripped channel as an anomaly will fire on nearly every calm sweep. Per-channel thresholds must be combined with the Binomial in mind: expect about n * p = 3.2 tripped channels on a calm sweep, and alarm on counts well above that, never on a single trip.

## The Central Limit Theorem

Take n independent random variables from almost ANY distribution, average them, and the average's distribution approaches a Normal as n grows. That is the **Central Limit Theorem**, and it is why the Gaussian appears everywhere: quantities that are sums of many small independent effects (sensor noise, aggregate latency, batch gradients) inherit the bell curve regardless of what shaped their parts.

<CodeBlock language="typescript" title="clt-demo.ts">
{`// Uniform(0, 1) is flat as a table. Average 64 of them:
function averageOfUniforms(n: number): number {
  let s = 0;
  for (let i = 0; i < n; i++) s += Math.random();
  return s / n;
}

const samples = Array.from({ length: 10_000 }, () => averageOfUniforms(64));
// Histogram these and the flat source produces a tight bell curve:
// mean 0.5, standard deviation 0.036. Where that comes from: Uniform(0, 1)
// has variance 1/12 (check it with distVariance on a fine grid over [0, 1]),
// and averaging n independent draws divides variance by n, so
// sd = sqrt((1/12) / 64) = 1 / sqrt(768) = 0.036. Or skip the algebra:
// compute the sd of the samples array directly; it lands within a hair of 0.036.
// Nothing Gaussian went in. Gaussian came out. That is the CLT working.`}
</CodeBlock>

This is the missing justification for the z-score recipe: a channel reading that aggregates many small independent physical effects is pushed toward Normal by the CLT, and once it is Normal, 3 sigma really does mean probability 0.0027. But read the fine print, because production data violates it in two standard ways. **Heavy tails:** if rare huge effects dominate (one GC pause, one solar flare), averages converge slowly or not at all, and 3-sigma events become routine. **Correlation:** the CLT needs the many small effects inside one reading to be independent, with none of them dominant. Hull vibration is a single shared driver that dominates them all, so the reading's distribution follows the hull's shape, whatever that is, instead of being pushed toward Normal. Correlation across channels is a different failure: it leaves each channel's distribution alone, but it makes trips arrive in clusters, which breaks the board-level Binomial count from the previous section. When your detector cries wolf in production, check these two before blaming the threshold.

## Covariance and Correlation

The fine print said "correlated" without measuring it. The measure is two lines of arithmetic. Take paired readings from two channels, x and y, and look at each pair's deviations from its own channel's mean. **Covariance** is the average product of those paired deviations. Channels that vibrate together produce deviations that share a sign, so the products pile up positive; channels that move independently produce as many opposite-sign products as matching ones, and the average cancels toward zero.

Covariance carries units (channel units squared), which makes its raw size hard to judge. Divide by both standard deviations and the units cancel: **correlation**, written rho, is cov(x, y) / (sigma_x * sigma_y), where sigma_x and sigma_y are the two channels' standard deviations. It always lands between -1 and 1: independent noise gives rho near 0, and two channels bolted to the same vibrating hull push rho toward 1.

<CodeBlock language="typescript" title="covariance.ts">
{`// Average product of paired deviations
function covariance(x: number[], y: number[]): number {
  const mx = x.reduce((s, v) => s + v, 0) / x.length;
  const my = y.reduce((s, v) => s + v, 0) / y.length;
  return x.reduce((s, v, i) => s + (v - mx) * (y[i] - my), 0) / x.length;
}

function correlation(x: number[], y: number[]): number {
  const sx = Math.sqrt(covariance(x, x));  // cov(x, x) is just Var[x]
  const sy = Math.sqrt(covariance(y, y));
  return covariance(x, y) / (sx * sy);
}`}
</CodeBlock>

Correlation is the number that prices the fine print. Average n independent readings and the noise variance divides by n. Average n readings that share a driver and the shared part never shrinks: the variance of the average floors at rho times the single-reading variance, no matter how large n grows. That floor is why a wall of correlated channels smooths less than the independence math promises, and it reappears anywhere averaging is supposed to cancel error, model ensembles included.

## Conditional Probability and the Independence Assumption

`P(A | B)`, the probability of A given that B happened, is computed by shrinking the world to outcomes where B is true and renormalizing (dividing by P(B) so the probabilities in the shrunken world again sum to 1): `P(A | B) = P(A and B) / P(B)`. Two events are **independent** when conditioning changes nothing: `P(A | B) = P(A)`. Knowing B told you nothing about A.

Every claim in this lesson quietly leaned on independence: the Binomial assumed channels trip independently; the CLT assumed effects accumulate independently. Independence is the assumption you buy convenience with, and hull channels bolted to the same frame are the standard counterexample. Bayes' theorem, covered in the next lesson of this module, is what you get when you run conditional probability backwards: from P(evidence | cause), which physics gives you, to P(cause | evidence), which the bridge crew actually needs.
