In the Training Loop module, L2 regularization came up as one of the standard answers to overfitting, though the crew's fix that night was early stopping. But why would adding a penalty on weight magnitude help at all? The answer comes from Bayesian probability: L2 regularization is equivalent to assuming a Gaussian prior on your weights (a Gaussian is the Normal bell curve from The Statistics of Signals). This lesson connects probability theory to the practical techniques you've already used.

## Priors and Posteriors as State

In frontend development, state management follows a clear pattern: you start with a default state, then update it as events arrive. Bayesian inference works identically.

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="bayes-as-state.ts">
{`// Frontend state management
type State = { count: number };
type Action = { type: 'increment' } | { type: 'decrement' };

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case 'increment': return { count: state.count + 1 };
    case 'decrement': return { count: state.count - 1 };
  }
}

// Bayesian inference is the same pattern:
// Prior (default state) + Evidence (action) = Posterior (new state)

// P(hypothesis | data) = P(data | hypothesis) * P(hypothesis) / P(data)
// posterior            = likelihood           * prior           / evidence

function bayesUpdate(
  prior: number[],        // P(hypothesis): your current beliefs
  likelihood: number[],   // P(data | hypothesis): how well each hypothesis explains the data
): number[] {
  // Unnormalized posterior
  const unnormalized = prior.map((p, i) => p * likelihood[i]);
  // Normalize so probabilities sum to 1. This total IS the evidence
  // P(data) from the formula: dividing by it is all the denominator
  // ever does.
  const total = unnormalized.reduce((s, v) => s + v, 0);
  return unnormalized.map(v => v / total);
}`}
</CodeBlock>

## Conditional Probability, the Grammar Underneath

`P(A | B)` reads "the probability of A, given that B happened." Conditioning shrinks the world: throw away every outcome where B is false, then ask how often A holds among what survives. Formally, `P(A | B) = P(A and B) / P(B)`, and the division is what renormalizes the shrunken world so its probabilities sum to 1 again.

The order of the bar matters more than any other notation in this lesson. `P(rapid clicks | bot)` asks how bots behave; `P(bot | rapid clicks)` asks what a click burst means. They are different numbers computed from different shrunken worlds, and swapping them is the classic base-rate mistake. Bayes' theorem, next, is nothing more than the algebra that converts the one you can measure into the one you actually want.

<CodeBlock language="typescript" title="bayes-example.ts">
{`// Scenario: Is a user a bot or human?
// Prior: 5% of traffic is bots
// Evidence: user clicked 100 times in 10 seconds

function bayesUpdate(prior: number[], likelihood: number[]): number[] {
  const unnormalized = prior.map((p, i) => p * likelihood[i]);
  const total = unnormalized.reduce((s, v) => s + v, 0);
  return unnormalized.map(v => v / total);
}

// Prior beliefs: [P(human), P(bot)]
let beliefs = [0.95, 0.05];

// Observation 1: 100 clicks in 10 seconds
// Likelihood: P(100 clicks | human) = 0.001, P(100 clicks | bot) = 0.8
beliefs = bayesUpdate(beliefs, [0.001, 0.8]);
console.log('After rapid clicks:', beliefs.map(b => b.toFixed(4)));
// [0.0232, 0.9768]: now we strongly suspect bot

// Observation 2: user solves a CAPTCHA correctly
// Likelihood: P(solve | human) = 0.95, P(solve | bot) = 0.1
beliefs = bayesUpdate(beliefs, [0.95, 0.1]);
console.log('After CAPTCHA pass:', beliefs.map(b => b.toFixed(4)));
// [0.1841, 0.8159]: bot still leads, but one human-like action
// dragged its lead from 98% down to 82%

// Each observation updates our beliefs incrementally
// This is EXACTLY how sequential learning works in ML`}
</CodeBlock>

## Regularization as a Prior

The connection runs deep: when you add L2 regularization to your loss function, you're making a Bayesian statement about your weights.

**Why squared error is a negative log probability.** Combine two things you already built. The Statistics of Signals gave you the Normal PDF, density proportional to `exp(-(error^2) / (2 * sigma^2))`, along with the observation that prediction residuals tend Gaussian. Information Theory for ML priced a probability at `-log(p)`. Now assume each training example's error (its `y_pred - y_true` gap) is independent bell-curve noise with a fixed spread `sigma`. Then `P(data | weights)` is a product of `exp(-error^2 / (2 * sigma^2))` terms, one per data point. Take `-log` of that product: the log turns the product into a sum and cancels the `exp`, leaving `sum(error^2) / (2 * sigma^2)` plus a constant that does not involve the weights. Constants and positive scale factors never move the location of a minimum, so minimizing squared error IS maximizing the Gaussian likelihood. The same move applied to a Gaussian prior on the weights, `P(w)` proportional to `exp(-w^2 / (2 * sigma_prior^2))`, yields `lambda * sum(w^2)` with `lambda = 1 / (2 * sigma_prior^2)`: the tighter your prior belief, the bigger the lambda.

<CodeBlock language="typescript" title="regularization-prior.ts">
{`import * as tf from '@tensorflow/tfjs';

// Standard loss: minimize prediction error
// L = sum((y_pred - y_true)^2)

// L2 regularized loss: minimize error + keep weights small
// L = sum((y_pred - y_true)^2) + lambda * sum(w^2)

// Bayesian interpretation (assuming each observation is the true value
// plus Gaussian noise of fixed variance, as derived above):
// sum((y_pred - y_true)^2)  =  -log P(data | weights) + const   [likelihood]
// lambda * sum(w^2)         =  -log P(weights) + const          [prior]
// Total loss                =  -log P(weights | data) + const   [posterior]
// Each equality holds up to constants and positive scale factors
// that do not move the minimum.

// Minimizing L2-regularized loss = finding the MAP estimate
// (Maximum A Posteriori: the most probable weights given data AND prior)

// The lambda * sum(w^2) term is equivalent to a Gaussian prior
// centered at zero with variance 1/(2*lambda)
// Larger lambda = smaller variance = tighter prior = more regularization

// Demonstration
const x = tf.tensor2d([[1], [2], [3], [4], [5]]);
const yTrue = tf.tensor2d([[2.1], [3.9], [6.2], [7.8], [10.1]]);

// Without regularization (pure maximum likelihood)
const wML = tf.variable(tf.randomNormal([1, 1]));
const optimizerML = tf.train.sgd(0.01);
for (let i = 0; i < 200; i++) {
  optimizerML.minimize(() => tf.losses.meanSquaredError(yTrue, tf.matMul(x, wML)));
}
console.log('ML estimate:', await wML.array());

// With L2 regularization (MAP with Gaussian prior)
const wMAP = tf.variable(tf.randomNormal([1, 1]));
const lambda = 0.1;
const optimizerMAP = tf.train.sgd(0.01);
for (let i = 0; i < 200; i++) {
  optimizerMAP.minimize(() => {
    const pred = tf.matMul(x, wMAP);
    const mseLoss = tf.losses.meanSquaredError(yTrue, pred);
    const l2Penalty = wMAP.square().sum().mul(lambda);
    return mseLoss.add(l2Penalty) as tf.Scalar;
  });
}
console.log('MAP estimate:', await wMAP.array());
// MAP estimate is pulled toward zero by the prior`}
</CodeBlock>

## Maximum Likelihood, Concretely

Before contrasting maximum likelihood with MAP, pin the term down with the smallest example that works: estimating a coin's bias. You flip a coin 10 times and see 7 heads. For any candidate bias p, the Binomial PMF from The Statistics of Signals tells you exactly how probable that outcome was. Maximum likelihood scans the candidates and keeps the one that made your data most probable.

<CodeBlock language="typescript" title="mle-coin.ts">
{`// Estimate a coin's bias by maximum likelihood.
// Data: 7 heads in 10 flips. Which bias p explains this best?

// The Binomial PMF from The Statistics of Signals:
// C(n, k) * p^k * (1-p)^(n-k)
function binomialProbability(n: number, k: number, p: number): number {
  let coeff = 1;
  for (let i = 0; i < k; i++) coeff *= (n - i) / (i + 1);
  return coeff * p ** k * (1 - p) ** (n - k);
}

let bestP = 0;
let bestL = 0;
for (let i = 0; i <= 20; i++) {
  const p = i / 20;                                 // 0.00, 0.05, ..., 1.00
  const likelihood = binomialProbability(10, 7, p); // P(7 heads | p)
  if (likelihood > bestL) { bestL = likelihood; bestP = p; }
}
console.log('Best p:', bestP.toFixed(2), 'likelihood:', bestL.toFixed(4));
// Best p: 0.70 likelihood: 0.2668

// Spot-check the neighborhood (C(10, 7) = 120):
// L(0.5) = 120 * 0.5^7 * 0.5^3 = 0.1172
// L(0.6) = 120 * 0.6^7 * 0.4^3 = 0.2150
// L(0.7) = 120 * 0.7^7 * 0.3^3 = 0.2668   <- the peak
// L(0.8) = 120 * 0.8^7 * 0.2^3 = 0.2013
// The peak lands at exactly k/n = 7/10: the observed frequency.
// No prior, no regularization: the data alone picks the answer.`}
</CodeBlock>

This is where the losses you already use come from. Binary cross-entropy from the Training Loop module is the negative log likelihood of 0/1 labels under the model's predicted probabilities, which is why a classifier that knows nothing and outputs 0.5 opens at ln(2), 0.6931: the negative log likelihood of a fair coin. And mean squared error is a negative log likelihood too, but only under the Gaussian noise assumption from the previous section. Training by minimizing loss is maximum likelihood wearing different clothes; MAP, next, is what you get when a prior joins in.

## Maximum Likelihood vs MAP

<CodeBlock language="typescript" title="ml-vs-map.ts">
{`// Maximum Likelihood (ML): Find weights that maximize P(data | weights)
//   = Find the weights that best explain the data
//   = No prior, no regularization
//   = Can overfit with limited data

// Maximum A Posteriori (MAP): Find weights that maximize P(weights | data)
//   = P(data | weights) * P(weights), likelihood times prior
//   = L2 regularization when prior is Gaussian
//   = L1 regularization (sum of |w|) when the prior is the Laplace
//     distribution, a sharp peak at zero with heavy tails, which is
//     why L1 pushes weights to exactly zero
//   = Better generalization

// With lots of data, ML and MAP converge (data overwhelms the prior)
// With little data, the prior matters a lot (regularization helps)

// This is why regularization helps more with small datasets:
// the prior (regularizer) fills in where data is missing

function mapEstimate(
  data: number[],
  priorMean: number,
  priorVariance: number,
  dataVariance: number
): number {
  const n = data.length;
  const dataMean = data.reduce((s, v) => s + v, 0) / n;

  // MAP estimate: weighted average of prior mean and data mean.
  // Each vote's weight is confidence, and confidence is 1/variance:
  // a tight distribution earns a big vote, a vague one a small vote.
  // The data side casts n votes of 1/dataVariance each; equivalently,
  // averaging n independent readings shrinks the mean's variance to
  // dataVariance/n (the averaging effect behind the Central Limit
  // Theorem in The Statistics of Signals), so its confidence is
  // n/dataVariance. For a Gaussian prior plus Gaussian noise this
  // weighted average is the exact posterior mean, not an approximation.
  const priorWeight = 1 / priorVariance;
  const dataWeight = n / dataVariance;

  return (priorWeight * priorMean + dataWeight * dataMean) /
         (priorWeight + dataWeight);
}

// Few data points: prior has strong influence
console.log('MAP (2 points):', mapEstimate([5, 7], 0, 1, 1).toFixed(3));
// 4.000: the data mean of 6, dragged a third of the way to the prior's 0

// Many data points: data dominates
console.log('MAP (100 points):', mapEstimate(
  Array(100).fill(6), 0, 1, 1
).toFixed(3));
// 5.941: one hundred votes of 6 against a single vote of 0`}
</CodeBlock>

## Dropout as Approximate Bayesian Inference

<CodeBlock language="typescript" title="dropout-bayes.ts">
{`import * as tf from '@tensorflow/tfjs';

// Dropout randomly zeros out neurons during training.
// Bayesian interpretation: dropout trains an ensemble of
// sub-networks, each with different weights zeroed out.
//
// Recall MAP: it keeps only the single most probable set of weights.
// The full posterior is a whole distribution of plausible weights.
// Each random sub-network behaves like one sample drawn from that
// distribution. Average many samples and you approximate the
// posterior mean; their spread plays the role of the posterior's
// width, the uncertainty computed below.
//
// At inference with dropout ON (Monte Carlo dropout; "Monte Carlo"
// is the standard name for estimating something by repeated random
// sampling):
// - Run the same input N times with random dropout
// - The variance of outputs estimates model uncertainty
//
// This is approximate Bayesian inference!

async function mcDropoutPredict(
  model: tf.LayersModel,
  input: tf.Tensor,
  nSamples: number
): Promise<{ mean: number[]; uncertainty: number[] }> {
  const predictions: number[][] = [];

  for (let i = 0; i < nSamples; i++) {
    // model.apply() with training:true keeps dropout ACTIVE. This is the
    // load-bearing line: model.predict() ignores a training option
    // entirely, silently disables dropout, and returns the same output
    // every run, an uncertainty of exactly zero for every input.
    const pred = model.apply(input, { training: true }) as tf.Tensor;
    predictions.push(await pred.array() as number[]);
    pred.dispose();
  }

  // Mean = best estimate
  // Standard deviation (the sqrt of the variance) = uncertainty:
  // how widely the sampled predictions spread, which is how wide
  // the posterior is
  const mean = predictions[0].map((_, j) =>
    predictions.reduce((s, p) => s + p[j], 0) / nSamples
  );
  const uncertainty = predictions[0].map((_, j) => {
    const m = mean[j];
    const variance = predictions.reduce((s, p) => s + (p[j] - m) ** 2, 0) / nSamples;
    return Math.sqrt(variance);
  });

  return { mean, uncertainty };
}

// High uncertainty = model is unsure = want more data in this region
// Low uncertainty = model is confident = predictions are reliable`}
</CodeBlock>
