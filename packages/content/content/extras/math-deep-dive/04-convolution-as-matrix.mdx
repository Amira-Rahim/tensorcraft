<Dialogue speaker="Instructor">
In the Signal Processing module, you applied convolution as a sliding window over data. That's the intuitive view. But mathematically, convolution is matrix multiplication in disguise. The kernel becomes a special structured matrix called a Toeplitz matrix, and the "sliding" becomes a single matrix-vector multiply. GPUs are built for matrix math, which is why they run convolutions so fast.
</Dialogue>

## The Sliding Window as a Matrix

When you convolve a kernel `[a, b, c]` with an input `[x1, x2, x3, x4, x5]`, you slide the kernel across and compute dot products. But you can express this as a single matrix multiplication:

<BridgeCallout bridge={frontmatter.concept.bridge} />

<CodeBlock language="typescript" title="toeplitz-basic.ts">
{`import * as tf from '@tensorflow/tfjs';

// Kernel: [1, 0, -1] (edge detector, like a CSS filter)
// Input:  [3, 7, 2, 8, 4]

// Sliding window (the intuitive way):
// Position 0: 1*3 + 0*7 + (-1)*2 = 1
// Position 1: 1*7 + 0*2 + (-1)*8 = -1
// Position 2: 1*2 + 0*8 + (-1)*4 = -2

const kernel = tf.tensor1d([1, 0, -1]);
const input = tf.tensor1d([3, 7, 2, 8, 4]);

// The SAME operation as a Toeplitz matrix:
const toeplitz = tf.tensor2d([
  [1,  0, -1,  0,  0],   // kernel at position 0
  [0,  1,  0, -1,  0],   // kernel at position 1
  [0,  0,  1,  0, -1],   // kernel at position 2
]);

const resultMatrix = tf.matMul(toeplitz, input.reshape([5, 1]));
console.log('Matrix result:', await resultMatrix.array());
// [[1], [-1], [-2]]: identical to the sliding window

// Using tf.conv1d for comparison
const resultConv = tf.conv1d(
  input.reshape([1, 5, 1]),
  kernel.reshape([3, 1, 1]),
  1,    // stride
  'valid'
);
console.log('Conv1d result:', await resultConv.array());
// [[[1], [-1], [-2]]]: same answer
//
// Naming caveat: what deep learning calls "convolution" (tf.conv1d and
// every conv layer) is really CROSS-CORRELATION, it slides the kernel
// without flipping it, which is what the Toeplitz above matches. True
// mathematical convolution flips the kernel first. The convolution
// theorem below is stated for the true (flipped) operation; to reproduce
// tf.conv1d through an FFT you flip the kernel before transforming.`}
</CodeBlock>

## Building a Toeplitz Matrix

The pattern is simple: each row of the Toeplitz matrix is the kernel shifted one position to the right, padded with zeros. The diagonals are constant. That's the defining property of a Toeplitz matrix.

<CodeBlock language="typescript" title="build-toeplitz.ts">
{`import * as tf from '@tensorflow/tfjs';

function buildToeplitz(kernel: number[], inputLength: number): number[][] {
  const kernelLength = kernel.length;
  const outputLength = inputLength - kernelLength + 1; // 'valid' padding
  const matrix: number[][] = [];

  for (let i = 0; i < outputLength; i++) {
    const row = new Array(inputLength).fill(0);
    for (let j = 0; j < kernelLength; j++) {
      row[i + j] = kernel[j];
    }
    matrix.push(row);
  }
  return matrix;
}

// Build Toeplitz for a 3-element kernel on 7-element input
const kernel = [1, -2, 1]; // second-difference operator: the discrete
// version of a second derivative (lesson 2 of this module), it measures
// how sharply the signal bends at each point
const T = buildToeplitz(kernel, 7);

console.log('Toeplitz matrix:');
T.forEach(row => console.log(row.map(v => v.toString().padStart(3)).join(' ')));
// Each row is the kernel shifted right by one position:
//   1 -2  1  0  0  0  0
//   0  1 -2  1  0  0  0
//   0  0  1 -2  1  0  0
//   0  0  0  1 -2  1  0
//   0  0  0  0  1 -2  1

// Apply it
const input = tf.tensor1d([1, 4, 6, 4, 1, 0, 2]);
const toeplitzTensor = tf.tensor2d(T);
const result = tf.matMul(toeplitzTensor, input.reshape([7, 1]));
console.log('Result:', await result.flatten().array());`}
</CodeBlock>

## The Convolution Theorem

A classic result, and the reason FFT-based convolution exists: **convolution in the time domain equals element-wise multiplication in the frequency domain**. The FFT and the frequency view here are the ones you built in Signal Processing lessons 1 and 2. The theorem means you can compute convolution by:

1. FFT the input
2. FFT the kernel
3. Multiply element-wise
4. Inverse FFT

For large kernels, this is dramatically faster than sliding the window.

<CodeBlock language="typescript" title="convolution-theorem.ts">
{`import * as tf from '@tensorflow/tfjs';

// Demonstrate the convolution theorem: run the direct path and the
// FFT path on the same input and compare the numbers.

// Why anyone bothers: direct convolution costs O(n * k) where n = input
// size, k = kernel size. The FFT route costs O(n * log(n)) no matter
// how big k gets. In neural networks kernels are small (3x3, 5x5), so
// the direct matrix-multiply path is usually faster. In audio, a reverb
// kernel is a recorded echo pattern of a room (an "impulse response")
// and can be 48000 samples long; there the FFT route wins massively.

// One catch before the code: the DFT silently assumes your signal
// repeats forever, so FFT-based convolution is CIRCULAR: samples the
// kernel would slide past on the right re-enter from the left, as if
// the array were a loop. Padding both signals to length n + k - 1
// gives the k - 1 wrapped samples nothing but zeros to land on, so
// the circular answer equals the ordinary linear one.

const n = 8;
const k = 3;
const input = tf.tensor1d([1, 2, 4, 3, 0, 1, 2, 1]);
const kernel = tf.tensor1d([0.25, 0.5, 0.25]); // smoothing kernel

// Path 1: direct convolution
const direct = tf.conv1d(
  input.reshape([1, n, 1]),
  kernel.reshape([k, 1, 1]),
  1,
  'valid'
);
console.log('Direct: ', await direct.flatten().array());
// [2.25, 3.25, 2.5, 1, 1, 1.5]
// Check position 0 by hand: 0.25*1 + 0.5*2 + 0.25*4 = 2.25

// Path 2: FFT both, multiply, inverse FFT.
// The naming caveat from the first block matters here: tf.conv1d slides
// WITHOUT flipping, so the FFT path needs the FLIPPED kernel. Ours is
// symmetric ([0.25, 0.5, 0.25] reads the same both ways), so the flip
// is a no-op; for an asymmetric kernel, tf.reverse it first.
const len = n + k - 1; // 10: room for the wraparound to hit only zeros
const inputF = tf.spectral.rfft(input.pad([[0, len - n]]));
const kernelF = tf.spectral.rfft(kernel.pad([[0, len - k]]));

// Element-wise COMPLEX multiply. tf.mul does not handle complex
// tensors, so use real/imag parts: (a+bi)(c+di) = (ac-bd) + (ad+bc)i
const a = tf.real(inputF);
const b = tf.imag(inputF);
const c = tf.real(kernelF);
const d = tf.imag(kernelF);
const product = tf.complex(
  a.mul(c).sub(b.mul(d)),
  a.mul(d).add(b.mul(c))
);

// Inverse FFT gives the FULL length-10 convolution; the 'valid' region
// starts after the k - 1 = 2 edge samples and holds n - k + 1 = 6 values.
const full = tf.spectral.irfft(product);
const viaFft = full.slice([k - 1], [n - k + 1]);
console.log('Via FFT:', await viaFft.array());
// [2.25, 3.25, 2.5, 1, 1, 1.5] (up to float32 rounding): the same six
// numbers, computed as a multiplication in the frequency domain

// The connection to matrix multiplication: for CIRCULAR convolution,
// the Toeplitz matrix becomes "circulant": each row still shifts the
// kernel right, but whatever falls off the right edge wraps back in on
// the left. Circulant matrices have a special property: FFT the input
// first, and multiplying by the matrix collapses into independent
// per-frequency scalings, where the scale factors are the FFT of the
// kernel; an inverse FFT brings you back. Name the FFT step F, its
// undo-step F^(-1), and the diagonal matrix of scale factors D, and
// that reads C = F^(-1) * D * F. The three-step pipeline you just ran
// IS that equation. This is WHY the convolution theorem works.`}
</CodeBlock>

## Why This Matters for GPUs

GPUs have thousands of cores optimized for matrix multiplication. By expressing convolution as a matrix multiply (via Toeplitz or the related im2col approach), convolution layers run at near-peak GPU throughput. Frameworks never materialize the giant Toeplitz matrix itself; im2col builds a compact matrix of input patches that achieves the same single-multiply effect, which is the structure-exploiting shortcut the bridge callout mentions. This is the fundamental reason deep learning took off when GPUs became accessible.

<CodeBlock language="typescript" title="performance-insight.ts">
{`import * as tf from '@tensorflow/tfjs';

// In practice, frameworks use im2col (image to column):
// 1. Rearrange input patches into columns of a matrix
// 2. Reshape kernel into a matrix
// 3. Single matrix multiply = all convolution outputs
//
// This trades memory for speed: classic CS tradeoff

// Benchmark: naive JS sliding window vs tf.conv1d, 100 runs each
const inputLength = 1000;
const kernelSize = 5;
const inputData = Float32Array.from({ length: inputLength }, () => Math.random());
const kernelData = Float32Array.from({ length: kernelSize }, () => Math.random());

// Baseline: the sliding window as a plain JS loop
const jsStart = performance.now();
for (let run = 0; run < 100; run++) {
  const out = new Float32Array(inputLength - kernelSize + 1);
  for (let i = 0; i < out.length; i++) {
    let sum = 0;
    for (let j = 0; j < kernelSize; j++) {
      sum += inputData[i + j] * kernelData[j];
    }
    out[i] = sum;
  }
}
const jsElapsed = performance.now() - jsStart;

// The same work through tf.conv1d (matrix multiply under the hood)
const input = tf.tensor1d(inputData).reshape([1, inputLength, 1]);
const filter = tf.tensor1d(kernelData).reshape([kernelSize, 1, 1]);

const tfStart = performance.now();
let result: tf.Tensor | null = null;
for (let i = 0; i < 100; i++) {
  result?.dispose();
  result = tf.conv1d(input, filter, 1, 'valid');
}
await result!.data(); // force the GPU to finish before reading the clock
const tfElapsed = performance.now() - tfStart;

console.log(\`Sliding window (JS): \${jsElapsed.toFixed(1)}ms\`);
console.log(\`tf.conv1d:           \${tfElapsed.toFixed(1)}ms\`);

// Run it and read your own numbers. At this toy size the plain loop can
// win: each conv1d call pays a fixed GPU-dispatch cost that dwarfs the
// 996 windows x 5 taps = 4980 multiply-adds. The matrix path pulls
// ahead as the work grows: make the kernel 2D, the input an image
// batch, the channels 64, and the JS loop falls hopelessly behind
// while conv stays one matrix multiply.`}
</CodeBlock>
